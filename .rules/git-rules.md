# Git/GitHub Работа - Строгие Правила

## КРИТИЧЕСКИЕ ЗАПРЕТЫ

### ❌ НИКОГДА НЕ ВЫПОЛНЯТЬ БЕЗ ЯВНОГО ПОДТВЕРЖДЕНИЯ:

1. **`git filter-repo`** - переписывает всю историю
2. **`git filter-branch`** - переписывает всю историю
3. **`git push --force`** или **`git push -f`** - перезаписывает remote
4. **`git reset --hard`** к старым коммитам - удаляет изменения
5. **`git rebase`** на pushed коммитах - меняет историю
6. **`git commit --amend`** на pushed коммитах - меняет историю
7. **Удаление веток на remote** - потеря данных
8. **Изменение коммитов старше 24 часов** - риск конфликтов

## ОБЯЗАТЕЛЬНАЯ ПРОЦЕДУРА ПЕРЕД ОПАСНЫМИ ОПЕРАЦИЯМИ

### Шаги:

1. **Создать backup ветку:**
   ```bash
   git branch backup-YYYY-MM-DD-HH-MM
   git push origin backup-YYYY-MM-DD-HH-MM
   ```

2. **Спросить пользователя:**
   ```
   ⚠️ ОПАСНАЯ ОПЕРАЦИЯ: [название операции]

   Что будет сделано:
   - [описание действия]

   Риски:
   - [возможные последствия]

   Backup ветка создана: backup-YYYY-MM-DD-HH-MM

   Вы подтверждаете выполнение? (ответьте "ДА ПОДТВЕРЖДАЮ")
   ```

3. **Дождаться явного подтверждения**
   - Только текст "ДА ПОДТВЕРЖДАЮ" означает разрешение
   - Любой другой ответ = отмена операции

4. **Выполнить операцию и отчитаться о результате**

## БЕЗОПАСНЫЕ ОПЕРАЦИИ (не требуют подтверждения)

### ✅ Чтение и просмотр:
- `git status` - статус изменений
- `git log` - история коммитов
- `git diff` - различия
- `git show` - показать коммит
- `git branch` - список веток
- `git remote -v` - список remotes
- `git reflog` - журнал операций

### ✅ Обычная работа:
- `git add` - добавление файлов
- `git commit -m "message"` - новый коммит
- `git push` (без --force) - отправка в remote
- `git pull` - получение изменений
- `git fetch` - скачивание веток
- `git checkout -b new-branch` - создание ветки
- `git stash` - временное сохранение

## ОПЕРАЦИИ, ТРЕБУЮЩИЕ ПОДТВЕРЖДЕНИЯ

### ⚠️ Изменение истории:
- `git commit --amend` - изменение последнего коммита
- `git rebase` - перебазирование
- `git reset --hard` - жесткий сброс
- `git cherry-pick` старых коммитов

### ⚠️ Работа с remote:
- `git push --force` - принудительная отправка
- `git push --force-with-lease` - безопасный force push
- `git push origin --delete branch-name` - удаление ветки

### ⚠️ Массовые изменения:
- `git filter-repo` - изменение всей истории
- `git filter-branch` - изменение всей истории
- Массовое переименование веток

## ПРАВИЛА РАБОТЫ С GITHUB

### 1. Загрузка/Скачивание
❌ **НЕ загружать и НЕ скачивать файлы/коммиты с GitHub без команды пользователя**
- Не делать `git pull` автоматически
- Не делать `git fetch` без необходимости
- Не клонировать репозитории самостоятельно

### 2. Изменение Remote
❌ **НЕ изменять remote репозиторий без явного разрешения**
- Не делать `push` без подтверждения результатов commit
- Не создавать/удалять ветки на GitHub
- Не изменять настройки репозитория

### 3. Конфликты
⚠️ **При конфликтах - спросить пользователя**
- Не разрешать merge конфликты самостоятельно
- Показать конфликт и спросить, как поступить
- Предложить варианты решения

### 4. Отчетность
✅ **Всегда сообщать о результатах**
- После `push` - показать результат
- После `pull` - показать что изменилось
- При ошибках - показать полный текст ошибки

## ПРАВИЛА КОММИТОВ

### Когда создавать коммит:
✅ Пользователь явно попросил: "создай коммит", "закоммить", "commit"
✅ Задача полностью завершена и протестирована
✅ Все связанные изменения сделаны

### Язык сообщений:
✅ **ТОЛЬКО АНГЛИЙСКИЙ** (English)
- Весь текст commit message должен быть на английском языке


### Когда НЕ создавать коммит:
❌ Пользователь только попросил "сохранить файл"
❌ Работа не завершена или имеет ошибки
❌ Изменения частичные или экспериментальные

### Формат commit message:
```
Краткое описание (50 символов)

Подробное описание изменений:
- Что сделано
- Зачем это нужно
- Какие файлы затронуты

Автор: Eduard Laas <info@slaed.net>
```

## ПРИМЕРЫ ОПАСНЫХ СИТУАЦИЙ

### ❌ НЕПРАВИЛЬНО:
```
Пользователь: "Удали подписи Claude из коммитов"
Ассистент: *запускает git filter-repo --force*
Результат: История уничтожена, репозиторий потерян
```

### ✅ ПРАВИЛЬНО:
```
Пользователь: "Удали подписи Claude из коммитов"
Ассистент:
⚠️ ОПАСНАЯ ОПЕРАЦИЯ: git filter-repo

Это переписывает ВСЮ историю Git и может привести к потере данных.

Альтернативы:
1. Удалить подписи только в будущих коммитах
2. Создать новый репозиторий с чистой историей
3. Продолжить с существующими подписями

Если все же нужен git filter-repo:
- Создам backup ветку
- Сделаю backup всего репозитория
- Потребуется force push (перезапишет GitHub)

Вы подтверждаете? (ответьте "ДА ПОДТВЕРЖДАЮ")
```

## ВОССТАНОВЛЕНИЕ ПОСЛЕ ОШИБОК

### Если произошла ошибка:

1. **Не паниковать**
2. **Проверить reflog:**
   ```bash
   git reflog --all
   ```

3. **Проверить backup ветки:**
   ```bash
   git branch -a | grep backup
   ```

4. **Восстановить из backup:**
   ```bash
   git reset --hard backup-branch-name
   ```

5. **Сообщить пользователю о проблеме и шагах восстановления**
