Личные сообщения SLAED — 8 вариантов оформления

Восемь принципиально разных подходов к странице index.php?name=account&op=privat. Все построены на существующих классах и токенах шаблона lite: base.css, theme.css и иконки Bootstrap Icons подключены как файлы репозитория, дополнительный CSS живёт только внутри каждого демо и снабжён собственным префиксом.

Никаких Composer, npm, React, Vue и CDN. Компоненты Magic UI не копировались — оттуда взяты только идеи (командная строка с токенами, колода фокуса, плавающая панель массовых действий).

Поле сообщения во всех вариантах — настоящий редактор. В демо смонтирован тот же Toast UI из plugins/editors/toastui, что отдаёт getTplTextarea() на боевой странице: полная панель инструментов, вставка изображений через файловый менеджер, смайлы, вкладки, скрытый текст и переключатель Markdown/Визуальный. Ниже 250 px он не сжимается — это ограничение драйвера, и каждая раскладка проверена именно с ним, а не с условной textarea.

только классы lite ноль зависимостей настоящий Toast UI в каждом варианте мобильный вид через @container клавиатурная навигация рабочий код не тронут

Рекомендация

  Вариант 2 «Две колонки» как основа, с механикой вариантов 1, 3 и 7 — собрано в финальном варианте

Двухпанельная раскладка — единственная, которая решает главную боль текущей страницы: сегодня открытие письма подменяет весь контейнер вкладки, и список исчезает. При этом она ложится на уже существующий контракт: правая панель — это ровно тот же htmx-свап в #rep<папка>, который делает setPrivateMessageRead. Данные Privat::getMessageList() и Privat::getMessageView() менять не нужно.

Что стоит взять из других вариантов:

  • Из варианта 1 — полки-плитки с счётчиками (sl-cat-ico + sl-cat-tone) вместо текстовых вкладок и штатную полосу sl-bulk-bar под списком: массовые операции у варианта 2 самое слабое место.
  • Из варианта 3 — плотность строки и колонку состояния чипсами; лента варианта 2 может быть на треть компактнее без потери читаемости.
  • Из варианта 7 — полосу активных фильтров и счётчик «найдено N из M». Это дёшево и сразу объясняет пользователю, почему список короткий. Фасеты со счётчиками — второй этап, когда появится кэш COUNT.
  • Из варианта 8 — колоду фокуса как дополнительный блок сверху, а не замену папкам: непрочитанные разбираются в один клик, а привычная модель входящие/исходящие/сохранённые остаётся.
  • Из варианта 6 — типографику области чтения: 62 знака в строке, 15/1.62. Текст письма — главное на странице.

Вариант 5 не рекомендую как основной: он требует группировки по паре участников, чего в схеме _privat нет, и конфликтует с обязательным заголовком сообщения. Вариант 8 хорош как источник идей, но целиком меняет ментальную модель раздела.

Что показала живая страница

Варианты рисовались не по догадкам: страница index.php?name=account&op=privat открывалась на стенде под учётной записью и разбиралась по разметке. Что выяснилось и учтено:

  Факты со стенда

  • Ящик реально большой: 240 писем при квоте 250, десять страниц по 25, и сверху уже висит информационный sl-alert про остаток в 10 сообщений. Вариант 7 рисовался под эту реальность, а не «на вырост».
  • Таблица списка — sl-table + sl-table-body, сортировка не включена; отправитель отдаётся ссылкой sl-author с иконкой bi-person; действия строки живут в sl-dial (шестерёнка), а не в ряду кнопок.
  • Метка состояния — sl-chip sl-message-in без тона, прочитанное гасится классом sl-hidden.
  • Просмотр письма — sl-forum-post целиком: аватар, ранг, рейтинг пользователя, всплывающая справка sl-float sl-tip, подпись в <small>.
  • Форма отправки — sl-form-row / sl-form-label / sl-form-field, поле получателя с автодополнением data-sl-user-search и <datalist>.
  • Поле сообщения — Toast UI, а не textarea. Панель из 22 кнопок (заголовки, форматирование, таблица, файловый менеджер, цитата, скрытый текст, вкладки, смайлы), внизу переключатели «Редактор / Просмотр» и «Markdown / Визуальный». Минимальная высота — 250 px. Именно этот редактор смонтирован во всех восьми демо.

  Побочная находка: на вкладке «Отправить» редактор не появляется

Когда вкладка «Отправить» открывается штатным htmx-свапом, Toast UI не монтируется: #1_toast остаётся пустым, а исходная <textarea> имеет display:none — поля для текста письма на экране нет вообще. Тот же фрагмент, загруженный обычным запросом (index.php?go=1&op=getPrivateMessageView&typ=4), собирается нормально.

Причина видна в EditorToastUi::getWidget(): инициализация — инлайновый скрипт, отданный вместе с полем, и он выходит по охране if(!ta||!root){return;}, пока внешний toastui-editor.all.min.js из того же свапа ещё грузится. Ошибок в консоли при этом нет. То же касается формы ответа после открытия письма.

Это дефект рабочего кода, а не оформления, и он не входил в задачу — код не менялся. Выношу отдельно, чтобы решение принималось осознанно.

Как устроены демо

  • Стили подключены прямо из репозитория: templates/lite/assets/css/base.css, theme.css, assets/vendor/bootstrap-icons, а также plugins/editors/toastui/assets/toastui-editor.min.css и скин templates/lite/assets/editors/toastui/skin.css.
  • Редактор монтируется теми же файлами и по той же схеме, что и драйвер: скрытая <textarea> остаётся источником, рядом стоит <div id="<id>_toast">, инициализация вызывает SlaedToastUi.register(). Файловый менеджер и окно смайлов драйвер рендерит для каждого поля отдельно — в демо они не воспроизводились, кнопки на панели присутствуют.
  • Весь дополнительный CSS лежит в теге <style> внутри каждого файла и использует собственный префикс (sl-pmbox-, sl-pmsplit-, sl-pmadm-, sl-pmcard-, sl-pmchat-, sl-pmzen-, sl-pmdense-, sl-pmflow-) — в тему он не попадает.
  • Мобильные раскладки написаны через @container, поэтому телефонные врезки в демо — настоящий мобильный вид, а не картинка.
  • Разметка семантическая: <table> с <th scope>, <time datetime>, <form role="search">, <nav>, <article>; у всех полей есть подписи, у иконок — aria-hidden, у состояний — aria-current / aria-pressed / aria-selected.
  • Клавиатура: интерактивные элементы — настоящие button и a href, действия по наведению дублируются на :focus-within, есть общий стиль :focus-visible.
  • Скрипты — несколько строк ванильного JS для переключения панелей и фильтров. Ни одной внешней зависимости и ни одного CDN.
  • Рабочие шаблоны и PHP-код не изменялись.
