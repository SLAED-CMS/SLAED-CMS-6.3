# База данных

Раздел **База данных** предназначен для выполнения основных операций системного администрирования MySQL таблиц вашего проекта.

> [!WARNING]
> Данный модуль предназначен исключительно для опытных системных администраторов. Необдуманные действия (особенно во вкладке "Запрос") могут привести к безвозвратной потере всей информации на сайте. Перед любыми серьезными манипуляциями рекомендуется создавать полные бекапы БД.

## Вкладки модуля

### 1. Главная
При переходе выводится подробная сводная таблица всех таблиц базы данных сайта.
**Колонки:**
* **Таблица** — системное имя (например, `port_users`).
* **Тип** — движок хранения (с современной архитектурой SLAED CMS обычно используется мощный `InnoDB`).
* **Сравнение** — локаль (Collation), например `utf8mb4_unicode_ci`.
* **Строк** — приблизительное или точное количество записей.
* **Дата** — время создания.
* **Размер** — занимаемый объем памяти на диске.
* **Расходы** — «Свободное пространство» (Data Free). Для движков вроде MyISAM здесь могут скапливаться остатки удаленных строк. В `InnoDB` этот параметр обычно равен 0 или скрыт системой.
* **Функции** — кнопка **Редактор**. Наведение на неё открывает выпадающее меню с двумя деструктивными опциями:
  * **Очистить (TRUNCATE)** — полностью удаляет все данные внутри таблицы, сбрасывая счетчики ID (остается пустая структура).
  * **Удалить (DROP)** — физически удаляет выбранную таблицу из базы данных навсегда.

### 2. Оптимизация
Действие оптимизации БД (переиндексация и физическое удаление пустых областей) запускается автоматически сразу же после клика по вкладке. Оптимизация выполняет перестройку таблиц и обновляет внутренние статистические данные (команда `OPTIMIZE TABLE`). 
> [!TIP]
> **Важно об InnoDB:** В современных таблицах InnoDB необходимость в регулярной оптимизации отсутствует (движок делает это автоматически). Используйте эту функцию вручную только после сверх-массового удаления записей (например, десятков тысяч старых новостей).

### 3. Ремонт
Действие запускается мгновенно при переходе на вкладку. 
> [!NOTE]
> В современных таблицах `InnoDB` повреждения встречаются крайне редко (система транзакций выполняет авто-восстановление после сбоя сервера). Функцию ремонта (`REPAIR TABLE`) следует применять, только если в логах хостинга есть явные сообщения о реальных ошибках индексов или повреждениях файлов MyISAM.

### 4. Запрос в базу данных
Инструмент для ручного выполнения прямых SQL-запросов (Дампов) без необходимости входить в phpMyAdmin.

**Поддержка системных макросов:**
Вместо жесткого прописывания реальных имён, вы можете использовать безопасные макротеги — система сама подставит актуальные ключи вашего сайта во время выполнения:
* `{prefix}` — автоматически заменится на ваш реальный префикс (например, `port`).
* `{engine}` — тип движка из конфига (например, `InnoDB`).
* `{charset}` — кодировка сайта (например, `utf8mb4`).
* `{collate}` — сравнение (например, `utf8mb4_unicode_ci`).

**Кнопки действий:**
* **Проверить синтаксис (Parse)** — анализирует ваш код и разбивает пакет команд на части, проверяя его валидность без реального выполнения.
* **Выполнить (Execute)** — применяет ваш SQL-код к базе.

## Техническая реализация (PDO)

Система SLAED CMS использует современный слой абстракции базы данных на базе **PDO (PHP Data Objects)**. Основная логика реализована в классе `Database` (`core/classes/pdo.php`).

### 1. Безопасность и Placeholders (Заполнители)
Для защиты от SQL-инъекций используется механизм подготовленных запросов (Prepared Statements). Система поддерживает два типа заполнителей в методе `getSqlQuery()`:

* **Именованные заполнители (`:name`):**
  ```php
  $db->getSqlQuery("SELECT * FROM {prefix}_users WHERE id = :id", ['id' => 1]);
  ```
* **Позиционные заполнители (`?`):**
  ```php
  $db->getSqlQuery("SELECT * FROM {prefix}_users WHERE id = ?", [1]);
  ```

### 2. Автоматическая фильтрация типов
При передаче параметров система автоматически определяет тип переменной и выполняет соответствующее преобразование:
* **NULL** → превращается в SQL `NULL`.
* **Boolean** → превращается в `1` или `0`.
* **Integer / Float** → передаются как числа.
* **String** → автоматически экранируются через `PDO::quote()`.

### 3. Обработка ошибок и логирование
* **SQLSTATE / Коды ошибок:** В случае сбоя система получает детальную информацию об ошибке (`PDOException`).
* **Лог ошибок:** Если активирована опция `error_log` в настройках безопасности, все ошибочные запросы записываются в системный журнал с указанием времени, типа запроса и текста ошибки.
* **Универсальный интерполятор:** Для целей отладки система умеет восстанавливать полный текст SQL-запроса (подставляя значения заполнителей), что позволяет легко копировать "проблемный" запрос и тестировать его вручную.

### 4. Производительность
* **Мониторинг времени:** Каждый запрос замеряется с точностью до микросекунд. 
* **Индикация:** В режиме отладки запросы, выполняющиеся дольше 0.01 сек, подсвечиваются красным цветом в общем списке запросов страницы.

### Примеры полезных запросов для вкладки «Запрос»

**1. Удаление неактивных пользователей (не заходивших с определенной даты):**
```sql
DELETE FROM `{prefix}_users` WHERE user_lastvisit < "2020-02-29 18:15:00";
```

**2. Удаление спам-ботов по их IP-адресу регистрации:**
```sql
DELETE FROM `{prefix}_users` WHERE user_last_ip = "193.201.225.104";
```

**3. Удаление «мёртвых душ» (зарегистрировались, но ни разу не заходили):**
```sql
DELETE FROM `{prefix}_users` WHERE user_lastvisit = "0000-00-00 00:00:00";
```

**4. Поднятие лимитов таблиц старых версий (хранение больших объемов текста):**
```sql
ALTER TABLE `{prefix}_stories` CHANGE `hometext` `hometext` MEDIUMTEXT NULL DEFAULT NULL;
ALTER TABLE `{prefix}_stories` CHANGE `bodytext` `bodytext` LONGTEXT NOT NULL;
```
