# Загрузки

Раздел **«Загрузки»** — это централизованная система управления файлами и медиа-контентом сайта. Он позволяет загружать файлы в директории различных модулей, управлять ими и настраивать шаблоны их отображения при использовании редактора.

---

## 1. Каталог файлов

Вкладка является основным файловым менеджером системы. В верхнем выпадающем списке **«Директория»** выберите модуль, файлами которого хотите управлять (например, `uploads/news` или `uploads/files`).

### Функции менеджера:
* **Загрузка:** Вы можете загрузить файл со своего компьютера или указать прямую ссылку на файл в интернете (система сама скачает его на сервер).
* **Приоритет источника:** Выбранный локальный файл всегда важнее ссылки. Ссылка используется только тогда, когда файл не был выбран вообще, а отклонённый локальный файл никогда не подменяется загрузкой по ссылке.
* **Правила для ссылки:** Допускаются только схемы `http` и `https` и только публично маршрутизируемые адреса. Загрузка отклоняется для локальных, приватных и зарезервированных адресов, в том числе после переадресации. Разрешено не более трёх переадресаций, действуют таймаут соединения и общий таймаут запроса, а объём загружаемых данных ограничен настройкой размера файла.
* **Список разрешённых адресов IPv6:** Система обращается только к тем адресам IPv6, чей префикс IANA передала одной из региональных регистратур. Пространство, которое IANA ещё не распределила, зарезервировано под будущее использование, и обращение к нему отклоняется. Список едет в поставке и обновляется вместе с системой.
* **Если ссылка отклонена без видимой причины:** Откройте `storage/logs/error_file.log`. Отказ по этому правилу пишется туда строкой `Remote address refused by the address policy` вместе с именем хоста и самим адресом. Если в строке стоит локальный или приватный адрес — всё работает как задумано. Если адрес выглядит обычным публичным, значит его префикс IANA передала уже после сборки этой версии.
* **Как добавить префикс вручную:** Запустите из командной строки `php tools/ipv6-registry-check.php` — инструмент сверит поставляемый список с реестром IANA и напечатает недостающие префиксы. Каждый из них добавляется одной строкой в массив `ALLOWSIX` в файле `core/classes/upload.php`. Инструмент ничего не меняет сам и ничего не записывает: правка остаётся за вами, потому что этот список решает, куда серверу разрешено ходить.
* **Основная директория:** Список всех файлов, загруженных в папку выбранного модуля.
* **Дополнительная директория (Эскизы):** Здесь хранятся автоматически созданные уменьшенные копии изображений (thumbnails), если модуль настроен на их генерацию.

## 2. Шаблоны

SLAED CMS позволяет задавать уникальный HTML-вид для каждого типа вставляемого файла. Это особенно полезно при вставке файлов через редактор.

Список блоков на этой вкладке формируется из настройки **«Форматы приложений»** вкладки «Конфигурации», а сохранение перестраивает файл шаблонов целиком. Поэтому удаление расширения из списка форматов удаляет и его шаблон, а переименование расширения оставляет новый блок пустым и теряет старый.

**Доступные переменные шаблона:**
* `[src]` — прямая ссылка на файл.
* `[tsrc]` — ссылка на файл предварительного просмотра (эскиз).
* `[width]`, `[height]` — ширина и высота окна вывода.
* `[twidth]` — ширина эскиза из настроек модуля.
* `[align]` — выравнивание (left, right, center).
* `[title]` — описание или заголовок файла.
* `[rel]` — атрибут для группировки изображений (например, для создания галерей).

## 3. Конфигурации

Тонкая настройка правил загрузки для всего сайта и каждого модуля в отдельности.

### Основные настройки:
* **Директория по умолчанию:** Папка, которая будет открываться при входе в модуль.
* **Форматы приложений:** Список расширений, для которых можно создавать уникальные шаблоны во вкладке «Шаблоны». Принимаются только те расширения, для которых у системы есть политика типа файла: всё остальное отбрасывается при сохранении, а отброшенные значения перечисляются в сообщении о сохранении.
* **Размеры по умолчанию:** Стандартная ширина и высота для медиа-объектов.

### Настройки модулей:
Для каждого системного модуля (Новости, Форум, Профиль и т.д.) можно задать индивидуальные лимиты:
* **Типы файлов:** Список разрешенных расширений (через запятую).
* **Лимиты размера:** Максимальный размер одного файла и общий размер всех файлов для одного модуля. Ограничение на один файл действует и для загрузок из этой панели — вкладка «Каталог файлов» берёт свои правила из записи **«Модуль: Все»**.
* **Размеры изображений:** Ограничения по ширине и высоте загружаемых картинок (в пикселях).
* **Авто-эскизы:** Ширина автоматически создаваемой миниатюры.
* **Права доступа:** Разрешение загрузки для обычных пользователей и гостей.

> [!IMPORTANT]
> Все лимиты этого раздела действуют на **файлы, сохраняемые на сервере**. Режим редактора «Встроить в текст» файл не сохраняет — он кодирует изображение в base64 прямо в текст материала, — поэтому ни список расширений, ни размер файла, ни квота модуля, ни размеры картинки, ни число файлов на него не распространяются. Единственная граница встраивания задана в коде и описана в разделе 6.

## 4. Поддерживаемые форматы

Система знает 21 формат, и только они могут быть сохранены в списках расширений:

* **Изображения:** `avif`, `gif`, `jpeg`, `jpg`, `png`, `webp`
* **Аудио:** `flac`, `m4a`, `mp3`, `oga`, `ogg`, `opus`, `wav`
* **Видео:** `mp4`, `webm`
* **Документы:** `pdf`
* **Архивы:** `7z`, `gz`, `rar`, `tar`, `zip`

Модулям по умолчанию открыты изображения и два архива. Остальные форматы из списка выше включаются модулю вручную во вкладке «Конфигурации».

Формат, которого нет в списке, сохранить в настройках нельзя. Файл, вставленный в материалы в неподдерживаемом формате, выводится обычной ссылкой на файл.

---

## 5. Файловая панель редактора

Гость видит в файловой панели редактора только те файлы, которые вернул его собственный текущий запрос на загрузку. Ранее загруженные файлы ему не показываются.

---

## 6. Встраивание изображений в текст

Режим **«Встроить в текст»** отличается от остальных тем, что ничего не кладёт на сервер: изображение кодируется в base64 и целиком становится частью текста материала. Отсюда два следствия, о которых нужно знать.

### Граница задана в коде, а не настройками

Одно встроенное изображение не может превышать **64 КБ** — это константа `Parser::EMBEDMAX`. Изображение сверх этого размера не выводится: система отбрасывает его при разборе текста. Настройками эта граница не меняется, зато она одинакова во всех модулях.

### Не каждое поле способно вместить встроенное изображение

64 КБ двоичных данных в base64 занимают около 87 КБ текста, поэтому вместить их может не всякое поле. Это не оплошность, а осознанное разделение.

**Поля, куда встроенное изображение помещается** — это те, где хранится сам материал:

| Модуль | Поле |
|---|---|
| Новости, Страницы, Контент | Текст материала |
| Форум | Сообщение |
| Комментарии, Личные сообщения | Текст |
| Файлы, Ссылки | Полное описание |
| Вопросы и ответы, Справка, Анекдоты | Ответ, статья, текст |
| Медиа, Заказы, Пожертвования | Заметка |
| Магазин | Описание товара |
| Рассылки, Сообщения | Текст письма |

**Поля, куда оно не помещается** — краткие описания (`Вступление` во всех модулях) и подпись в профиле пользователя.

Причина в том, как эти поля выводятся. Вступление рисуется списочным запросом своего модуля: на странице из двадцати материалов их будет двадцать. Подпись повторяется под каждым сообщением автора на странице. Двадцать встроенных картинок по 87 КБ — это почти два мегабайта разметки в одной странице, которую вдобавок нельзя нормально кешировать.

> [!TIP]
> В этих полях **графика не запрещена — запрещён один способ её доставки**. Загрузите картинку на сервер или укажите ссылку на неё: в поле попадёт короткий адрес в несколько десятков символов, а браузер скачает изображение один раз и переиспользует его на всех повторах. Для посетителя это быстрее, чем встроенная копия, которая передаётся заново при каждой загрузке страницы.

---

> [!TIP]
> Настройка **«Модуль: Все»** в конфигурациях задаёт правила для загрузок с вкладки «Каталог файлов» этой панели — независимо от того, какая директория выбрана. Она не применяется автоматически к модулям, у которых нет собственной записи: такие модули просто не могут быть целью загрузки из редактора.

> [!IMPORTANT]
> Если вы разрешаете загрузку файлов гостям, обязательно убедитесь, что в списке разрешенных типов (`FTYPE`) отсутствуют опасные расширения (такие как `php`, `php5`, `phtml`, `exe`), и установлены строгие лимиты на размер файла. Тип файла проверяется по содержимому, а не только по расширению, и исполняемые или активные в браузере форматы отклоняются даже тогда, когда они указаны в настройках.
