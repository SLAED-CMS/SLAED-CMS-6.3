# Шаблон

Раздел **«Шаблон»** (`admin.php?name=template`) — это встроенный инструмент управления внешним видом вашего сайта. В версии SLAED CMS 6.3 Phoenix система перешла на современную архитектуру шаблонов, обеспечивающую гибкость, высокую производительность и четкое разделение PHP-логики от HTML-представления.

---

## 1. Архитектура тем оформления

Современная тема (например, `simple`, `default`) имеет строгую структуру папок:

* **layouts/** — общие макеты-обёртки страниц (основной: `layouts/app.html`).
* **pages/** — шаблоны для полных страниц модулей.
* **partials/** — многократно используемые блоки (шапка, меню, подвал).
* **fragments/** — мелкие атомарные элементы (кнопки, строки таблицы, иконки).
* **assets/** — ресурсы темы: CSS (`assets/css/`), JS (`assets/js/`), сторонние библиотеки (`assets/vendor/`).

---

## 2. Синтаксис шаблонизатора (Phoenix Runtime)

Система использует собственный движок рендеринга `$tpl`. Ниже описан полный поддерживаемый синтаксис.

---

### 2.1 Вывод переменных

| Синтаксис | Поведение |
|---|---|
| `{{ variable }}` | Безопасный вывод — значение экранируется (`htmlspecialchars`). Безопасно для контента от пользователей. |
| `{{{ variable }}}` | «Сырой» вывод — без экранирования. Используется для уже подготовленного HTML-кода. |

> [!CAUTION]
> Используйте `{{{ variable }}}` только для доверенных данных, сформированных системой. Выводить через тройные скобки контент от пользователей — опасно (XSS).

**Ограничение:** имя переменной должно начинаться с буквы и содержать только `a-z`, `0-9`, `_`.

---

### 2.2 Комментарии

```html
{# Это комментарий — он полностью удаляется при компиляции и не попадает в HTML #}
```

Комментарии вырезаются до обработки любых других тегов, поэтому могут быть многострочными и оборачивать любой код.

---

### 2.3 Условия: `if`, `elseif`, `else`, `endif`

Условие проверяет, является ли переменная «непустой» (аналог PHP `!empty()`).

```html
{% if is_logged %}
    <p>Добро пожаловать, {{ username }}!</p>
{% elseif is_guest %}
    <p>Вы просматриваете сайт как гость.</p>
{% else %}
    <p>Доступ запрещён.</p>
{% endif %}
```

#### Проверка на «пустое» значение — оператор `!`

Поставьте `!` перед именем переменной, чтобы проверить обратное (аналог PHP `empty()`):

```html
{% if !items %}
    <p>Список пуст.</p>
{% endif %}
```

> [!NOTE]
> Поддерживаются только простые проверки наличия/отсутствия значения. Сравнения (`==`, `>`, `<`) и составные выражения (`&&`, `||`) в синтаксисе шаблонизатора не поддерживаются — для этого используйте данные, подготовленные в PHP-контроллере.

---

### 2.4 Цикл: `for`, `endfor`

```html
{% for item in items %}
    <li>{{ item }}</li>
{% endfor %}
```

* `item` — переменная итерации (каждый элемент массива).
* `items` — массив, переданный в шаблон. Если переменная не является массивом, цикл просто не выполнится (без ошибки).

> [!NOTE]
> Вложенные циклы поддерживаются. Имена переменных в `for` и `in` подчиняются тому же правилу: только `a-z`, `0-9`, `_`.

---

### 2.5 Включение фрагментов: `include`

Позволяет вставить один шаблон внутрь другого.

```html
{# Простое включение — дочерний шаблон наследует все переменные родителя #}
{% include 'partials/header.html' %}

{# Включение с изолированным скоупом — передаётся только один массив #}
{% include 'partials/card.html' with card_data %}
```

* Путь должен начинаться с одного из: `partials/`, `fragments/`, `layouts/`.
* Путь должен оканчиваться на `.html`.
* Разрешён include только из `partials/` и `fragments/` (не из `pages/`).

> [!WARNING]
> Защита от рекурсии: если шаблон `A` уже находится в стеке рендеринга и пытается включить сам себя (прямо или косвенно), включение будет проигнорировано.

---

### 2.6 Наследование макетов: `extends`, `block`, `endblock`

Механизм позволяет странице унаследовать общий макет (layout) и переопределить отдельные его зоны.

**Макет (`layouts/app.html`):**
```html
<!DOCTYPE html>
<html>
<head>
    {% block head %}
        <title>Мой сайт</title>
    {% endblock %}
</head>
<body>
    {% block content %}{% endblock %}
</body>
</html>
```

**Страница (`pages/news.html`), наследующая макет:**
```html
{% extends 'layouts/app.html' %}

{% block head %}
    <title>Новости — Мой сайт</title>
{% endblock %}

{% block content %}
    <h1>{{ title }}</h1>
    {{{ body }}}
{% endblock %}
```

**Правила:**
* Директива `{% extends '...' %}` должна быть **первой значимой строкой** в файле (до неё разрешены только пробелы и комментарии `{# ... #}`).
* В файле должен быть **ровно один** `{% extends %}`.
* Если блок не переопределён в дочерней странице, выводится содержимое по умолчанию из макета.
* Вложенные блоки (`{% block %}` внутри `{% block %}`) **не поддерживаются**.

## 3. Редактирование через панель управления

Встроенный редактор в AdminPanel доступен для **Legacy-тем** (файлы расположены в корне директории темы, например `lite`).

**Для Legacy-тем доступны вкладки:**
1. **Шаблоны:** Управление HTML-блоками оформления модулей.
2. **Стили:** Редактирование CSS-файлов темы.
3. **Редактор:** Встроенный **CodeMirror** с подсветкой синтаксиса.

> [!WARNING]
> Темы с современной структурой папок (`layouts/`, `pages/`, `partials/` и т.д.) не отображаются в классическом редакторе AdminPanel. Для работы с ними используйте FTP или IDE.

---

## 4. Глобальные теги (Legacy, `index.html`)

В классических Legacy-темах для сборки страницы используются специальные теги:

| Тег | Описание |
|---|---|
| `{%META%}` | Мета-теги страницы (`<meta>`) |
| `{%LINK%}` | Подключение стилей (`<link>`) |
| `{%SCRIPT%}` | Подключение скриптов (`<script>`) |
| `{%BLOCKS left%}` | Позиция для боковых блоков (слева) |
| `{%BLOCKS right%}` | Позиция для блоков (справа) |
| `{%BLOCKS center%}` | Позиция для центральных блоков |
| `{%MODULE%}` | Место вывода контента активного модуля |

> [!TIP]
> При использовании JavaScript внутри Legacy-шаблонов используйте HTML-сущности вместо кавычек: `&quot;` (двойная) и `&apos;` (одинарная), чтобы избежать конфликтов с парсером .
