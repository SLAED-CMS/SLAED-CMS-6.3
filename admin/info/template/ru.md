# Шаблонизатор (Phoenix Template Engine)

Раздел **«Шаблон»** (`admin.php?name=template`) — это инструмент управления внешним видом вашего сайта. В SLAED CMS система перешла на современную, высокопроизводительную архитектуру шаблонов, реализованную в классе `core/classes/template.php`. Она обеспечивает гибкость, строгую безопасность и полное разделение PHP-логики от HTML-представления. Устаревшие макеты (Legacy) и теги (вроде `{%MODULE%}`) полностью удалены.

---

## 1. Архитектура тем оформления

Все темы (например, `simple`, `default`, `admin`, `lite`) имеют строгую стандартизированную структуру:

* **layouts/** — общие макеты-обёртки (например, `layouts/app.html`). Содержат основную структуру (HTML, HEAD, BODY).
* **pages/** — шаблоны конкретных страниц модулей.
* **partials/** — многократно используемые блоки (шапка, меню, подвал, компоненты).
* **fragments/** — мелкие атомарные элементы (кнопки, иконки).
* **assets/** — статические ресурсы: CSS (`assets/css/`), JS (`assets/js/`), сторонние библиотеки.

Шаблоны компилируются в нативный PHP-код и кэшируются в директории `storage/cache/templates/<theme>/`, что гарантирует максимальную производительность при рендеринге.

> [!TIP]
> **Performance Edge:** Поскольку кэширование происходит автоматически только при изменении времени модификации файла `.html`, нет необходимости вручную очищать кэш при обновлении дизайна. Вы сразу видите изменения.

---

## 2. Программный интерфейс (API)

Для рендеринга шаблонов в PHP используются основные методы класса `Template`:

* `$tpl->getHtmlPage(string $name, array $data = [], string $layout = 'app')` — рендеринг полной страницы из директории `pages/`. Автоматически оборачивается в указанный `$layout`, если в шаблоне не переопределено наследование.
* `$tpl->getHtmlPart(string $name, array $data = [])` — рендеринг шаблона из директории `partials/`. Подходит для многократно используемых крупных блоков.
* `$tpl->getHtmlFrag(string $name, array $data = [])` — рендеринг фрагмента из директории `fragments/`. Идеально для мелких UI-элементов.

Все передаваемые переменные (`$data`) автоматически фильтруются: объекты и ресурсы отбрасываются для предотвращения вызова методов из шаблонов.

> [!NOTE]
> **Data Preparation:** Переводите объекты (например, записи из базы данных `PDOStatement`) в скалярные типы или ассоциативные массивы до передачи в метод `getHtmlPage`. Это гарантирует отсутствие неочевидных "побочных эффектов" в шаблонах.

## 3. Синтаксис и возможности (Phoenix Runtime)

### 3.1 Вывод переменных

| Синтаксис | Описание |
|---|---|
| `{{ var }}` | **Безопасный вывод** — значение экранируется (`htmlspecialchars`). Обязательно к использованию для контента. |
| `{{{ var }}}` | **«Сырой» вывод** — без экранирования. Используется для безопасного HTML-кода системы. |

> [!CAUTION]
> Переменные могут содержать только латинские буквы, цифры и подчеркивания: `^[a-z][a-z0-9_]*$`.

### 3.2 Комментарии

```html
{# Этот комментарий удаляется на этапе компиляции и не попадает в итоговый HTML #}
```

### 3.3 Условия: `if`, `elseif`, `else`, `endif`

Шаблонизатор поддерживает строгую, безопасную логику проверок. Доступны только атомарные проверки на наличие (`flag`) или отсутствие (`!flag`) значения (переменной) — аналог функций `!empty()` и `empty()` в PHP.

> [!IMPORTANT]
> **MVC Compliance:** Условия сравнения (`&&`, `||`, `==`, `>`, `<`) намеренно **запрещены**! Это сделано по стандартам строгого разделения логики (PHP) и представления (HTML). Вся сложная логика должна вычисляться в контроллере и передаваться в шаблон как подготовленный булевый флаг (например, `$data['is_admin'] = ($user['role'] == 1);`).

**Полный список поддерживаемых конструкций:**

| Конструкция | Использование / Поведение | Аналог в PHP |
|---|---|---|
| `{% if flag %}` | Проверка, что `flag` существует и не пуст (строка/массив не пусты, значение `true` или число `> 0`). Используется для вывода блока, когда данные есть. | `if (!empty($flag))` |
| `{% if !flag %}` | Инверсия: работает, если `flag` пуст, равен `false`, `0`, пустой строке `""` или вовсе не существует. Часто применяется для вывода сообщения "Нет данных". | `if (empty($flag))` |
| `{% elseif flag %}`| Ветка "иначе если" с проверкой наличия значения. Применяется для перебора состояний (например, ролей). | `elseif (!empty($flag))` |
| `{% elseif !flag %}`| Ветка "иначе если" с инверсией (ожидание пустого значения). Альтернативный сценарий. | `elseif (empty($flag))` |
| `{% else %}` | Запасная ветка, срабатывающая, если ни одно из предыдущих `if / elseif` не подошло. | `else` |
| `{% endif %}` | Завершение блока условий. | `endif` |

#### Примеры использования:

**Простая проверка на наличие (`flag`):**
```html
{% if user_name %}
    <p>Добро пожаловать, {{ user_name }}!</p>
{% endif %}
```

**Проверка на отсутствие значения (`!flag`):**
Отлично подходит для системных сообщений, когда, например, список или таблица не содержит данных.
```html
{% if !items %}
    <div class="alert alert-warning">Список элементов пуст. Данные не найдены.</div>
{% endif %}
```

**Комбинация `if`, `elseif`, `else` для обработки состояний:**
Поскольку операторы вроде `&&` или `==` не поддерживаются, логическое разделение на флаги `is_admin`, `is_moderator`, `is_user` подготавливается в PHP-логике перед передачей в шаблон.
```html
{% if is_admin %}
    <p>У вас полные права администратора.</p>
{% elseif is_moderator %}
    <p>Вы вошли как модератор.</p>
{% elseif is_user %}
    <p>Вы авторизованы как обычный пользователь.</p>
{% elseif !is_active %}
    <p>Ваш аккаунт деактивирован, функционал ограничен.</p>
{% else %}
    <p>Вы просматриваете систему как гость.</p>
{% endif %}
```

### 3.4 Циклы: `for`

Итерация по массивам. Если переменная не является массивом, цикл будет безопасно пропущен.

```html
{% for item in items %}
    <li>Значение: {{ item }}</li>
{% endfor %}
```

### 3.5 Включение фрагментов: `include`

Вставка других шаблонов (из `partials/` или `fragments/`) с возможностью изоляции области видимости.

```html
{# Полное наследование текущего контекста #}
{% include 'partials/header.html' %}

{# Передача изолированного массива данных (локальный скоуп) #}
{% include 'fragments/button.html' with btn_data %}
```

### 3.6 Наследование макетов: `extends` и `block`

Страницы могут наследовать базовый макет и переопределять в нём блоки.

**Базовый макет (`layouts/app.html`):**
```html
<!DOCTYPE html>
<html>
<head>
    <title>{% block title %}Сайт{% endblock %}</title>
</head>
<body>
    {% block content %}{% endblock %}
</body>
</html>
```

**Страница (`pages/home.html`):**
```html
{% extends 'layouts/app.html' %} {# Эта строка должна быть первой значимой строкой! #}

{% block title %}Главная страница{% endblock %}

{% block content %}
    <h1>Добро пожаловать</h1>
{% endblock %}
```

### 3.7 Компоненты и слоты (Components & Slots)

Мощнейший механизм для переиспользуемых UI-элементов с вложенным контентом.

**Компонент модального окна (`partials/modal.html`):**
```html
<div class="modal">
    <div class="header">
        {% slot header %}Заголовок...{% endslot %}
    </div>
    <div class="body">
        {# Базовый контент по умолчанию #}
        {{{ slot }}}
    </div>
</div>
```

**Использование на странице:**
```html
{% component 'partials/modal.html' with modal_settings %}
    {% slot header %}
        <h2>Правила сайта</h2>
    {% endslot %}
    
    <p>Текст правил...</p>
{% endcomponent %}
```

## 4. Ограничения и безопасность

> [!CAUTION]
> Шаблоны строго изолированы от глобальной области видимости PHP. Вы не можете получить прямой доступ к `$_GET`, `$_POST`, `$_COOKIE` или `$_SESSION`. Передача непроверенных пользовательских массивов целиком в шаблон рискованна. Всегда явно декларируйте, какие данные отправляются в `$tpl->getHtml...`.

> [!WARNING]
> У шаблонизатора есть встроенный лимит рекурсии. Если шаблон попытается подключить сам себя (циклический `include` или `extends`), чтобы избежать падения системы (Memory Exhaustion), это действие тихо блокируется, и ветка не рендерится.

* **Запрет на PHP:** Движок не исполняет обертки `<?php ... ?>`. Any injected PHP code is safely treated as plain text or filtered out.

---

## 5. Редактирование шаблонов

Для работы с современными темами (`layouts/`, `pages/`, `partials/`) используйте специализированные редакторы кода (например, VS Code, PhpStorm) и подключение файлов по FTP/SFTP. Это гарантирует надежную работу с новой структурой приложения.
