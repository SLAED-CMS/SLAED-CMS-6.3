[hr][color=red][b][i]Attention![/b]
This section is intended only for administrators who are well familiar with server software and the PHP programming language.[/i][/color][hr]
[justify]The «Editor» section allows direct management of main system files through the administration panel. File management is performed in the following tabs:
[li] [b][i]System Core[/i][/b] – system core injection file: config/system.php. In this tab, you can add code that will be placed in the system core.
[li] [b][i]System Header[/i][/b] – system header injection file: config/header.php. In this tab, you can insert code that will be injected into the system head. As a rule, this file is used for injecting Java scripts and meta tags.
[li] [b][i]System SEF[/i][/b] – SEF transformation rules configuration file at system level: config/rewrite.php. In this tab, you can modify or supplement the standard rules for transforming browser address bars. This feature is only supported if Mod Rewrite is installed on the server.
[li] [b][i]Server SEF[/i][/b] – SEF transformation rules configuration file at server level: .htaccess. In this tab, you can modify or supplement the standard rules for transforming browser address bars at server level. This feature is only supported if Mod Rewrite is installed on the server.
[li] [b][i]Rules for Robots[/i][/b] – configuration file for instructions and indexing parameters for search robots: robots.txt. In this tab, you can modify or supplement the text file located in the root directory of the site, which contains special instructions for search robots. These instructions can prohibit indexing of certain sections or pages on the site, indicate correct domain «mirroring», recommend that the search robot observe a certain time interval between downloading documents from the server, etc. In this file, you can specify site indexing parameters both for all robots at once and for each search engine separately.

To make changes to a file, go to the corresponding tab and make changes in the opened file content editor, click «Save» to save.[/justify]

[hr][color=red][b][i]Attention![/b]
If the configuration files do not have the appropriate access rights set (CHMOD - 666), the system will display a corresponding warning.[/i][/color][hr]
[b][color=green]Examples of using the injection editor in the «System Header» section[/color][/b]

[color=orangered][b][i]Redirecting a visitor from a specific website[/i][/b][/color]
Go to the «System Header» tab and add the following entry:
[php]$reflink = "#slaed.net#i";
$metlink = "news.html";
$referer = text_filter(getenv("HTTP_REFERER"));
if (preg_match($reflink, $referer)) {
echo '<meta http-equiv="refresh" content="0; url='.$metlink.'">';
}[/php]
[justify]$reflink – responsible for the address of the website from which the visitor came.
Instead of: slaed.net specify your domain.
$metlink – responsible for the page to which the visitor will be redirected.
Instead of: news.html specify the required page or website.

[color=orangered][b][i]Prohibiting copying information from the website[/i][/b][/color]
Everything that can be read and seen can accordingly be copied. There is no effective copy protection. But this does not mean that it cannot be hindered; you can disable the use of the right or other mouse buttons that are used for copying. This will be an insignificant but still an obstacle to copying for beginner users.
Go to the «System Header» tab and add the following entry:[/justify]
[php]echo '<script>
<!--//
function click() {
// To disable the left button, set the number 1
// To disable the third button, set the number 3
if (event.button == 2) {
// Enter your message here that will appear in the warning window
alert("Copyright Scriptic!");
}
}
document.onmousedown=click;
//-->
</script>';[/php]
[justify]Note that this code only works in Internet Explorer browsers. It is possible that something similar exists for other browsers. If you want to use a different code, simply replace this one with your code by inserting it between echo ' and ';[/justify]

[color=orangered][b][i]Redirecting a visitor from a specific country[/i][/b][/color]
Go to the «System Header» tab and add the following entry:
[php]$userlang = "Russia";
$metlink = "news.html";
$userip = user_geo_ip(getip(), 2);
if ($userip == $userlang) {
echo '<meta http-equiv="refresh" content="0; url='.$metlink.'">';
}[/php]
[justify]$userlang – responsible for the name of the country from which the visitor came.
The country name must not be arbitrary and must comply with the standards for using the class. The correct spelling of a country can be checked in the $COUNTRY_NAMES variable of the file: core/geo_ip.php
$metlink – responsible for the page to which the visitor will be redirected.
Instead of: news.html specify the required page or website.

[color=orangered][b][i]Prohibiting other websites from using images from the site[/i][/b][/color]
It is no secret that some websites, to save their traffic and server space, use remote images from other websites, thereby consuming other people's traffic and increasing server load. To prevent this, we suggest the following methods.
Go to the «Server SEF» tab and add after:[/justify]
[php]# Mod rewrite on
RewriteEngine On
RewriteBase /[/php]
the following entry:
[php]RewriteOptions MaxRedirects=100
RewriteCond %{HTTP_REFERER} !^http://(www\.)?slaed\.net/ [NC]
RewriteRule \.(jpe?g|gif|bmp|png)$ http://www.slaed.net/templates/default/images/logos/slaed_logo_60x60.png [L][/php]
[justify]Instead of: slaed specify the domain name of your website.
Instead of: net specify the domain zone of your website.
Instead of: http://www.slaed.net/templates/default/images/logos/slaed_logo_60x60.png specify a link to the logo or image that will be displayed on the website that uses images from the site.

[color=orangered][b][i]Combining domain with www and without[/i][/b][/color]
At first glance, a domain with the www prefix and without it seems to be the same, but it is not. The server recognizes them as two different domains and, as a rule, two completely different websites can be installed on them. Some hosters have the merging of two domains provided initially and done automatically, some have this setting in the hosting control panel. For hostings where merging is not provided, the following method can be used.
Go to the «Server SEF» tab and add after:[/justify]
[php]# Mod rewrite on
RewriteEngine On
RewriteBase /[/php]
the following entry:
[php]# Redirect
RewriteCond %{HTTP_HOST} !^www\.slaed\.net [NC]
RewriteRule ^(.*)$ http://www.slaed.net/$1 [R=301,L][/php]
[justify]Instead of: slaed specify the domain name of your website.
Instead of: net specify the domain zone of your website.
For this method to work, the hoster's server must support working with .htaccess, Mod Rewrite must be installed and activated.[/justify]

[color=orangered][b][i]Possible rules and settings[/i][/b][/color]
[justify]In the description below, possible rules with descriptions are presented that are acceptable for use in our case on «Server SEF», namely in the main .htaccess file, which is located in the main directory of the system.[/justify]

[php]# Prohibition of directory listing and viewing
Options All -ExecCGI -Indexes -Includes +FollowSymLinks[/php]

[php]# Index page of the website
DirectoryIndex index.php[/php]

[php]# Default website encoding
AddDefaultCharset utf-8[/php]

[php]# Redirect in case of corresponding server error
ErrorDocument 400 /index.php?error=400
ErrorDocument 401 /index.php?error=401
ErrorDocument 403 /index.php?error=403
ErrorDocument 404 /index.php?error=404
ErrorDocument 500 /index.php?error=500
ErrorDocument 503 /index.php?error=503[/php]

[php]# Security settings, relevant for versions below PHP 5.3.0, not relevant for PHP 5.4.0 and higher
php_flag register_globals off
php_flag safe_mode on
php_flag magic_quotes_gpc on[/php]

[php]# Prohibition of displaying server software versions
ServerSignature Off[/php]

The above rule is unfortunately not supported by all hosters. The settings described below are only available if mod_rewrite is installed on the server.

[php]# Enabling mod_rewrite
RewriteEngine On[/php]

[justify]The mod_rewrite module is a software module of the Apache web server (note that it will not run under other web servers!). Its primary function is URL action manipulation. The module is very versatile and comprehensive; some practical examples are shown here.[/justify]

[php]# Root directory
RewriteBase /[/php]

[php]# Redirect from www to without www
RewriteCond %{HTTP_HOST} ^www\.(.*) [NC]
RewriteRule ^(.*)$ http://%1/$1 [R=301,L][/php]

[php]# Redirect from without www to www
RewriteCond %{HTTP_HOST} ^[^.]+\.[^.]+$
RewriteCond %{HTTPS}s ^on(s)|
RewriteRule ^ http%1://www.%{HTTP_HOST}%{REQUEST_URI} [R=301,L][/php]

[php]# Redirect from http protocol to https
RewriteCond %{HTTPS} off
RewriteRule (.*) https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L][/php]

[php]# Redirect addresses with index.php to without index.php
RewriteCond %{THE_REQUEST} ^GET.*index\.php [NC]
RewriteRule (.*?)index\.php/*(.*) /$1$2 [R=301,L][/php]

[php]# Redirect to new category
RewriteRule ^old/(.*)$ /new/$1 [R=301,L][/php]

[php]# Request processing rules for blocking common exploits
RewriteCond %{QUERY_STRING} proc/self/environ [OR]
RewriteCond %{QUERY_STRING} mosConfig_[a-zA-Z_]{1,21}(=|\%3D) [OR]
RewriteCond %{QUERY_STRING} base64_(en|de)code\(.*\) [OR]
RewriteCond %{QUERY_STRING} base64_encode[^(]*\([^)]*\) [OR]
RewriteCond %{QUERY_STRING} (<|%3C)([^s]*s)+cript.*(>|%3E) [NC,OR]
RewriteCond %{QUERY_STRING} GLOBALS(=|\[|\%[0-9A-Z]{0,2}) [OR]
RewriteCond %{QUERY_STRING} _REQUEST(=|\[|\%[0-9A-Z]{0,2})
RewriteRule .* index.php [F][/php]

[php]# Blocking MySQL injections
RewriteCond %{QUERY_STRING} CONCAT.*\( [NC,OR]
RewriteCond %{QUERY_STRING} UNION.*SELECT.*\( [NC,OR]
RewriteCond %{QUERY_STRING} UNION.*ALL.*SELECT [NC]
RewriteRule ^(.*)$ index.php [F,L][/php]

[php]# Blocking file injections
RewriteCond %{REQUEST_METHOD} GET
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=http:// [OR]
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=(\.\.//?)+ [OR]
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=/([a-z0-9_.]//?)+ [NC]
RewriteRule .* - [F][/php]

[php]# Redirect for foreign domains
RewriteCond %{HTTP_HOST} !^slaed\.net$
RewriteRule ^(.*)$ http://slaed.net/$1 [R=301,L][/php]
