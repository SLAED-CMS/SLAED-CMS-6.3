# Конфигурации

Радел **Конфигурации** является визуальным интерфейсом для редактирования глобального файла настроек `config/global.php`. Любые изменения, внесенные в любой из вкладок, записываются непосредственно в этот файл конфигурации.

Настройки разделены на 7 смысловых вкладок (восьмая — «Документация» — открывает эту справку). Все вносимые изменения сохраняются общей кнопкой «Сохранить изменения» внизу каждой вкладки.

---

## 1. Основные
Управление базовой системной информацией, безопасностью и поведением сайта.

* **Версия** — не поле, а ссылка на сайт проекта с текущей версией SLAED CMS. Версия задаётся системой при сохранении настроек и вручную не редактируется.
* **Название сайта** — глобальный заголовок проекта.
* **Адрес сайта** — полный URL проекта со схемой (например, `https://slaed.loc`).
* **Установка логотипа сайта / Логотип сайта** — выбор файла логотипа (форматы `.png`, `.svg` и др.) из директории `templates/ВАША_ТЕМА/images/logos/`.
* **Описание** — короткое описание проекта, отображаемое на служебных страницах или используемое макетом.
* **Заметки администратора** — внутренний блок (блокнот). Текст будет виден вверху панели администратора всем авторизованным администраторам.
* **Дата открытия сайта** — дата запуска проекта.
* **E-Mail администратора** — контактный адрес (используется как адрес отправителя (`От`) в системных письмах).
* **Cookies и Сессии**:
  * **Название Cookies для пользователей** / **Название сессий для администраторов** — внутренние имена для авторизации.
  * **Время сохранения Cookies пользователя, в сутках** — срок жизни куки авторизации.
  * **Время работы сессий, в минутах** — время удержания сессии авторизованного лица до авто-выброса при бездействии.
* **Ссылка на сайт проверки IP адреса** — сервис, через который будут проверяться IP пользователей (по умолчанию whois.domaintools.com или аналогичный).
* **Тема оформления** — выбор текущего шаблона из папки `templates/`.
* **Модуль загружаемый на главной странице** — выбор (с помощью Ctrl) модулей, которые выводятся на главной странице сайта.
* **Модуль загружаемый на главной странице администратора** — стартовый модуль при входе в админ-панель.

**Интерфейс и разработка**:
* **Редактор пользователя** — выбор редактора содержимого для посетителей/пользователей (`config/global.php` → `editor.user`); это единственное место выбора редактора для пользователей. Редактор **для администраторов** в основном конфиге не задаётся — он выбирается индивидуально в разделе «Администраторы». Подробное описание всех редакторов, форматов хранения и работы с сырым HTML — в отдельном разделе «Редакторы содержимого» ниже.
* **Глобальное системное время** — таймзона сервера.
* **Синхронизировать время «PHP timezone» и «MySQL timezone»?** — приравнивает часовые пояса БД и PHP.
* **Активация расширений отладки** — включает дебаггер (POST, GET, COOKIE, Системная инфа и т.д.).
* **Видимость функций отладки** — кому показывать отладочную инфу («Все посетители» или «Только администраторы»).
* **Подсветка синтаксиса кода** — выбор библиотеки (например `Syntax Highlighter`).
* **Количество колонок при выводе модулей панели администратора** — определяет сетку главного меню админки.
* Глобальные переключатели (Да/Нет):
  * Активировать сессии посетителей? — включает учёт онлайн-посетителей и секцию «Кто на сайте» в блоке «Пользователи» (счётчики, «Подробнее» со списком посетителей, «Обновить»).
  * Отображать сообщения на главной странице?
  * Отображать скорость генерации страницы?
  * Активировать редактор отдела информации? (позволяет прямо из админки править эту документацию).
  * **Закрыть сайт на профилактику?** (сайт будет закрыт заглушкой для посетителей).
  * **Режим разработки** (Dev Mode — вывод строгих ошибок PHP).
* **Автообновление живых блоков (секунды, 0 — выкл.)** (`live_u`) — единый интервал фонового обновления для всех «живых» блоков сайта: секция «Кто на сайте» (и будущие живые блоки, например live-результаты голосования) сама перезапрашивает данные через htmx каждые N секунд без перезагрузки страницы. `0` (по умолчанию) — блоки обновляются только вручную кнопкой «Обновить». Учтите: фоновое обновление перерисовывает блок, поэтому раскрытый список «Подробнее» при очередном обновлении сворачивается.

## 2. SEO
Настройки поисковой оптимизации и формирования адресов.

* **Символ, отделяющий титлы и заголовки** — например `-` или `|`.
* **Максимальное количество знаков в описании** — длина мета-тега Description.
* **Использовать длинные заголовки? / Автоматическая генерация описания?**
* **Настройки ЧПУ (Человеко-Понятный УРЛ)**:
  * Разделитель ЧПУ, Разделитель заголовков ЧПУ.
  * **Активировать преобразование ссылок в ЧПУ?** — включение красивых адресов.
  * **Добавлять заголовок? / Добавлять заголовок категории?** — включение алиасов категорий и названий в URL.
* **Канонические адреса (`rel=canonical`)** — формируются автоматически, без настроек: каждая страница ссылается сама на себя; «шумные» параметры (`utm_*`, `PHPSESSID`, `fbclid`, `gclid` и пр.) в canonical **не попадают** — только значимые (`name`, `op`, `id`, `cat`, `num`, `let`). Страницы пагинации ссылаются на себя постранично, страница поиска отдаёт `noindex, follow`. Голый `/index.php` постоянным редиректом **301** сводится к `/`, чтобы не плодить дубль главной.
* **Всегда использовать HTTPS (перенаправлять с http)?** (`forcessl`) — 301-редирект любого `http`-запроса на `https`. Учитывает заголовок `X-Forwarded-Proto`, поэтому за прокси/балансировщиком (SSL терминируется снаружи) не зацикливается. **Включайте только если HTTPS реально настроен** на сервере — на http-only/dev-окружении оставляйте выключенным, иначе редирект уйдёт в бесконечную петлю.
* **Единый домен сайта (перенаправлять www на основной)?** (`forcehost`) — 301-редирект любого хоста, отличного от указанного в поле **«Адрес сайта»** (`homeurl`), на канонический: например `www.site.ru` → `site.ru` (или наоборот — туда, куда настроен `homeurl`). Убирает дубли www и зеркал; путь и параметры запроса сохраняются.

> [!NOTE]
> Редиректы `forcessl` / `forcehost` и сведение `/index.php` → `/` реализованы **портируемо на уровне PHP** (`core/security.php`), без `.htaccess` / nginx-правил — работают на любом сервере и применяются ко всему сайту, включая админку. По умолчанию оба **выключены** — существующие установки ничего не меняют, пока вы их не включите.

* **Open Graph / Schema.org** — переключатели и многострочные поля шаблонов (разметка карточек для соц-сетей и богатых сниппетов для поисковиков). Могут содержать подстановочные теги: `[title]`, `[desc]`, `[url]`, `[img]`, `[time]` и др.

## 3. Языковые / Геолокация
Управление мультиязычностью проекта и определением страны посетителя.

**Языки**:
* **Стандартный язык** — основной язык сайта по умолчанию (файлы берутся из директории `lang/`).
* **Активировать многоязыковые свойства?** — разрешает использование нескольких языков; материалы с указанным языком показываются только на нём.
* **Показывать флаги вместо меню?** — переключатель языков в виде флагов вместо выпадающего списка.
* **Автоматически переключать язык сайта под страну посетителя?** (`alang`) — при первом заходе (пока нет cookie выбора языка) страна определяется по IP через GeoIP и посетитель перенаправляется на соответствующий язык (например, DE → немецкий, US/GB → английский). Поисковых ботов авто-переключение не затрагивает. Требует включённого определения страны (ниже).

**Геолокация (GeoIP)**:
* **Определять страну посетителя по IP?** (`geoip_enabled`) — главный выключатель. От него зависят: флаги стран в списках посетителей («Кто на сайте», админ-мониторинг), авто-язык (`alang`) и гео-данные в статистике.
* **Время кэширования GeoIP, в секундах** (`geoip_cache`) — результат определения по IP кэшируется, чтобы не читать базу на каждом хите (по умолчанию 86400 = сутки).
* **Анонимизировать IP перед сохранением?** (`geoip_anon`) — при сохранении гео-данных адрес заменяется необратимым хэшем (sha1) — рекомендуется для соответствия GDPR.
* **Сохранять полный IP?** (`geoip_store`) — хранить исходный адрес полностью. Полный IP пишется только при сочетании «Сохранять полный IP = Да» и «Анонимизировать = Нет»; во всех остальных случаях сохраняется хэш.
* **Тестовый IP** — поле для проверки: введите адрес и сохраните — ниже в таблице «Параметры» отобразится результат определения (страна, континент, ASN, организация, поставщик).
* **Таблица баз** — статус локальных MaxMind-баз: **База стран** (`storage/geoip/country.mmdb`) и **База ASN** (`storage/geoip/asn.mmdb`) с размером и датой файла. Базы лежат на сервере — внешние запросы при определении не выполняются.

## 5. Краулеры
Распознавание поисковых роботов (краулеров) и переходов из поисковых систем.

* **Список поисковых ботов** (`bots`) — словарь User-Agent для определения ботов. Формат записи: `уникальная строка из user-agent=Имя для отображения`, записи разделяются запятой. Пример: `Googlebot=Google Bot`. Распознанный бот учитывается в сессиях отдельно от людей — не искажает счётчик гостей и показывается с собственным именем.
* **Список сайтов поисковых систем** (`fbots`) — домены поисковиков (через запятую). Переход с такого домена засчитывается в статистике как «приход из поисковой системы» (категория реферера).
* **Показывать поисковых ботов в блоке пользователей?** (`botsact`) — управляет секцией «Кто на сайте»: при «Да» боты идут отдельной строкой счётчика и попадают в раскрываемый список «Подробнее» (с флагом страны и модулем, где находятся); при «Нет» строка ботов скрыта, а сами боты считаются в числе гостей.

## 6. Оптимизация
> [!TIP]
> В верхней части вкладки выводится отчет по кэшу: для каждой подпапки `storage/cache` (например `templates/<тема>`, `pages/html`, `pages/assets`, `pages/data`, `changelog`) показано количество файлов, плюс общее число файлов и занимаемый объем. Список формируется автоматически — любая новая папка кэша появится в нём сама.

**Структура кэша**:
* `storage/cache/templates/<тема>` — скомпилированные шаблоны (управляются движком шаблонов, восстанавливаются автоматически).
* `storage/cache/pages/html` — готовые HTML-страницы (полностраничный кэш).
* `storage/cache/pages/assets` — объединённые CSS/JS бандлы.
* `storage/cache/pages/data` — структурированные данные (зарезервировано на будущее).

**Кнопка «Очистить весь кэш»** (зелёная, рядом с «Сохранить изменения») — полностью удаляет **все** файлы во всех подпапках `storage/cache` (шаблоны, страницы, ассеты, данные модулей). Защищённые `.htaccess` / `index.html` и сама структура папок сохраняются; всё пересоздаётся автоматически при следующих обращениях. Используйте после правки шаблонов/стилей/скриптов или для полного сброса.

**Полностраничное кэширование (HTML)**:
* **Кэширование** — уровни: `Нет`, `1 вид` (главная и страницы модулей) или `2 вид` (только главная).
* **Время сохранения кэша, в секундах** (`cache_t`) — срок свежести: страница старше этого значения пересоздаётся. Кэшируются только страницы гостей по GET-запросам (не админ, не авторизованный пользователь, не POST, без flash-сообщений).
* **Сжимать кэшируемые файлы?** — минификация сохраняемого HTML.
* **Активировать кэширование браузером?** (`cache_b`) — отправлять ли браузеру публичные заголовки кэша. Применяется только к кэшируемым гостевым страницам; некэшируемый HTML всегда получает `no-store`. Повторные запросы с `If-Modified-Since` получают `304`. При включённом таймере генерации (`db_t`) публичный браузерный кэш HTML подавляется, чтобы строка времени оставалась актуальной.
* **Время кэширования браузером, в сутках** (`cache_d`) — значение `max-age` для публичных ответов (кэшируемые HTML-страницы, OpenSearch/XSL, ассеты). Учитывается только при включённом «Активировать кэширование браузером».
* **Перестроение кэша одним процессом** (`cache_l`) — при истечении TTL пересборку выполняет один процесс, остальные временно получают предыдущую (stale) версию страницы. Снижает «стадо» одновременных пересборок при пиковом трафике. По умолчанию выключено; рекомендуется для высоконагруженных проектов.
* **Очистка устаревших файлов** — плановая задача `cachegc` удаляет файлы полностраничного кэша старше ретенции `max(cache_t × 24, 86400)` сек. Это серверная очистка диска (производная от `cache_t`), не связана с `cache_d` (браузерный `max-age`). Ручная кнопка «Очистить весь кэш» по-прежнему удаляет всё.

**Кэширование стилей (CSS)**:
* При включённом **Кэшировать стили темы оформления** все файлы из перечисленных **Директорий стилей** объединяются в один бандл. Поддерживается переменная `[theme]` (текущая тема).
* Опции: Выводить в шапке сайта, Сжимать (минимизировать), Конвертировать изображения в бинарный текст (Data URI / Base64).

**Кэширование скриптов (JS)**:
* При включённом **Кэшировать скрипты** файлы из поля «Файлы скриптов» (разделитель — запятая) объединяются в бандл.
* Опции: Выводить в шапке, Сжимать скрипты, **Асинхронная загрузка** (defer/async), Перенести скрипты вниз страницы.

> [!NOTE]
> Объединённые CSS/JS-бандлы отдаются через маршрут `index.php?go=asset&file=<хэш>&type=css|js`, а не прямой ссылкой — прямой доступ к `storage/cache` закрыт файлом `.htaccess`. Имя бандла зависит от состава файлов и их даты изменения, поэтому при правке исходников бандл пересоздаётся автоматически.

> [!TIP]
> Автоматическую очистку кэша можно включить в **Планировщике** — системное задание «Page cache cleanup». По умолчанию оно **выключено**; при активации выполняет ту же полную очистку, что и кнопка «Очистить весь кэш».

## 7. Почта
Настройки исходящих писем.

> [!IMPORTANT]
> Сайт **не отправляет письма во время запроса**. Любое письмо складывается в очередь, а доставкой занимается задание планировщика **`maildrain`**. Поэтому недоступный почтовый сервер больше не подвешивает страницу, а выключенное задание означает, что письма копятся и никуда не уходят. Состояние очереди видно в разделе «Рассылка» → вкладка «Очередь».

**Шаблон письма:**
* **Основной почтовый шаблон** — оформление письма.
* Тег `[text]` зарезервирован: на его место подставляется текст конкретного модуля (код подтверждения, пароль, уведомление). Удалять его нельзя.

**Транспорт:**
* **Транспорт** — способ отправки: встроенная почта PHP, `Sendmail` или `SMTP`. Остальные поля этой группы появляются в зависимости от выбора.
* **Путь к Sendmail** — только путь к программе, без аргументов.
* **Сервер SMTP**, **Порт SMTP**, **Шифрование**, **Аутентификация** (имя и пароль), **Таймаут соединения, секунды**.
  * Поле пароля можно оставить пустым — сохранится текущий.

**Отправитель:**
* **Имя отправителя** — пусто, берётся название сайта.
* **Адрес отправителя** — пусто, берётся E-Mail администратора со вкладки «Основные».
* **Адрес для ответа** — пусто, берётся отправитель каждого письма.

**Очередь и доставка:**
* **Писем в минуту** — ограничение скорости, `0` снимает его.
* **Попыток доставки** и **Задержка перед повтором, секунды** — сколько раз и с каким интервалом пробовать отправить письмо, прежде чем считать его отклонённым.
* **Хранить доставленные письма, дней** и **Хранить доставленные рассылки, дней** — как долго держать уже отправленное, прежде чем убрать из очереди. Для рассылок срок отдельный и обычно короче: их объём несопоставим.

**Проверка адресов:**
* **Проверять адреса перед рассылкой** — синтаксис, прошлые отказы и наличие домена. Недоступная проверка пропускается, письмо всё равно уходит.
* **Хранить результат проверки домена, секунд** — сколько помнить ответ о домене, чтобы не спрашивать DNS на каждое письмо.

**Проверка настроек:**
* **Тестовое письмо** — отправляет проверочное письмо выбранным транспортом. Сначала сохраните настройки; пустой адрес означает, что письмо уйдёт администратору. Результат показывает, принял ли транспорт письмо.

> [!CAUTION]
> Следите за синтаксисом при редактировании полей ЧПУ, кэша скриптов или словарей цензуры. Использование неправильных разделителей может нарушить работу системы маршрутизации пакетов или работу клиентской (JavaScript) части веб-приложения.

## Редакторы содержимого

Редактор содержимого задаётся **раздельно для двух ролей**, но в разных местах:

* **для пользователей** — на вкладке «Основные» полем **«Редактор пользователя»** (`config/global.php` → `editor.user`). Это единственное место выбора редактора для посетителей; персонального переопределения у них нет.
* **для администраторов** — в основном конфиге **не задаётся**. Редактор выбирается **индивидуально** для каждого администратора в разделе «Администраторы» (профиль администратора) и быстрым переключателем в панели. Если у нового администратора редактор не выбран, он подставляется автоматически (по умолчанию `plain`).

Выбранный редактор применяется ко всем полям содержимого во всех модулях, а не к какому-то одному разделу. Смена редактора влияет только на **новые** сохранения — уже сохранённый контент не переконвертируется и продолжает корректно отображаться, так как вывод всегда проходит через единый парсер.

Отдельно существует **редактор кода** (`editor.code`, по умолчанию CodeMirror) — он не относится к содержимому и в этих полях не выбирается. Он используется для редактирования кода и разметки в служебных разделах админки: шаблоны, блоки, SQL-запросы, файлы Шапки / `.htaccess` / `robots.txt` и т.п.

### Доступные редакторы содержимого

| Редактор | Роли | Формат хранения | Назначение |
|---|---|---|---|
| **Plain Textarea** (`plain`) | пользователь, админ | текст / Markdown (HTML экранируется) | простое поле без надстроек; разметка — через Markdown и BB-теги; сырой HTML — только через `[usehtml]` |
| **TOAST UI** (`toastui`) | пользователь, админ | Markdown | редактор с двумя режимами — **Markdown** (исходник) и **HTML WYSIWYG** (визуальный); оба режима при сохранении записывают **Markdown** |
| **TinyMCE** (`tinymce`) | только админ | HTML | визуальный WYSIWYG, хранит готовый HTML |
| **CKEditor** (`ckeditor`) | только админ | HTML | визуальный WYSIWYG, хранит готовый HTML |

### Как обрабатывается содержимое

* **Plain и TOAST UI** — ввод считается **текстом / Markdown-исходником**. Спецсимволы HTML (`<`, `>`, `&`) экранируются при сохранении, а на выводе содержимое разбирает парсер: Markdown плюс BB-теги (`[tabs]`, `[quote]`, `[hide]`, `[code]`, смайлы и т.д.). Это безопасный режим по умолчанию — пользовательский HTML не может выполниться.
* **TinyMCE и CKEditor** — ввод считается **готовым HTML**. Экранируются только кавычки и служебные символы (`"`, `$`, `'`, `\`), угловые скобки сохраняются, и на выводе HTML отдаётся как есть. Поэтому эти редакторы доступны **только администраторам**.

> [!NOTE]
> У TOAST UI два режима — **Markdown** и **HTML WYSIWYG**, переключаются вкладками. «HTML WYSIWYG» — это визуальное редактирование того же Markdown-документа (с форматированием, таблицами и т.п.), а не отдельный формат хранения: при сохранении в любом режиме записывается Markdown. Готовый («живой») HTML в базе дают только настоящие HTML-редакторы (TinyMCE/CKEditor).

### Сырой HTML в режимах Plain и TOAST UI (для администратора)

Сырой HTML в контенте нужен редко, поэтому отдельного «raw»-режима нет — для точечных случаев используется парный BB-тег **usehtml**. Принцип: открывающий тег `[usehtml]` ставится перед HTML-фрагментом, а закрывающий (такой же тег, но с косой чертой перед словом) — после него; всё, что окажется между ними, на выводе отрендерится как настоящий HTML. В редакторе TOAST UI этот парный тег вставляется кнопкой «HTML» на панели — вручную набирать не нужно.

Правила использования:

* внутри блока пишите обычные кавычки `"`, а **не** `&#034;` (иначе на выходе получите буквальную `&#034;`);
* BB-маркеры структуры (`[tabs]`, `[tab=…]`) оставляйте **снаружи** блока usehtml, чтобы их разобрал парсер;
* тег **доступен только Супер Администратору** — у всех остальных он удаляется на входе.

Аналогично работает парный тег **usephp** (открывающий `[usephp]`) — исполнение PHP-кода: кнопка «PHP» на панели TOAST UI, применять осознанно.

> [!CAUTION]
> Оба тега — `[usehtml]` и `[usephp]` — доступны **только Супер Администратору**. У всех остальных, включая обычных администраторов, теги вырезаются при сохранении, в любом поле и в любом редакторе. Возврата этой способности на выводе нет: чего нет в сохранённом тексте, то не отрисуется и не выполнится.

### Спец-теги содержимого — полный перечень

Всё, что перечислено ниже, разбирает единый парсер на выводе, независимо от выбранного редактора. Кроме BB-тегов парсер понимает Markdown (заголовки, списки и чек-листы, таблицы, цитаты и GFM-врезки `> [!NOTE]`, ссылки, картинки, блоки кода, выделение) — в формате `plain` Markdown намеренно не разбирается, а BB-теги и смайлы работают и там.

Столбец «Кому» означает, кто вправе **сохранить** тег. Проверка стоит на записи: тег, которого нет в сохранённом тексте, на выводе не появится.

**Блоки и структура**

| Тег | Что делает | Кому |
|---|---|---|
| `[quote]…[/quote]` | Цитата; вкладывается сама в себя | все |
| `[hide]…[/hide]` | Блок виден только авторизованным пользователям и в панели; гость видит заглушку | все |
| `[tabs=N]…[/tabs]` с `[tab=Название]…[/tab]` внутри | Вкладки; `N` — номер набора на странице | все |
| `[left]`, `[right]`, `[center]`, `[justify]` | Выравнивание блока, парные | все |
| `[hr]` | Горизонтальная линия | все |
| `[li]` | Маркер списка (`•`) | все |
| `[block=ID]` | Вставка готового блока по его номеру; работает только в доверенном (админском) содержимом на публичной части | админ |
| `[usehtml]…[/usehtml]` | Содержимое отдаётся как настоящий HTML | Супер Администратор |
| `[usephp]…[/usephp]` | Содержимое выполняется как PHP-код | Супер Администратор |

**Код**

| Тег | Что делает | Кому |
|---|---|---|
| `[code]…[/code]` | Блок кода без подсветки | все |
| `[php]…[/php]` | Блок PHP с подсветкой | все |
| `[code=язык]…[/code]` | Блок с подсветкой; языки: `bash`, `cpp`, `csharp`, `css`, `delphi`, `diff`, `groovy`, `java`, `jscript`, `php`, `plain`, `python`, `ruby`, `scala`, `sql`, `vb`, `xml` | все |

**Оформление текста (строчные)**

| Тег | Что делает | Кому |
|---|---|---|
| `[b]`, `[i]`, `[u]`, `[s]` | Жирный, курсив, подчёркнутый, зачёркнутый; парные | все |
| `[color=значение]…[/color]` | Цвет текста; допускается `#rrggbb` или имя цвета латиницей, иначе тег игнорируется | все |
| `[family=Название]…[/family]` | Шрифт; в названии только латиница и пробелы | все |
| `[size=N]…[/size]` | Размер в пикселях, значение приводится к диапазону 8–48 | все |

**Ссылки, картинки, вложения**

| Тег | Что делает | Кому |
|---|---|---|
| `[url]адрес[/url]`, `[url=адрес]текст[/url]` | Ссылка; `www.` дополняется до `https://`; ed2k-ссылки оформляются отдельно | все |
| `[mail]адрес[/mail]`, `[mail=адрес]текст[/mail]` | Почтовая ссылка; неверный адрес остаётся текстом | все |
| `[img]адрес[/img]` | Картинка | все |
| `[img=left]…[/img]`, `[img=right]…[/img]` | Картинка с обтеканием | все |
| `[img alt=Текст]…[/img]`, `[img=выравнивание alt=Текст]…[/img]` | Картинка с описанием | все |
| `[attach=файл align=X title=Y]` | Вложение из `uploads/<модуль>/`; для картинок миниатюра создаётся автоматически | все |
| `[attach=файл align=X title=Y width=W height=H]` | То же с явными размерами | все |
| `[attach=файл align=X title=Y width=W height=H rel=R]` | То же с атрибутом `rel` для галереи | все |
| `*01` … `*18` | Смайлы; набор берётся из картинок темы | все |

> [!NOTE]
> Небезопасные схемы ссылок (`javascript:`, `data:`, `vbscript:`) блокируются всегда — и в пользовательском содержимом, и в админском.

> [!TIP]
> Чтобы показать сам тег как пример, а не выполнить его, заключите его в обратные кавычки: код разбирается раньше BB-слоя, поэтому `[hr]`, `*01` и даже парные `[usehtml]…[/usehtml]` внутри кавычек остаются текстом.

**Опроса среди тегов нет — и не должно быть.** Опрос не вставляется тегом: он привязывается к материалу полем **«Опрос»** в форме добавления (Новости, Магазин) и выводится отдельным блоком над текстом. Опрос в боковой колонке — это блок `voting`, который сам выбирает подходящее голосование по настройке модуля. В произвольное место текста опрос попадает единственным способом — через `[block=ID]` с номером блока голосования, и только в админском содержимом.

### Рекомендации по выбору

* **Пользователям** — оставляйте `plain` или `toastui`: содержимое всегда экранируется, риск XSS исключён.
* **Администраторам, работающим визуально**, — `tinymce` или `ckeditor`.
* **Администраторам, пишущим разметку руками**, — `plain` или `toastui` (Markdown), а произвольный HTML — через `[usehtml]`.

> [!CAUTION]
> Не стоит расширять права пользовательского редактора до хранения сырого HTML: пользовательское содержимое должно экранироваться всегда, иначе появляется риск XSS. HTML-редакторы рассчитаны только на доверенных администраторов, а теги `[usehtml]`/`[usephp]` — только на Супер Администратора.
