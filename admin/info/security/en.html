[justify]The "Security" section is a powerful tool for protecting the website from various types of attacks, from SQL injections to uploading third-party scripts to the website directory. This section will help track, identify, and if necessary block the attacker, as well as any other user or visitor of the project.

[color=green][b]"Main" tab[/b][/color]
Provides statistics on website usage. To view statistics, click on the value (Information) next to the corresponding statistics file. The information will be displayed below the list of statistics files.
To download information as a TXT file, click on the value (Download).
To clear a statistics file, click on the value (Delete object).
To view the storage path and name of the statistics file on the server, click on the icon (i) to the left of the corresponding statistics name.

[b][i][color=orangered]Modified files statistics[/color][/i][/b]
Depending on the time specified in the settings ("Configurations" tab, parameter "File modification check interval,
in minutes"), the system checks all system files for deletions, modifications, and new additions.
Collecting this statistics is useful for security purposes: the actions described above with files can be tracked.

[b][i][color=orangered]Dynamic errors statistics[/color][/i][/b]
Tracks script and server errors. Records detailed information (error description, script, line, and time of the error) in the statistics log file on the server.

[b][i][color=orangered]Forbidden actions statistics[/color][/i][/b]
Tracks forbidden actions. Some methods of transmitting information cannot be used, but at the same time they are not critical to the security of the system. For example, using HTML code in the browser address bar when transmitting requests, or attempting to embed JavaScripts, IFrame, etc. Records detailed information (attacker's IP address, browser data, action description, time of the action) in the statistics log file on the server.

[b][i][color=orangered]User login statistics[/color][/i][/b]
Tracks all user logins to the website. Records:
[li] whether the login was successful;
[li] IP address of the logged-in user;
[li] Nickname;
[li] browser;
[li] date and time.

[b][i][color=orangered]All incoming information statistics[/color][/i][/b]
Tracks all actions performed by visitors on the website (global variables POST, GET, COOKIE, FILES, SESSION), essentially literally everything that users do, what information they request, what they send, etc.
Collecting statistics is useful for security purposes: you can track in detail what a particular IP did on the website.

[b][i][color=orangered]Attack statistics[/color][/i][/b]
The main information panel of the security system. Tracks attackers and their actions. Records detailed information (attacker's IP address, browser data, attack description, time of the attack) in the statistics log file on the server.

[b][i][color=orangered]Administrator login statistics[/color][/i][/b]
Tracks all administrator logins to the website. Records:
[li] whether the login was successful;
[li] IP address of the logged-in administrator;
[li] Nickname;
[li] browser;
[li] date and time.

[b][i][color=orangered]Static errors statistics[/color][/i][/b]
Tracks server errors. Records detailed information (error description, link, and time of the error) in the statistics log file on the server.

[b][i][color=orangered]File structure[/color][/i][/b]
Displays the entire file structure in the website directory: folders and the files they contain.
Updated depending on the setting: File modification check interval,
in minutes (specified in the "Configurations" tab).

[color=green][b]"Blocking" tab[/b][/color]
You can block any project visitor by IP address or IP network mask, by the browser used, as well as by the username of a user registered on the website. The number of blocked visitors is unlimited.

[b][i][color=orangered]Blocked IP Addresses[/i][/b][/color]
This subsection contains the list of blocked IP addresses. Addresses are entered in the format 255.255.255.255.
If necessary, entire subnets can be blocked. The following mask is used: 255.***.***.***

[b]Example 1:[/b]
IP: 77.245.112.0
Network mask: 255.255.***.***
The entire mask will be blocked, including up to 77.245.***.***

You can also block an attacker specifically by browser hash.

[b]Example 2:[/b]
Browser: Opera/9.64 (Windows NT 6.0; U; ru) Presto/2.1.1
Browser hash: 83897c6b59842b5554ba4e0d20bf201a

The hash can be seen in emails sent via the contact form, as well as in the user profile.
Using browser hash blocking, you can specifically filter out an attacker while users from their subnet will not be affected.

[b]To block a user by IP, the following fields must be filled in[/b]:
[li] [b][i]IP address[/i][/b] – must be filled in;
[li] [b][i]Network mask[/i][/b] – must be selected;
[li] [b][i]Browser hash[/i][/b] – filled in if necessary;
[li] [b][i]Duration, specified in days[/i][/b] – number of blocking days;
[li] [b][i]Blocking reason[/i][/b] – the blocking reason can be specified and will be shown to the user when accessing the website.

[b][i][color=orangered]Blocked users[/i][/b][/color]
This section contains the list of website users blocked by "Nickname".
To block a project user by "Nickname", the following fields must be filled in:
[li] [b][i]Nickname[/i][/b] – must be filled in;
[li] [b][i]Duration, specified in days[/i][/b] – number of blocking days;
[li] [b][i]Blocking reason[/i][/b] – the blocking reason can be specified and will be shown to the user when accessing the website;
[li] [b][i]Send email notification[/i][/b] – an email template can be filled in, which will be sent to the blocked user after blocking.

[color=green][b]"Login and Password" tab[/b][/color]
To enhance security, an additional login and password can be set for accessing the administration system. You can also restrict access to the project's administration system to a specific IP address or IP network mask. This protection method is the most optimal and excludes any unauthorized access to the administration panel.
[li] [b][i]Message when accessing with an incorrect IP[/i][/b] – the message that appears when attempting to access the administration panel from an unauthorized IP address.
[color=blue][b]Tip:[/color][/b] replace the message with something neutral to avoid giving the attacker additional information about the protection.
[li] [b][i]Message when login or password is entered incorrectly[/i][/b] – the message that appears when an incorrect administrator login and/or password is entered.
[color=blue][b]Tip:[/color][/b] replace the message with something neutral to avoid giving the attacker additional information about the protection.
[li] [b][i]Network mask for administrator panel access[/i][/b] – the range of IP addresses from which access to the administration system is allowed. If the IP address is dynamic (modem connection), the address range can be obtained from your provider(s).
[li] [b][i]Allowed administrator IP addresses[/i][/b] – this window lists the IP addresses from which access to the administration system is allowed. Used with connections having a static or dynamic IP address.
[li] [b][i]Additional administrator login and password[/i][/b] – additional protection of the administration system that excludes any unauthorized access to the website management panel. Authentication credentials are requested before entering the main administrator login and password. This method is called HTTP authentication.
[hr][color=red][b][i]Attention![/b]
HTTP authentication is only possible when running PHP as an Apache module or in FastCGI mode with the Mod Rewrite module installed. Note that this function does not work on Microsoft IIS servers and with the CGI version of PHP.[/i][/color][hr]
[color=green][b]"Configurations" tab[/b][/color]
In this tab, the main security system settings are configured. Explanations for some settings:
[li] [b][i]Maximum statistics file size, in bytes[/i][/b] – if the set size is reached, the file is packed into a gZip archive, the name of which is generated according to the packing date.
A new file is created. Applies to all statistics files displayed in the "Main" tab.
[li] [b][i]Database backup interval, in minutes[/i][/b] – the system can create backup copies of the database automatically. The interval between
DB backups is specified in minutes. The database copy is packed into a gZip archive and receives a name according to the creation time.
[li] [b][i]Automatic database backup?[/i][/b] – create DB backup copies or not.
[li] [b][i]Show error messages?[/i][/b] – responsible for displaying PHP system errors. We recommend disabling this (increases the security level)
if the website is running in normal mode. If the website is running in debug mode (e.g., testing, creating custom modules, blocks), we recommend enabling display to track errors and their causes. In disabled mode, errors are not shown even if they exist.
[li] [b][i]Show JavaScript error messages?[/i][/b] – similar to PHP errors (see the point above).
[li] [b][i]Block attackers?[/i][/b] – the user or IP is automatically added to the blocked list, after which access to the website is not possible.

[color=green][b]Possible problems and their solutions[/b][/color]
[li] Security management may be blocked as a result of excessive growth of log files. It is recommended to periodically clear logs of outdated messages.
[li] Additional login and password do not work – delete the additional login and password from the file: config/security.php, search by keys login and password
[li] Administrator access blocked by IP – delete your IP address from the file: config/security.php, search by key blocker_ip[/justify]
