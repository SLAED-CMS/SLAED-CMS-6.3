[justify]La section "Securite" est un outil puissant pour proteger le site contre divers types d'attaques, des injections SQL au telechargement de scripts tiers dans le repertoire du site. Cette section aidera a suivre, identifier et, si necessaire, bloquer l'attaquant, ainsi que tout autre utilisateur ou visiteur du projet.

[color=green][b]Onglet "Principal"[/b][/color]
Fournit des statistiques sur l'utilisation du site. Pour consulter les statistiques, cliquez sur la valeur (Information) a cote du fichier de statistiques correspondant. Les informations seront affichees sous la liste des fichiers de statistiques.
Pour telecharger les informations sous forme de fichier TXT, cliquez sur la valeur (Telecharger).
Pour effacer un fichier de statistiques, cliquez sur la valeur (Supprimer l'objet).
Pour afficher le chemin de stockage et le nom du fichier de statistiques sur le serveur, cliquez sur l'icone (i) a gauche du nom de la statistique correspondante.

[b][i][color=orangered]Statistiques des fichiers modifies[/color][/i][/b]
Le systeme verifie tous les fichiers du site pour detecter les suppressions, modifications et nouveaux ajouts selon la planification configuree dans le module « Scheduler » pour la tache filescan.
La collecte de ces statistiques est utile en termes de securite : les actions decrites ci-dessus sur les fichiers peuvent etre suivies.

[b][i][color=orangered]Statistiques des erreurs dynamiques[/color][/i][/b]
Suit les erreurs de scripts et de serveur. Enregistre des informations detaillees (description de l'erreur, script, ligne et heure de l'erreur) dans le fichier journal de statistiques sur le serveur.

[b][i][color=orangered]Statistiques des actions interdites[/color][/i][/b]
Suit les actions interdites. Certaines methodes de transmission d'informations ne peuvent pas etre utilisees, mais en meme temps elles ne sont pas critiques pour la securite du systeme. Par exemple, l'utilisation de code HTML dans la barre d'adresse du navigateur lors de la transmission de requetes, ou la tentative d'integration de JavaScripts, IFrame, etc. Enregistre des informations detaillees (adresse IP de l'attaquant, donnees du navigateur, description de l'action, heure de l'action) dans le fichier journal de statistiques sur le serveur.

[b][i][color=orangered]Statistiques de connexion des utilisateurs[/color][/i][/b]
Suit toutes les connexions des utilisateurs au site. Enregistre :
[li] si la connexion a ete reussie ;
[li] l'adresse IP de l'utilisateur connecte ;
[li] le pseudo ;
[li] le navigateur ;
[li] la date et l'heure.

[b][i][color=orangered]Statistiques de toutes les informations entrantes[/color][/i][/b]
Suit toutes les actions effectuees par les visiteurs sur le site (variables globales POST, GET, COOKIE, FILES, SESSION), essentiellement tout ce que les utilisateurs font, quelles informations ils demandent, ce qu'ils envoient, etc.
La collecte de statistiques est utile en termes de securite : il est possible de suivre en detail ce qu'une adresse IP particuliere a fait sur le site.

[b][i][color=orangered]Statistiques des attaques[/color][/i][/b]
Le panneau d'information principal du systeme de securite. Suit les attaquants et leurs actions. Enregistre des informations detaillees (adresse IP de l'attaquant, donnees du navigateur, description de l'attaque, heure de l'attaque) dans le fichier journal de statistiques sur le serveur.

[b][i][color=orangered]Statistiques de connexion des administrateurs[/color][/i][/b]
Suit toutes les connexions des administrateurs au site. Enregistre :
[li] si la connexion a ete reussie ;
[li] l'adresse IP de l'administrateur connecte ;
[li] le pseudo ;
[li] le navigateur ;
[li] la date et l'heure.

[b][i][color=orangered]Statistiques des erreurs statiques[/color][/i][/b]
Suit les erreurs du serveur. Enregistre des informations detaillees (description de l'erreur, lien et heure de l'erreur) dans le fichier journal de statistiques sur le serveur.

[b][i][color=orangered]Structure des fichiers[/color][/i][/b]
Affiche l'integralite de la structure des fichiers dans le repertoire du site : dossiers et fichiers qu'ils contiennent.
Mise a jour selon le calendrier configure dans le module « Scheduler » pour la tache filescan.

[color=green][b]Onglet "Blocage"[/b][/color]
Tout visiteur du projet peut etre bloque par adresse IP ou masque de reseau IP, par navigateur utilise, ainsi que par nom d'utilisateur enregistre sur le site. Le nombre de visiteurs bloques est illimite.

[b][i][color=orangered]Adresses IP bloquees[/i][/b][/color]
Cette sous-section contient la liste des adresses IP bloquees. Les adresses sont saisies au format 255.255.255.255.
Si necessaire, des sous-reseaux entiers peuvent etre bloques. Le masque suivant est utilise : 255.***.***.***

[b]Exemple 1 :[/b]
IP : 77.245.112.0
Masque de reseau : 255.255.***.***
L'ensemble du masque sera bloque, y compris jusqu'a 77.245.***.***

Il est egalement possible de bloquer un attaquant de maniere ciblee par le hash du navigateur.

[b]Exemple 2 :[/b]
Navigateur : Opera/9.64 (Windows NT 6.0; U; ru) Presto/2.1.1
Hash du navigateur : 83897c6b59842b5554ba4e0d20bf201a

Le hash peut etre vu dans les e-mails envoyes via le formulaire de contact, ainsi que dans le profil de l'utilisateur.
Grace au blocage par hash du navigateur, il est possible de filtrer de maniere ciblee un attaquant, sans que les utilisateurs de son sous-reseau ne soient affectes.

[b]Pour bloquer un utilisateur par IP, les champs suivants doivent etre remplis[/b] :
[li] [b][i]Adresse IP[/i][/b] – a remplir obligatoirement ;
[li] [b][i]Masque de reseau[/i][/b] – a selectionner obligatoirement ;
[li] [b][i]Hash du navigateur[/i][/b] – a remplir si necessaire ;
[li] [b][i]Duree, indiquee en jours[/i][/b] – nombre de jours de blocage ;
[li] [b][i]Raison du blocage[/i][/b] – la raison du blocage peut etre indiquee et sera affichee a l'utilisateur lors de l'acces au site.

[b][i][color=orangered]Utilisateurs bloques[/i][/b][/color]
Cette section contient la liste des utilisateurs du site bloques par "Pseudo".
Pour bloquer un utilisateur du projet par "Pseudo", les champs suivants doivent etre remplis :
[li] [b][i]Pseudo[/i][/b] – a remplir obligatoirement ;
[li] [b][i]Duree, indiquee en jours[/i][/b] – nombre de jours de blocage ;
[li] [b][i]Raison du blocage[/i][/b] – la raison du blocage peut etre indiquee et sera affichee a l'utilisateur lors de l'acces au site ;
[li] [b][i]Envoyer une notification par e-mail[/i][/b] – un modele d'e-mail peut etre rempli, qui sera envoye a l'utilisateur bloque apres le blocage.

[color=green][b]Onglet "Identifiant et mot de passe"[/b][/color]
Pour renforcer la securite, un identifiant et un mot de passe supplementaires peuvent etre definis pour l'acces au systeme d'administration. Il est egalement possible de restreindre l'acces au systeme d'administration du projet a une adresse IP specifique ou un masque de reseau IP. Cette methode de protection est la plus optimale et exclut tout acces non autorise au panneau d'administration.
[li] [b][i]Message lors de l'acces avec une IP incorrecte[/i][/b] – le message qui apparait lors d'une tentative d'acces au panneau d'administration depuis une adresse IP non autorisee.
[color=blue][b]Conseil :[/color][/b] remplacez le message par quelque chose de neutre afin de ne pas donner a l'attaquant d'informations supplementaires sur la protection.
[li] [b][i]Message lors de la saisie incorrecte de l'identifiant ou du mot de passe[/i][/b] – le message qui apparait lors de la saisie d'un identifiant et/ou mot de passe administrateur incorrect.
[color=blue][b]Conseil :[/color][/b] remplacez le message par quelque chose de neutre afin de ne pas donner a l'attaquant d'informations supplementaires sur la protection.
[li] [b][i]Masque de reseau pour l'acces au panneau d'administration[/i][/b] – la plage d'adresses IP a partir desquelles l'acces au systeme d'administration est autorise. Si l'adresse IP est dynamique (connexion modem), la plage d'adresses peut etre obtenue aupres de votre fournisseur(s).
[li] [b][i]Adresses IP autorisees de l'administrateur[/i][/b] – cette fenetre liste les adresses IP a partir desquelles l'acces au systeme d'administration est autorise. Utilisee pour les connexions avec une adresse IP fixe ou dynamique.
[li] [b][i]Identifiant et mot de passe supplementaires de l'administrateur[/i][/b] – protection supplementaire du systeme d'administration qui exclut tout acces non autorise au panneau de gestion du site. Les donnees d'authentification sont demandees avant la saisie de l'identifiant et du mot de passe principaux de l'administrateur. Cette methode s'appelle l'authentification HTTP.
[hr][color=red][b][i]Attention ![/b]
L'authentification HTTP n'est possible que lorsque PHP fonctionne en tant que module Apache ou en mode FastCGI avec le module Mod Rewrite installe. Notez que cette fonction ne fonctionne pas sur les serveurs Microsoft IIS et avec la version CGI de PHP.[/i][/color][hr]
[color=green][b]Onglet "Configurations"[/b][/color]
Dans cet onglet, les parametres principaux du systeme de securite sont configures. Explications pour certains parametres :
[li] [b][i]Taille maximale des fichiers de statistiques, en octets[/i][/b] – si la taille definie est atteinte, le fichier est compresse dans une archive gZip dont le nom est genere en fonction de la date de compression.
Un nouveau fichier est cree. S'applique a tous les fichiers de statistiques affiches dans l'onglet "Principal".
[li] La planification des sauvegardes de la base de donnees et de l'analyse des fichiers est maintenant configuree dans le module « Scheduler », ou vous pouvez activer les taches, definir les expressions cron et les lancer manuellement.
[li] [b][i]Sauvegarde automatique de la base de donnees ?[/i][/b] – creer des copies de sauvegarde de la BD ou non.
[li] [b][i]Afficher les messages d'erreur ?[/i][/b] – responsable de l'affichage des erreurs systeme PHP. Nous recommandons de desactiver (augmente le niveau de
securite) si le site fonctionne en mode normal. Si le site fonctionne en mode debogage (par exemple : tests, creation de modules personnalises, blocs), nous recommandons d'activer l'affichage pour suivre les erreurs et leurs causes. En mode desactive, les erreurs ne sont pas affichees meme si elles existent.
[li] [b][i]Afficher les messages d'erreur JavaScripts ?[/i][/b] – par analogie avec les erreurs PHP (voir le point ci-dessus).
[li] [b][i]Bloquer les attaquants ?[/i][/b] – l'utilisateur ou l'IP est automatiquement ajoute a la liste de blocage, apres quoi l'acces au site est impossible.

[li] [b][i]Captcha (ALTCHA)[/i][/b] – protection anti-spam auto-hébergée basée sur la preuve de travail, sans services externes, CDN ni Google. Activable séparément pour l’inscription, le formulaire de contact, les commentaires, ainsi que la connexion utilisateur et administrateur (jamais / après des échecs / à chaque connexion).
[li] [b][i]Difficulté, durée de vie et clé secrète[/i][/b] – la difficulté (faible / normale / élevée) définit le coût de la preuve de travail ; la durée de vie limite la validité d’un défi. La clé maître du site est stockée dans [i]config/security.php[/i] (partagée par les jetons CSRF, le captcha et l’obscurcissement des noms de champs) ; le bouton la régénère. Les données éphémères (marqueurs à usage unique et compteurs) se trouvent dans [i]storage/captcha[/i].
[color=green][b]Problemes possibles et leurs solutions[/b][/color]
[li] La gestion de la securite peut etre bloquee en raison d'une augmentation excessive de la taille des fichiers journaux. Il est recommande de purger periodiquement les journaux des messages obsoletes.
[li] L'identifiant et le mot de passe supplementaires ne fonctionnent pas – supprimez l'identifiant et le mot de passe supplementaires du fichier : config/security.php, recherche par les cles login et password
[li] Acces administrateur bloque par IP – supprimez votre adresse IP du fichier : config/security.php, recherche par la cle blocker_ip[/justify]
