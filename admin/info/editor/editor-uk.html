[hr][color=red][b][i]Увага![/b]
Даний розділ призначений тільки для адміністраторів, які добре знайомі з серверним ПЗ і мовою PHP.[/i][/color][hr]
[justify]Розділ «Редактор» дозволяє безпосередньо через панель адміністрування керувати основними системними файлами. Керування файлами проводиться у вкладках:
[li] [b][i]Ядро системи[/i][/b] – файл впровадження в ядро системи: config/system.php. У вкладці можна додати код, який буде розміщено в ядрі системи.
[li] [b][i]Шапка системи[/i][/b] – файл впровадження в шапку системи: config/header.php. У вкладці можна вставити код, який буде впроваджено в head системи. Як правило, даний файл використовують для впровадження java-скриптів і мета тегів.
[li] [b][i]Правила Apache[/i][/b] – файл конфігурацій правил перетворень ЧПУ на серверному рівні: .htaccess. У вкладці можна змінити або доповнити стандартні правила перетворень адресних рядків браузера на серверному рівні. Дана можливість підтримується тільки у випадку встановленого на сервері Mod Rewrite.
[li] [b][i]Правила для роботів[/i][/b] – файл конфігурацій інструкцій і параметрів індексування для пошукових роботів: robots.txt. У вкладці можна змінити або доповнити текстовий файл, що знаходиться в кореневій директорії сайту, в якому записуються спеціальні інструкції для пошукових роботів. Ці інструкції можуть забороняти до індексації деякі розділи або сторінки на сайті, вказувати на правильне «дзеркалювання» домену, рекомендувати пошуковому роботу дотримуватися певного часового інтервалу між завантаженням документів з сервера тощо. У цьому файлі Ви можете вказати параметри індексування сайту як для всіх роботів одразу, так і для кожної пошукової системи окремо.

Для внесення змін у файл перейдіть у відповідну вкладку і внесіть зміни у відкритий редактор вмісту файлу, для збереження натисніть «Зберегти».[/justify]

[hr][color=red][b][i]Увага![/b]
Якщо на конфігураційні файли не будуть встановлені відповідні права доступу (CHMOD - 666), то система видасть відповідне попередження.[/i][/color][hr]
[b][color=green]Приклади використання редактора впроваджень у відділі «Шапка системи»[/color][/b]

[color=orangered][b][i]Перенаправлення відвідувача, який прийшов з певного сайту[/i][/b][/color]
Перейдіть у вкладку «Шапка системи» і додайте наступний запис:
[php]$reflink = "#slaed.net#i";
$metlink = "news.html";
$referer = text_filter(getenv("HTTP_REFERER"));
if (preg_match($reflink, $referer)) {
echo '<meta http-equiv="refresh" content="0; url='.$metlink.'">';
}[/php]
[justify]$reflink – відповідає за адресу сайту, з якого прийшов відвідувач.
Замість: slaed.net вкажіть свій домен.
$metlink – відповідає за сторінку, куди буде перенаправлено відвідувача.
Замість: news.html вкажіть необхідну сторінку або сайт.

[color=orangered][b][i]Забороняємо копіювати інформацію з сайту[/i][/b][/color]
Все що можна прочитати і побачити, відповідно можна скопіювати. Ефективного захисту від копіювання не існує. Але це не означає, що йому не можна перешкоджати, можна відключити використання правої або інших кнопок миші, які застосовуються для копіювання, це стане незначною, але все ж перешкодою в копіюванні для початківців користувачів.
Перейдіть у вкладку «Шапка системи» і додайте наступний запис:[/justify]
[php]echo '<script>
<!--//
function click() {
// Щоб відключити ліву кнопку поставте цифру 1
// Щоб відключити третю кнопку поставте цифру 3
if (event.button == 2) {
// Тут введіть свій напис, який з'явиться у вікні попередження
alert("Copyright Scriptic!");
}
}
document.onmousedown=click;
//-->
</script>';[/php]
[justify]Зауважимо, що працює цей код тільки на браузерах Internet Explorer. Не виключено що і для інших браузерів є щось подібне. Якщо захочете скористатися іншим кодом, просто замініть цей на свій код, вставивши його між echo ' і ';[/justify]

[color=orangered][b][i]Перенаправлення відвідувача з певної країни[/i][/b][/color]
Перейдіть у вкладку «Шапка системи» і додайте наступний запис:
[php]$userlang = "Russia";
$metlink = "news.html";
$userip = user_geo_ip(getip(), 2);
if ($userip == $userlang) {
echo '<meta http-equiv="refresh" content="0; url='.$metlink.'">';
}[/php]
[justify]$userlang – відповідає за назву країни, з якої прийшов відвідувач.
Назва країни не повинна бути довільною і повинна відповідати стандартам використання класу. Використовуйте результат user_geo_ip() як еталон коректного значення країни.
$metlink – відповідає за сторінку, куди буде перенаправлено відвідувача.
Замість: news.html вкажіть необхідну сторінку або сайт.

[b][color=green]Приклади використання редактора впроваджень у відділі «Серверний ЧПУ»[/color][/b]

[color=orangered][b][i]Встановлення заборони на використання іншими сайтами будь-яких зображень з сайту[/i][/b][/color]
Ні для кого не секрет, що деякі сайти для економії свого трафіку і розміру використовуваного місця на сервері застосовують віддалені зображення з інших сайтів, тим самим поглинають чужий трафік і підвищують навантаження на сервер. Щоб цьому перешкодити, пропонуємо до використання наступні методи.
Перейдіть у вкладку «Серверний ЧПУ» і додайте після:[/justify]
[php]# Mod rewrite on
RewriteEngine On
RewriteBase /[/php]
наступний запис:
[php]RewriteOptions MaxRedirects=100
RewriteCond %{HTTP_REFERER} !^http://(www\.)?slaed\.net/ [NC]
RewriteRule \.(jpe?g|gif|bmp|png)$ http://www.slaed.net/templates/default/images/logos/slaed_logo_60x60.png [L][/php]
[justify]Замість: slaed вкажіть ім'я домену свого сайту.
Замість: net вкажіть зону домену свого сайту.
Замість: http://www.slaed.net/templates/default/images/logos/slaed_logo_60x60.png вкажіть посилання на логотип або зображення, яке буде відображатися на тому сайті, який використовує зображення з сайту.

[color=orangered][b][i]Об'єднання домену з www і без[/i][/b][/color]
На перший погляд домен з приставкою www і без неї є однаковим, насправді це не так. Сервером вони ініціюються як два різних домени і, як правило, на них можна встановити два абсолютно різних сайти. У деяких хостерів злиття двох доменів передбачено спочатку і проводиться автоматично, у деяких дане налаштування існує в панелі керування хостингом, для хостингів у яких злиття не передбачено можна скористатися наступним методом.
Перейдіть у вкладку «Серверний ЧПУ» і додайте після:[/justify]
[php]# Mod rewrite on
RewriteEngine On
RewriteBase /[/php]
наступний запис:
[php]# Redirect
RewriteCond %{HTTP_HOST} !^www\.slaed\.net [NC]
RewriteRule ^(.*)$ http://www.slaed.net/$1 [R=301,L][/php]
[justify]Замість: slaed вкажіть ім'я домену свого сайту.
Замість: net вкажіть зону домену свого сайту.
Для роботи даного методу, сервер хостера повинен підтримувати роботу з .htaccess, Mod Rewrite повинен бути встановлений і активований.[/justify]

[color=orangered][b][i]Можливі правила та налаштування[/i][/b][/color]
[justify]В описі нижче, вашій увазі пропонуються можливі правила з описом, які допустимі до використання в нашому випадку на «Серверному ЧПУ», а саме в основному файлі .htaccess, який знаходиться в головній директорії системи.[/justify]

[php]# Заборона лістингу і перегляду директорій
Options All -ExecCGI -Indexes -Includes +FollowSymLinks[/php]

[php]# Індексна сторінка сайту
DirectoryIndex index.php[/php]

[php]# Кодування сайту за замовчуванням
AddDefaultCharset utf-8[/php]

[php]# Редирект, у випадку відповідної помилки на сервері
ErrorDocument 400 /index.php?error=400
ErrorDocument 401 /index.php?error=401
ErrorDocument 403 /index.php?error=403
ErrorDocument 404 /index.php?error=404
ErrorDocument 500 /index.php?error=500
ErrorDocument 503 /index.php?error=503[/php]

[php]# Налаштування безпеки, актуальні для версій нижче PHP 5.3.0, для PHP 5.4.0 і вище неактуальні
php_flag register_globals off
php_flag safe_mode on
php_flag magic_quotes_gpc on[/php]

[php]# Заборона показу версій серверного ПЗ
ServerSignature Off[/php]

Наведене вище правило, підтримується на жаль не всіма хостерами. Описані нижче налаштування доступні тільки у випадку встановленого на сервері mod_rewrite.

[php]# Включення mod_rewrite
RewriteEngine On[/php]

[justify]Модуль mod_rewrite є програмним модулем веб сервера Apache (зверніть увагу, що він не буде виконуватися під іншими веб серверами!). Його первинна функція - маніпуляція дій з URL. Модуль дуже універсальний і різнобічний, тут показані деякі реальні приклади.[/justify]

[php]# Коренева директорія
RewriteBase /[/php]

[php]# Редирект з www на без www
RewriteCond %{HTTP_HOST} ^www\.(.*) [NC]
RewriteRule ^(.*)$ http://%1/$1 [R=301,L][/php]

[php]# Редирект з без www на www
RewriteCond %{HTTP_HOST} ^[^.]+\.[^.]+$
RewriteCond %{HTTPS}s ^on(s)|
RewriteRule ^ http%1://www.%{HTTP_HOST}%{REQUEST_URI} [R=301,L][/php]

[php]# Редирект з протоколу http на https
RewriteCond %{HTTPS} off
RewriteRule (.*) https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L][/php]

[php]# Редирект адрес з index.php на без index.php
RewriteCond %{THE_REQUEST} ^GET.*index\.php [NC]
RewriteRule (.*?)index\.php/*(.*) /$1$2 [R=301,L][/php]

[php]# Редирект на нову категорію
RewriteRule ^стара/(.*)$ /нова/$1 [R=301,L][/php]

[php]# Правила обробки запитів для блокування поширених експлойтів
RewriteCond %{QUERY_STRING} proc/self/environ [OR]
RewriteCond %{QUERY_STRING} mosConfig_[a-zA-Z_]{1,21}(=|\%3D) [OR]
RewriteCond %{QUERY_STRING} base64_(en|de)code\(.*\) [OR]
RewriteCond %{QUERY_STRING} base64_encode[^(]*\([^)]*\) [OR]
RewriteCond %{QUERY_STRING} (<|%3C)([^s]*s)+cript.*(>|%3E) [NC,OR]
RewriteCond %{QUERY_STRING} GLOBALS(=|\[|\%[0-9A-Z]{0,2}) [OR]
RewriteCond %{QUERY_STRING} _REQUEST(=|\[|\%[0-9A-Z]{0,2})
RewriteRule .* index.php [F][/php]

[php]# Блокування MySQL ін'єкцій
RewriteCond %{QUERY_STRING} CONCAT.*\( [NC,OR]
RewriteCond %{QUERY_STRING} UNION.*SELECT.*\( [NC,OR]
RewriteCond %{QUERY_STRING} UNION.*ALL.*SELECT [NC]
RewriteRule ^(.*)$ index.php [F,L][/php]

[php]# Блокування файлових ін'єкцій
RewriteCond %{REQUEST_METHOD} GET
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=http:// [OR]
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=(\.\.//?)+ [OR]
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=/([a-z0-9_.]//?)+ [NC]
RewriteRule .* - [F][/php]

[php]# Редирект для чужих доменів
RewriteCond %{HTTP_HOST} !^slaed\.net$
RewriteRule ^(.*)$ http://slaed.net/$1 [R=301,L][/php]
