# Редактор

Раздел **Редактор** позволяет вносить «горячие» изменения в основные системные файлы конфигурации проекта прямо через панель управления ресурса (без необходимости подключения по FTP). Интерфейс предлагает удобный редактор с подсветкой синтаксиса кода (CodeMirror).

> [!WARNING]
> Данный раздел предназначен только для главных администраторов (Суперпользователей), хорошо знакомых с серверным программным обеспечением, синтаксисом регулярных выражений Apache и языком программирования PHP. Любая синтаксическая опечатка (например, не закрытая кавычка или скобка) в этих файлах вызовет фатальную ошибку 'HTTP 500' и полностью "положит" весь сайт вместе с админкой.

---

## Вкладки файлов

### 1. Ядро системы

Редактирование файла `config/system.php`. 
Сюда можно добавлять собственные PHP-функции и логику, которая будет доступна на уровне ядра во всех модулях системы.

> [!NOTE]
> При вставке PHP-кода в эту вкладку (и во вкладку «Шапка системы») **не нужно** писать открывающие теги `<?php` и закрывающие `?>`. Система сама добавляет их, а также защитную конструкцию `if (!defined('FUNC_FILE')) die('Illegal file access');` при сохранении.

### 2. Шапка системы

Редактирование файла `config/header.php`.
Код, размещенный здесь, будет интегрирован непосредственно в секцию `<head>` HTML-страниц вашего сайта.
Как правило, эта вкладка применяется для быстрого добавления:

* Глобальных счетчиков аналитики (Яндекс Метрика, Google Analytics), если они реализованы через PHP или `<script>`.
* Дополнительных META-тегов (помимо стандартных SEO-настроек).
* Динамических редиректов.

### 3. Правила Apache

Редактирование главного конфигурационного файла сервера `public/.htaccess`, лежащего в корне документов сайта (`public/`). Файл `.htaccess` уровня проекта, который нужен только при корне на всём проекте, здесь не редактируется.
Панель позволяет изменять и дополнять правила маршрутизации ЧПУ (Человеко-понятный УРЛ), настраивать сжатие, кеширование браузера и безопасность.

> [!IMPORTANT]
> Для работы этого функционала ваш веб-сервер (Apache/OpenLiteSpeed) обязаны поддерживать работу с директивами `.htaccess`, а модуль `mod_rewrite` должен быть активирован.

> [!NOTE]
> **Nginx и IIS не читают `.htaccess`.** На таких серверах эти правила (включая маршрутизацию ошибок на фирменную страницу CMS) нужно задавать в конфиге самого сервера. Для Nginx добавьте в блок `server` правила ниже; в поставляемом файле `nginx.conf.example` они уже есть.

```nginx
fastcgi_intercept_errors off;
error_page 400 401 402 403 404 500 503 /index.php?error=$status;
error_page 502 504 /error.html;
```

Без этого при ошибке (например, 404) посетитель увидит стандартную страницу веб-сервера, а не оформленную страницу SLAED.

> [!IMPORTANT]
> Директива `fastcgi_intercept_errors off` обязательна. Иначе Nginx перехватит ответ PHP и подменит фирменную страницу ошибки своей собственной, а заодно срежет заголовок `Cache-Control: no-store` (и ошибка может закешироваться). На Apache это поведение задаётся набором директив `ErrorDocument` — они уже включены в стандартный `.htaccess` проекта.

Как это устроено:

* **Ошибки, которые отдаёт живой PHP** (`400 401 402 403 404 500 503`) маршрутизируются на `/index.php?error=NNN`, и их рисует сам движок — фирменная страница с логотипом, текстом и поиском. Коды проверяются по «белому списку» в ядре, поэтому подделать произвольный или несуществующий статус через `?error=` нельзя.
* **Коды `502` и `504`** означают, что PHP недоступен (перегрузка, падение, простой пула). Обслужить их движок уже не может, поэтому они отдают отдельный файл `public/error.html` в корне документов сайта. Он **полностью автономен** — все стили, иконки и логотип встроены внутрь, без единой внешней ссылки на CSS, шрифты или картинки, — поэтому корректно отображается, даже когда сервер «лежит» и остальные файлы недоступны.

### 4. Правила для роботов

Редактирование файла `public/robots.txt` (также лежащего в корне документов сайта).
Здесь хранятся инструкции для поисковых пауков (Яндекс, Google, Bing и др.). Вы можете запрещать к индексации служебные разделы (Disallow), разрешать страницы (Allow), указывать путь к `Sitemap.xml` или управлять параметром `Crawl-delay`.

## Примеры полезных внедрений (Snippets)

### Примеры для вкладки «Шапка системы»

**1. Перенаправление посетителя из определенной страны:**
Используя встроенную функцию `user_geo_ip()`, можно ловить гостей из нужных регионов и отправлять их на другие адреса:

```php
$userlang = "Russia";
$metlink = "https://example.com/ru-version/";
$userip = user_geo_ip(getip(), 2);
if ($userip == $userlang) {
    echo '<meta http-equiv="refresh" content="0; url='.$metlink.'">';
}
```

**2. Блокировка вызова правой кнопки мыши (базовая защита от копирования):**
(Вставляется как HTML скрипт прямо внутрь PHP через `echo`):

```php
echo '<script>
function click(event) {
    if (event.button == 2) { 
        alert("Копирование материалов запрещено!"); 
    }
}
document.onmousedown = click;
</script>';
```

### Примеры для вкладки «Правила Apache» (.htaccess)

> [!CAUTION]
> Код ниже добавляется **строго после** строк включения движка реврайтов (т.е. после *RewriteEngine On* и *RewriteBase /*).

**1. Защита от хотлинкинга (Использование ваших картинок на чужих сайтах):**
Данное правило запретит другим сайтам вызывать картинки с вашего хостинга, экономя вам трафик, и вместо ваших фото покажет загрушку.

```apache
RewriteCond %{HTTP_REFERER} !^http://(www\.)?slaed\.net/ [NC]
RewriteRule \.(jpe?g|gif|bmp|png)$ http://www.slaed.net/templates/default/images/bad-hotlink.png [L]
```

*(Не забудьте заменить `slaed\.net` на ваш домен).*

**2. 301 Редирект с www на без-www:**
Объединяет вес сайта для поисковиков.

```apache
RewriteCond %{HTTP_HOST} ^www\.(.*) [NC]
RewriteRule ^(.*)$ http://%1/$1 [R=301,L]
```

**3. Принудительный редирект на защищенный HTTPS протокол:**
Если у вас куплен и установлен SSL сертификат.

```apache
RewriteCond %{HTTPS} off
RewriteRule (.*) https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]
```

**4. Блокировка показа версий серверного ПО:**
(Базовая мера безопасности). Добавляется в любое место `.htaccess`.

```apache
ServerSignature Off
```

**5. Запрет листинга и просмотра файловых директорий браузером:**

```apache
Options All -ExecCGI -Indexes -Includes +FollowSymLinks
```

**6. Кеширование браузера и сжатие статики (PageSpeed):**
Заставляет браузер хранить стили, скрипты, шрифты и картинки локально и отдавать текстовые ответы в сжатом виде. Эти блоки уже включены в стандартный `.htaccess` проекта — здесь они приведены для справки и тонкой настройки.

Каждый адрес стиля или скрипта, который печатает система, несёт версию своего содержимого: `templates/lite/assets/css/theme.css?v=0a5af6e4ae`. Под таким адресом файл не меняется никогда, поэтому браузер хранит его год и не переспрашивает сервер; изменённый файл получает новый адрес и приходит к посетителю на следующей же странице. Всё остальное (стили и скрипты без версии, шрифты, картинки, иконки, звуки) хранится неделю и после неё сверяется с сервером по `ETag`. Страницы сайта не кешируются никогда.

```apache
# Сжатие: по типу ответа, а не по имени файла — так сжимаются и сами страницы, которые строит index.php
# WOFF2/WOFF, картинки и архивы уже сжаты и намеренно не перечислены
<IfModule mod_deflate.c>
AddOutputFilterByType DEFLATE text/html text/plain text/css text/javascript text/xml text/xsl
AddOutputFilterByType DEFLATE application/javascript application/json application/xml application/xhtml+xml
AddOutputFilterByType DEFLATE application/rss+xml application/xslt+xml application/opensearchdescription+xml image/svg+xml
</IfModule>

# Срок хранения в кеше браузера: стиль или скрипт с версией (?v=) — год, любой другой статический файл — неделя
<IfModule mod_headers.c>
<FilesMatch "(?i)\.(?:css|js|mjs)$">
<If "%{QUERY_STRING} =~ /(?:^|&)v=[^&]/">
Header set Cache-Control "public, max-age=31536000, immutable"
</If>
<Else>
Header set Cache-Control "public, max-age=604800"
</Else>
</FilesMatch>
<FilesMatch "(?i)\.(?:woff2?|ttf|otf|eot|jpe?g|png|gif|webp|avif|svg|ico|mp3|ogg|wav)$">
Header set Cache-Control "public, max-age=604800"
</FilesMatch>
</IfModule>
```

> [!NOTE]
> Без модуля `mod_headers` сроки не задаются, и браузер угадывает их сам по дате изменения файла. Версия в адресе при этом всё равно гарантирует, что изменённый файл придёт по новому адресу.

> [!NOTE]
> **На Nginx эти директивы не работают** — сроки и сжатие задаются в блоке `server`. Готовые правила есть в поставляемом файле `nginx.conf.example`: выбор между годом и неделей делается на уровне `server` переменной `$asset_cache` по `$arg_v`, потому что `if` внутри `location` отменил бы его `try_files`.

```nginx
gzip on;
gzip_vary on;
gzip_types text/plain text/css text/javascript text/xml text/xsl application/javascript application/json application/xml
    application/xhtml+xml application/rss+xml application/xslt+xml application/opensearchdescription+xml image/svg+xml;

set $asset_cache "public, max-age=604800";
if ($arg_v) {
    set $asset_cache "public, max-age=31536000, immutable";
}

location ~* \.(?:css|js|mjs)$ {
    try_files $uri /index.php?$args;
    add_header Cache-Control $asset_cache;
}

location ~* \.(?:woff2?|ttf|otf|eot|jpe?g|png|gif|webp|avif|svg|ico|mp3|ogg|wav)$ {
    try_files $uri /index.php?$args;
    add_header Cache-Control "public, max-age=604800";
}
```

> [!IMPORTANT]
> Версии адресов берутся из кеша конфигурации `config/local.php`. Если файл темы или плагина заменён вручную, удалите `config/local.php` (или сохраните любые настройки в админке) — иначе страница продолжит печатать старую версию, и вернувшиеся посетители останутся со старым файлом.
