[hr][color=red][b][i]Attention ![/b]
Cette section est destinée uniquement aux administrateurs qui maîtrisent bien les logiciels serveur et le langage de programmation PHP.[/i][/color][hr]
[justify]La section « Éditeur » permet de gérer directement les fichiers système principaux via le panneau d'administration. La gestion des fichiers s'effectue dans les onglets suivants :
[li] [b][i]Noyau du système[/i][/b] – fichier d'injection dans le noyau du système : config/system.php. Dans cet onglet, vous pouvez ajouter du code qui sera placé dans le noyau du système.
[li] [b][i]En-tête du système[/i][/b] – fichier d'injection dans l'en-tête du système : config/header.php. Dans cet onglet, vous pouvez insérer du code qui sera injecté dans le head du système. En règle générale, ce fichier est utilisé pour l'injection de scripts Java et de balises meta.
[li] [b][i]Apache rules[/i][/b] – fichier de configuration des règles de transformation SEF au niveau serveur : .htaccess. Dans cet onglet, vous pouvez modifier ou compléter les règles standard de transformation des barres d'adresse du navigateur au niveau serveur. Cette fonctionnalité n'est disponible que si Mod Rewrite est installé sur le serveur.
[li] [b][i]Règles pour les robots[/i][/b] – fichier de configuration des instructions et paramètres d'indexation pour les robots de recherche : robots.txt. Dans cet onglet, vous pouvez modifier ou compléter le fichier texte situé dans le répertoire racine du site, qui contient des instructions spéciales pour les robots de recherche. Ces instructions peuvent interdire l'indexation de certaines sections ou pages du site, indiquer le « miroir » correct du domaine, recommander au robot de recherche de respecter un certain intervalle de temps entre les téléchargements de documents depuis le serveur, etc. Dans ce fichier, vous pouvez spécifier les paramètres d'indexation du site aussi bien pour tous les robots à la fois que pour chaque moteur de recherche séparément.

Pour apporter des modifications à un fichier, accédez à l'onglet correspondant et effectuez les modifications dans l'éditeur de contenu du fichier qui s'ouvre, cliquez sur « Enregistrer » pour sauvegarder.[/justify]

[hr][color=red][b][i]Attention ![/b]
Si les fichiers de configuration n'ont pas les droits d'accès appropriés définis (CHMOD - 666), le système affichera un avertissement correspondant.[/i][/color][hr]
[b][color=green]Exemples d'utilisation de l'éditeur d'injection dans la section « En-tête du système »[/color][/b]

[color=orangered][b][i]Redirection d'un visiteur provenant d'un site spécifique[/i][/b][/color]
Accédez à l'onglet « En-tête du système » et ajoutez l'entrée suivante :
[php]$reflink = "#slaed.net#i";
$metlink = "news.html";
$referer = text_filter(getenv("HTTP_REFERER"));
if (preg_match($reflink, $referer)) {
echo '<meta http-equiv="refresh" content="0; url='.$metlink.'">';
}[/php]
[justify]$reflink – responsable de l'adresse du site d'où vient le visiteur.
Au lieu de : slaed.net indiquez votre domaine.
$metlink – responsable de la page vers laquelle le visiteur sera redirigé.
Au lieu de : news.html indiquez la page ou le site requis.

[color=orangered][b][i]Interdire la copie d'informations du site[/i][/b][/color]
Tout ce qui peut être lu et vu peut également être copié. Il n'existe pas de protection efficace contre la copie. Mais cela ne signifie pas qu'on ne peut pas l'entraver ; vous pouvez désactiver l'utilisation des boutons droit ou autres de la souris utilisés pour copier. Ce sera un obstacle insignifiant mais tout de même un obstacle à la copie pour les utilisateurs débutants.
Accédez à l'onglet « En-tête du système » et ajoutez l'entrée suivante :[/justify]
[php]echo '<script>
<!--//
function click() {
// Pour désactiver le bouton gauche, mettez le chiffre 1
// Pour désactiver le troisième bouton, mettez le chiffre 3
if (event.button == 2) {
// Entrez ici votre message qui apparaîtra dans la fenêtre d'avertissement
alert("Copyright Scriptic!");
}
}
document.onmousedown=click;
//-->
</script>';[/php]
[justify]Notez que ce code ne fonctionne que sur les navigateurs Internet Explorer. Il est possible que quelque chose de similaire existe pour d'autres navigateurs. Si vous souhaitez utiliser un autre code, remplacez simplement celui-ci par votre code en l'insérant entre echo ' et ';[/justify]

[color=orangered][b][i]Redirection d'un visiteur d'un pays spécifique[/i][/b][/color]
Accédez à l'onglet « En-tête du système » et ajoutez l'entrée suivante :
[php]$userlang = "Russia";
$metlink = "news.html";
$userip = user_geo_ip(getip(), 2);
if ($userip == $userlang) {
echo '<meta http-equiv="refresh" content="0; url='.$metlink.'">';
}[/php]
[justify]$userlang – responsable du nom du pays d'où vient le visiteur.
Le nom du pays ne doit pas être arbitraire et doit correspondre aux normes d'utilisation de la classe. Utilisez la sortie de user_geo_ip() comme référence de valeur pays valide.
$metlink – responsable de la page vers laquelle le visiteur sera redirigé.
Au lieu de : news.html indiquez la page ou le site requis.

[b][color=green]Exemples d'utilisation de l'éditeur d'injection dans la section « SEF serveur »[/color][/b]

[color=orangered][b][i]Interdire à d'autres sites d'utiliser les images du site[/i][/b][/color]
Ce n'est un secret pour personne que certains sites, pour économiser leur trafic et l'espace utilisé sur le serveur, utilisent des images distantes d'autres sites, consommant ainsi le trafic d'autrui et augmentant la charge du serveur. Pour empêcher cela, nous proposons les méthodes suivantes.
Accédez à l'onglet « SEF serveur » et ajoutez après :[/justify]
[php]# Mod rewrite on
RewriteEngine On
RewriteBase /[/php]
l'entrée suivante :
[php]RewriteOptions MaxRedirects=100
RewriteCond %{HTTP_REFERER} !^http://(www\.)?slaed\.net/ [NC]
RewriteRule \.(jpe?g|gif|bmp|png)$ http://www.slaed.net/templates/default/images/logos/slaed_logo_60x60.png [L][/php]
[justify]Au lieu de : slaed indiquez le nom de domaine de votre site.
Au lieu de : net indiquez la zone de domaine de votre site.
Au lieu de : http://www.slaed.net/templates/default/images/logos/slaed_logo_60x60.png indiquez un lien vers le logo ou l'image qui sera affiché sur le site qui utilise des images de votre site.

[color=orangered][b][i]Fusion du domaine avec www et sans[/i][/b][/color]
À première vue, un domaine avec le préfixe www et sans semble être le même, mais ce n'est pas le cas. Le serveur les reconnaît comme deux domaines différents et, en règle générale, deux sites complètement différents peuvent y être installés. Certains hébergeurs ont la fusion de deux domaines prévue initialement et effectuée automatiquement, certains ont ce paramètre dans le panneau de contrôle de l'hébergement. Pour les hébergements où la fusion n'est pas prévue, vous pouvez utiliser la méthode suivante.
Accédez à l'onglet « SEF serveur » et ajoutez après :[/justify]
[php]# Mod rewrite on
RewriteEngine On
RewriteBase /[/php]
l'entrée suivante :
[php]# Redirect
RewriteCond %{HTTP_HOST} !^www\.slaed\.net [NC]
RewriteRule ^(.*)$ http://www.slaed.net/$1 [R=301,L][/php]
[justify]Au lieu de : slaed indiquez le nom de domaine de votre site.
Au lieu de : net indiquez la zone de domaine de votre site.
Pour que cette méthode fonctionne, le serveur de l'hébergeur doit prendre en charge le travail avec .htaccess, Mod Rewrite doit être installé et activé.[/justify]

[color=orangered][b][i]Règles et paramètres possibles[/i][/b][/color]
[justify]Dans la description ci-dessous, nous vous présentons les règles possibles avec descriptions qui sont acceptables pour une utilisation dans notre cas sur « SEF serveur », notamment dans le fichier principal .htaccess, qui se trouve dans le répertoire principal du système.[/justify]

[php]# Interdiction du listing et de la visualisation des répertoires
Options All -ExecCGI -Indexes -Includes +FollowSymLinks[/php]

[php]# Page d'index du site
DirectoryIndex index.php[/php]

[php]# Encodage par défaut du site
AddDefaultCharset utf-8[/php]

[php]# Redirection en cas d'erreur serveur correspondante
ErrorDocument 400 /index.php?error=400
ErrorDocument 401 /index.php?error=401
ErrorDocument 403 /index.php?error=403
ErrorDocument 404 /index.php?error=404
ErrorDocument 500 /index.php?error=500
ErrorDocument 503 /index.php?error=503[/php]

[php]# Paramètres de sécurité, pertinents pour les versions inférieures à PHP 5.3.0, non pertinents pour PHP 5.4.0 et supérieur
php_flag register_globals off
php_flag safe_mode on
php_flag magic_quotes_gpc on[/php]

[php]# Interdiction de l'affichage des versions des logiciels serveur
ServerSignature Off[/php]

La règle ci-dessus n'est malheureusement pas prise en charge par tous les hébergeurs. Les paramètres décrits ci-dessous ne sont disponibles que si mod_rewrite est installé sur le serveur.

[php]# Activation de mod_rewrite
RewriteEngine On[/php]

[justify]Le module mod_rewrite est un module logiciel du serveur web Apache (notez qu'il ne fonctionnera pas sous d'autres serveurs web !). Sa fonction principale est la manipulation d'actions avec URL. Le module est très universel et polyvalent ; quelques exemples pratiques sont présentés ici.[/justify]

[php]# Répertoire racine
RewriteBase /[/php]

[php]# Redirection de www vers sans www
RewriteCond %{HTTP_HOST} ^www\.(.*) [NC]
RewriteRule ^(.*)$ http://%1/$1 [R=301,L][/php]

[php]# Redirection de sans www vers www
RewriteCond %{HTTP_HOST} ^[^.]+\.[^.]+$
RewriteCond %{HTTPS}s ^on(s)|
RewriteRule ^ http%1://www.%{HTTP_HOST}%{REQUEST_URI} [R=301,L][/php]

[php]# Redirection du protocole http vers https
RewriteCond %{HTTPS} off
RewriteRule (.*) https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L][/php]

[php]# Redirection des adresses avec index.php vers sans index.php
RewriteCond %{THE_REQUEST} ^GET.*index\.php [NC]
RewriteRule (.*?)index\.php/*(.*) /$1$2 [R=301,L][/php]

[php]# Redirection vers une nouvelle catégorie
RewriteRule ^ancienne/(.*)$ /nouvelle/$1 [R=301,L][/php]

[php]# Règles de traitement des requêtes pour bloquer les exploits courants
RewriteCond %{QUERY_STRING} proc/self/environ [OR]
RewriteCond %{QUERY_STRING} mosConfig_[a-zA-Z_]{1,21}(=|\%3D) [OR]
RewriteCond %{QUERY_STRING} base64_(en|de)code\(.*\) [OR]
RewriteCond %{QUERY_STRING} base64_encode[^(]*\([^)]*\) [OR]
RewriteCond %{QUERY_STRING} (<|%3C)([^s]*s)+cript.*(>|%3E) [NC,OR]
RewriteCond %{QUERY_STRING} GLOBALS(=|\[|\%[0-9A-Z]{0,2}) [OR]
RewriteCond %{QUERY_STRING} _REQUEST(=|\[|\%[0-9A-Z]{0,2})
RewriteRule .* index.php [F][/php]

[php]# Blocage des injections MySQL
RewriteCond %{QUERY_STRING} CONCAT.*\( [NC,OR]
RewriteCond %{QUERY_STRING} UNION.*SELECT.*\( [NC,OR]
RewriteCond %{QUERY_STRING} UNION.*ALL.*SELECT [NC]
RewriteRule ^(.*)$ index.php [F,L][/php]

[php]# Blocage des injections de fichiers
RewriteCond %{REQUEST_METHOD} GET
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=http:// [OR]
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=(\.\.//?)+ [OR]
RewriteCond %{QUERY_STRING} [a-zA-Z0-9_]=/([a-z0-9_.]//?)+ [NC]
RewriteRule .* - [F][/php]

[php]# Redirection pour les domaines étrangers
RewriteCond %{HTTP_HOST} !^slaed\.net$
RewriteRule ^(.*)$ http://slaed.net/$1 [R=301,L][/php]
