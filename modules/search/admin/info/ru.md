# Модуль «Поиск»

> [!NOTE]
> Модуль `Search` — это комплексное решение, которое отвечает сразу за две связанные задачи: предоставление удобного frontend-поиска по разделам сайта для посетителей и детализированный сбор поисковой (SEO) статистики для администраторов.

## Описание
В текущей реализации система поиска не сводится к одной простой форме. Модуль работает как интеллектуальный агрегатор, способный выполнять поиск как по стандартным контент-модулям, так и по специализированным компонентам системы.

**Ключевые возможности модуля:**
- Единая frontend-форма поиска с возможностью выбора целевого раздела (модуля).
- Автоматический сбор и сохранение статистики запросов пользователей.
- Каждый модуль ищет по своим правилам, его обработчик поиска лежит в самом модуле.
- Панель администратора с подробной аналитикой, топом популярных запросов и ручными инструментами очистки.
- Таблица источников в панели показывает, какие модули умеют искать, и включает их отметкой.

---

## Пользовательская часть (Frontend)

Публичный поиск доступен по адресу: `/search`.

Интерфейс поиска позволяет пользователю:
- Искать текстовые совпадения сразу по всей базе данных сайта (во всех включенных модулях по умолчанию).
- Сузить область поиска до конкретного модуля (например, только в «Статьях», «Форуме» или «Новостях»).
- **Интеллектуальная подсветка (Highlighting):** При выводе результатов поиска, а также при переходе на конкретную страницу (например, просмотр файла), целевые поисковые слова, переданные через URL-параметр `&word=...`, автоматически подсвечиваются ярким фоном в заголовках и тексте для быстрого визуального ориентирования.

> [!IMPORTANT]
> При каждом поиске система проверяет минимальную длину введенной строки (задается в Конфигурациях). Если анализатор запросов включен, искомая фраза фиксируется в таблице `sport_search`, формируя аналитическую базу интересов.

## Панель администратора (Admin)

Административная часть расположена в панели управления.

Она разделена на 5 логических экранов:

### 1. Главная (Журнал запросов)
Над списком стоят плитки: всего запросов, уникальных запросов, последний запрос, топ запросы и топ модуль. Плитки считают те же записи, что показывает фильтр.

Показывает сырой хронологический лог всех поисковых запросов пользователей в таблице `sport_search`. 
Для каждой записи фиксируется текст фразы (word), целевой модуль (modul), количество вводов (score) и дата последней активности (time). Поддерживается фильтрация по модулям и поиск по тексту фразы для быстрого нахождения нужных ключей.

**Отмеченные.** Флажок в конце строки или клавиша X на строке под курсором (курсор водят J и K) отмечает строку, флажок в шапке — всю страницу. Внизу таблицы — «Отмечено: N», выбор действия и «OK»; действие уходит на сервер через 10 секунд, до этого его отменяет кнопка «Отменить» в уведомлении. Так же устроен топ запросов. Действие — **Удалить**; в топе удаляется фраза целиком, все её записи в пределах фильтра.

**Все страницы.** Когда отмечена вся страница, а страниц больше одной, над таблицей предлагается **«Отметить все N»** — все строки текущего фильтра. Выбранное действие тогда уходит на сервер через те же 10 секунд порциями по 100 строк: строка над таблицей показывает «Обработано X из N», кнопка «Пауза» останавливает и продолжает работу, «Снять отметку» возвращает выбор к странице. Строки, появившиеся после показа списка, не затрагиваются; закрытая вкладка останавливает работу, уже обработанное остаётся.

### 2. Топ запросов
Агрегированная аналитическая сводка. В отличие от сырого лога, группирует все одинаковые запросы в единый «хит-парад». Экран позволяет понять, что именно чаще всего ищут ваши посетители. Эти данные бесценны для корректировки контент-плана или структуры навигации на сайте.

### 3. Конфигурации
Страница состоит из окна «Основные» и таблицы источников под ним. Кнопка «Сохранить» записывает и настройки, и отметки таблицы.

**Основные.** Анализатор запросов, наименьшая и наибольшая длина запроса, число записей и номеров страниц в выдаче.

**Источники.** Таблица показывает все места, где поиск может искать. Это типы материалов и активные модули сайта, открытые всем посетителям. В строке стоят название, идентификатор, модуль и состояние. Отметка в конце строки включает источник в поиск. Отметка в шапке колонки ставит или снимает все отметки сразу.

| Модуль | Что это |
|---|---|
| Материалы | Тип материалов Node |
| Модуль | Модуль сайта со своей страницей |

| Состояние | Что это |
|---|---|
| Включено | Источник участвует в поиске и стоит в выборе раздела на странице поиска |
| Выключено | Источник умеет искать, но в поиск не включён |
| Нет обработчика | Модуль не несёт обработчика поиска. Отметки у него нет, включить его нельзя |

Переключатель над таблицей оставляет строки одного состояния. Он показывает все строки, включённые, выключенные или строки без обработчика. Строки он только прячет. Отметки спрятанных строк сохраняются вместе с остальными.

Модуль, закрытый для части посетителей, в таблицу не попадает и в поиске не участвует.

### 4. Очистка (Удалить)
Гибкий инструмент обслуживания и оптимизации базы данных поиска. Поддерживает массовое удаление старых поисковых логов (например, старше X суток), возможность чистить пустые запросы или сбрасывать лог выборочно для конкретных модулей, чтобы не перегружать БД `sport_search`. Кнопка «Удалить» сначала запрашивает подтверждение «Удалить статистику поиска?»: удалённые записи не восстанавливаются. Удаляется только то, что называет выбранный режим: по модулю — записи модуля из списка поиска, по дням — записи старше указанного числа дней. Режим без модуля, с модулем не из списка или с 0 дней ничего не удаляет, и панель отвечает «Ошибка».

При правке записи пустой текст запроса не сохраняется: панель отвечает «Оставлено пустым поле с заголовком/названием!». Модуль записи выбирается из того же списка, что и в фильтре; модуль, который у записи уже стоит, остаётся в выборе, даже если его в этом списке нет.

### 5. Информация
Встроенная справочная система (текущий документ).

## Опции конфигурации

Настройки модуля физически хранятся в файле `config/search.php`.

| Параметр | Описание |
|---|---|
| **Источники** | Модули, по которым разрешён поиск. Их отмечают в таблице источников, список хранится в ключе `mods`. Отметка типа материалов хранится в настройках самого типа. |
| **Минимум символов** | Минимальная длина поисковой строки. |
| **Максимум символов** | Верхний лимит поисковой строки для защиты базы от переполнения и обрезки SQL-запроса. |
| **Записей на странице сайта** | Сколько результатов показывает страница поисковой выдачи на сайте. Пустое поле берёт число из «Конфигураций» (раздел «Пагинация»), оно видно в поле серым. |
| **Номеров страниц в пагинаторе сайта** | Сколько номеров страниц показывает пагинатор выдачи; пустое поле так же берёт общее число. |
| **Анализатор запросов** | Глобальный переключатель, запускающий запись поисковых фраз в таблицу `sport_search`. |

> [!WARNING]
> Значение параметра **«Минимум символов»** критически важно для безопасности и производительности. Слишком короткие слова (например, 1-2 буквы) сильно нагружают SQL-сервер при поиске по большим таблицам `LIKE %text%` и выдают много нерелевантного «мусора». Рекомендуемый минимум: 3 символа.

## Обработчик поиска модуля

Модуль поиска не знает ни одного модуля по имени. Чтобы модуль участвовал в поиске, он сам несёт обработчик. Это файл `modules/<имя>/search.php`. Обработчики есть у форума и опросов. Типы материалов ищет читатель Node, им файл не нужен.

### 1. Что делает обработчик
Файл возвращает одну функцию. Поиск передаёт ей состояние запроса и получает строки модуля.

- Из состояния обработчик берёт слово `word` и предел числа строк `lim`.
- Обработчик сам решает, что видно посетителю. Он знает, какие записи опубликованы, какие разделы открыты и на каком языке они показаны. Поиск этих правил не знает и ничего не добавляет.
- Слово подставляется в запрос параметром. Знаки `%` и `_` в нём экранируются, как в обработчике форума.

### 2. Что возвращает строка

| Ключ | Что это |
|---|---|
| `link` | Параметры адреса записи для `getSeoUrl()`. Обязателен |
| `title` | Заголовок, уже экранированный для HTML. Обязателен |
| `time` | Дата записи. Обязателен |
| `content` | Текст, из которого поиск вырезает отрывок |
| `safe`, `trust` | Как парсер читает `content`. `safe` читает текст безопасно. `trust` вдобавок исполняет теги `[usehtml]`, `[usephp]` и `[block]`, его ставят только там, где запись этих тегов проверена при сохранении |
| `edit` | Адрес правки записи, его видит модератор модуля |
| `cid` | Категория записи |
| `nick`, `upath`, `user`, `post` | Автор записи |
| `comments`, `reads` | Счётчики комментариев и просмотров |

Строку без `link` и ответ, который не является списком, поиск пропускает и пишет об этом в журнал сайта с именем модуля. Остальные источники при этом ищутся как обычно.

> [!IMPORTANT]
> Обработчик запускается только для активного модуля, открытого всем посетителям и включённого в таблице источников. Поиск по именам колонок таблицы не ведётся, потому что по ним нельзя узнать, какие записи модуль показывает, а какие скрывает.

## Оптимизация и Производительность механизма

Таблица статистики поисковых фраз (`sport_search`) использует интеллектуальный счетчик весов (колонка `score`). 
При самом первом поиске слова создается уникальная запись со `score = 1`. Если другой или этот же пользователь ищет данное слово повторно в этом же целевом модуле, система не дублирует записи! Она просто обновляет время использования строки (`time`) и инкрементит `score + 1`. Таким образом таблица остается компактной.

> [!CAUTION]
> **Контроль нагрузки:** При гигантской базе данных контента поиск по текстовым полям (`intro` и `body`) без использования нативных полнотекстовых индексов (FULLTEXT) может вызывать замедление СУБД из-за сканирования (Full Table Scan). Если сайт очень большой (десятки тысяч статей), старайтесь ограничивать количество одновременно включённых в поиск источников и вовремя использовать вкладку «Удалить» для сброса поисковых логов.
