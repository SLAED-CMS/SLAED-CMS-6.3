[justify]Le module «Journal des modifications» (Changelog) est conçu pour afficher l'historique des commits (modifications) dans le système de contrôle de version Git. C'est un outil utile pour les développeurs et les administrateurs permettant de suivre toutes les modifications apportées au code du projet.

Le module prend en charge deux sources de données :

[li] [b]Git local[/b] – lecture des commits directement depuis le dépôt Git local sur le serveur.
[li] [b]API GitHub[/b] – récupération des commits via l'API GitHub pour les dépôts distants.

[color=green][b]Onglet «Accueil»[/b][/color]
La page principale affiche une liste de commits avec des possibilités de filtrage et de recherche. Filtres disponibles :

[li] [b][i]Recherche[/i][/b] – recherche dans le texte du message de commit.
[li] [b][i]Auteur[/i][/b] – filtrage par nom d'auteur du commit.
[li] [b][i]Fichier[/i][/b] – filtrage par nom de fichier modifié (Git local uniquement).
[li] [b][i]Date de/à[/i][/b] – filtrage des commits par plage de dates.

Pour chaque commit, les éléments suivants sont affichés :
[li] Sujet du commit
[li] Hash du commit (raccourci)
[li] Nom et email de l'auteur
[li] Date et heure du commit
[li] Corps du message (si disponible)
[li] Statistiques des modifications – nombre de lignes ajoutées et supprimées (optionnel)
[li] Liste des fichiers modifiés (optionnel)

[color=green][b]Onglet «Configuration»[/b][/color]
Cet onglet permet de configurer les paramètres du module :

[u]Source de données[/u]
[li] [b][i]Source[/i][/b] – sélection de la source des commits : «Git local» ou «API GitHub».

[u]Paramètres GitHub (si API GitHub sélectionnée)[/u]
[li] [b][i]GitHub Owner[/i][/b] – nom du propriétaire du dépôt (utilisateur ou organisation).
[li] [b][i]GitHub Repository[/i][/b] – nom du dépôt.
[li] [b][i]GitHub Token[/i][/b] – jeton d'accès personnel pour l'authentification. Recommandé pour augmenter la limite de requêtes API.

[u]Paramètres d'affichage[/u]
[li] [b][i]Nombre de commits[/i][/b] – nombre maximum de commits à charger (10 à 500).
[li] [b][i]Par page[/i][/b] – nombre de commits affichés par page (5 à 50).
[li] [b][i]Cache TTL[/i][/b] – durée de vie du cache en secondes. Par défaut 900 secondes (15 minutes). Définissez 0 pour désactiver la mise en cache.
[li] [b][i]Grouper par date[/i][/b] – regroupement des commits par jour avec les en-têtes «Aujourd'hui», «Hier», «Cette semaine».
[li] [b][i]Afficher les fichiers[/i][/b] – affichage de la liste des fichiers modifiés pour chaque commit.
[li] [b][i]Afficher les statistiques[/i][/b] – affichage du nombre de lignes ajoutées/supprimées.
[li] [b][i]Export[/i][/b] – activer la fonctionnalité d'export de l'historique des modifications.

[color=green][b]Export[/b][/color]
Lorsque l'option d'export est activée, des onglets supplémentaires apparaissent dans la barre de navigation :
[li] [b]Export TXT[/b] – export au format texte.
[li] [b]Export Markdown[/b] – export au format Markdown pour utilisation dans la documentation.

[hr][color=blue][b]Attention ![/b][/color]

[li] Pour travailler avec Git local, Git doit être installé sur le serveur et le projet doit se trouver dans un dépôt Git.
[li] Lors de l'utilisation de l'API GitHub sans jeton, il y a une limite de 60 requêtes par heure. Avec un jeton – 5000 requêtes par heure.
[li] La mise en cache aide à réduire la charge du serveur et de l'API GitHub. Pour des modifications fréquentes, réduisez le TTL du cache.
[li] Les statistiques de fichiers (lignes ajoutées/supprimées) ne sont disponibles que lors de l'utilisation de Git local.[hr]

[color=green][b]Utilisation sur le site[/b][/color]
Le module peut également être affiché sur la partie publique du site, permettant aux visiteurs de consulter l'historique des modifications du projet. Pour activer l'accès public, activez le module dans le panneau d'administration sous «Modules» et définissez les droits d'accès appropriés.[/justify]
