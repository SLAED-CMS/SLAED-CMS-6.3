[justify]The «Changelog» module is designed to display the commit history (changes) in the Git version control system. It is a useful tool for developers and administrators to track all changes made to the project code.

The module supports two data sources:

[li] [b]Local Git[/b] – reading commits directly from the local Git repository on the server.
[li] [b]GitHub API[/b] – fetching commits via the GitHub API for remote repositories.

[color=green][b]«Home» Tab[/b][/color]
The main page displays a list of commits with filtering and search capabilities. Available filters:

[li] [b][i]Search[/i][/b] – search in commit message text.
[li] [b][i]Author[/i][/b] – filter by commit author name.
[li] [b][i]File[/i][/b] – filter by changed file name (local Git only).
[li] [b][i]Date from/to[/i][/b] – filter commits by date range.

For each commit, the following is displayed:
[li] Commit subject
[li] Commit hash (shortened)
[li] Author name and email
[li] Commit date and time
[li] Message body (if available)
[li] Change statistics – number of added and deleted lines (optional)
[li] List of changed files (optional)

[color=green][b]«Settings» Tab[/b][/color]
This tab configures the module parameters:

[u]Data Source[/u]
[li] [b][i]Source[/i][/b] – select commit source: «Local Git» or «GitHub API».

[u]GitHub Settings (when GitHub API is selected)[/u]
[li] [b][i]GitHub Owner[/i][/b] – repository owner name (user or organization).
[li] [b][i]GitHub Repository[/i][/b] – repository name.
[li] [b][i]GitHub Token[/i][/b] – personal access token for authentication. Recommended to increase API request limit.

[u]Display Parameters[/u]
[li] [b][i]Number of commits[/i][/b] – maximum number of commits to load (10 to 500).
[li] [b][i]Per page[/i][/b] – number of commits displayed per page (5 to 50).
[li] [b][i]Cache TTL[/i][/b] – cache lifetime in seconds. Default is 900 seconds (15 minutes). Set to 0 to disable caching.
[li] [b][i]Group by date[/i][/b] – group commits by day with headers «Today», «Yesterday», «This Week».
[li] [b][i]Show files[/i][/b] – display list of changed files for each commit.
[li] [b][i]Show statistics[/i][/b] – display number of added/deleted lines.
[li] [b][i]Export[/i][/b] – enable changelog export functionality.

[color=green][b]Export[/b][/color]
When the export option is enabled, additional tabs appear in the navigation bar:
[li] [b]Export TXT[/b] – export in text format.
[li] [b]Export Markdown[/b] – export in Markdown format for use in documentation.

[hr][color=blue][b]Please Note![/b][/color]

[li] To work with local Git, Git must be installed on the server and the project must be in a Git repository.
[li] When using the GitHub API without a token, there is a limit of 60 requests per hour. With a token – 5000 requests per hour.
[li] Caching helps reduce server load and GitHub API usage. For frequent changes, reduce the cache TTL.
[li] File statistics (added/deleted lines) are only available when using local Git.[hr]

[color=green][b]Website Usage[/b][/color]
The module can also be displayed on the public part of the website, allowing visitors to view the project's change history. To activate public access, enable the module in the administrator panel under «Modules» and set the appropriate access rights.[/justify]
