# Журнал изменений (Changelog)

Раздел **«Журнал изменений»** (`admin.php?name=changelog`) — это специализированная консоль мониторинга для разработчиков и администраторов. Модуль агрегирует данные из систем контроля версий, позволяя отслеживать все правки, внесённые в код проекта, прямо из панели управления сайтом.

---

## 1. Источники данных

Система SLAED CMS 6.3 Phoenix поддерживает два способа получения истории коммитов:
1. **Локальный Git:** Чтение данных непосредственно из Git-репозитория, в котором развернут проект на вашем сервере (требуется установленный Git на хостинге).
2. **GitHub API:** Получение информации об изменениях из удалённого репозитория на GitHub.

---

## 2. Управление журналом (Главная)

На главной странице выводится хронологический список правок. Каждая запись содержит:
* **Заголовок и Хеш:** Краткая суть изменений и уникальный идентификатор коммита.
* **Автор:** Имя и E-Mail разработчика, внесшего изменения.
* **Статистика:** Количество добавленных (`+`) и удаленных (`-`) строк кода (только для локального Git).
* **Список файлов:** Перечень измененных файлов в рамках данного коммита.

### Фильтрация и поиск:
Для быстрого анализа доступны фильтры:
* **Поиск:** Поиск по тексту сообщения коммита.
* **Автор:** Фильтр по имени конкретного разработчика.
* **Файл:** Поиск коммитов, затрагивающих конкретный файл (только для локального Git).
* **Период:** Фильтрация по датам «С» и «По».

---

## 3. Настройки и производительность

Вкладка **«Конфигурации»** определяет технические параметры взаимодействия с репозиторием.

### Параметры GitHub API:
* **GitHub Owner & Repository:** Имя владельца и название репозитория на GitHub.
* **GitHub Token:** Персональный токен доступа. 
  > [!IMPORTANT]
  > Использование токена увеличивает лимит запросов к GitHub API с 60 до 5000 в час, что критично для активных проектов.

### Параметры отображения и кэширования:
* **Кэширование (Cache TTL):** Время жизни кэша в секундах (по умолчанию 900 сек / 15 минут). Позволяет значительно снизить нагрузку на сервер и экономить лимиты GitHub API.
* **Пагинация:** Настройка количества коммитов, загружаемых за один раз (от 10 до 500) и отображаемых на одной странице (от 5 до 50).
* **Группировка:** Опция группировки коммитов по временным периодам («Сегодня», «Вчера», «На этой неделе»).

---

## 4. Экспорт данных

Если в настройках включена опция **«Экспорт»**, на панели навигации появляются две дополнительные вкладки:
* **Export TXT:** Формирование текстового отчета по истории изменений.
* **Export Markdown:** Генерация истории в формате Markdown для последующего использования в документации проекта (например, в файлах `CHANGELOG.md`).

---

> [!TIP]
> Модуль можно вывести на публичную часть сайта, чтобы ваши пользователи могли видеть прогресс разработки. Для этого включите модуль в разделе «Модули» и установите соответствующие права доступа.

> [!WARNING]
> Статистика добавленных и удаленных строк (`Show statistics`) доступна только при использовании источника **«Локальный Git»**. GitHub API не предоставляет эти данные в рамках стандартного запроса списка коммитов.
