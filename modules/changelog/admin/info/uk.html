[justify]Модуль «Історія змін» (Changelog) призначений для відображення історії комітів (змін) у системі керування версіями Git. Це корисний інструмент для розробників та адміністраторів, що дозволяє відстежувати всі зміни, внесені в код проекту.

Модуль підтримує два джерела даних:

[li] [b]Локальний Git[/b] – читання комітів безпосередньо з локального Git-репозиторію на сервері.
[li] [b]GitHub API[/b] – отримання комітів через API GitHub для віддалених репозиторіїв.

[color=green][b]Вкладка «Головна»[/b][/color]
На головній сторінці відображається список комітів з можливістю фільтрації та пошуку. Доступні фільтри:

[li] [b][i]Пошук[/i][/b] – пошук за текстом повідомлення коміту.
[li] [b][i]Автор[/i][/b] – фільтрація за ім'ям автора коміту.
[li] [b][i]Файл[/i][/b] – фільтрація за ім'ям зміненого файлу (тільки для локального Git).
[li] [b][i]Дата з/по[/i][/b] – фільтрація комітів за діапазоном дат.

Для кожного коміту відображається:
[li] Заголовок (subject) коміту
[li] Хеш коміту (скорочений)
[li] Ім'я автора та email
[li] Дата та час коміту
[li] Тіло повідомлення (якщо є)
[li] Статистика змін – кількість доданих та видалених рядків (опціонально)
[li] Список змінених файлів (опціонально)

[color=green][b]Вкладка «Налаштування»[/b][/color]
У цій вкладці налаштовуються параметри роботи модуля:

[u]Джерело даних[/u]
[li] [b][i]Джерело[/i][/b] – вибір джерела комітів: «Локальний Git» або «GitHub API».

[u]Налаштування GitHub (при виборі GitHub API)[/u]
[li] [b][i]GitHub Owner[/i][/b] – ім'я власника репозиторію (користувач або організація).
[li] [b][i]GitHub Repository[/i][/b] – назва репозиторію.
[li] [b][i]GitHub Token[/i][/b] – персональний токен доступу для автентифікації. Рекомендується для збільшення ліміту запитів API.

[u]Параметри відображення[/u]
[li] [b][i]Кількість комітів[/i][/b] – максимальна кількість комітів, що завантажуються (від 10 до 500).
[li] [b][i]На сторінці[/i][/b] – кількість комітів, що відображаються на одній сторінці (від 5 до 50).
[li] [b][i]Cache TTL[/i][/b] – час життя кешу в секундах. За замовчуванням 900 секунд (15 хвилин). Встановіть 0 для вимкнення кешування.
[li] [b][i]Групувати за датою[/i][/b] – групування комітів за днями із заголовками «Сьогодні», «Вчора», «Цього тижня».
[li] [b][i]Показувати файли[/i][/b] – відображення списку змінених файлів для кожного коміту.
[li] [b][i]Показувати статистику[/i][/b] – відображення кількості доданих/видалених рядків.
[li] [b][i]Експорт[/i][/b] – увімкнути можливість експорту історії змін.

[color=green][b]Експорт[/b][/color]
При увімкненій опції експорту на панелі навігації з'являються додаткові вкладки:
[li] [b]Export TXT[/b] – експорт у текстовий формат.
[li] [b]Export Markdown[/b] – експорт у формат Markdown для використання в документації.

[hr][color=blue][b]Зверніть увагу![/b][/color]

[li] Для роботи з локальним Git на сервері має бути встановлений Git, а проект має знаходитися в Git-репозиторії.
[li] При використанні GitHub API без токена діє обмеження в 60 запитів на годину. З токеном – 5000 запитів на годину.
[li] Кешування допомагає знизити навантаження на сервер та GitHub API. При частих змінах зменшіть TTL кешу.
[li] Статистика файлів (додані/видалені рядки) доступна лише при використанні локального Git.[hr]

[color=green][b]Використання на сайті[/b][/color]
Модуль також може відображатися на публічній частині сайту, дозволяючи відвідувачам переглядати історію змін проекту. Для активації публічного доступу увімкніть модуль у панелі адміністратора, розділ «Модулі», та встановіть відповідні права доступу.[/justify]
