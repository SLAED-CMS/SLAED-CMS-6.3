[justify]Модуль «История изменений» (Changelog) предназначен для отображения истории коммитов (изменений) в системе управления версиями Git. Это полезный инструмент для разработчиков и администраторов, позволяющий отслеживать все изменения, внесённые в код проекта.

Модуль поддерживает два источника данных:

[li] [b]Локальный Git[/b] – чтение коммитов непосредственно из локального Git-репозитория на сервере.
[li] [b]GitHub API[/b] – получение коммитов через API GitHub для удалённых репозиториев.

[color=green][b]Вкладка «Главная»[/b][/color]
На главной странице отображается список коммитов с возможностью фильтрации и поиска. Доступные фильтры:

[li] [b][i]Поиск[/i][/b] – поиск по тексту сообщения коммита.
[li] [b][i]Автор[/i][/b] – фильтрация по имени автора коммита.
[li] [b][i]Файл[/i][/b] – фильтрация по имени изменённого файла (только для локального Git).
[li] [b][i]Дата с/по[/i][/b] – фильтрация коммитов по диапазону дат.

Для каждого коммита отображается:
[li] Заголовок (subject) коммита
[li] Хеш коммита (сокращённый)
[li] Имя автора и email
[li] Дата и время коммита
[li] Тело сообщения (если есть)
[li] Статистика изменений – количество добавленных и удалённых строк (опционально)
[li] Список изменённых файлов (опционально)

[color=green][b]Вкладка «Настройки»[/b][/color]
В данной вкладке настраиваются параметры работы модуля:

[u]Источник данных[/u]
[li] [b][i]Источник[/i][/b] – выбор источника коммитов: «Локальный Git» или «GitHub API».

[u]Настройки GitHub (при выборе GitHub API)[/u]
[li] [b][i]GitHub Owner[/i][/b] – имя владельца репозитория (пользователь или организация).
[li] [b][i]GitHub Repository[/i][/b] – название репозитория.
[li] [b][i]GitHub Token[/i][/b] – персональный токен доступа для аутентификации. Рекомендуется для увеличения лимита запросов API.

[u]Параметры отображения[/u]
[li] [b][i]Количество коммитов[/i][/b] – максимальное количество загружаемых коммитов (от 10 до 500).
[li] [b][i]На странице[/i][/b] – количество коммитов, отображаемых на одной странице (от 5 до 50).
[li] [b][i]Cache TTL[/i][/b] – время жизни кэша в секундах. По умолчанию 900 секунд (15 минут). Установите 0 для отключения кэширования.
[li] [b][i]Группировать по дате[/i][/b] – группировка коммитов по дням с заголовками «Сегодня», «Вчера», «На этой неделе».
[li] [b][i]Показывать файлы[/i][/b] – отображение списка изменённых файлов для каждого коммита.
[li] [b][i]Показывать статистику[/i][/b] – отображение количества добавленных/удалённых строк.
[li] [b][i]Экспорт[/i][/b] – включить возможность экспорта истории изменений.

[color=green][b]Экспорт[/b][/color]
При включённой опции экспорта на панели навигации появляются дополнительные вкладки:
[li] [b]Export TXT[/b] – экспорт в текстовый формат.
[li] [b]Export Markdown[/b] – экспорт в формат Markdown для использования в документации.

[hr][color=blue][b]Обратите внимание![/b][/color]

[li] Для работы с локальным Git на сервере должен быть установлен Git и проект должен находиться в Git-репозитории.
[li] При использовании GitHub API без токена действует ограничение в 60 запросов в час. С токеном – 5000 запросов в час.
[li] Кэширование помогает снизить нагрузку на сервер и GitHub API. При частых изменениях уменьшите TTL кэша.
[li] Статистика файлов (добавленные/удалённые строки) доступна только при использовании локального Git.[hr]

[color=green][b]Использование на сайте[/b][/color]
Модуль также может отображаться на публичной части сайта, позволяя посетителям просматривать историю изменений проекта. Для активации публичного доступа включите модуль в панели администратора, раздел «Модули», и установите соответствующие права доступа.[/justify]
