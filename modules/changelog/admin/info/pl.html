[justify]Moduł «Dziennik zmian» (Changelog) służy do wyświetlania historii commitów (zmian) w systemie kontroli wersji Git. Jest to przydatne narzędzie dla programistów i administratorów, pozwalające śledzić wszystkie zmiany wprowadzone w kodzie projektu.

Moduł obsługuje dwa źródła danych:

[li] [b]Lokalny Git[/b] – odczyt commitów bezpośrednio z lokalnego repozytorium Git na serwerze.
[li] [b]GitHub API[/b] – pobieranie commitów przez API GitHub dla zdalnych repozytoriów.

[color=green][b]Zakładka «Strona główna»[/b][/color]
Na stronie głównej wyświetlana jest lista commitów z możliwością filtrowania i wyszukiwania. Dostępne filtry:

[li] [b][i]Wyszukiwanie[/i][/b] – wyszukiwanie w tekście wiadomości commita.
[li] [b][i]Autor[/i][/b] – filtrowanie według nazwy autora commita.
[li] [b][i]Plik[/i][/b] – filtrowanie według nazwy zmienionego pliku (tylko dla lokalnego Git).
[li] [b][i]Data od/do[/i][/b] – filtrowanie commitów według zakresu dat.

Dla każdego commita wyświetlane są:
[li] Temat (subject) commita
[li] Hash commita (skrócony)
[li] Imię autora i email
[li] Data i czas commita
[li] Treść wiadomości (jeśli dostępna)
[li] Statystyki zmian – liczba dodanych i usuniętych linii (opcjonalnie)
[li] Lista zmienionych plików (opcjonalnie)

[color=green][b]Zakładka «Ustawienia»[/b][/color]
W tej zakładce konfigurowane są parametry modułu:

[u]Źródło danych[/u]
[li] [b][i]Źródło[/i][/b] – wybór źródła commitów: «Lokalny Git» lub «GitHub API».

[u]Ustawienia GitHub (przy wyborze GitHub API)[/u]
[li] [b][i]GitHub Owner[/i][/b] – nazwa właściciela repozytorium (użytkownik lub organizacja).
[li] [b][i]GitHub Repository[/i][/b] – nazwa repozytorium.
[li] [b][i]GitHub Token[/i][/b] – osobisty token dostępu do uwierzytelniania. Zalecany do zwiększenia limitu żądań API.

[u]Parametry wyświetlania[/u]
[li] [b][i]Liczba commitów[/i][/b] – maksymalna liczba commitów do załadowania (od 10 do 500).
[li] [b][i]Na stronie[/i][/b] – liczba commitów wyświetlanych na jednej stronie (od 5 do 50).
[li] [b][i]Cache TTL[/i][/b] – czas życia pamięci podręcznej w sekundach. Domyślnie 900 sekund (15 minut). Ustaw 0, aby wyłączyć buforowanie.
[li] [b][i]Grupuj według daty[/i][/b] – grupowanie commitów według dni z nagłówkami «Dzisiaj», «Wczoraj», «W tym tygodniu».
[li] [b][i]Pokaż pliki[/i][/b] – wyświetlanie listy zmienionych plików dla każdego commita.
[li] [b][i]Pokaż statystyki[/i][/b] – wyświetlanie liczby dodanych/usuniętych linii.
[li] [b][i]Eksport[/i][/b] – włącz możliwość eksportu historii zmian.

[color=green][b]Eksport[/b][/color]
Po włączeniu opcji eksportu na pasku nawigacyjnym pojawiają się dodatkowe zakładki:
[li] [b]Export TXT[/b] – eksport do formatu tekstowego.
[li] [b]Export Markdown[/b] – eksport do formatu Markdown do wykorzystania w dokumentacji.

[hr][color=blue][b]Uwaga![/b][/color]

[li] Aby pracować z lokalnym Git, na serwerze musi być zainstalowany Git, a projekt musi znajdować się w repozytorium Git.
[li] Podczas korzystania z GitHub API bez tokena obowiązuje limit 60 żądań na godzinę. Z tokenem – 5000 żądań na godzinę.
[li] Buforowanie pomaga zmniejszyć obciążenie serwera i GitHub API. Przy częstych zmianach zmniejsz TTL pamięci podręcznej.
[li] Statystyki plików (dodane/usunięte linie) są dostępne tylko przy użyciu lokalnego Git.[hr]

[color=green][b]Użycie na stronie[/b][/color]
Moduł może być również wyświetlany w publicznej części witryny, umożliwiając odwiedzającym przeglądanie historii zmian projektu. Aby aktywować dostęp publiczny, włącz moduł w panelu administratora w sekcji «Moduły» i ustaw odpowiednie prawa dostępu.[/justify]
