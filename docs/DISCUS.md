# Архитектурное обсуждение: Единый текстовый парсер SLAED

**Дата:** 2026-02-27
**Участники:** Eduard Laas + Claude (Sonnet 4.6)
**Статус:** Архитектура согласована, реализация не начата

---

## 1. Исходная идея

Объединить `bb_decode()` и Markdown-парсер (`filterMarkdown()`) в единую функцию-фабрику,
которая понимает одновременно:
- Markdown: `**жирный**`, `# Заголовок`, `| table |`, ...
- BB-коды SLAED: `[b]жирный[/b]`, `[url=...]`, `[quote]`, ...

**Мотивация:**
- Один проход вместо двух → нет конфликтов
- BB-коды через `addStash()` / `filterUrl()` → XSS-защита автоматически
- Пользователи получают мощь Markdown (таблицы, task-листы, заголовки)

---

## 2. Критический разбор

### 2.1 Проблема: обратная совместимость НЕ гарантирована

Тезис «не потеряете ни одной старой статьи» — неверен без дополнительных мер.

Старый BB-код контент может случайно совпасть с Markdown-синтаксисом:

```
--- Введение ---     → станет <hr>
## Раздел            → станет <h2>
> Текст              → станет <blockquote>
1. Первый пункт      → станет <ol>
```

**Решение:** Поле `format` (`bb` / `md` / `mixed`) + режимный парсер.

---

### 2.2 Проблема: чистота функции (pure function)

`filterMarkdown()` — чистая функция: текст на входе → HTML на выходе. Нет доступа к БД, конфигу, файловой системе.

Некоторые BB-теги нарушают это:

| Тег | Проблема |
|-----|----------|
| `[attach]` | Запрос к БД / файловой системе |
| `[usephp]` | Выполняет PHP-код (`eval`) |
| `[tabs]` | JS-зависимая структура, нужен счётчик |

**Решение:** Эти теги остаются вне `filterMarkdown()` — обрабатываются в оркестраторе.

---

### 2.3 Проблема: два независимых stash — конфликт токенов

`bb_decode()` (оркестратор) создаёт внешние stash-токены.
`filterMarkdown()` создаёт внутренние токены (`\x02salt:N\x03`).

При одинаковом формате внутренний парсер «переварит» внешние токены.

**Решение:** Разные форматы:

| Уровень | Формат токена |
|---------|---------------|
| Внешний (bb_decode) | `\x01BB:N\x01` |
| Внутренний (filterMarkdown) | `\x02salt:N\x03` |

---

## 3. Согласованная архитектура

### Принцип: `bb_decode()` как умный оркестратор (шим)

```
bb_decode($text, $mod, $mode = 'bb')
│
├─ Этап 1: серверные теги → outerStash[]
│    [usephp]  → только admin, eval → стэш
│    [usehtml] → только admin → стэш
│    [attach]  → DB/FS lookup → стэш
│    [tabs]    → JS-компонент → стэш
│    [code]    → <pre><code> → стэш
│    [quote]   → рекурсия bb_decode() → стэш
│    [hide]    → рекурсия bb_decode() → стэш
│    *01 смайл → <img> → стэш
│
├─ Этап 2: $text = filterMarkdown($text, $safe, $mode)
│    mode='bb'    → только инлайны: [b][i][u][color][url][img] + **bold** `code`
│    mode='md'    → полный Markdown, без BB-кодов
│    mode='mixed' → Markdown-блоки + BB-инлайны
│
└─ Этап 3: strtr($text, outerStash) → финальный HTML
```

---

## 4. Режимы filterMarkdown($src, $safe, $mode)

| Синтаксис | `bb` | `md` | `mixed` |
|-----------|:----:|:----:|:-------:|
| `# Заголовок` (ATX) | ✗ | ✓ | ✓ |
| `--- (hr)` | ✗ | ✓ | ✓ |
| `> цитата (Markdown)` | ✗ | ✓ | ✓ |
| `\| table \|` | ✗ | ✓ | ✓ |
| `- список` | ✗ | ✓ | ✓ |
| `**жирный**` | ✓ | ✓ | ✓ |
| `` `code` `` | ✓ | ✓ | ✓ |
| `[b]...[/b]` | ✓ | ✗ | ✓ |
| `[url=...]...[/url]` | ✓ | ✗ | ✓ |
| `[color=...]` | ✓ | ✗ | ✓ |
| `[img]...[/img]` | ✓ | ✗ | ✓ |

`mode = 'bb'` — дефолт. Все старые вызовы `bb_decode($text, $conf['name'])` продолжают работать без изменений.

---

## 5. Преимущества архитектуры

1. **Обратная совместимость** — старые статьи не ломаются (`mode='bb'` отключает блочный Markdown)
2. **Чистота** — `filterMarkdown()` остаётся pure function без side-эффектов
3. **Безопасность** — все BB-инлайны проходят через `filterUrl()` + `addStash()` → XSS исключён
4. **Без двойного парсинга** — один проход через pipeline
5. **API совместимость** — `bb_decode()` получает третий параметр с дефолтом:
   ```php
   function bb_decode(string $text, string $mod = '', string $mode = 'bb'): string
   ```
   Существующие вызовы не требуют изменений.

## 6. Пять решений, зафиксированных до начала реализации

| # | Решение | Принято |
|---|---------|---------|
| 1 | Формат внешнего токена: `\x01BB:N\x01` | ✓ |
| 2 | Сигнатура: `bb_decode(string $text, string $mod = '', string $mode = 'bb'): string` | ✓ |
| 3 | Смайлы — в Этапе 1 (`bb_decode`), не в `filterMarkdown` | ✓ |
| 4 | `[quote]`/`[hide]` — рекурсивный вызов `bb_decode()` в Этапе 1 | ✓ |
| 5 | В режиме `'bb'`: блочный Markdown отключён, `**bold**` и `` `code` `` разрешены | ✓ |
