# Расширения типов Node

Статус: утверждено.

## Цель

Определить безопасный контракт специального поведения, которое нельзя выразить стандартными возможностями, полями, ресурсами и представлениями Node.

## Расширения-кандидаты

- Поддержка: приватная цепочка обращения и ответов с доступом владельца и модераторов.
- Внешний материал: получение источника и периодическая синхронизация вне публичного запроса.
- Ссылки: необязательная фоновая проверка доступности внешнего адреса.

Базовые новости, документация, файлы, ссылки и медиа не требуют расширения: закрепление, опрос, связи, дерево, поля, источники, проигрыватель, наследование прав материалом и его ресурсами, переходы и жалобы входят в стандартный контракт Node. Оглавление, предыдущий и следующий документ вычисляются стандартной выборкой дерева. Расширение добавляется только при появлении специального поведения.

Общий контракт называется `NodeExtension` и находится в `core/classes/node/extension.php`. Конкретные реализации находятся в `modules/node/ext/`: закрытая карта — в `load.php`, приватная поддержка — `final class NodeSupport` в `support.php`, внешняя синхронизация — `final class NodeSync` в `sync.php`. Файлы реализаций создаются только вместе с рабочим поведением соответствующего этапа.

## Общий контракт

```php
interface NodeExtension
{
    public function filterNodeConfig(array $config, array $settings, array $fields): array;
    public function filterNodeData(NodeType $type, array $data, ?Node $node = null): array;
    public function getNodeScope(NodeType $type): array;
    public function checkNodeAction(NodeType $type, Node|NodeTarget $node, string $action): bool;
    public function updateNodeAction(NodeType $type, NodeTarget $node, string $action): void;
    public function addNodeData(Node $node, array $data): void;
    public function updateNodeData(Node $before, Node $after, ?array $data): void;
    public function deleteNodeData(Node $node): void;
    public function getNodeData(NodeType $type, array $nodes, string $mode): array;
}
```

Расширение загружается единственной функцией:

```php
function getNodeExtension(string $key, Database $db, NodeContext $context): ?NodeExtension;
```

- Пустой ключ возвращает `null`; неизвестный ключ отклоняется как `NodeException::INVALID`.
- `NodeInput` получает последний массив `ext`. Для стандартного типа он обязан быть пустым; в `_nodes` этот массив не сохраняется.
- `filterNodeConfig()` проверяет и канонизирует настройки расширения с учётом эффективных стандартных настроек и полей типа.
- `filterNodeData()` проверяет и канонизирует данные формы до транзакции.
- `getNodeScope()` возвращает ровно `join`, `where`, `params` для доверенного серверного ограничения основной SQL-выборки с псевдонимом `n`. Значения передаются только параметрами, а фильтр применяется до подсчёта и пагинации.
- `checkNodeAction()` принимает только `comment`, `rate`, `favorite`, `asset`, `report` после успешного разрешения цели. Расширение может вернуть запрет, но не может включить выключенную возможность или расширить основные права.
- `updateNodeAction()` принимает то же закрытое имя после успешного фактического действия и внутри его транзакции изменяет только данные расширения. Он не является обработчиком самого действия и не выполняет необратимую работу.
- `addNodeData()`, `updateNodeData()` и `deleteNodeData()` изменяют только принадлежащие расширению данные внутри транзакции `NodeService`. Для смены состояния `updateNodeData()` получает `data = null`.
- `getNodeData()` принимает массив уже доступных `Node` или `NodeTarget` и возвращает карту по ID одной пакетной выборкой. Текущий элемент передаётся шаблону отдельно как `ext`, без изменения точного контракта `NodeView`.
- `checkNodeAction()` является только дополнительной проверкой закрытого системного действия, а `updateNodeAction()` — ограниченной транзакционной реакцией после результата. Специальная административная команда и фоновая задача не маскируются общим строковым методом; их точные методы и маршруты утверждаются вместе с конкретным расширением.

Порядок записи однозначен: разрешение и нормализация расширения выполняются до транзакции; внутри неё читается исходный материал, изменяются стандартные данные, вызывается один соответствующий метод расширения и только затем выполняется `COMMIT`. Физическое удаление вызывает расширение до удаления `_nodes`. Ошибка откатывает обе части. Сетевые и другие необратимые операции внутри транзакционных методов запрещены.

## Версии и жизненный цикл

- Отдельной версии расширения, таблицы `_node_extensions` и колонки версии схемы нет.
- Таблицы зарегистрированного расширения входят в единственный `setup/sql/table.sql`, а их изменение — в штатное SQL-обновление версии SLAED.
- Форму настроек расширения версионирует общий `config/node.php → version`; текущий класс повторно проверяет её перед активацией типа.
- Ключ расширения можно установить, заменить или очистить только у отключённого типа без материалов. Для проверки используется существование текущих строк `_nodes`, поэтому отдельный сохраняемый признак блокировки не создаётся.
- При наличии материала `_node_types.ext` неизменяем. После физического удаления всех материалов принадлежащие расширению строки также удалены общей транзакцией, и у отключённого пустого типа ключ снова можно изменить.
- Отключение типа оставляет ключ, настройки, материалы и данные расширения без изменения; повторное включение проходит полную актуальную проверку.
- Физическое удаление типа возможно только без материалов и удаляет его конфигурацию обычным утверждённым путём. Отдельная установка, удаление и мигратор расширения не создаются.

## Поддержка

`NodeSupport` превращает назначенный ему тип в приватную Ticket System и заменяет старый модуль `help`. Штатный публичный тип называется `help`, ключ расширения и имя файла — `support`, класс — `NodeSupport`, а режим представления — `support`. Материал `_nodes` является обращением, глобальные комментарии — перепиской, категории — отделами с существующими правами, а `_node_support` хранит только назначение, очередь ответа, приоритет, конкурентную версию и последнюю активность.

Владелец видит только собственные обращения, модератор типа — разрешённую ему очередь с сохранением прав категории. Расширение не создаёт собственных пользователей, сообщений, категорий, файлов, уведомлений и ACL. Обычная справочная база реализуется стандартным типом `docs` и к `NodeSupport` отношения не имеет.

После первого видимого комментария `updateNodeAction(..., 'comment')` атомарно переводит ответ автора в ожидание поддержки, ответ администратора — в ожидание автора, обновляет `activity` и увеличивает `_node_support.version`. Остальные действия не изменяют строку поддержки.

Единственная специальная команда класса объединяет редактирование рабочей карточки:

```php
public function updateNodeSupport(
    int $id,
    int $aid,
    int $state,
    int $prio,
    int $version
): void;
```

Она проверяет права и ожидаемую версию, а затем одной операцией меняет назначение, состояние и приоритет. Отдельные методы для каждого поля не создаются.

Административную очередь предоставляет один специальный метод чтения:

```php
public function getNodeSupportList(
    NodeType $type,
    int $page,
    int $limit,
    ?int $state = null,
    ?int $aid = null,
    ?int $prio = null
): array;
```

Он возвращает `nodes`, `ext`, `count`, применяет права типа и категорий до подсчёта и не обслуживает публичный список владельца. Начальная очередь содержит `state = 0`, сортируется по `prio DESC`, затем `activity ASC` и `id ASC`; явные фильтры позволяют получить ожидающие автора, закрытые, неназначенные или закреплённые за конкретным администратором обращения. Произвольная SQL-сортировка из запроса не поддерживается.

Публичная операция `POST op=support` позволяет владельцу изменить только открытое/закрытое состояние собственного обращения с проверкой CSRF и версии. Административная `GET|POST op=support` показывает и изменяет полную рабочую карточку; обычный административный URL типа остаётся единственным списком очереди. Отдельный контроллер, файл маршрутов и публичные операции `close`/`reopen` не создаются.

Изменяемые настройки типа для расширения содержат ровно один ключ:

```php
'ext' => [
    'mail' => true,
],
```

`mail` является строгим логическим значением. Допустимые состояния и приоритеты не объявляются константами класса и не являются настройками конкретного типа: единые карты находятся в `config/node.php` как `support.state = [staff => 0, author => 1, closed => 2]` и `support.prio = [low => 0, normal => 1, high => 2, urgent => 3]`. `NodeSupport` читает их из уже загруженного `$conf['node']`, строго проверяет полный состав и не хранит второй список.

Включённая настройка `mail` использует существующие `Mail`, его очередь, `_admins.smail`, права `node-help` и email владельца: новое обращение уведомляет подписанных модераторов, ответ владельца — назначенного оператора либо доступных модераторов, ответ администратора — владельца. Собственный ответ и служебное изменение карточки письмо не создают; приватный текст ответа в письмо не копируется. Отдельная таблица, почтовый класс и набор мелких переключателей не создаются.

Профиль требует зарегистрированного автора, `features.categories`, `features.comments`, `features.submit`, прямое создание `Published`, режим комментариев `Open`, выключенные публичные интеграции и представление `support`. Рейтинги, избранное, опросы, главная, закрепление, расписание, связи, дерево и структурированные ресурсы выключены. Файлы исходного обращения добавляются существующим файловым окном редактора как `[attach]`; закрытое обращение запрещает новые ответы, но сохраняет владельцу и модератору чтение переписки и уже вставленных файлов.

## Внешняя синхронизация

`NodeSync` обслуживает тип с ключом расширения `sync` и заменяет обновление старого `content` во время публичного просмотра. Один материал имеет одну строку `_node_sync` и один RSS/Atom-источник; полученное содержимое сохраняется в стандартном `_nodes.body`.

Вход расширения содержит точный набор:

```php
[
    'url' => 'https://example.com/feed.xml',
    'refresh' => 3600,
]
```

- `url` обязателен и до сохранения проходит только локальную нормализацию внешнего `http` или `https` без учётных данных. DNS, адрес назначения, перенаправления и ответ проверяет общий `Feed` только во время явной или плановой синхронизации.
- `refresh` равен `0` либо находится в диапазоне `300..31536000`; ноль отключает автоматическую проверку, но сохраняет ручной запуск.
- Неизвестные ключи, несколько URL, собственный шаблон, имя PHP-обработчика и произвольные HTTP-заголовки отклоняются.
- `filterNodeConfig()` принимает для расширения только пустой массив: транспорт принадлежит глобальному `config/rss.php`, а расписание конкретного источника — строке `_node_sync`.
- `filterNodeData()` возвращает только канонические `url` и `refresh`. `addNodeData()`, `updateNodeData()` и `deleteNodeData()` создают, заменяют и удаляют служебную строку в общей транзакции материала без сетевого запроса.
- Изменение URL очищает `etag`, `modified`, `checked`, `synced`, `fails` и `error`, а `due` назначает текущую дату при ненулевом `refresh`. Изменение только периода сохраняет валидаторы и историю результата, пересчитывая `due` без запуска сети.
- `getNodeData()` пакетно возвращает разрешённому административному представлению `url`, `refresh`, `due`, `checked`, `synced`, `fails`, `error`; публичное представление не получает URL источника и техническую ошибку.

Специальные операции:

```php
public function updateNodeSync(int $id): array;
public function updateNodeSyncList(int $limit): array;
```

`updateNodeSync()` получает снимок материала и строки источника, выполняет `Feed::getFeedContent()` вне транзакции, затем повторно проверяет URL и `_nodes.version`. Ответ `304` или совпадающее тело обновляет только служебное состояние; новое безопасное тело проходит предел `node.body`, после чего один условный SQL меняет только `_nodes.body`, `_nodes.updated` и `_nodes.version` в одной транзакции со строкой синхронизации. После фиксации инвалидируется существующий HTML-кеш. Ошибка сохраняет прежнее тело и получает ограниченную повторную задержку.

`updateNodeSyncList()` выбирает только готовые строки активных типов и материалов не в корзине по индексу `due, id`. Предел `1..50` относится к сетевым источникам и не использует `limits.syncbatch = 500`, предназначенный для пакетных ID глобальных подсистем.

Существующий системный планировщик получает зарегистрированное задание `nodesync` с расписанием `*/5 * * * *`, `lock_timeout = 180`, ручным запуском и настройкой `limit = 10`. Его фиксированный адаптер `addNodeSyncTask()` находится среди существующих системных заданий и вызывает только `updateNodeSyncList()`; одиночная ручная проверка использует административный `POST op=sync`. Отдельные cron-файл, точка входа, публичный маршрут, таблица заданий, динамический реестр callback и синхронизация из публичного запроса не создаются.

Общий `Feed` находится в `core/classes/feed.php`, использует стандартный `config/rss.php` и одновременно заменяет `rss_read()` у остающихся потребителей RSS. NodeSync не копирует HTTP, XML, шаблон ленты и правила безопасности.

## Ограничения

- Расширение не обходит `NodeService` для обычного пользовательского и административного CRUD основной сущности. Единственное узкое исключение — утверждённый фоновый `NodeSync`, который после повторной проверки источника и версии условно меняет только `body`, `updated`, `version` и собственное служебное состояние одной транзакцией.
- Расширение не получает имя класса, таблицы или файла из запроса.
- Расширение не формирует HTML темы.
- Ошибка расширения не оставляет составную запись в промежуточном состоянии.
- Собственная таблица требует доказанного запроса, индекса и жизненного цикла.
- Расширение использует зарегистрированные виды `_node_relations`, но не создаёт параллельное хранилище обычных связей материалов.
- Одному типу назначается не более одного расширения через `_node_types.ext`; массив обработчиков и порядок нескольких расширений не создаются.
- `modules/node/ext/load.php` разрешает только заранее зарегистрированные ключи и фиксированные файлы; значение базы, конфигурации или запроса никогда не становится частью пути.

## Критерии готовности

- Один контракт обслуживает как минимум поддержку и синхронизацию без ветвления по имени типа.
- Порядок вызовов расширения однозначен и покрыт тестами.
- Отключение и повторное включение не уничтожают данные.
- Неуспешная операция откатывает основную и дополнительную запись.

## Открытые вопросы

Блокирующих вопросов по расширениям первой версии нет. Схемы и специальные методы `NodeSupport` и `NodeSync` утверждены.
