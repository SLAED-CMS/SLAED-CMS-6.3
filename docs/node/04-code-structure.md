# Структура кода Node

Статус: утверждено.

## Цель

Зафиксировать границы `core`, модуля, расширений и темы, а также имена и загрузку файлов до реализации классов.

## Утверждённые корни

```text
core/classes/node/
modules/node/
```

## Утверждённые файлы ядра

| Файл | Компонент |
|---|---|
| `core/classes/node/entity.php` | `Node` |
| `core/classes/node/type.php` | `NodeType` |
| `core/classes/node/typeinput.php` | `NodeTypeInput` |
| `core/classes/node/input.php` | `NodeInput` |
| `core/classes/node/relation.php` | `NodeRelation` |
| `core/classes/node/asset.php` | `NodeAsset` |
| `core/classes/node/target.php` | `NodeTarget` |
| `core/classes/node/context.php` | `NodeContext` |
| `core/classes/node/service.php` | `NodeService` |
| `core/classes/node/query.php` | `NodeQuery` |
| `core/classes/node/view.php` | `NodeView` |
| `core/classes/node/extension.php` | `interface NodeExtension` |
| `core/classes/node/status.php` | `enum NodeStatus` |
| `core/classes/node/exception.php` | `NodeException` |
| `core/classes/node/load.php` | закрытая карта загрузки классов Node |

Каталог задаёт контекст, поэтому `node` не повторяется в именах `type.php`, `service.php` и `query.php`.

Глобальный `final class Field` находится в `core/classes/field.php` и обслуживает всех потребителей дополнительных полей. Он не входит в каталог Node; каталог `core/classes/field/`, `FieldManager`, `FieldService`, `FieldRegistry` и пустые интерфейсы не создаются.

`Field` не объявляет собственного конструктора и не имеет состояния. Он предоставляет ровно шесть начальных публичных методов: `getFieldTypeList()`, `filterFieldList()`, `filterFieldValues()`, `checkFieldValues()`, `getFieldForm()` и `getFieldView()`. CRUD определений и запись конфигурации в класс не входят.

Глобальный `final class Point` находится в `core/classes/point.php` и является единственным владельцем правил начисления, журнала `_points` и изменения агрегата `_users.points`. Он получает `Database` и `$conf['points']` при создании и предоставляет один публичный метод `addEvent()`; отдельный класс и таблица баллов внутри Node не создаются.

Глобальный `final class Feed` находится в `core/classes/feed.php` и является единым владельцем безопасной загрузки и разбора RSS/Atom. Он заменяет существующую реализацию `rss_read()` для всех остающихся потребителей в той же партии и не создаёт параллельный RSS-клиент внутри Node.

Неверное определение останавливает `filterFieldList()` стандартным `InvalidArgumentException`; отдельные `FieldException`, `FieldError` и иерархия ошибок не создаются. Node преобразует исключение на своей границе в существующий `NodeException::INVALID`.

- `NodeInput` является `final readonly` DTO с одним конструктором и полными наборами содержательных значений создания или изменения материала; последний массив `ext` передаёт данные зарегистрированному расширению и не является колонкой `_nodes`. Состояние передаётся созданию отдельно, а имена колонок и произвольные ключи из запроса в объект не попадают.
- `NodeTypeInput` является `final readonly` DTO с одним конструктором и публичными типизированными свойствами `title`, `intro`, `ext`, `sort`, `settings` и `fields`; неизменяемое `name` и ожидаемая `version` передаются сервису отдельно, а `id`, `active`, `created` и `updated` назначаются системой.
- `NodeType` является `final readonly` снимком метаданных базы, эффективных настроек и проверенных полей типа; его свойства читаются напрямую без геттеров и не изменяются после сборки в `NodeQuery`.
- `Node` является `final readonly` результатом чтения основной записи и запрошенных связанных наборов; в конце объекта находятся nullable-проекции `uname` и `ctitle`, получаемые соединениями того же основного запроса. Он не выполняет ленивых SQL-запросов, а `null` явно обозначает не загруженное тяжёлое или вычисляемое значение либо скрытый IP.
- `NodeRelation` и `NodeAsset` являются `final readonly` представлениями всех колонок одноимённых таблиц и используются внутри `Node::$rels` и `Node::$assets`; они не содержат вложенный `Node` и не выполняют запросов. Отдельный объект дополнительной категории не создаётся, потому что `cids` является списком целых ID.
- `NodeTarget` является `final readonly` лёгкой целью глобальных подсистем с общим `NodeType`, идентичностью, заголовком, режимом и счётчиками. Он не дублирует содержимое полного `Node`, не строит URL и не выполняет запросов.
- `NodeContext` является `final readonly` снимком пользователя, его эффективных групп, отдельной личности администратора, разрешённых типов модерации, права управления Node, IP и языка. Модуль собирает его на границе запроса; классы ядра не читают пользовательские или административные глобальные переменные.
- `NodeStatus` является целочисленным PHP `enum` и централизует допустимые состояния и переходы.
- Режим `_nodes.comon` использует существующий глобальный `CommentMode`; отдельный enum Node и логическое упрощение трёх режимов не создаются.
- `NodeException` является единственной ошибкой публичного API ядра; отдельная иерархия исключений и `NodeError` не создаются.
- `NodeQuery` получает общий `Field` вместе с `Database` и `NodeContext`, затем при необходимости одно зарегистрированное расширение через `setNodeExtension()`. `NodeService` дополнительно получает общий `Point` и необязательный `NodeExtension` последним аргументом конструктора; сами классы Node могут читать только `$conf['node']` и `$conf['fields']['node']` и не создают отдельный объект конфигурации.
- `NodeQuery::getNodeContent()` предоставляет лёгкую проекцию материала с `intro` и `body` без запросов полей, категорий, связей и ресурсов; проверки доступа не дублируются и используют тот же внутренний предикат, что полный `getNode()`.
- `NodeView` получает `Parser` и общий `Field`, не выполняет SQL и не создаёт HTML. Единственный публичный `getNodeView()` преобразует доступный `Node` или `NodeTarget` в безопасный массив данных одного закрытого режима представления.
- В первой версии каталог остаётся плоским. `NodeTypeInput` не получает интерфейс, фабрику, наследование, геттеры или сеттеры; `Registry`, `Provider`, `Repository`, `Manager`, `Factory` и пустые внутренние подкаталоги не создаются.

## Загрузка классов

- Composer и `vendor/autoload.php` не являются зависимостью рабочей системы.
- Composer может использоваться только на стенде разработки для тестов и инструментов качества.
- `core/system.php` подключает `core/classes/field.php` и создаёт один глобальный экземпляр `$fld = new Field()` без конфигурации и других зависимостей.
- `config/points.php` загружается штатной сборкой в `$conf['points']` и автоматически попадает в `config/local.php`; отдельный runtime-кеш баллов отсутствует.
- `core/system.php` подключает `core/classes/point.php` и создаёт один экземпляр `Point` с общей `Database` и уже загруженной `$conf['points']`; владельцы событий получают этот экземпляр явно.
- `core/system.php` один раз подключает `core/classes/node/load.php`.
- `load.php` регистрирует через `spl_autoload_register()` закрытую явную карту «класс — файл», а не формирует путь из входных параметров.
- `NodeView` создаётся по требованию владельцем представления из уже загруженных `Parser` и `Field`; отдельный глобальный экземпляр и обязательная загрузка на каждом запросе не создаются.
- `Feed` подключается только потребителем RSS/Atom и получает уже загруженную область `$conf['rss']`; глобальный экземпляр и загрузка на каждом запросе не создаются.
- Подключаются только классы, реально потребовавшиеся в текущем запросе.
- Отдельный класс `NodeLoader`, именованная глобальная функция и общий рефакторинг загрузки остальных классов SLAED не создаются.

## Граница Core

В `core/classes/node/` находятся только независимые модели, контракты и сервисы управления материалами. Ядро не знает названий конкретных типов, административной разметки и активной темы.

Глобальный `$conf` является уже загруженным снимком конфигурации SLAED и допускается как read-only зависимость Node. Классы не заменяют его элементы во время обычного чтения или записи материала. Административное сохранение передаёт полностью проверенные массивы пакетному режиму существующей `setConfigFile()`; этот режим сохраняет нативные `string`, `int`, `bool`, `null` и вложенные массивы без строкового преобразования. Отдельная функция Node не создаётся, а `config/local.php` напрямую не записывается. Это исключение не распространяется на пользовательские глобальные данные.

`node` не содержит собственного текстового редактора, загрузчика и файлового окна. `intro` и `body` строятся существующим `getTplTextarea()`, который получает публичное имя типа как `mod` и хранилище `node.intro` или `node.body`. Редактор использует штатное место `<type>.attach`, `$conf['uploads'][<type>]`, `Upload`, `FileManager` и каталог `uploads/<type>`.

Структурированный ресурс выбирается существующим `getFileManagerField()` с тем же местом `<type>.attach`; один экземпляр поля выбирает один файл, сохранённый путь или разрешённый внешний URL, а несколько ресурсов добавляются повторением поля. Форма передаёт обычный multipart-файл существующему `getUploadService()` либо проверяет выбранный путь через `getUploadTakenFile()`. Ядро Node управляет только проверенной записью `_node_assets`; место `node.asset`, специальный загрузчик, отдельный файловый JavaScript и каталоги `temp` или `public` не создаются.

Контролируемая отдача использует расширенную существующую функцию `getFileStream()` и существующий класс `Cache`. Отдельные `NodeFile`, `NodeStream`, файловый кеш и копия ресурса в `storage/cache` не создаются; авторизация и SQL остаются в модуле и сервисе Node.

## Граница модуля

`modules/node/` связывает маршрутизацию SLAED с ядром, предоставляет публичные и административные сценарии, подключает зарегистрированные расширения и языковые ресурсы.

Утверждённое минимальное дерево:

```text
modules/node/
├── index.php
├── .htaccess
├── lang/
├── ext/
│   ├── load.php
│   ├── support.php
│   └── sync.php
└── admin/
    ├── index.php
    ├── .htaccess
    ├── lang/
    └── info/
        └── ru.md
```

- Корневой `index.php` является единой публичной точкой входа зарегистрированных типов и технических операций Node.
- `admin/index.php` является единой административной точкой входа материалов, типов и настроек.
- `lang/` и `admin/lang/` разделяют публичные и административные языковые константы штатным способом SLAED. Специфичные имена используют `_NODE_*`, а существующие глобальные константы общих действий не копируются.
- Стандартные защитные файлы каталогов могут добавляться по общему соглашению проекта, но не образуют архитектурных компонентов.
- Каталоги `controllers`, `repositories`, `managers`, `factories`, `src` и `modules/node/sql` не создаются.
- Единственный DDL находится в `setup/sql/table.sql`, а обновление — в штатном SQL-файле версии SLAED.
- `ext/load.php` является закрытой картой ключа расширения к заранее известным классу и файлу; значение `_node_types.ext` не преобразуется в путь.
- `support.php` содержит `final class NodeSupport`, а `sync.php` — `final class NodeSync`; файлы появляются вместе с реализацией соответствующего этапа, а не как пустые заготовки.
- `getNodeExtension()` из `ext/load.php` создаёт зарегистрированный экземпляр с `Database` и `NodeContext`, возвращает `null` для пустого ключа и отклоняет неизвестный ключ. Только для ключа `sync` тот же закрытый загрузчик лениво создаёт общий `Feed` из `$conf['rss']` и передаёт его `NodeSync`; отдельный `NodeExtensionManager` или `NodeExtensionRegistry` не создаётся.
- `NodeSync` использует общий `Feed` и существующий системный планировщик. Собственные HTTP-клиент, cron-контроллер, очередь заданий и запуск синхронизации из публичного просмотра не создаются.
- Единственный адаптер `addNodeSyncTask()` находится рядом с существующими системными заданиями в `core/system.php`, фиксированно подключает закрытый загрузчик расширений и вызывает `NodeSync::updateNodeSyncList()` с настройкой задания. Универсальный реестр PHP-callback, имя файла или функции в конфигурации не создаются.

## Граница расширений

Расширение реализует специальное поведение типа, но не заменяет права, транзакции, базовую запись и выборки ядра.

## Граница темы

Все HTML, CSS-классы и визуальные варианты находятся в `templates/<theme>/`. PHP передаёт факты, данные, URL и семантические флаги.

## Граница дальнейшего проектирования

Для первой версии границы данных `_node_support` и `_node_sync` утверждены. Новая таблица расширения проектируется только одновременно с доказанным специальным поведением.

## Критерии готовности

- Для каждого файла известно назначение и владелец загрузки.
- Зависимости направлены от модуля к публичному API ядра, а не наоборот.
- В ядре отсутствуют HTML, языковые строки и имена конкретных типов.
- В контроллерах отсутствуют SQL и бизнес-правила.
- Другие модули не подключают файлы `modules/node/` для доступа к данным.

## Открытые вопросы

Блокирующих вопросов по расположению, именованию и общему контракту расширений нет.
