# Отображение Node

Статус: действующий контракт реализованного Node; этапы S00–S20.8 и их проверки записаны в [PROGRESS.md](PROGRESS.md).

## Цель

Обеспечить полностью разное отображение типов при едином ядре и сохранить границу шаблонной системы SLAED.

## Режимы представления

Базовый набор состоит из списка, полного материала, карточки и блока. Результат поиска Node выводится общей строкой модуля search наравне с прочими модулями, собственного режима и фрагмента у него нет (решение пользователя 2026-09-26, S20.5). Печать использует тот же `view.html` и печатные стили темы; отдельный `print.html` не создаётся.

Ресурсы имеют отдельный закрытый набор режимов `image`, `gallery`, `download`, `player`, `none` и `link`. Это ключи подготовщиков данных, а не имена PHP-файлов или шаблонные пути. Тип связывает свою устойчивую роль ресурса с одним режимом через `config/node.php`; тема получает уже подготовленные данные и самостоятельно определяет HTML.

Модель представления получает готовый контролируемый URL Node для локального файла. Внешний HTTP/HTTPS-источник плеера остаётся внешним адресом после проверки доступа. Шаблон не знает физический путь и не определяет права.

Стандартные назначения связываются с режимами так: `cover` использует `image`, `gallery` — `gallery`, `download` — `download`, `source` — `player`, а `poster` подготавливается для плеера и самостоятельно не выводится. Пользовательское имя назначения не создаёт новый режим отображения.

Режим ресурса `link` по NOD-202 передаёт проверенный URL маршрута `asset`, название, число переходов и доступность жалобы. Тема отображает переход на сайт; адрес не маскируется под скачивание, прямой внешний URL не обходит учёт перехода. Режим материала `media` выводит характеристики Field, плеер, галерею и скачивания; строки `ed2k` не превращаются в активные ссылки.

## Принципы

- Ядро возвращает данные, а не HTML.
- Единый `NodeView::getNodeView()` подготавливает массив одного режима из уже загруженного `Node` или `NodeTarget`, но не вызывает шаблон и не выполняет SQL.
- Сервис представления подготавливает модель с текстами, URL, значениями и семантическими флагами.
- Тема владеет HTML, CSS-классами и визуальной структурой.
- Тип выбирает шаблон, но не передаёт произвольный путь из запроса.
- Существует документированная последовательность fallback.
- Предпросмотр использует тот же путь подготовки и шаблон, что будущая публикация.

## Формы и редактор

Node не создаёт текстовый редактор, файловый редактор, драйвер или отдельное окно загрузки. Поля `intro` и `body` в публичной и административной формах строятся существующим `getTplTextarea()`:

```php
getTplTextarea([
    'id' => '1',
    'name' => 'intro',
    'value' => $intro,
    'mod' => $type->name,
    'store' => 'nodes.intro',
]);
```

Для `body` меняются только `id`, `name`, `value` и `store = nodes.body`. Выбор активного редактора остаётся в существующем `$conf['editor']`; Node не хранит и не переопределяет его в `config/node.php`. В `getEditorRoomData()` добавляются только стандартные хранилища `nodes.intro` как `TEXT` и `nodes.body` как `MEDIUMTEXT`, после чего размер и возможность встроенного изображения проверяются общими `checkEditorTextRoom()` и Parser.

`mod = $type->name` автоматически передаёт драйверу штатное место `<type>.attach`, правило `$conf['uploads'][<type>]` и каталог `uploads/<type>`. Встроенное файловое окно создаёт существующий `getFileManagerWindow()`; собственные шаблоны, JavaScript, маршруты загрузки и обработчик файлов Node не создаются. Повторяемые строки ресурсов в форме материала обслуживает общий компонент plugins/system/slaed.js по data-хуку, не знающий о Node и доступный любой форме; без JavaScript форма показывает фиксированное число пустых строк и остаётся рабочей.

## Размещение шаблонов

Каждая публичная тема хранит составные представления Node внутри собственных каталогов:

```text
templates/<theme>/
├── partials/node/
│   ├── list.html
│   └── view.html
└── fragments/node/
    ├── card.html
    ├── block.html
    ├── image.html
    ├── gallery.html
    ├── download.html
    ├── player.html
    ├── link.html
    └── tree.html
```

- `partials/node/` содержит крупные самостоятельные представления Node, а `fragments/node/` — повторяемые элементы внутри них.
- `list.html` и `view.html` вызываются через `$tpl->getHtmlPart()`, а восемь повторяемых элементов — через `$tpl->getHtmlFrag()`. `tree.html` выводит ветку дерева документов типа с `features.tree` — путь к родителю, уровень с детьми текущего, предыдущий и следующий документ — и попадает в `view.html` готовым `tree_html` (05 — «Заметки реализации S20.4»).
- Режим ресурса `none` не создаёт HTML автоматически и не имеет своего файла.
- Имена файлов внутри этих каталогов не получают префикс `node-`: контекст уже задан директорией.
- Общие `link`, `button`, `alert`, `pager`, поля формы и другие стандартные элементы SLAED остаются в корне `partials/` или `fragments/` и включаются из шаблонов Node без копирования.
- Отдельные `form.html` и `field.html` не создаются: Node собирает формы из общих шаблонов полей SLAED.
- Шаблоны Node не размещаются в `modules/node/`, `core/` или общем каталоге вне темы. Переключение темы не зависит от другой темы и не меняет PHP-код.
- `pages/` остаётся уровнем полного документа и layout; представление материала Node является содержимым страницы и не создаёт собственную страницу без отдельного HTTP-сценария.
- Административная часть сначала использует общие шаблоны `templates/admin`. Каталог `templates/admin/{partials,fragments}/node/` создаётся только для подтверждённой уникальной структуры, которую нельзя собрать существующими шаблонами.

## Выбор представления типом

Тип задаёт единый режим в `view.mode`. Ключ `default` использует базовые файлы Node без поиска подкаталога. Остальные ключи, например `article`, `faq`, `docs`, `files`, `media` и `support`, выбирают одноимённый подкаталог. Значение является безопасным именем, а не путём или именем файла.

Штатный тип `help` использует `view.mode = support`: пользовательский список показывает только его обращения и состояние ответа, полный вид объединяет материал с глобальной веткой комментариев, а административное представление добавляет рабочую карточку назначения и приоритета. Файлы исходного обращения уже находятся в обработанном тексте как редакторские `[attach]`; отдельный блок ресурсов поддержки не формируется. Приватность и допустимые действия определяются до шаблона; тема не решает, кому доступен тикет.

`partials/node/support/view.html` выводит те же живые части, что `view.html`: избранное, опрос, ресурсы, рейтинг, ветку дерева и связанные карточки. У `help` их нет — расширение support запрещает типу эти функции, — но режим `support` может выбрать и тип без расширения, и тогда включённые функции видны (решение пользователя 2026-09-26, S20.5).

Состав штатных режимов темы lite (решение пользователя 2026-09-26, S20.6):

- `article` — базовый комплект и есть статья: своего подкаталога нет, `getNodeTplName()` отдаёт базовые файлы.
- `docs` — оглавление: `docs/card.html` — строка с заголовком, одной строкой анонса и чипом категории, без обложки, автора и кнопки; `docs/view.html` — без чипов автора и просмотров.
- `faq` — аккордеон: `faq/card.html` — нативный `<details>`, вопрос в `<summary>`, анонс-ответ раскрывается на месте со ссылкой на полный материал, без скриптов; `faq/view.html` — вопрос и ответ без чипов автора и просмотров.
- `files` — карточка файла: `files/card.html` показывает размер и число скачиваний первого ресурса роли с `mode = download` (ключ `download`) и прямую кнопку скачивания рядом с «Подробнее»; `files/view.html` выводит ресурсы над текстом.
- `media` — плитки: `media/list.html` собирает карточки в сетку (одна колонка на узком экране, две и три шире), `media/card.html` — постер со значком воспроизведения, название и чип года из поля `year` или даты; `media/view.html` выводит плеер и галерею, затем дополнительные поля над текстом, связанные — той же сеткой. Обложка карточки любого типа берёт сначала первое изображение стандартной роли `poster`, затем роли с `image` и `gallery`.

Классы режимов — `sl-node-toc`, `sl-node-toc-intro`, `sl-node-faq`, `sl-node-faq-body`, `sl-node-file`, `sl-node-tiles`, `sl-node-tile`, `sl-node-tile-cover` в theme.css lite; ключ `download` получает карточка списка любого режима (связанная карточка — лёгкая цель без ресурсов — его не имеет), подписи `download_label` и `hits_label` — все шаблоны материала. Та же обложка с приоритетом `poster` уходит в `og:image` полного материала. Тема admin режимов не имеет.

Для `view.mode = faq` каждое представление разрешается независимо:

```text
partials/node/faq/list.html    -> partials/node/list.html
partials/node/faq/view.html    -> partials/node/view.html
fragments/node/faq/card.html   -> fragments/node/card.html
fragments/node/faq/block.html  -> fragments/node/block.html
```

Та же схема применяется к `image`, `gallery`, `download`, `player` и `link`. Режим может переопределить только отличающиеся файлы, а остальные получит из базового комплекта. Произвольного пути из запроса, fallback между темам и fallback к старым шаблонам нет. Отсутствие базового файла является ошибкой темы. Template сам fallback не выполняет: у него есть только getHtmlPage(), getHtmlPart() и getHtmlFrag(), а отсутствующий файл — ошибка. S13 добавляет `Template::checkTemplateFile(string $kind, string $name): bool` — проверку наличия файла текущей темы без вывода; выбор делает `getNodeTplName()` в core/system.php — общая для контроллера модуля и файлового блока blocks/node.php: она спрашивает файл режима, при отказе берёт базовый и запоминает ответ на запрос. NodeView шаблон не вызывает и имён файлов не знает.

## Граница переопределения

Конкретный материал не выбирает шаблон. Node не ищет файлы по ID, заголовку, дополнительному полю или другому значению материала; файлы вида `view-1050.html` и каталоги отдельных материалов не поддерживаются.

Повторяемаяся структура оформляется как `view.mode` типа. Различия содержания одного материала передаются шаблону как данные и семантические флаги в рамках общего контракта, но не меняют шаблонный путь.

## Дополнительные поля

Модель представления получает результат `Field::getFieldView()` в ключе `fields`. Это упорядоченный ассоциативный массив по устойчивым именам полей; одна и та же структура поддерживает общий перебор и прямое обращение специального режима, например `fields.source`.

Каждая запись содержит только `name`, `type`, `label_text`, `hint_text`, `value`, `value_text`, `value_html`, `value_href` и `items`. Общий вывод перебирает записи через существующий `fragments/field-value.html`; режим типа может использовать те же данные в собственной структуре без нового PHP-подготовщика.

- Обычные значения выводятся через экранируемый `value_text`.
- `value_html` разрешён только для обработанного `Parser` содержимого `textarea`.
- Проверенные `url` и `email` получают `value_href`, но разметкой ссылки владеет тема.
- `items` позволяет теме раздельно вывести выбранные варианты `select`; каждый элемент содержит `value` и `label_text`.
- Каноническое `value` предназначено для условий и структурированного отображения, но не является raw HTML.
- Неактивные, пустые и потерявшие определение значения не создают строку вывода; логические `false` и числовые нули остаются полноценными значениями.

## Контракт данных NodeView

`NodeView::getNodeView()` возвращает одинаковый набор коротких ключей `id`, `type`, `mode`, `href`, `title`, `intro`, `intro_html`, `body_html`, `author`, `ahref`, `ctitle`, `chref`, `date`, `date_iso`, `mtime_iso`, `views`, `comnum`, `rating`, `ratings`, `fields`, `assets`.

- Обычные строки выводятся экранируемым синтаксисом шаблона; без экранирования разрешены только значения с суффиксом `_html`, созданные `Parser`, `Field` или шаблонным помощником.
- `intro_html` и `body_html` рендерятся безопасно с доверием к тегам: сырым HTML или исполняемым кодом становится только содержимое `[usehtml]`/`[usephp]`, которые при записи сохраняет один главный администратор; `intro` не содержит текста `<script>` и `<style>`.
- URL не экранируются в PHP и передаются через `href`, `ahref`, `chref` и ресурсный `href` или `rhref`.
- Пустое значение остаётся типизированным: строка `''`, массив `[]`, nullable-число или `null`; произвольные дополнительные ключи режим не добавляет.
- Ресурсы сгруппированы в `assets` по роли и не раскрывают физический путь, исходный `src`, состояние жалобы или её автора.
- Связанные материалы передаются внешнему шаблону отдельным массивом подготовленных `NodeTarget`, а не вкладываются обратно в один элемент.

## SEO-данные

Контроллер передаёт существующему `setHead()` только подготовленные факты страницы. Список использует `kind = collection`; материал — утверждённый типом `article`, `news` или `website`. Источниками служат `title`, обычный `intro`, `author`, `date_iso`, `mtime_iso`, URL первой подходящей обложки и основная категория. `NodeView` не строит meta-теги, canonical и JSON-LD и не принимает готовую разметку из административных настроек.

Массив представления отдельно не кешируется. Итоговый HTML может попасть только в штатный страничный кеш SLAED по правилам маршрута; шаблоны продолжают использовать собственный существующий кеш компиляции.

Зарегистрированное расширение пакетно возвращает отдельную карту через `NodeExtension::getNodeData()`. При вызове конкретного шаблона значение текущего материала передаётся как `ext`; оно не добавляет произвольные ключи в точный контракт `NodeView`, не содержит готовый HTML и не получает собственного кеша.

## Критерии готовности

- Новости, FAQ и документация имеют различную HTML-структуру без условий в ядре.
- Шаблон не выполняет SQL и проверки прав.
- Тема может переопределить отображение без изменения PHP.
- Все raw HTML-границы явно перечислены и безопасны.
