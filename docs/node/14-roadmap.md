# Этапы реализации Node

Статус: первичный вариант.

## Цель

Разбить реализацию на завершённые партии, каждая из которых имеет собственный результат, проверку и безопасную точку остановки.

## Этап 0 — утверждение контрактов

Утвердить цели, имена, схему данных, структуру кода, публичный API и маршруты. Код не создаётся.

Готово, когда документы `01`–`07` не содержат блокирующих открытых вопросов для базового CRUD.

## Этап 1 — схема и базовые модели

Создать DDL первой версии, модели материала и типа, связи с несколькими категориями, срок публикации, очередь жалоб ресурсов, установку и проверку схемы. Никаких публичных маршрутов.

Проверка: установка на чистую базу, повторный запуск обновления, PHPUnit, PHPStan, lint и schema-проверка проекта.

## Этап 2 — чтение и NodeQuery

Реализовать получение одного материала и предсказуемые списки без дополнительных полей и расширений.

Проверка: фильтры, пагинация, права чтения, бюджет SQL и отсутствие N+1.

## Этап 3 — типы, глобальные поля и настройки

Реализовать административно создаваемые типы, профили и клонирование, использование существующих прав категорий, полную проверку перед активацией, единый конфигурационный формат дополнительных полей, настройки и кеш определений. Node автоматически применяет контролируемую отдачу для типа с категориями или расширением; изменение этих признаков атомарно меняет серверную защиту дерева загрузок и не оставляет окно прямого доступа. Одновременно перевести текущих потребителей полей на именованный JSON и удалить позиционный формат.

Проверка: создать тип через HTTP, перезагрузить запрос, сохранить материал, подтвердить именованные значения в базе, отсутствие старого формата и очистку кеша.

## Этап 4 — запись и жизненный цикл

Реализовать создание, предпросмотр, изменение, модерацию, публикацию, окончание видимости, отключение, восстановление и удаление с проверкой `version` и транзакциями.

Проверка: каждый переход через HTTP, права, CSRF, сохранённое состояние, принудительный откат и журналы.

## Этап 5 — маршруты и отображение

Подключить публичные и административные точки входа, режимы представления, шаблонный контракт и контролируемую отдачу структурированных ресурсов и редакторских файлов для материалов с ограниченным доступом.

Проверка: список, просмотр, категория, предпросмотр, canonical, шаблонные и UI-гейты.

## Этап 6 — глобальные интеграции

Подключать категории, комментарии, рейтинг, избранное, баллы, поиск, RSS, sitemap и блоки отдельными проверяемыми партиями.

Проверка определяется в `09-integrations.md` отдельно для каждой подсистемы.

## Этап 7 — простые типы

Создать утверждённые типы первой поставки: `news`, `docs` и `files`. `news` проверяет стандартные возможности контента, `docs` — иерархию `parent`, `files` — несколько ресурсов, контролируемое скачивание и `hits`. Ни один из трёх типов не получает собственного PHP-расширения.

## Этап 8 — расширения

Сначала приватная поддержка, затем синхронизация внешнего содержимого. Ссылки и медиа сначала доказываются стандартными возможностями; расширение получают только при подтверждённом специальном поведении.

Проверка: специальное поведение, собственные таблицы, транзакции, отключение и повторное включение.

## Этап 9 — перенос данных

Импортировать полезные данные старых модулей по одному в порядке, утверждённом в `12-migration.md`. Один тип — одна отдельная партия с новыми ID и новым маршрутом.

## Этап 10 — удаление наследия

После приёмки отключать старый модуль без возврата к нему. Старый код, конфигурацию и таблицы удалять отдельной утверждённой операцией с резервной копией.

## Правила каждого этапа

- Точный перечень файлов и схемы.
- Один измеримый результат.
- Явные зависимости.
- Проверка статического анализа и поведения.
- Реальный HTTP для изменяющих пользовательских сценариев.
- Проверка постоянного результата в базе.
- Проверка `storage/logs/error_php.log`, `error_sql.log` и `error_site.log` после административных записей.
- Отдельный отчёт по завершении.

## Открытые вопросы

- Размер партий внутри интеграций.
- Порядок переноса данных после первых трёх доказательных типов.
