# Интеграции Node с SLAED

Статус: каркас.

## Цель

Подключить `node` к существующим глобальным подсистемам без их дублирования и без жёстких списков конкретных типов.

## Подсистемы

Для каждой интеграции необходимо зафиксировать целевой контракт, необходимые изменения, ошибки и проверку.

Настройки поиска, RSS, sitemap, блоков и SEO принадлежат `config/node.php → types → <name> → integrations`; общий код не содержит список имён типов.

### Категории

Динамическая регистрация типа вместо фиксированных списков модулей, сохранение дерева, языков и прав. `_nodes.cid` хранит одну основную категорию и определяет язык и основной маршрут; `_node_categories` хранит только дополнительные связи. Список категории объединяет оба индексируемых источника и возвращает материал один раз. Строковые списки по образцу старого `news.assoc` не используются.

### Комментарии

Динамический resolver цели вместо фиксированной карты таблиц, сохранение веток, модерации и счётчиков.

### Рейтинг и избранное

Глобальный ID материала и его тип.

### Поиск

Единая выборка опубликованных типов, индексируемые поля и формат результата.

### RSS и sitemap

Получение материалов через публичный read API и устойчивые маршруты.

### Блоки и главная

Использование `NodeQuery` без собственного SQL к таблицам `node`.

### Пользователи и уведомления

Авторство, права, административные уведомления и пользовательские публикации.

### Баллы

Раздел `integrations.points` сопоставляет зарегистрированные события Node с существующей системой баллов, например создание, публикацию, скачивание и внешний переход. Отключённое событие не начисляет баллы; тип не задаёт имя функции или произвольный обработчик.

### Файловый менеджер

Единое окно и место `node.asset` режима поля из `docs/UPLOAD-FIELD-2026.md` являются единственным интерфейсом выбора структурированного ресурса. `node` принимает результат выбора, повторно проверяет файл, путь или внешний адрес на сервере и сохраняет одну строку `_node_assets`; для нескольких ресурсов операция повторяется без второго загрузчика.

Каждый тип получает собственную область `uploads/node/<type>`. Файлы `[attach]` редактора находятся в её корне, а их уменьшенные копии — в `thumb`; структурированные ресурсы `_node_assets` проходят через `temp` и после сохранения находятся в `public`. Контекст редактора обязан передать публичное имя текущего типа, чтобы общий файловый менеджер выбрал правильную область.

`Upload` назначает безопасное имя один раз. Node не переименовывает файл повторно, не копирует его в `storage/node` и не создаёт собственного закрытого хранилища. Единые правила веб-сервера запрещают доступ ко всем каталогам `temp` и выполнение PHP во всём дереве `uploads`.

Ресурс наследует состояние материала, право чтения его основной категории и дополнительные ограничения расширения; собственные `access` и `groups` у роли отсутствуют. Возможность `report` помечает конкретную строку `_node_assets`, а не меняет состояние материала. Способ отдачи не настраивается: тип с категориями или расширением автоматически закрывает сервером весь `uploads/node/<type>` и отдаёт файлы через Node без отдельного каталога и копирования.

### Отдача ресурсов

Общий технический адрес `index.php?name=node&op=asset&id=<id>` проверяет ресурс, материал, основную категорию и ограничения расширения. При прямой отдаче режим `download` атомарно увеличивает `_node_assets.hits` и перенаправляет на разрешённый локальный или внешний URL; при контролируемой отдаче этот же адрес обслуживает локальный ресурс.

- Локальные `image`, `gallery`, `poster` и `player` в прямом режиме используют URL из `uploads/node/<type>/public` и не проходят через PHP.
- В прямом режиме веб-сервер самостоятельно обслуживает MIME, длину, кеширование и диапазоны для плеера и продолжения скачивания.
- В контролируемом режиме прямой доступ запрещён ко всему дереву типа, включая корень редакторских файлов и `thumb`; структурированные ресурсы обслуживает Node, а адрес редакторского `[attach]` проектируется отдельным контрактом.
- Внешний URL передаётся клиенту только после проверки допустимой схемы; сервер его не скачивает, не измеряет и не проксирует.
- `none` не создаёт автоматическую ссылку.
- `hits` означает одно разрешённое начало скачивания через Node, а не количество частей файла или всех HTTP-запросов. `HEAD`, повторный `Range` и прямое отображение изображения счётчик не увеличивают.
- `HEAD`, отказ и отсутствующий файл не увеличивают `hits`.
- Изменение `hits` не меняет `_nodes.version`, `_nodes.updated` и `_node_assets.updated`.
- Простому типу без категорий и расширения общий файловый ответ для визуальных ресурсов не требуется. Типу с категориями или расширением нужен контролируемый ответ с `HEAD`, MIME и `Range`; его API утверждается отдельно.

## Критерии готовности

- Ни одна интеграция не содержит список имён мигрированных типов в общем коде.
- Другие модули не обращаются напрямую к таблицам `node`.
- Удаление и изменение статуса синхронно обновляют связанные глобальные данные.
- Составные операции участвуют в одной транзакции или имеют явно описанную компенсацию.

## Открытые вопросы

- Очерёдность адаптации глобальных систем.
- Минимальный новый контракт регистрации типа в каждой глобальной подсистеме.
- Где проходит граница начисления пользовательских баллов.
