## Результат аудита

[Рабочий ToDo](TODO.md): первоначальные 43 задачи закрыты, результаты повторного аудита — в партии G. [Проверка приложенного пакета](review.md) сохраняет подтверждения, частичные подтверждения и уточнения по всем 11 замечаниям, а также анализ действующего рейтинга. Её первоначальные предложения не заменяют принятые контракты. Пользовательские решения и технические уточнения NOD-175–NOD-223 находятся в [журнале](15-decisions.md).

Рейтинг сохраняет звёзды 1..5 и пальцы 5/1. Аккаунт определяется uid, гость — IP при разрешении гостей; это независимые участники. Повтор добавляет оценку после текущего интервала, 0 снимает ожидание. Аннулирование доступно главному администратору без обнуления срока. Старые агрегаты и достоверные сроки сохраняются; вымышленная история не создаётся. Голосование не начисляет и не списывает баллы.

Первые окна: S01 — класс Point, S02 — класс Rating. Их подключение к работающей системе выделено в S04/S05; общая инфраструктура не стоит перед классами. Field готов до NodeQuery, Feed — до NodeSync. Расширения находятся в core/classes/node/ext/. Для типов определены общий пакет конфигурации с восстановлением, блокировки, защищённая выдача всех локальных файлов и приватный preview. Feed хранит Markdown независимо от темы. Все десять профилей имеют стартовые настройки без отдельных расширений links/media.

Публикация, ранее оставшаяся без начисления, может получить баллы при следующей фактической публикации. За отложенный материал награда выдаётся после наступления срока через устойчивую очередь владельца, с защитой от повторов. Старые балансы сохраняются.

## Граница готовности

Документы 01–14, points.md и ratings.md содержат действующие контракты; решения G1/G2 отмечены в TODO.md, 15 — история решений. Закрытие дизайна подтверждает согласованность плана; установленная схема, программная реализация, HTTP, безопасность и производительность ещё должны пройти приёмку из [13-testing.md](13-testing.md). Исполняемый DDL создаётся только при реализации в setup/sql/table.sql. Данные старых модулей на стенде не импортируются и не удаляются этой работой.

## Правила ведения плана

- Документ-владелец определяет действующий контракт; остальные ссылаются на него.
- Историческое решение сохраняется с указанием последующего уточнения, а не удаляется.
- Новая продуктовая развилка открывает соответствующую задачу ToDo до изменения утверждённого поведения.
- При реализации каждый этап подтверждает свой результат, постоянные данные и требуемые проверки; промежуточный успех не объявляется готовностью всей первой версии.
