# Node — план реализации

Статус: проектирование, реализация не начата.

Этот каталог содержит согласованный план новой контентной подсистемы SLAED. `node` должен одновременно обслуживать разные типы материалов и постепенно заменить однотипные модули без создания отдельной CMS внутри SLAED.

## Правила ведения плана

- Текст документации и пояснения пишутся на русском языке.
- Идентификаторы PHP, SQL, имена файлов и каталогов пишутся на английском языке.
- Непринятое имя помечается как кандидат и не используется как утверждённый контракт.
- Одно решение имеет одного владельца: другие документы ссылаются на него, а не копируют его полностью.
- Утверждённые решения записываются в `15-decisions.md`.
- Реализация не начинается, пока не утверждены схема данных, границы кода, API и маршруты соответствующего этапа.
- Каждый этап реализации должен иметь собственные критерии готовности и проверки.

## Текущее состояние

Утверждены техническое имя `node`, каталоги `core/classes/node/` и `modules/node/`, базовые классы и их короткие файлы со строчными именами, пять основных таблиц и единый глобальный ID. `_nodes.cid` хранит основную категорию, а `_node_categories(id, nid, cid)` — дополнительные категории материала. Язык и стандартные права чтения определяются основной категорией; отдельная ACL типа не создаётся. Корзина работает через состояние, дополнительные поля и настройки используют глобальную конфигурационную систему, а рабочая система не зависит от Composer. История редакций не хранится; `version` защищает материал от одновременного перезаписывания. Один материал может иметь несколько структурированных ресурсов, не смешанных с редакторскими `[attach]`; отдельного `private`, файловой ACL роли и ручной настройки способа отдачи нет. Тип с категориями или расширением автоматически закрывает сервером всё своё дерево загрузок и обслуживает его через Node. Остальные имена согласовываются до фиксации в коде.
