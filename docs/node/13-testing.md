# Тестирование Node

Статус: каркас.

## Цель

Определить проверяемые контракты каждого слоя и условия, при которых этап реализации считается завершённым.

## Уровни тестирования

### Модели и правила

Статусы, типы, поля, настройки, права, связи и переходы жизненного цикла.

### Хранение

CRUD, фильтры, сортировка, пагинация, индексы, транзакции и конкурентные изменения.

### Расширения

Регистрация, валидация, дополнительные таблицы, откат и отключение.

### Интеграции

Категории, комментарии, рейтинг, избранное, поиск, RSS, sitemap и блоки.

Для категорий проверяются одна основная и несколько дополнительных связей, запрет повторной пары `(nid, cid)`, отсутствие основной категории среди дополнительных, замена полного набора в одной транзакции, выборка материала из каждой категории без дублей, отказ категории другого типа и каскадная очистка при физическом удалении материала.

### HTTP

Публичные списки и просмотр, административное создание и изменение, права, CSRF, загрузки, редиректы и сохранение результата в базе.

Для прямой отдачи проверяются серверный запрет доступа к `temp` и выполнения PHP, ответы `200`/`206` из `public`, локальный и внешний `302` маршрута `download`, `403`/`404`, `HEAD`, MIME, внешний URL без серверного обращения и изменение `hits` только при разрешённом переходе через Node. Прямые и диапазонные запросы к публичному файлу счётчик не изменяют.

Для контролируемой отдачи проверяются прямой отказ ко всему `uploads/node/<type>`, состояние материала, `pread` основной категории, дополнительное ограничение расширения, контролируемые `GET`, `HEAD` и `Range` структурированного ресурса, недоступность редакторского файла и `thumb` в обход Node, а также смена режима без окна незащищённого доступа.

Для материала в нескольких категориях проверяются: дополнительная категория не обходит `pread` основной, закрытая дополнительная категория не появляется недоступному пользователю, а все публичные интеграции используют ту же общую проверку доступа.

Для автоматического выбора отдачи проверяются три случая: `categories`, `ext` и простой тип без обоих признаков. Изменение этих признаков должно сначала применить и проверить серверную защиту, а затем активировать новую конфигурацию. Отдельного пользовательского значения режима не существует.

Счётчик `hits` увеличивается ровно один раз при разрешённом начале `download`; `HEAD`, отказ, отсутствующий файл, повторные диапазоны и обычный показ изображения его не меняют.

Для жалоб проверяются `POST` с CSRF, идемпотентная установка `reported`, ограничение частоты, административная очистка и автоматический сброс после замены ресурса.

Для профилей проверяется создание независимой конфигурации без runtime-ссылки на профиль. Клонирование создаёт новое неизменяемое `name`, экспорт не содержит данных, секретов, абсолютных путей и файлов. Тип с ошибкой зависимости, поля, роли ресурса, каталога или расширения остаётся отключённым.

Списки принимают только зарегистрированные сортировки, применяют утверждённое значение по умолчанию и отвергают произвольные имена SQL-колонок и выражения из конфигурации.

Для времени публикации проверяются материал до `published`, внутри разрешённого интервала и после `expires`; наступление срока не должно менять состояние и версию записи.

### Миграция

Новые глобальные ID, перенос нужных связей, контроль количества и отсутствие runtime-зависимости от старых таблиц.

### Производительность

Бюджет SQL, отсутствие N+1, массовые операции и кеш.

## Обязательные проверки этапа с кодом

- `php -l` для каждого изменённого PHP-файла.
- `php vendor/bin/phpunit`.
- `php vendor/bin/phpstan`.
- `php vendor/bin/php-cs-fixer check`.
- `npm run ui:gates` при изменении `core`, модулей, шаблонов, тестов или UI-инструментов.
- Реальный HTTP-маршрут для изменяющего сценария с проверкой базы и журналов.

## Критерии готовности

- Каждый публичный контракт имеет положительные и отрицательные тесты.
- Каждый переход состояния имеет проверку прав и недопустимого перехода.
- Каждая транзакция имеет сценарий принудительной ошибки и отката.
- Каждый перенесённый тип имеет набор новых контрольных маршрутов.
- Бюджеты запросов закреплены автоматической проверкой или воспроизводимым профилем.

## Открытые вопросы

- Структура тестовых фикстур для динамических типов.
- Способ измерения SQL-бюджета.
- Минимальный набор браузерных сценариев первой версии.
