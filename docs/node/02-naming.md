Статус: утверждено.

## Цель

Зафиксировать единый словарь до проектирования схемы и публичного API, чтобы одно понятие не получило несколько имён в PHP, SQL, маршрутах и документации.

## Термины документации

- **Материал (`Node`)** — одна публикация с глобальным идентификатором: новость, страница, вопрос, документ, файл или медиа.
- **Тип** — описание полей, возможностей, маршрутов и представлений группы материалов; стандартные права чтения принадлежат категориям.
- **Поле** — типизированное дополнительное значение материала.
- **Возможность** — стандартное поведение, которое ядро уже умеет подключать к типу.
- **Расширение** — PHP-компонент со специальным поведением, которого нет в стандартных возможностях.
- **Режим представления** — способ подготовки и отображения материала: список, карточка, полный материал, блок, поиск или печать.
- **Публичное имя типа** — уникальный ключ зарегистрированного типа, используемый в параметре `name` и видимый снаружи.

Для штатной Ticket System утверждены разные имена по ответственности: публичный тип `help`, технический ключ расширения `support`, класс `NodeSupport`, файл `modules/node/ext/support.php`, таблица `_node_support` и режим представления `support`.

## Обязательные правила проекта

- Классы и `enum` используют PascalCase, только буквы, длина 4–24 символа.
- PHP-файлы используют только строчные латинские буквы до расширения `.php`.
- Предпочтительно одно короткое слово; контекст каталога в имени файла не повторяется.
- Методы используют camelCase, начинаются с `get`, `set`, `add`, `update`, `delete`, `is`, `check` или `filter`.
- Методы содержат глагол и существительное, только буквы, длина 6–24 символа.
- Переменные соответствуют строгим правилам SLAED по длине и регистру.
- Специфичные для Node языковые константы используют префикс `_NODE_*`; существующие глобальные константы для общих понятий переиспользуются без дублирования.

## Имена, которые ещё не утверждены

Для первой версии неутверждённых имён нет. Новые события и точки расширения не резервируются заранее и именуются только вместе с реальным сценарием.

## Запрещённые подходы

- Не использовать два английских термина для одной сущности, например `Node` и `Entry`.
- Не называть тип отдельным модулем внутри ядра.
- Не использовать имя конкретного типа в общем API.
- Не повторять `node` в именах файлов внутри `core/classes/node/`; имя каталога уже задаёт контекст.
- Не добавлять временные алиасы классов или методов после утверждения контракта.
- Не утверждать имя только потому, что оно знакомо по другой CMS.

## Критерии готовности

- Каждое имя из схемы базы и публичного API присутствует в этом документе.
- Нет конфликтов с существующими классами, функциями, таблицами и маршрутами SLAED.
- Все имена проходят правила `.rules/global.md`.
- Имена отражают назначение и не зависят от первого реализованного типа.
