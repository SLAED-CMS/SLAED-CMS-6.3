# Маршрутизация Node

Статус: проектирование завершено; реализация и её проверки выполняются по 13-testing.md и 14-roadmap.md.

## Цель

Дать каждому типу стабильный новый публичный URL и направить разные логические разделы в единое ядро.

## Утверждённые принципы

- Публичное имя раздела не обязано совпадать с техническим именем `node`.
- Публичный список типа открывается через `index.php?name=<type>`, например `index.php?name=faq`.
- Материал открывается по глобальному `_nodes.id`, например `index.php?name=faq&op=view&id=1050`.
- Ресурс использует маршрут своего типа `index.php?name=<type>&op=asset&id=123`, где `id` — `_node_assets.id`.
- Один реестр связывает уникальное публичное имя с типом и обработчиком `node`.
- Публичное имя типа неизменяемо после создания и является ключом его настроек и дополнительных полей.
- Наличие имени в `config/node.php` направляет запрос в фиксированный `modules/node/index.php`; имя запроса никогда не участвует в построении пути к файлу.
- Модуль загружает тип из `_node_types` и проверяет его `active`; неизвестный или отключённый тип отвечает `404`.
- Зарегистрированный тип не возвращается к одноимённому файлу старого модуля при ошибке, отключении или отсутствии записи в базе.
- Маршруты имён, которых нет в реестре Node, продолжают обрабатываться обычной маршрутизацией SLAED без обращения к таблицам Node.
- Старые URL и ID не являются контрактом новой системы и не влияют на её схему.
- В ядре нет алиасов совместимости, карт ID, возврата к старым таблицам и пустых модулей-переходников.
- Одновременное наличие старых модулей и Node допустимо только на стенде разработки; совместимость, приоритеты и диагностика конфликтов не входят в рабочий код.

## Полный bootstrap виртуального типа

Реестр `node.types` читается из штатного конфига до выбора физического обработчика и языка. Для зарегистрированного имени, включая отключённое или аварийное, используется только фиксированный Node; возврата к одноимённому старому модулю нет. Зарезервированный путь `index.php?name=node` остаётся недоступным.

Публичный запрос и домашняя ветка сначала определяют эффективное имя: явное name либо штатный домашний модуль. Если имя принадлежит Node, обрабатываются только разрешённые op и file отсутствует либо равен index; затем загружается `modules/node/lang/<language>.php` через штатный getLang('node'), а конфигурационное name сохраняется публичным именем типа. Язык выбирается существующим механизмом SLAED; отсутствие перевода использует штатный fallback, не каталог фиктивного модуля типа.

Общие параметры layout и блоков берутся из `conf.modules['node']`; права материалов и активность типа определяются NodeType/NodeContext, а не записью старого модуля. NodeContext собирается из текущего пользователя, групп и административных прав один раз общим `getNodeContext(): NodeContext` в core/system.php. Явный name, домашний вход, глобальный AJAX и фоновые операции используют одну сборку; фоновый контекст задаётся доверенным адаптером, а не HTTP-параметром super.

Admin использует фиксированный `modules/node/admin/index.php`, язык административного Node и уже утверждённые права manage/mods. Глобальные комментарии, рейтинг и избранное сохраняют собственные маршруты, подключая core/classes/node/load.php и общий загрузчик расширений. Неизвестные обычные имена вне Node идут прежним маршрутом SLAED без SQL к Node.

Маркер незавершённой конфигурации проверяется до HTML-кеша и dispatch. Затронутый тип получает 503 и no-store; отсутствующий/отключённый тип — 404. Диагностика и восстановление доступны через административный вход без попытки собрать невалидный NodeType.


## Публичные маршруты

| Маршрут | Метод | Назначение |
|---|---|---|
| `index.php?name=<type>` | `GET` | список типа |
| `index.php?name=<type>&cat=<cid>&num=<page>` | `GET` | страница списка категории |
| `index.php?name=<type>&order=views&dir=desc` | `GET` | список с разрешённой сортировкой |
| `index.php?name=<type>&let=A` | `GET` | буквенный фильтр, если он включён типом |
| `index.php?name=<type>&op=view&id=<nid>` | `GET` | полный материал |
| `index.php?name=<type>&op=add` | `GET`, `POST` | форма, предпросмотр и отправка материала |
| `index.php?name=<type>&op=asset&id=<aid>` | `GET`, `HEAD` | ресурс материала |
| `index.php?name=<type>&op=attach&id=<nid>&key=<name>` | `GET`, `HEAD` | файл `[attach]` материала |
| `index.php?name=<type>&op=attach&id=<nid>&key=<name>&thumb=1` | `GET`, `HEAD` | уменьшенная копия `[attach]` |
| `index.php?name=<type>&op=report&id=<aid>` | `POST` | жалоба на ресурс |
| `index.php?name=help&op=support&id=<nid>` | `POST` | закрытие или повторное открытие собственного обращения |

- Пустой `op` означает список. Общий закрытый набор первой версии содержит только `view`, `add`, `asset`, `attach` и `report`; зарегистрированное расширение `support` добавляет только операцию `support`. Неизвестное либо не разрешённое текущим расширением значение отвечает `404`. Отдельная операция `liste` не создаётся.
- Параметр `let` принимает ровно одну Unicode-букву или цифру и передаётся в `NodeQuery::setNodeLetter()`; отключённый типом фильтр или неверное значение отвечает `400`.
- Известная операция с неподдерживаемым HTTP-методом отвечает `405 Method Not Allowed` с заголовком `Allow`; она не заменяется редиректом или показом списка.
- `cat`, `num` и `id` принимают только положительные целые значения; `num` по умолчанию равен `1`.
- Список принимает необязательные `order=<key>&dir=asc|desc`; отсутствие использует настройки типа, а неизвестное или запрещённое значение отвечает `400 Bad Request`.
- Явно переданные `order` и `dir`, совпадающие с настройками типа по умолчанию, перенаправляются на тот же URL без этих параметров. Нестандартная разрешённая сортировка остаётся рабочим представлением списка, но не индексируется и не попадает в HTML-кеш.
- `view` проверяет совпадение глобального `_nodes.id` с типом маршрута и возвращает общий `404` для отсутствующего или недоступного материала.
- `add` доступен только типу с включённой публичной отправкой и пользователю, разрешённому его `workflow`.
- `GET add` показывает форму. `POST add` принимает в теле `action=preview` или `action=submit`, CSRF и данные `NodeInput`.
- `preview` выполняет полную нормализацию и проверку, использует обычную подготовку представления, но не пишет материал, связи и ресурсы.
- `submit` определяет по `workflow` и `NodeContext` разрешённый начальный `Pending` или `Published`, явно передаёт его в `NodeService::addNode()` и после успеха перенаправляет на безопасный GET. Публичный `Draft` не создаётся.
- Публичное изменение существующего материала не входит в первую версию.
- Операции `liste`, `send`, `loading` и `broken`, отдельный параметр `page` и публичные алиасы не создаются.
- Комментарии, рейтинг и избранное используют существующие глобальные маршруты SLAED и не дублируются в `modules/node/index.php`.
- `POST op=support` доступен только владельцу опубликованного обращения типа с расширением `support`, принимает CSRF, ожидаемую `_node_support.version` и только целевое `state = 0|2`. Ответственный и приоритет берутся из текущей строки, а не из публичного запроса. Повтор значения не создаёт запись; конфликт версии отвечает `409`.

## Маршруты ресурса

- `GET|HEAD index.php?name=<type>&op=asset&id=<id>` получает ресурс и материал, затем требует точного совпадения их типа с публичным именем маршрута и проверяет назначение, состояние, даты публикации и окончания видимости, право чтения основной категории и дополнительные ограничения расширения.
- `POST index.php?name=<type>&op=report&id=<id>` принимает жалобу только после той же проверки типа и доступности ресурса, CSRF и ограничения частоты.
- Оба маршрута разрешают ресурс через `NodeQuery::getNodeAsset()`; модуль не выполняет собственный SQL к `_node_assets`.
- Разрешённый `GET` режима `download` передаёт вызов `NodeService::updateNodeAssetHits()` в callback `$start` общей файловой функции. Он выполняется только непосредственно перед телом ответа `200` либо `206` с нулевого байта; внешний редирект учитывается перед разрешённым `302`. `HEAD`, `304`, `416` и повторный диапазон счётчик не меняют.
- Жалоба после CSRF и ограничения частоты вызывает `NodeService::updateNodeAssetReport()`. Административный разбор с явным результатом `полезная/отклонённая` вызывает `NodeService::deleteNodeAssetReport()` и требует права модерации этого типа или главного администратора.
- Роль ресурса не имеет собственного `access` и списка групп; смешанный режим доступа внутри одного материала не поддерживается.
- По NOD-206 способ отдачи всех типов один: контролируемые `asset/attach`, без прямых локальных URL и переключателя режима.
- Веб-сервер запрещает прямой доступ ко всему `uploads/<type>`, а маршрут `asset` после проверки прав сам обслуживает структурированный ресурс без перенаправления на локальный URL.
- Внешний URL при контролируемой отдаче может быть передан редиректом только после проверки прав; Node не способен отозвать уже раскрытый внешний адрес.
- `HEAD` выполняет те же проверки и возвращает заголовки полного файла без тела и увеличения `hits`.
- Контролируемый `GET` возвращает полный `200`, один допустимый диапазон — `206`, неудовлетворимый или повреждённый диапазон — `416`; несколько синтаксически корректных диапазонов не собираются в multipart и игнорируются с полной отдачей `200`.
- `If-None-Match` имеет приоритет над `If-Modified-Since` и после проверки доступа может завершить обычный `GET` или `HEAD` ответом `304`. `If-Range` разрешает `206` только при совпадении валидатора, иначе возвращается полный `200`.
- Неизвестный, отключённый, удалённый, недоступный или принадлежащий другому типу ресурс не раскрывает существование локального пути и отвечает общим `404`.
- Редакторские файлы и `thumb` также не получают прямых URL. Контролируемые адреса сохранённого вложения и новой загрузки определены ниже; эти файлы не требуют строки `_node_assets`.
- Штатный HTML-кеш SLAED допускает только анонимный `GET` списка с пустым `op` и сортировкой типа по умолчанию: основной список, категорию и пагинацию. Ключ включает только `name`, `cat`, `num` и уже существующие тему, язык, схему, версию и поколение кеша.
- Наличие `let`, нестандартных `order` или `dir` отключает HTML-кеш текущего ответа. Эти варианты обычно имеют низкую повторяемость, поэтому отдельные кеш-файлы для них не создаются.
- `view`, `add`, `asset`, `attach` и `report` в HTML-кеш страниц не входят. Это сохраняет точный учёт просмотра материала и не кеширует формы или ответы с проверкой доступа к файлу.
- Реестр допустимых имён для HTML-кеша берётся из уже загруженного `config/node.php`; имя не превращается в путь и не требует SQL до проверки кеша. Комбинации параметров проверяются по маршруту, неизвестный, повторный или лишний параметр отключает кеширование текущего ответа.
- Публичные физические файлы кеширует веб-сервер, а контролируемые ответы используют только частный HTTP-кеш браузера с обязательной повторной проверкой прав.

Для режима `link` маршрут `asset` проверяет доступ и внешний HTTP/HTTPS, вызывает `updateNodeAssetHits()` перед `302` и использует действие Point `visit`, если оно включено. Режим `download` сохраняет `download`; рейтинг не участвует. `HEAD` не увеличивает счётчик и не начисляет баллы. Жалоба использует существующий `report`; отдельные `linkout` и `broken` не возвращаются.

## SEO и canonical

- Node использует существующий `setHead()` и не создаёт собственный SEO-класс, генератор canonical, Open Graph или Schema.org.
- Основной список, категория и страница пагинации индексируются. Для них передаётся `kind = collection`; `num = 1` в канонический URL не входит.
- Полный доступный материал индексируется. Его `kind` определяется закрытой настройкой типа: `article`, `news` или `website`.
- Материал передаёт в `setHead()` заголовок, обычный текст вступления, автора, даты публикации и изменения, URL обложки и основную категорию. Эти данные уже подготовлены `NodeView`; произвольный JSON-LD из настройки типа не принимается.
- Буквенный фильтр `let` и нестандартная сортировка получают `robots = noindex, follow`. Canonical для них не выводится существующим правилом `setHead()`.
- Ошибки, формы и служебные маршруты сохраняют общесистемный `noindex`; Node не дублирует эту проверку.
- После перенаправления явно переданных стандартных `order` и `dir` остаётся один индексируемый и кешируемый URL списка.

## Маршрут вложения редактора

- `attach` обслуживает редакторские вложения любого типа Node; прямые URL из `uploads/<type>` не выдаются.
- В сохранённой ветке `id` является глобальным ID материала, `key` — единственным именем файла, созданным `Upload`, а необязательный `thumb=1` выбирает одноимённую уменьшенную копию. Другие значения `thumb` отклоняются.
- Имя читается через `getVar('get', 'key', 'raw')`, не декодируется повторно, имеет предел 255 байт и обязано целиком совпасть со своим `basename()` после замены обратных разделителей.
- Дополнительно имя обязано пройти `FileManager::checkFileName()`, а расширение — актуальное разрешение места загрузки и безусловный запрет активных форматов `Upload`. Проверка выполняется повторно при каждом запросе и не доверяет факту прежней загрузки.
- Тип берётся из проверенного `NodeType`, а не используется как сырой сегмент пути. `FileManager` разрешает `realpath()` только внутри `uploads/<type>`; выход через `..`, абсолютный путь, stream wrapper, alternate data stream и симлинк получает общий `404`.
- В сохранённой ветке после `NodeQuery::getNodeContent()` маршрут через `Parser::getAttachList()` подтверждает точное присутствие `key` в исходном `intro` или `body` доступного материала. Лёгкая проекция не загружает поля, категории, связи и ресурсы; знание имени чужого файла не даёт доступа к нему.
- Оригинал находится только в корне типа, уменьшенная копия — только в `thumb`; произвольный вложенный путь через этот маршрут недоступен.
- Файл отдаётся утверждённым `getFileStream()` без изменения `hits`; отсутствие материала, ссылки в тексте, файла или права отвечает одинаковым `404`.
- Параметр `file` намеренно не используется: он уже управляет выбором PHP-файла модуля в глобальном `index.php` и остаётся под строгим `filterVar()`.

## Защищённый предпросмотр загрузки

По NOD-199 новый файл показывается без создания временного материала и остаётся в `uploads/<type>`. Для него используется та же операция `attach` в отдельной форме: `GET|HEAD index.php?name=<type>&op=attach&key=<name>&preview=1`; параметр `id` отсутствует. Сочетание `id` с `preview`, неизвестное значение флага или лишний параметр отклоняется. Флаг выбирает ветку обработки и не является разрешением доступа.

Маршрут проверяет тип, право работы с формой/загрузками, допустимость файла и владельца через штатный файловый слой. Зарегистрированный владелец определяется по аккаунту, гость — по текущей сессии, модератор — по праву на файловую область типа. Чужое имя, другая гостевая сессия, отсутствие файла или права отвечают общим `404`. Обход через присланные `uid`, IP или исходное имя файла запрещён. `thumb=1` разрешён только после проверки оригинала; производная копия не имеет отдельного владельца.

Форма и предпросмотр получают эти адреса только для подтверждённых локальных загрузок. Ветка применяется и к ещё не сохранённым структурированным ресурсам. После сохранения используются обычные `attach&id=...` и `asset&id=...`; временный адрес не подменяет права опубликованного материала. Ответ предпросмотра имеет `Cache-Control: private, no-store`, не меняет счётчики и не пишет материал в БД.

По NOD-206 прямой доступ ко всем файловым каталогам Node закрыт, в том числе у простых типов без категорий и расширения. Это устраняет обход проверки владельца нового файла; новая загрузка не становится публичной из-за знания её имени.

## Административные маршруты

В примерах используется стандартное имя `admin.php`; фактическое имя административного файла берётся из `$afile`.

| Маршрут | Метод | Назначение |
|---|---|---|
| `admin.php?name=node` | `GET` | все материалы |
| `admin.php?name=node&type=news` | `GET` | материалы одного типа |
| `admin.php?name=node&op=add&type=news` | `GET`, `POST` | форма и создание материала |
| `admin.php?name=node&op=edit&id=1050` | `GET`, `POST` | форма и изменение материала |
| `admin.php?name=node&op=status&id=1050` | `POST` | изменение состояния материала |
| `admin.php?name=node&op=delete&id=1050` | `POST` | физическое удаление материала |
| `admin.php?name=node&op=types` | `GET` | список типов |
| `admin.php?name=node&op=type` | `GET`, `POST` | форма и создание типа |
| `admin.php?name=node&op=type&type=news` | `GET`, `POST` | форма и изменение типа |
| `admin.php?name=node&op=config` | `GET`, `POST` | общие настройки Node |
| `admin.php?name=node&op=info` | `GET` | документация модуля |
| `admin.php?name=node&op=support&id=1050` | `GET`, `POST` | рабочая карточка обращения поддержки |
| `admin.php?name=node&op=sync&id=1050` | `POST` | ручное обновление внешнего материала |

- `type` содержит неизменяемое публичное имя типа; `tid` не передаётся в административных URL.
- `id` в операциях материала является глобальным `_nodes.id`; обработчик дополнительно проверяет выбранный тип записи.
- Право `_admins.modules = node` открывает управление Node и типами, а `node-<type>` — модерацию материалов только указанного типа; главный администратор имеет полный доступ.
- Список прав администраторов получает зарегистрированные типы Node как виртуальные пункты, но все они ведут в единый `modules/node/admin/index.php` и не создают каталоги модулей.
- `status`, ожидаемая `version`, CSRF-токен и изменяемые значения передаются только в теле `POST`; версия обязательна как для материалов, так и для существующих типов.
- Успешная изменяющая операция завершается перенаправлением на канонический GET по схеме Post/Redirect/Get.
- `NodeException::CONFLICT` возвращает `409 Conflict` без перенаправления и без записи. Форма сохраняет нормализованные отправленные значения, повторно читает актуальную запись и отмечает поля или разделы, значения которых различаются.
- «Открыть актуальную» выполняет обычный канонический `GET` и отказывается от отправленных значений. «Продолжить с моими данными» только переносит их в редактируемую форму с актуальной `version`; само действие не пишет базу или конфигурацию.
- Следующее нажатие сохранения является новым обычным `POST`, снова проверяет CSRF и `version`. Повторное конкурентное изменение снова даёт `409`; скрытого принудительного сохранения нет.
- Для конфликта смены состояния или удаления данные формы сохранять нечего: редактор обязан открыть актуальную запись и заново подтвердить действие.
- `GET` для `status` и `delete` отклоняется без изменения данных.
- Отдельные операции `save`, `saveadd` и `saveedit` не создаются: `GET` показывает форму, а `POST` на тот же маршрут сохраняет её.
- Неизвестные `op` не переходят на список молча и отвечают `404`.
- Для типа `help` обычный `admin.php?name=node&type=help` выводит очередь через `NodeSupport::getNodeSupportList()` и остаётся её единственным каноническим списком. Необязательные `state`, `aid`, `prio` и `num` фильтруют очередь; их отсутствие показывает ожидающие поддержку обращения по убыванию приоритета и возрастанию `activity`.
- `GET op=support` показывает материал, переписку и рабочие поля `aid`, `state`, `prio`, `version`. `POST` принимает эти четыре значения только от главного администратора или модератора типа, вызывает `updateNodeSupport()` и завершает операцию через Post/Redirect/Get. Для типа без расширения `support` маршрут отвечает `404`.
- `POST op=sync` требует CSRF, право модерации типа и расширение `sync`, вызывает `updateNodeSync()` для текущего материала независимо от `due` и завершает успешную либо неизменившую содержимое проверку через Post/Redirect/Get. Ошибка источника показывает безопасное сообщение и сохраняет прежний текст; `GET`, публичный маршрут и произвольный URL в этой операции отсутствуют.

## Критерии готовности

- Для каждого типа определены список, просмотр, категория, добавление и административный маршрут.
- Не существует двух канонических адресов одного материала.
- Несовпадение `name` и фактического типа материала не раскрывает материал по чужому маршруту.
- Неизвестный или отключённый тип не позволяет подключить произвольный файл.

Реестр использует сочетание базы и конфигурации: `_node_types` хранит идентичность, публичное имя и активность, а `config/node.php` — проверенные настройки по тому же неизменяемому имени. Маршрутизатор сначала проверяет наличие точного ключа конфигурации без SQL, после чего `modules/node/index.php` получает полный тип через `NodeQuery::getNodeType()`.

Публичного маршрута `index.php?name=node` нет, а `node` запрещён как имя типа. Техническое имя используется только для каталога кода и административной точки `admin.php?name=node`.

При совпадении имени тестовый старый модуль не рассматривается как альтернативный обработчик: зарегистрированный ключ Node безусловно принадлежит Node. Перед выпуском заменённые каталоги модулей удаляются из поставки.
