# Маршрутизация Node

Статус: каркас.

## Цель

Дать каждому типу стабильный новый публичный URL и направить разные логические разделы в единое ядро.

## Утверждённые принципы

- Публичное имя раздела не обязано совпадать с техническим именем `node`.
- Публичный список типа открывается через `index.php?name=<type>`, например `index.php?name=faq`.
- Материал открывается по глобальному `_nodes.id`, например `index.php?name=faq&op=view&id=1050`.
- Общий технический маршрут ресурса использует `index.php?name=node&op=asset&id=123`, где `id` — `_node_assets.id`; список материалов и просмотр материала через `name=node` не создаются.
- Один реестр связывает уникальное публичное имя с типом и обработчиком `node`.
- Публичное имя типа неизменяемо после создания и является ключом его настроек и дополнительных полей.
- Старые URL и ID не являются контрактом новой системы и не влияют на её схему.
- В ядре нет алиасов совместимости, карт ID, возврата к старым таблицам и пустых модулей-переходников.

## Необходимо описать

- Разрешение `name`, `op`, `id`, категории и пагинации.
- Центральный реестр публичных имён типов.
- SEO-маршруты и canonical.
- Административные маршруты.
- Конфликты ключей типов с реальными модулями.
- Кешируемые операции и допустимые параметры.

## Маршрут ресурса

- `GET index.php?name=node&op=asset&id=<id>` получает ресурс, материал и тип, затем проверяет назначение, состояние, даты публикации и окончания видимости, право чтения основной категории и дополнительные ограничения расширения.
- Роль ресурса не имеет собственного `access` и списка групп; смешанный режим доступа внутри одного материала не поддерживается.
- Способ отдачи не настраивается: включённые `categories` или непустой `ext` автоматически требуют контролируемой отдачи всего дерева типа; простой тип без обоих признаков использует прямую отдачу визуальных ресурсов.
- При прямой файловой отдаче режим `download` атомарно увеличивает `hits` и перенаправляет на разрешённый локальный или внешний URL. Локальные `image`, `gallery`, `poster` и `player` получают прямые URL и обслуживаются веб-сервером.
- При контролируемой файловой отдаче веб-сервер запрещает прямой доступ ко всему `uploads/node/<type>`, а маршрут `asset` после проверки прав сам обслуживает структурированный ресурс без перенаправления на локальный URL.
- Внешний URL при контролируемой отдаче может быть передан редиректом только после проверки прав; Node не способен отозвать уже раскрытый внешний адрес.
- `HEAD` выполняет те же проверки без увеличения `hits`; контролируемая локальная отдача должна поддерживать корректные MIME, длину и диапазоны.
- Неизвестный, отключённый, удалённый или недоступный ресурс не раскрывает существование локального пути и отвечает общим отказом.
- Редакторские файлы и `thumb` при контролируемой отдаче также не получают прямых URL. Отдельный контролируемый адрес для `[attach]` утверждается до реализации, поскольку эти файлы не имеют строки `_node_assets`.
- При прямой отдаче каталог физически публичен: знание прямого URL позволяет обойти Node и состояние материала. Поэтому такой режим автоматически доступен только простому типу без категорий и расширения; `download` публикуется ссылкой на Node, чтобы считать разрешённые начала скачивания.

## Критерии готовности

- Для каждого типа определены список, просмотр, категория, добавление и административный маршрут.
- Не существует двух канонических адресов одного материала.
- Несовпадение `name` и фактического типа материала не раскрывает материал по чужому маршруту.
- Неизвестный или отключённый тип не позволяет подключить произвольный файл.

Реестр использует сочетание базы и конфигурации: `_node_types` хранит идентичность, публичное имя и активность, а `config/node.php` — проверенные настройки по тому же неизменяемому имени.

Общий `name=node` зарезервирован для технических операций подсистемы и не является публичным типом материала.
