# Цели и границы Node

Статус: первичный вариант.

## Цель

Создать единое контентное ядро SLAED, которое обслуживает несколько типов материалов одновременно, использует существующие глобальные подсистемы и устраняет повторяющийся CRUD однотипных модулей.

## Какие проблемы решаются

- Одинаковые списки, формы, настройки и административные действия реализованы в нескольких модулях отдельно.
- Исправление общего поведения приходится повторять и проверять во многих местах.
- Специальные возможности смешаны с базовым жизненным циклом материала.
- Новый контентный раздел требует копирования существующего модуля.
- Глобальные подсистемы используют жёсткие списки поддерживаемых модулей.

## Целевые свойства

- Один экземпляр `node` одновременно обслуживает все зарегистрированные типы.
- Простой тип создаётся из административной панели без PHP-кода.
- Специальное поведение подключается расширением без изменения ядра.
- Типы имеют независимые поля, настройки, маршруты и шаблоны; отдельная ACL типов не создаётся.
- Категории, комментарии, рейтинг, избранное, пользователи и шаблонизатор не дублируются.
- Публичное чтение использует существующие права категорий, а все записи проходят централизованные проверки, валидацию и транзакции.
- Число SQL-запросов не растёт от количества строк списка.
- Новый публичный контракт не зависит от ID, URL, таблиц и API заменяемых модулей.
- Темы управляют HTML и внешним видом без бизнес-логики.

## Модули-кандидаты на полную замену

| Старый модуль | Целевой тип | Особое поведение |
|---|---|---|
| `news` | новости | закрепление, связи, опросы |
| `pages` | страницы | базовый тип материала |
| `faq` | вопросы и ответы | специализированное отображение |
| `help` | поддержка | приватное обращение, ответы и закрытие цепочки |
| `jokes` | короткие материалы | упрощённая форма |
| `content` | внешний материал | загрузка и периодическое обновление источника |
| `links` | ссылки | проверка адресов и статистика переходов |
| `files` | файлы | загрузка, скачивание и жалобы |
| `media` | медиа | источники, проигрыватель и метаданные |

## Что не входит в Node

- Учётные записи и авторизация.
- Форумные темы и сообщения.
- Торговая корзина, товары, заказы и платежи.
- Личные сообщения.
- Общий шаблонизатор и визуальная система темы.
- Собственные категории и комментарии, дублирующие существующие.
- Выполнение PHP, SQL или произвольных классов из настроек типа.
- Универсальная замена любого модуля SLAED.

## Граница подсистемы

SLAED управляет сайтом, пользователями, безопасностью, маршрутизацией верхнего уровня и темами. `node` управляет типами материалов, их данными, состояниями, связями и выборками. Расширение управляет только специальным поведением конкретного типа.

## Критерии успеха первой версии

- Одновременно работают три эталонных типа первой поставки: `news`, `docs` и `files`.
- `news` подтверждает полный стандартный контентный сценарий, `docs` — иерархию `parent`, а `files` — несколько ресурсов, скачивания и `hits`.
- Для добавления простого типа не меняется ядро и не создаётся новая таблица.
- Для добавления расширения не меняются `NodeService` и базовый репозиторий.
- Публичный и административный CRUD покрыты автоматическими и реальными HTTP-проверками.
- Права проверяются в сервисном слое, а не только в контроллере.
- Составная запись либо завершается целиком, либо откатывается.
- Списки не содержат N+1-запросов.
- Каждый тип имеет один новый канонический маршрут, использующий глобальный ID материала.
- Документация является отдельным новым типом с иерархией; она не подменяет существующую приватную поддержку `help`.

## Вне первой версии

- Перенос данных всех девяти модулей одним выпуском.
- Публичный headless API, пока внутренние контракты не стабилизированы.
- Конструктор произвольной бизнес-логики из административной панели.
- Обобщение `node`-компонентов для других предметных областей без второго реального потребителя.
