# Состояние реализации

Единственная точка входа. Команда пользователя во всех окнах одна: «Работай по плану docs/node/PROGRESS.md». Она означает: выполнить этап из блока «Передача следующему окну» по протоколу ниже. Закрытые задачи проектирования не означают выполненную реализацию.

## Протокол окна

1. Текущий этап — тот, что назван в блоке «Передача следующему окну»; таблица ниже его подтверждает. Этап не выбирается по памяти, по истории чата или по желанию исполнителя.
2. Прочитать раздел «Вход в каждое новое окно» и карточку этапа в [14-roadmap.md](14-roadmap.md), затем документы из строки «Прочитать» блока передачи. Остальное не читать.
3. Проверить git status и фактическое состояние зависимостей по коду и артефактам, а не по записям предыдущего окна. Расхождение с записью — сначала в блок передачи, потом работа.
4. Выполнить ровно один этап. Следующий этап в том же окне не начинать, даже если остались силы и контекст.
5. Развилка, которую не решает план, задаётся пользователю через AskUserQuestion; молчаливый выбор запрещён. Ответ вносится в документ-владелец до продолжения.
6. Закрыть окно: обновить строку таблицы (состояние, команды проверок и их результат), затем целиком заменить блок передачи — следующий этап, что прочитать, изменённые файлы, выполненные проверки, остаток. Незавершённый этап остаётся в блоке под тем же ID с точным остатком. Отчёт — по .rules/report.md. Коммит — только по команде пользователя.
7. Блок передачи всегда указывает этап, с которого начнёт следующее окно; после S19.8 он сообщает, что план выполнен. Окно без обновлённого блока считается незакрытым.
