# Безопасность и производительность Node

Статус: утверждено.

## Цель

Сделать безопасность и предсказуемую стоимость запросов частью контракта, а не этапом доработки после CRUD.

## Безопасность

- Ввод читается через `getVar()` на границе запроса.
- Внутренний слой получает нормализованные типизированные данные.
- Модуль один раз строит `NodeContext` из доверенного состояния SLAED; классы ядра не читают пользователя, администратора, группы, права модерации, IP или язык непосредственно из запроса и глобальных переменных.
- `NodeContext::$mods` содержит только валидные зарегистрированные имена типов из существующих прав `_admins.modules` вида `node-<name>`; значение `name`, присланное запросом, не может добавить право.
- `_admins.modules` хранится как неиндексируемый `TEXT`, но административное сохранение строит его только из разрешённого реестра, удаляет повторы и не принимает неизвестные или сформированные клиентом ключи.
- Разрешённое чтение глобального `$conf` ограничено областями `node`, `fields.node` и штатным правилом `uploads.<type>` для уже разрешённого типа; обычные операции Node не изменяют конфигурацию, не принимают её ключи из запроса и не используют её значения как произвольные имена файлов, классов, таблиц или SQL-колонок.
- `final readonly NodeInput` принимает только `cid`, `cids`, `aname`, `title`, `intro`, `body`, `fields`, `poll`, `home`, `comon`, `pinned`, `pubdate`, `expires`, `rels` и `assets`; он не позволяет массово назначить поля основной записи, принадлежащие системе. Вложенные `rid` и `assets.id` являются только проверяемыми ссылками, а не назначаемыми идентификаторами.
- `NodeInput` не содержит состояние; `addNode()` принимает отдельный `NodeStatus`, разрешает для новой записи только `Draft`, `Pending` или `Published` и проверяет право через `NodeContext` и `workflow`.
- `cids`, `rels` и `assets` проверяются как полные наборы, а `fields` — как полный набор активных редактируемых полей; неизвестные структурные ключи, повторения, чужие идентификаторы, объекты, ресурсы и недопустимая глубина отклоняются до транзакции. Неизвестное устойчивое имя внутри `fields` является утверждённым исключением: общий `Field` безопасно исключает его из результата.
- Входная связь принимает только `rid`, зарегистрированный `type` и неотрицательный `sort`; `nid`, идентификатор и дата не принимаются из формы, а существование, доступность, тип и отсутствие цикла проверяются до записи.
- Входной ресурс содержит только обязательные `id`, `kind`, `role`, `src`, `name`, `title`, `intro`, `sort`; положительный `id` обязан принадлежать изменяемому материалу, а `null` создаёт новую строку. Служебные метаданные, счётчики, жалоба и даты из формы не принимаются.
- Изменяющие операции требуют CSRF и серверной проверки прав.
- SQL использует именованные параметры.
- Динамические имена таблиц и колонок выбираются только из реестра.
- Загрузка проверяет содержимое, расширение, MIME, размер и безопасный путь.
- Настройка типа может только ужесточить глобальные пределы безопасности.
- Значение дополнительного поля `decimal` содержит не более 65 цифр при `scale` не более 18; знак и десятичная точка не входят в подсчёт, а конфигурация не может увеличить эти пределы.
- `Field` ограничивает набор 256 определениями, `select` — 256 вариантами и 64 выбранными значениями, строки — пределами типа, а итоговый канонический JSON — 1048576 байт до SQL; настройка поля может только уменьшить предел.
- `title`, `intro` и подпись варианта `select` не принимают HTML; шаблон получает текст, а неизвестное имя языковой константы с начальным `_` отклоняется при проверке определения.
- Неверное определение не фильтруется частично: `filterFieldList()` останавливает весь набор на первой ошибке, а технический текст `InvalidArgumentException` попадает только в журнал.
- `default` не применяется при редактировании и не может ссылаться на отключённый вариант; неактивное поле не принимает ввод, а его прежнее значение сохраняет сервис без доверия скрытому POST-параметру.
- При изменении содержимого сервис сохраняет неактивные известные значения, заменяет активные и удаляет ключи без определения; `updateNodeStatus()` не переписывает JSON и не создаёт окно для изменения поля через операцию состояния.
- URL дополнительного поля допускает только `http`, `https` или путь от корня; протокол-независимая форма, учётные данные, опасные схемы и автоматическое добавление протокола запрещены. Старый `filterWebUrl()` не используется, поэтому регистр пути и запроса не теряется.
- `Feed` принимает только внешний `http` или `https` без учётных данных, перед каждым запросом и перенаправлением разрешает имя заново и отклоняет loopback, частные, link-local, multicast, зарезервированные и неопределённые IP-адреса. DNS rebinding проверяется по фактическому адресу соединения.
- Загрузка ленты ограничивается значениями `rss.bytes = 2097152`, `rss.timeout = 10` и `rss.redirects = 3` из стандартного `config/rss.php`. Превышение размера, времени, числа перенаправлений или неподдерживаемый тип содержимого являются ошибкой без частичного сохранения.
- RSS/Atom разбирается XML-парсером без сетевого доступа и внешних сущностей. Удалённые заголовки, адреса и описания нормализуются до построения сохраняемого тела; исходный XML, ответ сервера и непроверенный HTML не попадают в `_nodes.body`.
- Сетевой запрос NodeSync не выполняется внутри публичного просмотра или транзакции базы. После загрузки источник и версия материала проверяются повторно, поэтому устаревший ответ не перезаписывает параллельное административное изменение.
- Ошибка синхронизации хранит только безопасный короткий текст без тела ответа, локального пути, данных авторизации и строки запроса URL; полная диагностическая запись использует существующий `Logger` с маскированием чувствительных параметров.
- Роль ресурса проверяется по активному типу материала, а её `kinds`, `extensions`, `maxbytes`, `min`, `max`, `canlink` и `report` применяются сервером независимо от присланной формы.
- Ресурс не имеет собственных прав и наследует состояние материала, право чтения основной категории и ограничения расширения; смешанный публичный и закрытый доступ к ресурсам одного материала не поддерживается.
- Материал не может содержать более `limits.maxassets = 100` строк ресурсов; предел конкретного назначения проверяется дополнительно, а сумма настроенных пределов не ослабляет общий лимит.
- Удаление, публикация и связанные изменения выполняются транзакционно.
- `updateNode()`, `updateNodeStatus()` и `deleteNode()` требуют ожидаемую `version`; изменяющий SQL включает её в условие и отклоняет устаревшее состояние.
- `updateNodeType()`, `updateNodeTypeStatus()` и `deleteNodeType()` также требуют ожидаемую `_node_types.version`; изменение базы и конфигурации при конфликте не начинается, а успешная операция увеличивает версию ровно на один.
- Открытая форма не держит блокировку базы. При конфликте сервер не объединяет значения автоматически, не меняет скрытно ожидаемую версию и не предоставляет параметр принудительной записи.
- Отправленные и актуальные значения сравниваются только после полной нормализации; HTML и текст обеих сторон проходят обычные границы экранирования административного шаблона.
- Разрешение конфликта не использует сессию, временную таблицу, историю редакций или серверный черновик: значения живут только в ответе формы и следующем явном `POST`.
- Административные изменения типов и схемы журналируются.
- `Point` принимает только закрытые действия и ключи данных, проверяет серверные ASCII `scope` и `source` и не позволяет обычному владельцу события передать сумму; исключением является `adjust` от существующего администратора с обязательной текстовой причиной.
- `Point` получает только `$conf['points']`; административное сохранение проверяет весь набор, вызывает существующую `setConfigFile()` для `config/points.php`, проверяет её возвращаемый `bool` и показывает только фактически перечитанные значения. `config/local.php` напрямую не изменяется.
- Конфигурация принимает только канонические десятичные строки, полный закрытый набор `actions` и известные ключи `active`, `actions`, `points`, `period`, `limit`. `active` допускает только `'0'` и `'1'`; числовые правила допускают `'0'` или положительную запись без знака, пробела и ведущего нуля. `Point` строго проверяет и один раз преобразует их во внутренние `bool` и `int`; нативные скаляры и частичная нормализация отклоняются.
- Обычное `points` ограничено диапазоном `0..1000`, `adjust` — ненулевым диапазоном `-1000000..1000000`, `period` — значением `0` или `60..31536000`, `limit` — значением `0` или `1..10000`; период и предел включаются только вместе.
- Временной предел считается по `uid`, `action` и скользящему `created` во всей системе; контекст не позволяет обойти предел через другой модуль или тип, а IP и cookie не становятся идентичностью системы баллов.
- Сочетание `_points(uid, action, scope, source)` уникально, `rid` допускает только одну отмену исходного положительного события с `rid IS NULL` и `action != 'adjust'`, а строка пользователя и исходное событие блокируются в постоянном порядке до изменения баланса. Компенсацию и ручную корректировку отменять через `rid` запрещено.
- `_points` не хранит IP и не принимает HTML в `note`; `scope`, `source` и `mid` не используются как динамические PHP-классы, пути, таблицы или SQL-выражения.
- `source` создаётся только доверенным владельцем события и не читается из пользовательского запроса. Повтор источника безопасен, а ошибка автоматического начисления журналируется и не блокирует основное действие.
- Административное изменение баланса требует существующего `aid`, CSRF-проверки, непустой причины и строгого знакового целого, прочитанного как текст; `filterNum()` для отрицательной разницы не используется. Баланс не изменяется напрямую. Общий сброс хранит случайный ID и подтверждённый курсор только в административной сессии, читает до 500 пользователей по возрастающему ID, обрабатывает каждого отдельной транзакцией и формирует устойчивый источник каждой части.
- `Point` выполняется до `COMMIT` владельца. В существующей транзакции он использует `SAVEPOINT`, чтобы локальная ошибка атомарно убрала только журнал и изменение баланса; без внешней транзакции он сам владеет `BEGIN`, `COMMIT` и `ROLLBACK`.
- Административный журнал ограничен 50 строками на страницу. Индексы по пользователю, действию и дате не позволяют независимым фильтрам сканировать всю `_points`.
- `ruid` автора первой жалобы доступен только сервису и административному разбору, не передаётся в данные публичного шаблона и очищается одновременно с `reported`.
- `_nodes.ip` является служебным полем, не входит в публичный API и показывается только уполномоченным администраторам и модераторам.
- `Node::$ip` равен `null` во всех остальных контекстах; публичный `Node` не содержит скрытого IP, который контроллер мог бы случайно вывести.
- Ключи и структура `_nodes.field` проверяются по зарегистрированному определению; неизвестные имена полей отбрасываются, а неверная структура известного значения, недопустимая глубина и превышение 1048576 байт канонического JSON отклоняются до SQL.
- Изменение `config/node.php`, области Node в `config/fields.php` и правила типа в `config/uploads.php` выполняет пакетный режим существующей `setConfigFile()` с блокировкой всего цикла чтения и записи, временными файлами, проверкой PHP, атомарной заменой каждого файла и проверяемым результатом. Пакет сохраняет только нативные `string`, `int`, `bool`, `null` и массивы; неподдерживаемые и исполняемые значения отклоняются до записи.
- Пакет принимает только имена конфигурационных файлов внутри `CONFIG_DIR` и полное проверенное содержимое каждого источника; пути, зарезервированные файлы, неизвестная форма пакета и передача `$arr` или `$act` вместе с пакетом отклоняются.
- Все исходные файлы заменяются одной пакетной операцией с откатом уже заменённых файлов; промежуточный `config/local.php` из части нового состояния не создаётся.
- После успешной замены исходников инвалидируются OPcache и `config/local.php`, затем общий кеш пересобирается один раз; ошибка оставляет прежние источники и прежний runtime-кеш.
- Техническое `name` типа не редактируется после создания.
- Тип нельзя активировать, пока единая проверка не подтвердила его настройки, зависимости, поля, ресурсы, каталоги и расширение.
- Создание, изменение, включение, отключение и удаление типа требуют `NodeContext::$manage` или `super` через четыре утверждённых метода `NodeService`; право модерации отдельного типа этого доступа не даёт, а прямое изменение `_node_types` из контроллера запрещено.
- Физическое удаление типа проверяет отсутствие материалов, пакетно удаляет его настройки, поля и правило из стандартного `config/uploads.php`, но не удаляет файловый каталог автоматически.
- Маршрут ресурса не принимает путь, имя файла, MIME или внешний URL из запроса; единственный входной идентификатор разрешается через `_node_assets` и проверенный тип материала.
- После разрешения идентификатора маршрут получает проверенный `NodeAsset`; необработанная строка PDO и массив с произвольными ключами между ядром и модулем не передаются.
- `NodeAsset` неизменяем и содержит только сохранённый проверенный `src`; он не вычисляет путь, не обращается к сети или файловой системе и не выбирает режим отдачи самостоятельно.
- Внешний ресурс разрешает только зарегистрированные URL-схемы и перенаправляется без серверного запроса, поэтому пользовательский адрес не становится SSRF-входом.
- Локальный `src` канонизируется при сохранении и обязан находиться внутри стандартного `uploads/<type>`; маршрут ресурса не принимает файловый путь из запроса.
- Общее правило веб-сервера запрещает выполнение PHP во всём `uploads`; отдельные правила `temp` и специальное дерево Node не создаются.
- При контролируемой отдаче веб-сервер запрещает прямой доступ ко всему `uploads/<type>`, включая редакторские файлы и `thumb`; тип не активируется, если этот запрет и контролируемая отдача не подтверждены.
- Контролируемая отдача выбирается автоматически при включённых `categories` или непустом `ext`; ручного переключателя нет.
- При прямой отдаче локальные файлы физически публичны независимо от состояния отдельного материала; такой режим остаётся только у простого типа без категорий и расширения.
- Жалоба на ресурс является изменяющим `POST`-действием с CSRF, проверкой доступности ресурса и ограничением частоты; она не может отключить материал или ослабить права.
- Получение ресурса, учёт скачивания и изменение жалобы проходят только через `getNodeAsset()`, `updateNodeAssetHits()`, `updateNodeAssetReport()` и `deleteNodeAssetReport()`; каждый изменяющий метод повторно проверяет контекст и тип, не доверяя контроллеру.
- Очистить жалобу может главный администратор или модератор данного типа; общее право управления конфигурацией Node не является правом модерации его материалов. Разбор блокирует строку ресурса и повторно проверяет открытую жалобу внутри общей транзакции начисления и очистки, поэтому два модератора не создают две награды.
- Файловая функция получает только уже разрешённый канонический путь; сама она не выполняет SQL и не определяет права. Проверка доступа завершается до условного `304`, открытия диапазона и вызова `$start`.
- Переданный MIME не берётся из URL или имени, а `inline` дополнительно ограничивается закрытым безопасным реестром. Активные и неизвестные форматы скачиваются как `application/octet-stream` с `nosniff`.
- `Range` применяется только к `GET`; один удовлетворимый диапазон получает `206`, неудовлетворимый или повреждённый — `416`, а несколько корректных диапазонов игнорируются и получают полный `200`. `If-Range` с несовпадающим валидатором также даёт полный ответ.
- Частный HTTP-кеш не является решением о доступе: каждый условный запрос заново проходит тип, материал, состояние, даты, категорию и расширение, и только затем может получить `304`.
- Маршрут `attach` не использует зарезервированный глобальным маршрутизатором параметр `file`; `key` читается как raw-строка и затем проверяется целиком без повторного URL-декодирования.
- Один `FileManager::checkFileName()` не считается проверкой пути, потому что метод применяет `basename()`. До него маршрут запрещает любое отличие исходного `key` от собственного basename, а после него повторно проверяет расширение и канонический корень через `realpath()`.
- Вложение отдаётся только если его безопасное имя найдено общей грамматикой парсера в исходном `intro` или `body` уже доступного материала; поиск по всем материалам, SQL `LIKE`, доверие одному имени и доступ к произвольному файлу типа запрещены.
- Административные `add`, `edit`, `type` и `config` изменяют данные только через `POST` с CSRF; `status` и `delete` не имеют изменяющего поведения по `GET`.
- Изменение и удаление материала принимают ожидаемую `version` только из тела `POST`; `id` в URL не заменяет проверку конкурентного изменения и прав.
- После успешного административного `POST` выполняется перенаправление на канонический `GET`, исключающее повтор операции при обновлении страницы.
- Публичный `add` принимает только `POST` с `action=preview|submit`, CSRF и проверками `workflow`; предпросмотр проходит ту же валидацию, но не начинает транзакцию записи.
- Публичная отправка допускает только `Pending` или `Published`; прямую публикацию определяют `features.moderation` и эффективные группы пользователя из закрытого списка `workflow.publish`, а не присланное состояние.
- Комбинация публичного доступа гостей и отключённой модерации требует явного подтверждения в административной форме типа.
- Неизвестный публичный `op`, неподдерживаемый HTTP-метод и несовпадение типа не переходят к действию по умолчанию.

## Производительность

- Бюджет считается как разница публичных `$db->qnum` и `$db->sqltime` непосредственно до и после обработчика Node. Загрузка SLAED, тема, блоки и самостоятельные запросы глобальных подсистем в бюджет Node не входят и измеряются общим счётчиком страницы.
- Числа являются верхней границей успешного сценария; меньшее количество разрешено, превышение требует профиля и нового решения.
- Нулевая настройка баллов не выполняет SQL. Обычное ненулевое начисление использует одну блокировку пользователя, один `INSERT` журнала и один `UPDATE` агрегата внутри общей транзакции; обычное чтение сайта `_points` не присоединяет.

| Сценарий | Обычный бюджет | Верхняя граница |
|---|---:|---:|
| анонимный список из HTML-кеша | `0` | `0` |
| список без HTML-кеша | `3` | `7` |
| полный материал | `5` | `6` со связанными карточками |
| контролируемый `[attach]` | `2` | `2` |
| чтение или `HEAD` ресурса | `2` | `2` |
| начало `download` с учётом `hits` | `3` | `3` |
| жалоба на ресурс | `3` | `3` |
| административный список | `3` | `3` |
| форма изменения материала | `5` | `5` |
| смена состояния | `6` | `6` |
| физическое удаление | `2` | `2` плюс самостоятельная очистка глобальных интеграций |

- Три базовых запроса списка получают тип, страницу материалов и общее количество. Нужные стандартному представлению `uname` и `ctitle` присоединяются к запросу страницы по первичным ключам и не создают отдельных запросов. Дополнительные категории, связи, связанные карточки и ресурсы добавляют не более одного пакетного запроса каждый, поэтому максимум равен семи и не зависит от размера страницы.
- Полный материал выполняет запрос типа, основной записи, дополнительных категорий, связей и ресурсов; карточки целей связей добавляют шестой пакетный запрос.
- `getNodeContent()` выполняет только основной запрос материала после запроса типа, поэтому контролируемое вложение всегда укладывается в два. Полный `getNode()` на этом маршруте запрещён.
- `getNodeAsset()` получает ресурс, материал, тип маршрута и право основной категории одной соединённой выборкой после получения `NodeType`; третьим запросом может быть только разрешённое изменение `hits` либо совместное изменение `reported` и `ruid`.
- Списки запрещают N+1 для авторов, полей, категорий, рейтинга и избранного.
- Метаданные типов кешируются только внутри текущего `NodeQuery`, а настройки и поля берутся из уже загруженного глобального `$conf`; второго runtime-кеша Node не создаёт.
- Штатный HTML-кеш SLAED обслуживает только анонимные списки Node с пустым `op`, сортировкой типа по умолчанию и параметрами `name`, `cat`, `num`; просмотр материала, буквенный фильтр, нестандартная сортировка, формы, ресурсы и изменяющие маршруты всегда выполняются живым запросом.
- После успешного содержательного изменения материала или типа обеспечивается вызов существующего `Cache::addEpoch()`, уже ограниченный одним выполнением за запрос. Публичную запись инвалидирует сервис, административную может раньше инвалидировать штатный слой базы; откат после изменяющего административного SQL допускает лишнюю инвалидацию, но не доступность устаревшего HTML.
- Просмотр и служебные изменения `views`, `hits`, `reported` или `ruid` поколение не меняют.
- Материалы, списки и результаты SQL не сериализуются в отдельный файловый кеш; Redis, таблица кеша и собственный сборщик мусора Node не создаются до подтверждённой необходимости.
- Списки не выбирают и не декодируют `_nodes.field`, если режим представления не использует дополнительные поля.
- Списки оставляют `body`, `fields`, `cids`, `rels` и `assets` равными `null`, пока представление не запросило их; требуемые связанные наборы загружаются одной партией для страницы, а `Node` не выполняет ленивых запросов.
- Индексы проектируются под подтверждённые фильтры и сортировки.
- Массовая синхронизация с комментариями, рейтингом, избранным и другими глобальными подсистемами передаёт не более `limits.syncbatch = 500` уникальных положительных ID за вызов. Больший набор делится до границы интеграции.
- Сетевая очередь `_node_sync` не использует `limits.syncbatch`: одно задание планировщика принимает `limit` от `1` до `50`, по умолчанию `10`, и обрабатывает строки последовательно. Индекс `(due, id)` сохраняет стоимость выбора независимо от общего числа источников.
- Глобальная блокировка существующего планировщика исключает параллельный запуск одной очереди. Одиночная ручная проверка всё равно повторно сверяет URL и `_nodes.version`, поэтому не требует отдельного `locked`, `status` или таблицы заданий.
- Долгий обход Node использует индексируемый курсор `id > <последний ID> ORDER BY id ASC LIMIT 500`; `OFFSET`, один SQL на материал и накопление полного набора в памяти запрещены.
- Публичная страница содержит от `1` до типового `list.limit` записей, а значение типа не превышает системный `limits.maxlist = 100`. Буквенный фильтр использует составной индекс `title`, проверенную единственную букву или цифру и параметризованный префикс `LIKE`.
- Поиск, RSS и доставка почты сохраняют собственные пределы `search.slimit`, `rss.max` и `mail.batch`; `syncbatch` не меняет размер их публичного результата или очереди.
- Уведомление поддержки получает адрес только из сохранённой учётной записи администратора или владельца после проверки их роли в текущем обращении. Адрес, получатель, ссылка и текст письма из запроса не принимаются; приватное тело комментария в почтовую очередь не копируется.
- Счётчики не должны задерживать отдачу страницы без необходимости.
- Счётчик ресурса увеличивается одним атомарным `UPDATE` через `$start` только перед полным телом или диапазоном `download` с нулевого байта; прямые запросы, `HEAD`, `304`, `416` и последующие диапазоны не учитываются.
- Контролируемая отдача не выполняет повторный SQL-запрос внутри цикла чтения и не записывает файл в `storage/cache`; существующий файловый дескриптор читается ограниченными блоками.
- Установка `reported` выполняется идемпотентно, а очередь использует индекс `(reported, id)` без сканирования всех ресурсов.
- Изменение `hits`, `reported` и `ruid` не увеличивает версию материала и не меняет даты изменения материала или ресурса.
- Полнотекстовый поиск не строится последовательным обходом дополнительных полей.
- SQL не фильтрует и не сортирует JSON дополнительных полей; индексируемые значения принадлежат базовой схеме или расширению.

### Временной бюджет

На стенде с отключённым Xdebug и прогретой MariaDB проверяется не среднее, а `p95` повторных запросов:

- чтение и подготовка модели Node — не более `150 ms`;
- проверка доступа к файлу без передачи его байтов — не более `50 ms`;
- административная запись без загрузки файла — не более `300 ms`;
- среднее время одного SQL-запроса — не более `10 ms`, что совпадает с существующим порогом отладочной панели SLAED.

Количество SQL является жёсткой автоматической проверкой. Время фиксируется воспроизводимым профилем, а не нестабильным PHPUnit-тестом; превышение сначала исследуется через штатную SQL-трассировку.

## Проверяемые сценарии

- Поддельный тип, поле, расширение и маршрут.
- Попытка повысить файловые лимиты выше глобальных.
- Частичная ошибка расширения внутри записи.
- Массовое удаление с комментариями и избранным.
- Список с максимальным набором полей и связей.
- Одновременная публикация и редактирование.
- Серверный запрет `temp` и выполнения PHP, прямая отдача и Range публичных файлов, полный запрет дерева в контролируемом режиме, контролируемые `GET`, `HEAD` и `Range`, локальный и внешний редирект, а также отказ недоступному ресурсу.
- Публикация до `published`, видимость внутри интервала и недоступность после `expires` без фонового изменения состояния.
- Наследование состояния материала, права основной категории и ограничений расширения без отдельной ACL роли ресурса, повторная жалоба, очистка жалобы и ограничение частоты.

## Критерии готовности

- Зафиксирована модель угроз.
- Утверждены бюджеты запросов ключевых маршрутов.
- Все составные записи имеют тест отката.
- Проверки прав невозможно обойти прямым вызовом публичного сервиса.
- Логи не содержат секретов и необработанных загружаемых данных.
