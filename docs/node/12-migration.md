# Перенос данных из заменяемых модулей

Статус: каркас.

## Цель

Импортировать полезные данные по одному типу, не перенося в `node` ограничения, ID, URL, таблицы и runtime-контракты старых модулей.

## Общий процесс одного типа

1. Зафиксировать полезные исходные данные и их количество.
2. Описать преобразование полей и состояний в новый контракт.
3. Выполнить разовый импорт с выдачей новых глобальных ID.
4. Перепривязать нужные глобальные данные к новым ID внутри импортёра.
5. Проверить количество, контрольные записи и файлы.
6. Включить новый канонический маршрут типа.
7. Проверить чтение и запись через реальный HTTP.
8. После приёмки отключить старый модуль без возврата к нему из рабочего кода.
9. Удаление старого кода и таблиц выполнять отдельной утверждённой операцией с резервной копией.

## Матрица миграции

Для `pages`, `faq`, `news`, `jokes`, `content`, `help`, `links`, `files` и `media` необходимо отдельно описать:

- поля;
- статусы;
- категории;
- комментарии;
- рейтинг;
- избранное;
- авторов и баллы;
- данные, из которых строятся новые URL;
- файлы;
- настройки;
- расширение;
- проверку и откат.

При этом `help` переносится как приватная поддержка, а не как документация. Для `content` отдельно переносится адрес источника и период обновления; получение внешнего содержимого принадлежит расширению синхронизации.

## Требования к импортёру

- Импорт работает вне рабочего кода новой системы.
- Временная карта исходных и новых ID принадлежит только импортёру и его отчёту.
- Ни одна временная колонка или таблица соответствия не добавляется в рабочую схему `node`.
- Ошибка не включает новый маршрут.
- Отчёт содержит количество прочитанных, созданных, обновлённых и отклонённых строк.
- Изменение глобальных связей выполняется только после успешного импорта материалов.

## Критерии готовности

- Для первого типа существует сухой прогон и полный отчёт.
- Сверены количества и выборочные контрольные суммы текста.
- Новые адреса открывают материалы по глобальным ID.
- Комментарии, категории и избранное указывают на правильные ID.
- В рабочем коде отсутствуют обращения к старым таблицам и возврат к старому модулю.
