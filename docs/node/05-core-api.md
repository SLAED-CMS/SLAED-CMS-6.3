# Публичный API ядра Node

Статус: проектирование завершено; реализация и её проверки выполняются по 13-testing.md и 14-roadmap.md.

## Цель

Определить минимальный стабильный API, через который модуль `node` и другие подсистемы SLAED читают и изменяют материалы.

## Утверждённые базовые имена

- `Node`
- `NodeType`
- `NodeTypeInput`
- `NodeInput`
- `NodeRelation`
- `NodeAsset`
- `NodeContext`
- `NodeService`
- `NodeQuery`
- `NodeView`
- `NodeExtension`
- `enum NodeStatus`
- `NodeException`

`NodeStatus` использует case-имена `Draft = 0`, `Pending = 1`, `Published = 2`, `Disabled = 3` и `Deleted = 4`. Значения базы не сравниваются с числовыми литералами в прикладном PHP-коде.

Матрица переходов из 03-database.md является закрытой константой перечисления, а единственная проверка — `public function checkStatusMove(self $to): bool` (решение пользователя 2026-09-23, S08). Повтор текущего состояния не является переходом и даёт `false`: `updateNodeStatus()` обрабатывает его до вызова проверки как успешную операцию без записи.

`NodeException` использует внутренние числовые коды `NOTFOUND = 1`, `DENIED = 2`, `INVALID = 3`, `CONFLICT = 4` и `STORAGE = 5`. Текст исключения предназначен для журнала, не является пользовательским сообщением и не участвует в определении причины.

## Принципы API

- Чтение не раскрывает структуру SQL и таблиц.
- Запись всегда проходит права, валидацию, транзакции и очистку кеша.
- Публичный API не содержит условий по имени типа.
- Входные данные представлены типизированными объектами, а не необязательным массивом произвольной формы.
- `NodeInput` допускает только поля пользовательского ввода; ID, счётчики, даты аудита и вычисляемые значения назначает сервис.
- `NodeTypeInput` допускает только изменяемые `title`, `intro`, `ext`, `sort`, `settings`, `fields`, `uploads` и `rating`; идентичность, активность, версия и даты типа через массовое назначение недоступны.
- `NodeTypeInput` является неизменяемым объектом данных с публичными readonly-свойствами; вызывающий код читает их напрямую, поэтому геттеры и сеттеры отсутствуют.
- `NodeContext` создаётся общей сборкой `getNodeContext()` из core/system.php один раз на запрос и передаётся явно; ядро не читает глобальные `$user`, `$locale` и адрес клиента.
- `NodeQuery` и `NodeService` читают настройки непосредственно из уже загруженного `$conf['node']` и `$conf['fields']['node']`; файловая интеграция читает штатное правило `$conf['uploads'][<type>]`. Они не получают копию конфигурации в конструкторе и не изменяют глобальный массив.
- Ошибки имеют различимые причины и не зависят от текста локализации.
- Отдельный репозиторий первой версии не создаётся: чтение принадлежит `NodeQuery`, запись и транзакции — `NodeService`.

Зарегистрированные типы Node не копируются в реестры комментариев, рейтинга, избранного, поиска и других глобальных подсистем. Их единственным источником остаются `_node_types` и `config/node.php`, а разрешение типа и материала выполняется через общий контракт `NodeQuery`. Глобальная подсистема передаёт публичное имя типа и глобальный ID; отдельные списки таблиц Node, `Registry`, `Provider` и таблица регистраций не создаются.

## Общий API дополнительных полей

`final class Field` из `core/classes/field.php` обслуживает Node и остальные области через шесть методов:

```php
public function getFieldTypeList(): array
public function filterFieldList(array $fields): array
public function checkFieldValues(array $fields, array $values, bool $required = true): array
public function filterFieldValues(array $fields, array $values): array
public function getFieldForm(Template $tpl, array $fields, array $values = [], array $errors = []): array
public function getFieldView(Parser $prs, array $fields, array $values, string $module): array
```

- `Field` не объявляет собственного конструктора и не имеет состояния, не читает `$conf`, не работает с базой и не записывает конфигурацию.
- `getFieldTypeList()` возвращает закрытый реестр типов, а `filterFieldList()` проверяет определения и приводит их к каноническому порядку и типам.
- `checkFieldValues()` проверяет переданные значения и возвращает массив `имя поля => код ошибки`; пустой массив означает успех. Тип, формат и пределы проверяются всегда, а `$required = false` отключает только требование заполнения незавершённого черновика.
- После успешной проверки `filterFieldValues()` удаляет неизвестные ключи и возвращает канонические типизированные значения для сохранения. Неверное значение не исправляется молча.
- `getFieldForm()` получает `Template` только на время построения стандартных строк формы и не читает POST самостоятельно. Значения и ошибки всегда передаёт контроллер.
- `getFieldView()` получает `Parser` и имя модуля только на время подготовки безопасного публичного представления; шаблоны сохраняют владение HTML.
- CRUD определений и запись файла конфигурации остаются вне этого класса. Их сохранение выполняет существующая `setConfigFile()`.
- `core/system.php` создаёт один глобальный экземпляр `$fld = new Field()`. `NodeQuery` и `NodeService` получают его явно, поэтому не создают второй механизм полей.

`getFieldView()` возвращает упорядоченный ассоциативный массив, индексированный устойчивым именем поля:

```php
[
    'source' => [
        'name' => 'source',
        'type' => 'url',
        'label_text' => 'Источник',
        'hint_text' => 'Официальная страница',
        'value' => 'https://example.com',
        'value_text' => 'https://example.com',
        'value_html' => '',
        'value_href' => 'https://example.com',
        'items' => [],
    ],
]
```

- Ключ позволяет специальному шаблону обратиться к `fields.source`, а повторённый `name` остаётся доступен при переборе, потому что шаблонизатор не передаёт ключ текущего элемента.
- Возвращаются только активные поля с присутствующим значением; `false` и `0` не считаются пустыми. Порядок совпадает с каноническим порядком определений: `sort`, затем имя.
- `value` содержит каноническое скалярное значение или массив, `value_text` — готовое отображаемое текстовое значение, а `value_html` — только безопасный результат `Parser` для `textarea`.
- `value_href` заполняется только для проверенного `url` или `email`. Остальные типы получают пустую строку и не могут превратить произвольное значение в ссылку.
- `items` содержит выбранные варианты `select` в виде `['value' => 'pdf', 'label_text' => 'PDF']`; для остальных типов это пустой массив. Одиночный `select` также получает один элемент, поэтому специальному шаблону не нужна отдельная ветка данных.
- Сохранённые имена без определения и отсутствующие варианты не выводятся. Явно отключённое поле не выводится, а сохранённый отключённый вариант существующего активного поля сохраняет подпись и показывается.

`filterFieldList()` атомарен: полностью возвращает канонический набор либо бросает стандартный `InvalidArgumentException`. Техническое сообщение указывает путь первой ошибки, например `price.options.scale`, предназначено для журнала и не является пользовательским текстом. Частично исправленный, урезанный или молча дополненный набор не возвращается.

`NodeService` преобразует такое исключение в `NodeException::INVALID`, сохраняя исходное как `previous`. `NodeQuery` журналирует ошибку уже сохранённой конфигурации и считает соответствующий тип невалидным. Отдельные `FieldException`, `FieldError` и подклассы не создаются; другие потребители при необходимости ловят стандартный `InvalidArgumentException`.

## Реестр и значения Field

`getFieldTypeList()` возвращает единый реестр формы:

```php
'text' => [
    'title' => '_FIELDINPUT',
    'control' => 'text',
    'multi' => false,
    'options' => ['min', 'max'],
],
```

В каждой записи присутствуют только `title`, `control`, `multi` и `options`. `title` хранит имя общей языковой константы, `control` — закрытый семантический ключ стандартного элемента формы, `multi` — возможность включить множественное значение в определении поля, `options` — закрытый список допустимых параметров. Классы, callback, SQL, пути шаблонов и CSS в реестр не входят.

| Тип | `control` | `multi` | Допустимые `options` |
|---|---|---:|---|
| `text` | `text` | нет | `min`, `max` |
| `textarea` | `textarea` | нет | `min`, `max` |
| `select` | `select` | да | `items`, `min`, `max` |
| `bool` | `checkbox` | нет | нет |
| `int` | `number` | нет | `min`, `max` |
| `decimal` | `number` | нет | `min`, `max`, `scale` |
| `date` | `date` | нет | `min`, `max` |
| `datetime` | `datetime` | нет | `min`, `max` |
| `email` | `email` | нет | `min`, `max` |
| `url` | `url` | нет | `min`, `max` |

Только `select` поддерживает `multi = true` в первой версии. Новый технический тип поля добавляется кодом в `Field` вместе с тестами; административная форма создаёт определения зарегистрированных типов, но не исполняемый тип поведения.

Имена типов в реестре используют существующие `_FIELDINPUT`, `_FIELDAREA`, `_FIELDSELECT`, `_FIELDDATE`, `_FIELDTIME`, `_EMAIL`, `_URL` и новые `_FIELDS_BOOL`, `_FIELDS_INT`, `_FIELDS_DECIMAL`. Новые константы принадлежат общей административной системе полей и добавляются одновременно во все шесть административных языков. Реестр хранит их имена строками; публичный запрос не загружает административный язык ради работы с полями.

`select.options.items` хранит варианты по устойчивым техническим ключам:

```php
'items' => [
    'open' => [
        'title' => '_OPEN',
        'active' => true,
        'sort' => 10,
    ],
    'closed' => [
        'title' => '_CLOSED',
        'active' => true,
        'sort' => 20,
    ],
],
```

Запись варианта содержит только `title`, `active`, `sort`. Технический ключ является сохраняемым значением и после использования не переименовывается без отдельного изменения данных; `title` можно менять. `active = false` исключает вариант из нового выбора, но сохраняет его подпись при выводе прежнего значения. Варианты сортируются по `sort`, затем по ключу; отдельный ID и таблица не создаются.

Имя дополнительного поля и ключ варианта `select` проверяются одинаково: `^[a-z][a-z0-9_]{0,31}$`. Длина составляет 1–32 символа, первый символ является строчной латинской буквой, остальные также могут быть цифрами или `_`. Значения вроде `2status`, `Release`, `статус` и `some-value` отклоняются.

`title` поля обязателен и ограничен 255 Unicode-символами, `intro` необязателен и ограничен 1000. Оба значения содержат простой текст без HTML либо имя существующей языковой константы. Начальный `_` однозначно обозначает константу: неизвестное имя является ошибкой определения и не показывается как буквальный текст. Пустой `intro` нормализуется в `''`; `select.items.*.title` следует тем же правилам `title`.

`min` и `max` являются включительными и зависят от типа: для `text`, `textarea`, `email`, `url` это количество Unicode-символов; для `int` — целые значения; для `decimal` — точные десятичные строки; для `date`, `datetime` — значения в каноническом формате; для множественного `select` — количество выбранных вариантов. Одиночный `select` запрещает `min`, `max`, а `bool` запрещает любые параметры.

`decimal.options.scale` обязателен и принимает целое значение от `1` до `18`. Значение сохраняется с фиксированным числом знаков: `1.2` при `scale = 2` становится `'1.20'`. `min`, `max` нормализуются с той же точностью и сравниваются без преобразования во `float`; `scale = 0` не поддерживается, потому что его назначение закрывает `int`.

Одно значение `decimal` содержит не более 65 цифр всего, включая целую и дробную части. Знак и десятичная точка не считаются. Этот защитный предел совпадает с максимальной точностью `DECIMAL` MariaDB/MySQL, находится внутри `Field` и не увеличивается конфигурацией поля.

`Field` применяет неизменяемые верхние пределы:

| Объект | Предел |
|---|---:|
| определения одного набора | 256 |
| варианты одного `select` | 256 |
| значения множественного `select` | 64 |
| `text` | 4096 Unicode-символов |
| `textarea` | 262144 Unicode-символа |
| `email` | 254 Unicode-символа |
| `url` | 2048 Unicode-символов |
| канонический JSON значений | 1048576 байт |

Параметр `max` может только уменьшить предел типа. Размер JSON проверяется после нормализации и до SQL; запас относительно `MEDIUMTEXT` не используется как разрешение принять чрезмерный запрос. Отдельная конфигурация защитных пределов не создаётся.

`default` применяется только при создании активного поля и только когда вызывающий код не передал значение; изменение существующей сущности и обычное чтение его не используют. Для множественного `select` это массив уникальных активных ключей. Отключённый вариант не может быть значением по умолчанию.

`active = false` исключает поле из формы и публичного вывода, но не уничтожает сохранённое значение. Сочетание `active = false`, `req = true` отклоняется как противоречивое. Обязательность включается для целевого состояния `Pending` или `Published`; `Draft` и `Disabled` допускают незаполненное поле. Пустая строка и пустой массив означают отсутствие, тогда как `false`, `0` и `'0.00'` являются значениями.

При изменении `NodeService` объединяет полный набор активных значений формы с прежними неактивными значениями из сохранённого JSON. Отсутствующее необязательное активное поле удаляется, неизвестное имя формы игнорируется, а сохранённое имя без актуального определения очищается при этой записи. `updateNodeStatus()` не переписывает JSON и проверяет готовность по уже сохранённым значениям.

Канонизация значений:

| Тип | Результат |
|---|---|
| `text` | края удалены, переносы строк запрещены |
| `textarea` | `CRLF` и `CR` заменены на `LF`, остальные пробелы и отступы сохранены |
| `select` | разрешённые ключи; `multi` без повторов и в порядке определения |
| `bool` | нативный `bool` только из `true`, `false`, `1`, `0`, `'1'`, `'0'` |
| `int` | знаковый 64-битный `int` без `+` и лишних ведущих нулей |
| `decimal` | строка с точкой и фиксированным `scale`, без экспоненты и запятой |
| `date` | реальная дата `YYYY-MM-DD` |
| `datetime` | `YYYY-MM-DD HH:MM:SS` из строгого `YYYY-MM-DDTHH:MM[:SS]` |
| `email` | проверенный адрес с сохранённым регистром локальной части и нижним регистром домена |
| `url` | абсолютный `http`/`https` либо путь от корня `/...` |

URL с `//host/path`, учётными данными или схемой `javascript`, `data`, `file` отклоняется; регистр пути и запроса сохраняется, адрес без схемы не дополняется автоматически. `Field` не использует существующий `filterWebUrl()`, который приводит весь адрес к нижнему регистру. `checkFieldValues()` и `filterFieldValues()` вызывают одну внутреннюю нормализацию, чтобы проверка и результат не расходились.

`checkFieldValues()` использует закрытые машинные коды:

| Код | Причина |
|---|---|
| `required` | обязательное значение отсутствует |
| `type` | значение имеет неверную структуру |
| `format` | неверен формат числа, даты, времени, адреса почты или URL |
| `choice` | значение отсутствует в разрешённом списке |
| `min` | нарушен нижний предел длины, значения или количества элементов |
| `max` | нарушен верхний предел длины, значения или количества элементов |

На одно поле возвращается только первая ошибка в устойчивом порядке проверок. Неизвестные входные имена не образуют ошибку: они не попадают в результат `filterFieldValues()`. Коды не содержат локализованный текст или HTML; `getFieldForm()` сопоставляет их общим языковым сообщениям при подготовке формы.

## Заметки реализации S06

- Отсутствие `default` записывается пустой строкой у строковых типов (`text`, `textarea`, одиночный `select`, `decimal`, `date`, `datetime`, `email`, `url`), пустым массивом у множественного `select` и `null` у `bool` и `int`, у которых любое нативное значение является настоящим значением.
- `datetime` принимает строгую HTML-форму `YYYY-MM-DDTHH:MM[:SS]` и собственную каноническую `YYYY-MM-DD HH:MM:SS`; форма показывает сохранённое значение с `T`.
- `getFieldView()` вызывает `Parser::filterContent()` в безопасном режиме: значение `textarea` — необработанный пользовательский текст. Границы `min` и `max` при выводе не применяются, жёсткие пределы типа остаются.
- `getFieldForm()` возвращает строки по имени поля с ключами `name`, `type`, `label_for`, `label_text`, `hint_id`, `hint_text`, `error_text`, `is_required`, `field_html`; имя элемента — `field[<имя>]`, у множественного `select` — с `[]`. Перед флажком `bool` стоит скрытый `0`, поэтому снятый флажок сохраняется как `false`.
- Превышение 1 МиБ канонического JSON `checkFieldValues()` сообщает кодом `max` у поля с самым длинным значением; `filterFieldValues()` при неверном значении бросает `InvalidArgumentException`.
- Сообщения шести кодов — `_FIELDS_REQ`, `_FIELDS_TYPE`, `_FIELDS_FORMAT`, `_FIELDS_CHOICE`, `_FIELDS_MIN`, `_FIELDS_MAX` в шести lang; подписи типов и экрана — `_FIELDS_*` в шести admin/lang.
- Экран admin/modules/fields.php: области задаёт `getFieldAreas()`; имя и тип сохранённого поля и ключи его вариантов не меняются; отклонённый набор возвращается в форму с путём первой ошибки и отправленным текстом.

## Общий API RSS и Atom

`final class Feed` из `core/classes/feed.php` заменяет старую реализацию `rss_read()` и предоставляет один публичный метод:

```php
public function __construct(array $conf, ?Closure $send = null)
public function getFeedContent(string $url, string $etag = '', string $modified = ''): array
```

Конструктор принимает уже загруженную `$conf['rss']` и необязательный доверенный транспорт по NOD-208. `null` выбирает штатную реализацию; PHP-callback не читается из конфигурации или запроса. Метод возвращает точные ключи:

```php
[
    'ok' => true,
    'changed' => true,
    'code' => 200,
    'body' => '...',
    'etag' => '...',
    'modified' => '...',
    'error' => '',
]
```

- `ok` означает завершённую допустимую HTTP- и XML-операцию, `changed` — наличие нового тела; ответ `304` даёт `ok = true`, `changed = false` и пустой `body`.
- `body` содержит канонический Markdown по NOD-207, ограниченный `rss.max`; `rss.temp` не используется. Переключение темы не меняет сохранённый документ.
- `etag` и `modified` возвращают только проверенные значения ответных заголовков. `code` содержит окончательный HTTP-код, а `error` — безопасное короткое сообщение без тела ответа и секретных частей URL.
- Класс не выполняет SQL, не знает Node, не выводит HTML и не пишет кеш. Старый `rss_read()` удаляется после одновременного перевода остающихся RSS-потребителей; обёртка совместимости не создаётся.
- Пределы транспорта читаются из стандартного `config/rss.php`: `bytes = 2097152`, `timeout = 10`, `redirects = 3`. Они являются целыми десятичными строками и проверяются до сетевого запроса. Сейчас этих трёх ключей в config/rss.php нет: S07 добавляет их и удаляет ключ temp вместе с его полем шаблона в modules/rss/admin/index.php.

### Формат документа и транспорта Feed

Успешный изменившийся ответ сериализуется в UTF-8 с LF и одним завершающим переводом строки. Для каждой записи, в порядке ленты до `rss.max`, выводятся заголовок второго уровня, необязательная нормализованная дата UTC, проверенная HTTP/HTTPS-ссылка и текстовое описание, разделённые пустыми строками. Пустая корректная лента даёт пустое тело, а повреждённый XML не считается пустой лентой. Случайная дата, тема, классы CSS и шаблон `rss.temp` в результат не добавляются.

Данные XML не считаются разметкой SLAED. HTML описания преобразуется в обычный текст с границами абзацев; script/style и исполняемое содержимое отбрасываются. Литеральные Markdown/BB-метасимволы экранируются; `[attach]`, `[hide]`, `[url]`, HTML и специальные маркеры Parser из источника не должны становиться командами. Точный формат: Feed предваряет обратной косой чертой каждый ASCII-знак пунктуации полученного текста, включая саму обратную косую черту; CR/CRLF становятся LF, управляющие символы кроме LF/TAB удаляются. Parser до BB/свободных блоков защищает пары backslash + ASCII punctuation как литеральные токены и раскрывает после разбора с HTML-экранированием. Правило применяется слева направо, пара backslash даёт одну литеральную косую черту. getAttachList следует тому же правилу и не распознаёт экранированную открывающую скобку. Служебные заголовки и ссылки Feed добавляются после экранирования текста; в URL символы закрытия Markdown-ссылки кодируются процентно. Изменение общего Parser входит в этап Feed с регрессиями существующих форматов. Нельзя считать `safe=true` достаточным запретом BB-команд. Все потребители отображают результат через штатный Parser в безопасном режиме. Собственные инструкции и исходный HTML ленты не исполняются.

Тестовый транспорт имеет контракт `Closure(string $op, array $request): array` с двумя закрытыми операциями `resolve` и `get`. Первая принимает host и возвращает только `addresses:string[]`; Feed проверяет все адреса и выбирает допустимый IP. Для литерального IP операция resolve не требуется. Вторая выполняет ровно один HTTP-запрос. В запросе строго заданы `url`, `headers`, `timeout`, `bytes` и проверенный `ip`; метод всегда GET, автоматические редиректы выключены. Ответ содержит ровно `code:int`, `headers:array<string,string[]>`, `body:string`; транспортная ошибка бросает `RuntimeException`, которую Feed преобразует в свой отказ. HTTP-операция транспорта выполняет один переход, не весь цикл редиректов; неизвестная операция отклоняется.

Feed валидирует URL до обращения, разрешает только HTTP/HTTPS без пользовательских реквизитов, проверяет публичность адреса и привязывает соединение к проверенному IP. Каждый redirect проходит те же проверки; Cookie/Authorization не пересылаются. Проверка размера действует при чтении потока и после тестового ответа, таймаут — на всю операцию, число переходов — не более `rss.redirects`. TLS-проверка остаётся включённой; внешние XML-сущности и DTD запрещены. Валидаторы запроса относятся только к своему URL. Тесты подменяют обе операции одного транспорта; DNS и HTTP полностью воспроизводятся без внешней сети, включая private-IP redirect и попытку DNS rebinding.

При ошибке любого обязательного шага `ok=false`, `changed=false`, `body=''`, ошибка содержит безопасный код/текст. NodeSync сохраняет прежние body/валидаторы/время успешного обновления; факт ошибки журналируется отдельно. Слишком большой итоговый документ отклоняется до записи согласно пределу NodeInput.

### Заметки реализации S07

Решения пользователя 2026-09-23:

- Политика адресов одна: Feed вызывает `Upload::checkPublicAddress()`, ставший публичным статическим; списки сетей и их сверка с реестром IANA остаются только в Upload.
- Остающиеся потребители работают через три помощника core/system.php: `getRssBlock()` (прежний `rss_load()`), `getRssBody()` — Markdown для `_blocks`.`content` (показ блока, добавление и правка в admin/modules/blocks.php) и `getRssView()` — страница ленты account и модуля rss.
- `_blocks`.`content` остаётся `TEXT`: документ длиннее 65535 байт считается неудачной загрузкой, блок сохраняет прежнее тело и сдвигает время обновления.
- Подпись ссылки записи — имя хоста её адреса.

Реализация:

- Коды `error`: `config` (предел вне формы — до любого запроса), `support` (нет DOM), `url`, `address`, `transport`, `timeout`, `bytes`, `redirect`, `status`, `type`, `xml`. Текст ответа, адрес и сообщение транспорта в ошибку не попадают.
- Адрес запроса: только порт по умолчанию схемы, хост по грамматике DNS из двух и более меток (Unicode через intl) или литерал IP; фрагмент не отправляется. При ответе из нескольких адресов выбирается наименьший IPv4, иначе наименьший IPv6; один непубличный адрес в ответе отклоняет хост. Штатный `get` сверяет `CURLINFO_PRIMARY_IP` с закреплённым адресом, прокси из окружения отключён, сжатие раскрывается до проверки размера.
- Валидаторы: `If-None-Match` и `If-Modified-Since` уходят только первым переходом и только проверенной формы (RFC 9110 ETag, IMF-fixdate); `304` без отправленного валидатора или после перенаправления — `status`. На `304` без заголовка возвращается отправленный валидатор; после перенаправления `etag` и `modified` пусты.
- Документ: `<!DOCTYPE` и `<!ENTITY` отклоняются до разбора, XML читает `DOMDocument` с `LIBXML_NONET`, HTML описаний — `Dom\HTMLDocument` (HTML5) с отбрасыванием script, style, iframe, object, svg, form-элементов и прочего исполняемого содержимого; блочный элемент и `br` завершают абзац. Даты — RFC 822 и RFC 3339 с `!`, неразобранная дата опускается. Запись без заголовка получает заголовком хост ссылки, запись без заголовка и ссылки пропускается. Ссылка записи кодирует процентами `(`, `)`, `[`, `]`, `*`, `` ` ``, `\` и всё вне безопасного набора; IPv6-литерал в ссылке записи не выводится.
- Parser: правило литерала действует во всех режимах и форматах, кроме сырых областей, где обратная косая черта остаётся как есть: код Markdown (строка, блок, отступ), пары `[code]`, `[php]`, `[usephp]`, `[usehtml]`, HTML-тег и элемент script/style. Так доверенные блоки с JavaScript и атрибутами не меняются. Литерал хранится отдельным видом токена (`L` в ключе), поэтому строка из одного литерала остаётся абзацем. `getAttachList()` применяет то же правило той же регуляркой и читает все три формы тега одним выражением. Где правило действует, решает слой кода, который вывод проходит до литералов, поэтому метод прочитывает текст так, как его читает каждый вывод — plain, Markdown в доверенном и в безопасном режиме, — и объединяет имена: тег внутри кода перечисляется (надмножество выводимого), экранированный — нет. Если движок PCRE не справился с сырыми областями, вывод превращает в литералы все пары, а список читает текст без литералов — сбой скрывает разметку и расширяет список, но не наоборот.
- Проверка документа: байтовый поиск `<!DOCTYPE` не видит документ в UTF-16, поэтому документ с разобранным doctype тоже отклоняется кодом `xml`. Страница ленты account и модуля rss рендерится через `filterDoc()` без записи в кеш парсера — адрес выбирает посетитель; блок, чей адрес задаёт администратор, кешируется через `filterContent()`.


## Контекст запроса

```php
final readonly class NodeContext
{
    public function __construct(
        public int $uid,
        public array $groups,
        public int $aid,
        public array $mods,
        public bool $manage,
        public bool $super,
        public string $ip,
        public string $lang,
        public bool $task = false
    ) {}
}
```

- `uid` является ID пользователя сайта или `0` для гостя; `groups` содержит уникальные целые ID всех эффективных групп пользователя.
- `aid` является отдельным ID администратора или `0`; идентификатор пользователя никогда не подменяет идентификатор администратора.
- `mods` содержит уникальные публичные имена типов, которые текущий администратор может модерировать; префикс хранения `node-` внутрь ядра не передаётся.
- `manage` разрешает управление Node, типами и настройками, а `super` обозначает главного администратора и подразумевает `manage` и модерацию любого типа.
- `manage`, непустой `mods` или `super` требуют положительный `aid`; обычный публичный контекст получает `aid = 0`, `mods = []`, `manage = false`, `super = false`.
- Модерация материала разрешается только главному администратору или имени типа в `mods`; `workflow` не создаёт пользовательских модераторов. Права чтения категории всё равно проверяются по `uid` и `groups`.
- На границе запроса существующее право администратора `node` преобразуется в `manage`, а ключи `_admins.modules` вида `node-<name>` — в `mods`. Новая таблица ACL и роль-модель не создаются.
- Объект не читает сессию, cookie, глобальные переменные или базу и не получает фабрику, геттеры и сеттеры; общая сборка `getNodeContext()` из core/system.php создаёт один проверенный снимок на запрос, а SQL эффективных групп пользователя выполняется в ней же, вне бюджета Node.
- Конструктор ничего не преобразует, но отклоняет противоречивый снимок `NodeException::INVALID` (S08): отрицательные `uid`/`aid`; `groups` не список уникальных положительных `int`; `mods` не список уникальных имён `^[a-z][a-z0-9]{0,19}$` (префикс `node-` внутрь не передаётся); `manage`, `super` или непустой `mods` при `aid = 0`; `task = true` вместе с любым из `uid`, `aid`, `groups`, `mods`, `manage`, `super`. Нормализацию (уникальность, порядок) выполняет `getNodeContext()` до создания объекта.

## Ошибки

`NodeException` наследует `RuntimeException` и является единственным исключением публичного API Node. Отдельные подклассы и `NodeError` не создаются.

| Код | Причина | Типичный ответ модуля |
|---|---|---:|
| `NOTFOUND = 1` | изменяемый материал или связанная сущность не существует | `404` |
| `DENIED = 2` | контекст не разрешает действие | `403` |
| `INVALID = 3` | входные данные, состояние или переход недопустимы | `422` |
| `CONFLICT = 4` | ожидаемая `version` устарела | `409` |
| `STORAGE = 5` | операция хранения не завершилась | `500` |

- Причина читается стандартным `getCode()`; дополнительный метод и второй объект ошибки не создаются.
- Числовые значения кодов являются внутренним стабильным контрактом `NodeException`, а HTTP-коды назначает модуль.
- Модуль выбирает локализованный пользовательский текст по коду и не выводит текст исключения, SQL или внутреннюю причину сбоя.
- Исходное исключение хранения передаётся как `previous` для журнала.
- `NodeQuery::getNode()` по-прежнему возвращает одинаковый `null` для отсутствующей и недоступной записи; `NOTFOUND` и `DENIED` применяются к операциям, где вызывающая сторона должна различить причину.
- При `CONFLICT` сервис не изменяет данные и не занимается интерфейсом разрешения конфликта. Контроллер повторно читает доступный актуальный `Node` или `NodeType` и сравнивает его с уже нормализованным объектом ввода.
- Отдельные `NodeConflict`, метод слияния и флаг обхода `version` в публичном API не создаются.

## Контракты чтения и записи

### Чтение одного материала

Точная форма результата чтения:

```php
final readonly class Node
{
    public function __construct(
        public int $id,
        public int $tid,
        public int $cid,
        public int $uid,
        public string $aname,
        public ?string $ip,
        public string $title,
        public string $intro,
        public ?string $body,
        public ?array $fields,
        public int $poll,
        public bool $home,
        public CommentMode $comon,
        public bool $pinned,
        public int $comnum,
        public int $views,
        public int $score,
        public int $ratings,
        public NodeStatus $status,
        public int $version,
        public string $created,
        public string $updated,
        public ?string $pubdate,
        public ?string $expires,
        public ?array $cids,
        public ?array $rels,
        public ?array $assets,
        public ?string $uname,
        public ?string $ctitle
    ) {}
}
```

- `pubdate` соответствует `_nodes.published`; остальные скалярные свойства сохраняют утверждённые имена колонок.
- `status` преобразуется в `NodeStatus`, `comon` — в существующий `CommentMode`, `field` декодируется в `fields`, а строки JSON наружу не возвращаются.
- `body`, `fields`, `cids`, `rels` и `assets` равны `null`, только если набор не загружен текущей проекцией; пустая строка или `[]` означают загруженное пустое значение.
- `uname` содержит актуальное `_users.name` зарегистрированного автора, а `ctitle` — исходное название основной категории. Они загружаются нужными представлению `LEFT JOIN` того же основного запроса либо равны `null`; `aname` остаётся сохранённым именем только анонимного автора.
- Загруженный `cids` содержит только `int[]`, `rels` — только `NodeRelation[]`, а `assets` — только `NodeAsset[]`; массивы строк PDO наружу не передаются.
- `ip` равен `null`, если `NodeContext` не разрешает его видеть; уполномоченный административный запрос получает сохранённое значение, включая допустимую пустую строку.
- `getNode()` загружает полный материал: `body` является строкой, а `fields`, `cids`, `rels` и `assets` — массивами.
- Список выбирает тяжёлые значения только по требованиям представления типа и догружает необходимые наборы для всей страницы пакетно без N+1.
- Объект не выполняет ленивую загрузку, не изменяется после создания и не получает геттеры, сеттеры, фабрику или отдельный `NodeItem`. `NodeRelation` и `NodeAsset` являются объектами данных, а не новыми слоями доступа.

### Цель глобальной подсистемы

Лёгкая цель представлена отдельным объектом без текста и связанных наборов:

```php
final readonly class NodeTarget
{
    public function __construct(
        public NodeType $type,
        public int $id,
        public int $uid,
        public string $title,
        public CommentMode $comon,
        public int $comnum,
        public int $score,
        public int $ratings
    ) {}
}
```

`NodeType` является общим неизменяемым объектом для целей одного типа и позволяет вызывающей подсистеме проверить свою возможность. URL остаётся ответственностью маршрутизирующего слоя и в `NodeTarget` не хранится.

`NodeTarget.uid` является сохранённым автором материала, а не текущим читателем. Общий Rating использует его для запрета собственной оценки по NOD-182: сравнение двух положительных ID не требует дополнительного запроса или нового поля цели. Значение `0` означает отсутствие зарегистрированного автора и не доказывает владение гостя.

```php
public function getNodeTarget(string $type, int $id): ?NodeTarget
public function getNodeTargetList(array $refs): array
```

- Одиночный метод принимает ожидаемое публичное имя типа и глобальный ID.
- Пакет принимает отображение `глобальный ID => публичное имя типа`, например `[1050 => 'news', 1051 => 'docs']`, размером не более `limits.syncbatch`.
- Пакет возвращает `array<int, NodeTarget>` по глобальным ID в порядке входа; недоступные, отключённые, удалённые и не совпавшие с ожидаемым типом цели отсутствуют.
- Неположительный ID, неверное имя, неправильный тип ключа или значения и превышение предела дают `NodeException::INVALID`; пустой пакет возвращает `[]`.
- Смешанный пакет использует не более двух SQL-запросов независимо от количества типов и не загружает `body`, `fields`, `cids`, `rels` или `assets`.
- Оба метода используют один предикат типа, состояния, дат, основной категории и расширения; одиночный путь не имеет отдельной ослабленной проверки.

Точная форма связи:

```php

- Свойства точно отражают строку `_node_relations`; `created` остаётся канонической строкой базы.

- Вложенный целевой `Node` отсутствует: связанные материалы читаются отдельной явной пакетной выборкой без рекурсии и скрытого SQL.
- Объект не получает входной DTO, геттеры, сеттеры или собственный сервис.

}
```

- Свойства точно отражают строку `_node_assets`; `created`, `updated` и непустой `reported` остаются каноническими строками базы. `ruid` равен зарегистрированному автору первой открытой жалобы либо `0`.
- `mime`, `size`, `width`, `height`, `duration` и `reported` равны `null`, когда значение неизвестно или неприменимо.
- Локальный путь или внешний URL остаётся одним проверенным `src`; вычисляемые признаки локальности и способа отдачи в объекте не дублируются.
- Объект не получает геттеры, сеттеры, фабрику или собственный сервис.

```php
$query = new NodeQuery($db, $context, $fld);
$query->setNodeExtension($ext);
$node = $query->getNode($id, $type);
```

Конструктор `NodeQuery`:

```php
public function __construct(Database $db, NodeContext $context, Field $field)
```

Контракт метода:

```php
public function getNode(int $id, NodeType $type): ?Node
public function getNodeContent(int $id, NodeType $type): ?Node
public function setNodeExtension(?NodeExtension $ext): self
```

- `NodeQuery` получает `Database`, `NodeContext` и общий `Field` при создании, поэтому выполнить чтение без контекста или проверки определений полей нельзя. Зарегистрированное расширение назначается до первого чтения через `setNodeExtension()`; стандартный тип использует `null`.
- Материал ищется только по глобальному `_nodes.id`; второй публичный идентификатор первой версии не создаётся.
- Переданный `NodeType` ограничивает результат типом текущего маршрута и не позволяет открыть материал через чужое публичное имя.
- Метод применяет активность типа, состояние материала, `published`, `expires`, `pread` основной категории и ограничения расширения с учётом `NodeContext`. Право категорий вычисляется в PHP по одной предвыборке категорий типа и попадает в SQL предикатом по `cid`; алгоритм — «Права чтения» в 06-types.md.
- Для отсутствующего и недоступного материала возвращается одинаковый `null`, чтобы публичный API не раскрывал существование закрытой записи.
- SQL, массив строки базы и причина отказа наружу не возвращаются.
- Алиасы `getNodeById()`, `findNode()` и параметр отключения проверки доступа не создаются.
- `getNodeContent()` применяет тот же тип, состояние, даты, основную категорию и `NodeContext`, но выполняет только основной запрос материала с автором и категорией. Он возвращает `body` строкой, а `fields`, `cids`, `rels` и `assets` — как `null`.
- `getNodeContent()` нужен контролируемому `[attach]` и другим сценариям, которым необходим исходный текст без связанных наборов. Полный `getNode()` использует ту же внутреннюю загрузку и добавляет категории, связи и ресурсы тремя отдельными запросами.
- Свободный массив проекций, логический параметр сокращённого чтения и отдельный объект результата не создаются.

### Списки

Базовый список строится одним `NodeQuery`:

```php
$query = new NodeQuery($db, $context, $fld);
$nodes = $query
    ->setNodeType($type)
    ->setNodeExtension($ext)
    ->setNodeCategory($cid)
    ->setNodeLetter($letter)
    ->setNodePage($page, $limit)
    ->getNodeList();
$total = $query->getNodeCount();
```

Начальный контракт:

```php
public function setNodeType(NodeType $type): self
public function setNodeExtension(?NodeExtension $ext): self
public function setNodeCategory(int $cid): self
public function setNodeLetter(string $letter): self
public function setNodePage(int $page, int $limit): self
public function getNodeList(): array
public function getNodeCount(): int
```

- Все настраивающие методы возвращают текущий `NodeQuery` для цепочки вызовов.
- `setNodeType()` ограничивает выборку одним зарегистрированным типом.
- `setNodeExtension()` требует точного соответствия расширению выбранного типа; неизвестный, лишний или отсутствующий обязательный экземпляр даёт `NodeException::INVALID`.
- `setNodeCategory()` включает материалы, у которых категория является основной или дополнительной, без дублей; право основной категории материала всё равно обязательно.
- `setNodeLetter()` принимает пустую строку либо ровно одну Unicode-букву или цифру и ограничивает заголовок этим начальным символом без учёта регистра. Непустое значение разрешено только при `list.alpha = true`; шаблон SQL использует параметр и экранирует служебные символы `LIKE`.
- `setNodePage()` принимает страницу от `1` и размер, не превышающий системный и типовой предел.
- `getNodeList()` возвращает `Node[]` и пустой массив при отсутствии результатов.
- `getNodeCount()` применяет те же фильтры, но не пагинацию и сортировку.
- Произвольный массив фильтров, имя SQL-колонки и SQL-выражение API не принимает.
- Дополнительные утверждённые фильтры используют единый словарь `Node`:

```php
public function setNodeAuthor(int $uid): self
public function setNodeStatus(NodeStatus $status): self
public function setNodeOrder(string $order, string $dir = 'desc'): self
public function setNodePublished(?string $from, ?string $until): self
```

- `setNodeAuthor()` ограничивает выборку значением `_nodes.uid`.
- `setNodeStatus()` принимает только `NodeStatus` и не ослабляет доступ из `NodeContext`.
- `setNodeOrder()` принимает только ключ `published`, `updated`, `title`, `views` или `rating` и направление `asc` или `desc`.
- Переданный ключ обязан входить в разрешённый список текущего `NodeType`; неизвестный, запрещённый типом ключ или другое направление дают `NodeException::INVALID`.
- При включённой возможности `pinned` закреплённые материалы всегда идут первыми независимо от выбранного направления.
- `published`, `updated` и `title` сортируются по одноимённой колонке, затем по `id` в том же направлении.
- `views` сортируется по просмотрам, затем по `published DESC, id DESC`.
- `rating` помещает записи без оценок последними, сортирует остальные по `score / ratings`, затем по количеству `ratings`, `published DESC` и `id DESC`.
- Имена колонок, SQL и алиасы `new`, `old`, `best`, `popular` из вызывающего кода не принимаются.
- `setNodePublished()` ограничивает только `_nodes.published` каноническими строками `YYYY-MM-DD HH:MM:SS`. `from` включается, `until` исключается; одна граница может быть `null`, но не обе. Неверная дата или непустая пара `from >= until` даёт `NodeException::INVALID`.
- Неоднозначный `setNodePeriod()` и выбор имени колонки вызывающей стороной не создаются. Публичные параметры периода в первой версии отсутствуют.

### Полные выборки интеграций

NodeQuery дополняется следующими конкретными методами без свободного массива фильтров:

```php
public function setNodeTypes(array $types): self
public function setNodeSearch(string $text): self
public function setNodeHome(bool $home = true): self
public function getNodeTree(int $after = 0, int $limit = 500): array
public function getNodeSitemap(int $after = 0, int $limit = 500): array
```

setNodeTypes принимает непустой NodeType[] без повторных ID и заменяет одиночный тип; каждый обязан быть разрешён текущему контексту. Общая фабрика подготавливает нужное расширение отдельно для каждого типа. Один произвольно назначенный setNodeExtension не распространяется на смешанный набор.

setNodeSearch принимает нормализованный текст до 255 символов; пустой текст снимает фильтр. Буквальная подстрока ищется в title/intro/body параметризованным LIKE с экранированием %, _ и escape-символа; JSON-поля не сканируются. setNodeHome(true) требует home=1 и разрешённую интеграцию главной, false снимает фильтр. getNodeCount использует ровно те же условия доступа и поиска до пагинации.

Смешанная выборка компилирует отдельную ветку каждого типа с его расширением и объединяет UNION ALL, затем применяет глобальные порядок/пагинацию. Каждый placeholder получает уникальное имя ветки и вхождения; значения всегда связаны параметрами. Данные одного расширения не ослабляют права другого типа. Точное совпадение строк по числовому ID исключает дубли.

getNodeTargetList принимает не более 500 ссылок, группирует по типу, одним SQL получает нужные типы, вторым UNION ALL — доступные лёгкие цели. Типы/расширения собираются из общего ядра без дополнительных SQL; getNodeData для тяжёлых данных здесь не вызывается. Результат остаётся картой по глобальному ID в порядке входа. Недоступная ветка не раскрывает причину и не блокирует остальные разрешённые цели.

getNodeTree работает с одним типом с features.tree, возвращает строки id/title/parent/sort по id>after до limit (1..500), без body/fields/assets. parent содержит только доступного родителя, иначе null; дерево не вводит наследование ACL поверх основной категории. Интерфейс может собирать оглавление последовательными партиями; повторного SQL на каждую строку нет.

getNodeSitemap возвращает только id/name/title/cid/ctitle/published/updated для публичных типов с integrations.sitemap, по глобальному id>after (1..500). Это закрытая проекция, не массив SQL-колонок от вызывающего кода. URL строится штатной маршрутизацией по этим данным; отсутствующий/отключённый/истёкший материал не выдаётся. Курсор относится к последнему выданному ID, а пустая партия завершает обход.


### Запись

Точная форма входного объекта материала:

```php
final readonly class NodeInput
{
    public function __construct(
        public int $cid,
        public array $cids,
        public string $aname,
        public string $title,
        public string $intro,
        public string $body,
        public array $fields,
        public int $poll,
        public bool $home,
        public CommentMode $comon,
        public bool $pinned,
        public ?string $pubdate,
        public ?string $expires,
        public array $rels,
        public array $assets,
        public array $ext
    ) {}
}
```

- `cid` содержит основную категорию, а `cids` — полный набор дополнительных категорий без основной.
- `rels` и `assets` содержат полные желаемые наборы; пустой массив очищает набор, частичного или отсутствующего состояния нет. `fields` является полным набором активных редактируемых полей: сервис сохраняет прежние неактивные значения и не принимает их из формы.
- `pubdate` соответствует колонке `_nodes.published`; короткое имя соблюдает правило переменных до восьми букв, а SQL и конфигурация сохраняют утверждённое имя `published`.
- `aname` используется только для анонимного автора; при создании `uid` и `ip` берутся из `NodeContext`, а при изменении сохранённые `uid` и `ip` не заменяются контекстом редактора.
- `ext` содержит входные данные одного зарегистрированного расширения и не сохраняется в `_nodes`; тип без расширения принимает только пустой массив.
- `id`, `tid`, `uid`, `ip`, `status`, `version`, `created`, `updated`, `comnum`, `views`, `score` и `ratings` не входят в объект и назначаются системой.
- Конструктор фиксирует верхнеуровневые типы, а `NodeService` проверяет значения по `NodeType`, права, даты, категории, поля, связи и ресурсы.
- Свойства читаются напрямую; интерфейс, фабрика, наследование, геттеры, сеттеры и режим частичного обновления не создаются.

`NodeInput` не переносит настройки типа на уровень материала. `NodeService` принимает особенности материала только при включённой соответствующей возможности типа: отключённые `categories`, `comments`, `poll`, `home`, `pinned`, `related`, `tree` и `schedule` допускают только свои пустые значения. Для `comments` пустым режимом является `CommentMode::Disabled`; непустое запрещённое значение считается неверным вводом и не игнорируется молча.

Элемент `assets` имеет закрытую форму:

```php
[
    'id' => null,
    'kind' => 'file',
    'role' => 'download',
    'src' => 'manual.pdf',
    'name' => 'manual.pdf',
    'title' => 'Manual',
    'intro' => 'Description',
    'sort' => 0,
]
```

- Все восемь ключей обязательны; дополнительные ключи запрещены, а значения нормализуются до создания `NodeInput`.
- `id = null` создаёт новую строку, положительный `id` ссылается на существующий ресурс текущего материала; ноль, повтор, отсутствующий или чужой ID отклоняется.
- `kind` выбирается из закрытого системного набора и проверяется по роли типа, `role` — по реестру текущего `NodeType`.
- `src` является результатом общего загрузчика либо разрешённым внешним URL и повторно канонизируется сервисом; произвольный файловый путь не принимается.
- `nid`, `mime`, `size`, `width`, `height`, `duration`, `hits`, `reported`, `ruid`, `created` и `updated` форма не принимает; метаданные локального файла и служебные данные жалобы определяет сервер.
- Отсутствие прежнего `id` в полном наборе удаляет только строку `_node_assets`; физический файл не удаляется автоматически.
- Отдельный `NodeAssetInput` не создаётся: вложенную закрытую форму проверяет `NodeService` вместе с лимитами и остальными данными материала.

`NodeService` предоставляет четыре операции:

```php
public function __construct(Database $db, NodeContext $context, Field $field, ?Point $point = null, ?NodeExtension $ext = null)
public function addNode(NodeType $type, NodeInput $input, NodeStatus $status): Node
public function updateNode(int $id, NodeInput $input, int $version): Node
public function updateNodeStatus(int $id, NodeStatus $status, int $version): Node
public function deleteNode(int $id, int $version): void
```

- `addNode()` создаёт материал из `NodeType` и `NodeInput` сразу в явно переданном `Draft`, `Pending` или `Published`; остальные начальные состояния запрещены, а право на выбранное состояние проверяет сервис.
- `updateNode()` изменяет содержательные данные существующего материала.
- `updateNodeStatus()` выполняет все допустимые переходы `NodeStatus`: отправку на проверку, публикацию, отключение, перемещение в корзину и восстановление.
- `deleteNode()` физически удаляет материал, его категории, связи и ресурсы отдельным административным действием.

`NodeService` получает `Database`, `NodeContext`, общий Field, nullable Point и необязательное расширение при создании; требование Point определяется операцией по контракту конструктора. Наличие экземпляра обязано точно соответствовать `NodeType::$ext`; стандартный тип не принимает непустой `NodeInput::$ext`. `addNode()` назначает начальную версию `1` и фиксирует содержимое с разрешённым начальным состоянием одной транзакцией; промежуточная запись и последующий вызов `updateNodeStatus()` не требуются. Остальные методы требуют ожидаемую `version`, проверяют её в изменяющем SQL и не допускают тихого перезаписывания или удаления уже изменённого материала. `updateNode()` и `updateNodeStatus()` возвращают заново прочитанный сохранённый `Node`; успешный `deleteNode()` ничего не возвращает.

После конфликта `updateNode()` контроллер оставляет введённый `NodeInput` в форме и показывает актуальные значения только для отличающихся полей и разделов. Действие продолжения принимает актуальную версию как новую основу, но само ничего не сохраняет; обычное последующее сохранение снова вызывает неизменённый `updateNode()` с этой версией. Автоматического слияния и варианта записи без версии нет.

Отдельные методы публикации, отключения, корзины и восстановления не создаются: они дублировали бы единый автомат состояний. Каждая операция записи проверяет `NodeContext`, выполняется транзакционно и возвращает результат только после успешного завершения всей составной записи.

`updateNodeStatus()` использует закрытую матрицу переходов из модели данных. Повтор текущего состояния возвращает неизменённый `Node` без SQL-обновления и увеличения `version`; невозможный переход отклоняется до изменения связанных данных.

### Запись общих счётчиков

```php
public function updateNodeViews(int $id, NodeType $type): void
public function updateNodeComments(int $id, NodeType $type, int $count): void
public function updateNodeRating(int $id, NodeType $type, int $score, int $ratings): void
```

Методы принадлежат NodeService. Views повторяет право публичного просмотра и атомарно добавляет один просмотр; контекст запроса вызывает его один раз для успешного view, не для preview/HEAD/ошибки. Comments и Rating принимают проверенные итоги от доверенного владельца общей подсистемы внутри его транзакции после блокировки типа и материала; SQL контроллера к _nodes запрещён. Они не начинают второй COMMIT и не меняют version/updated.

Все значения неотрицательные и проверяются на вместимость; score/count согласованы по шкале 1..5, count=0 требует score=0. Для комментариев итог берётся из видимых комментариев этого материала, а не из HTTP-поля. Реакция расширения на фактическое действие выполняется владельцем один раз в той же транзакции.

Для независимости Rating NodeService допускает `?Point $point = null` в конструкторе. Это допустимо для операций рейтинга и иных действий без баллов; операции с начислением/компенсацией требуют явно переданный общий Point до первого SQL. Никакого ленивого создания Point внутри обработки рейтинга нет.


### Операции ресурсов

```php
// NodeQuery
public function getNodeAsset(int $id, NodeType $type): ?NodeAsset

// NodeService
public function updateNodeAssetHits(int $id, NodeType $type): void
public function updateNodeAssetReport(int $id, NodeType $type): void
public function deleteNodeAssetReport(int $id, NodeType $type, bool $useful): void
```

- `getNodeAsset()` возвращает ресурс только после проверки его материала, точного типа маршрута, состояния, дат, основной категории, роли и ограничений расширения. Отсутствие, несовпадение типа и запрет одинаково дают `null`.
- `updateNodeAssetHits()` повторяет проверку доступа и допустимости режима `download` или `link`, затем одним атомарным запросом увеличивает `hits` непосредственно перед разрешённым `GET`-скачиванием или внешним переходом. `HEAD`, показ, отказ и последующие диапазоны счётчик не меняют.
- `updateNodeAssetReport()` повторяет проверку доступности и включённой жалобы, после внешней проверки CSRF и ограничения частоты идемпотентно устанавливает `reported` и текущий зарегистрированный `ruid`, только если жалоба ещё отсутствует. Гость сохраняется как `ruid = 0`; повтор не меняет первого автора.
- `deleteNodeAssetReport()` доступен только главному администратору или модератору типа и требует явного решения `useful`. Метод блокирует строку ресурса и повторно проверяет непустой `reported` внутри транзакции; параллельное второе решение становится успешной пустой операцией. Полезная жалоба с `ruid > 0` создаёт для него `report` с источником из ID ресурса и случайного серверного ID операции; начисление и очистка жалобы входят в ту же транзакцию. Отклонённая или гостевая жалоба баллы не создаёт. После решения `reported` и `ruid` очищаются вместе. Общее право управления Node само по себе не даёт права разбирать материалы и жалобы конкретного типа.
- Изменение `hits`, `reported` и `ruid` не меняет `_nodes.version`, `_nodes.updated` и `_node_assets.updated`.
- Отдельный сервис ресурсов, прямой SQL из модуля и методы-алиасы не создаются.

### Чтение типов

```php
public function getNodeType(string $name): ?NodeType
public function getNodeTypeList(): array
```

Точная форма результата:

```php
final readonly class NodeType
{
    public function __construct(
        public int $id,
        public string $name,
        public string $title,
        public string $intro,
        public string $ext,
        public bool $active,
        public int $sort,
        public int $version,
        public string $created,
        public string $updated,
        public array $settings,
        public array $fields,
        public array $uploads,
        public array $rating
    ) {}
}
```

- `getNodeType()` получает метаданные из `_node_types`, настройки из `$conf['node']['types'][$name]` и возвращает один неизменяемый снимок `NodeType`.
- База является источником `id`, `name`, `title`, `intro`, `ext`, `active`, `sort`, `version`, `created` и `updated`; конфигурация является источником возможностей, полей представления, процесса, ресурсов и интеграций.
- `settings` содержит полную эффективную конфигурацию типа после проверки и объединения с `defaults`, а `fields` — проверенные определения `$conf['fields']['node'][$name]`.
- `created` и `updated` используют канонические строки базы `YYYY-MM-DD HH:MM:SS`; скрытого преобразования часового пояса объект не выполняет.
- Свойства читаются напрямую; геттеры, сеттеры, наследование и отдельные объекты каждого раздела настроек не создаются.
- Полноценный тип существует только при точном совпадении неизменяемого `name` в обоих источниках и успешной проверке всей итоговой конфигурации.
- В публичном контексте отсутствующий, отключённый или повреждённый тип возвращает `null`; внутренние подробности не раскрываются.
- `getNodeTypeList()` выполняет один запрос и возвращает `NodeType[]` без N+1. Обычный контекст получает только активные валидные типы, уполномоченный административный контекст — также отключённые валидные типы.
- Повторное получение одного имени через тот же экземпляр `NodeQuery` использует его память запроса и не повторяет SQL или сборку конфигурации.
- Память типов принадлежит экземпляру `NodeQuery` и живёт только до конца запроса; статический процессный кеш и постоянная таблица кеша не создаются.
- Настройки, поля, правило загрузок и рейтинг читаются из уже загруженных `$conf['node']`, `$conf['fields']['node']`, `$conf['uploads']` и `$conf['ratings']`; Node не сериализует их повторно и не создаёт собственного runtime-кеша.
- `NodeRegistry`, `NodeProvider`, фабрика и статические методы `NodeType` не создаются.
- `NodeConfig` и параметр конфигурации в конструкторах не создаются; `NodeQuery` получает `Database`, `NodeContext` и общий `Field`, а `NodeService` дополнительно получает общий `Point`.

По NOD-213 `NodeType.uploads` содержит сохраняемое правило загрузок без вычисляемых абсолютных путей, а `rating` — четыре настройки его рейтинга. Метаданные `node.types[name].version` сверяются с БД и исключаются из `settings`. Операции общих экранов для типа собирают остальные свойства из актуального NodeType под общей блокировкой и передают ожидаемую версию из формы; присланные пользователем чужие области не принимаются.

### Запись типов

Точная форма входного объекта:

```php
final readonly class NodeTypeInput
{
    public function __construct(
        public string $title,
        public string $intro,
        public string $ext,
        public int $sort,
        public array $settings,
        public array $fields,
        public array $uploads,
        public array $rating
    ) {}
}
```

Конструктор фиксирует восемь верхнеуровневых типов без преобразования и скрытых зависимостей. Проверка содержимого массивов, допустимых ключей, системных пределов, зависимостей возможностей, полей, ресурсов и расширения остаётся в `NodeService`, где доступна актуальная конфигурация; вложенные объекты и ресурсы сервис отклоняет.

```php
public function addNodeType(string $name, NodeTypeInput $input): NodeType
public function updateNodeType(string $name, NodeTypeInput $input, int $version): NodeType
public function updateNodeTypeStatus(string $name, bool $active, int $version): NodeType
public function deleteNodeType(string $name, int $version): void
```

- `addNodeType()` принимает новое безопасное публичное имя отдельно от изменяемых данных и всегда создаёт отключённый тип.
- `updateNodeType()` находит тип по неизменяемому имени и изменяет значения `NodeTypeInput` при совпадении ожидаемой версии. Ключ `ext` можно установить, заменить или очистить только у отключённого типа без материалов; настройки уже назначенного расширения можно изменять после полной проверки.
- `updateNodeTypeStatus()` является единственной операцией включения и отключения; она требует ожидаемую версию, а перед включением повторяет полную проверку типа, его конфигурации, полей, ресурсов, каталогов и расширения.
- `deleteNodeType()` требует ожидаемую версию, выполняет физическое удаление только при отсутствии материалов, категорий и пользовательских файлов (NOD-196), удаляет разделы типа из `node.php`, `fields.node` и стандартного `uploads.php`, но не удаляет каталог и файлы.
- Все четыре операции требуют `NodeContext::$manage` или `super`, проходят через единый сервис и возвращают проверенный итоговый `NodeType`, кроме успешного физического удаления.
- Новый тип получает `version = 1`; каждое успешное изменение данных, конфигурации или активности увеличивает её ровно на единицу, а несовпадение даёт `NodeException::CONFLICT` без частичной записи.
- Отдельные `NodeTypeService`, `NodeTypeManager`, массовое назначение и альтернативные методы включения не создаются.

### Инвалидация кеша

NodeService и владельцы глобальных изменений следуют единому протоколу Cache из 11-security-performance.md: маркер до начала записи, подтверждённый COMMIT, принудительное новое поколение, удаление маркера. Вызов административного SQL до COMMIT не заменяет финальную инвалидацию. Операция типа дополнительно ожидает согласованную публикацию конфигурации. Views, hits, reported и ruid не инвалидируют HTML; их представление в уже закешированном списке может отставать до штатного TTL, но живые маршруты читают актуальное значение. Содержимое, видимость, категории, comnum, score и ratings инвалидируют.

NodeQuery не создаёт постоянного кеша SQL. Для границы времени добавляется getNodeDeadline(): ?int: ближайший будущий published/expires среди потенциальных Published-материалов выбранных типов и фильтров, включая ещё не наступившую публикацию. Права и расширения сохраняются, только временной предикат снимается. Метод выполняет один агрегатный SQL на промахе HTML-кеша, возвращает Unix-время или null и не вызывает запрос на попадании. Бюджет обычного списка не включает этот отдельный запрос построения метаданных HTML-кеша.

## Расширения

Точный общий контракт:

```php
interface NodeExtension
{
    public function filterNodeConfig(array $config, array $settings, array $fields): array;
    public function filterNodeData(NodeType $type, array $data, ?Node $node = null): array;
    public function getNodeScope(NodeType $type): array;
    public function checkNodeAction(NodeType $type, Node|NodeTarget $node, string $action): bool;
    public function updateNodeAction(NodeType $type, NodeTarget $node, string $action): void;
    public function addNodeData(Node $node, array $data): void;
    public function updateNodeData(Node $before, Node $after, ?array $data): void;
    public function deleteNodeData(Node $node): void;
    public function getNodeData(NodeType $type, array $nodes, string $mode): array;
}

function getNodeExtension(string $key, Database $db, NodeContext $context): ?NodeExtension;
```

- `getNodeExtension()` находится в `core/classes/node/ext/load.php`, использует только закрытую карту и создаёт расширение с текущими `Database` и `NodeContext`. Пустой ключ возвращает `null`, неизвестный — `NodeException::INVALID`. Карта пополняется вместе с файлом класса: на S08 она пуста, `support` добавляет S14, `sync` — S15; пустые файлы расширений заранее не создаются.
- `filterNodeConfig()` получает настройки самого расширения, полный эффективный стандартный раздел типа без `ext` и проверенные определения полей; возвращает канонический массив либо бросает `NodeException::INVALID`.
- `filterNodeData()` проверяет и канонизирует `NodeInput::$ext` до начала изменяющей транзакции. При изменении получает текущий материал, при создании — `null`.
- `getNodeScope()` возвращает точные ключи `join`, `where`, `params`. `join` и `where` являются доверенными SQL-фрагментами зарегистрированного PHP-класса для основного псевдонима `n`, а значения находятся только в `params`; конфигурация и запрос не могут передать SQL. Ограничение применяется до подсчёта и пагинации во всех публичных чтениях материала, списка, цели и ресурса.
- `checkNodeAction()` после успешного чтения цели принимает только закрытые действия `comment`, `rate`, `favorite`, `asset`, `report` и может дополнительно запретить их. Он не может разрешить отключённую возможность типа, обойти основное право или выполнить само действие.
- `updateNodeAction()` вызывается для того же закрытого действия только после его успешного фактического выполнения и изменяет исключительно принадлежащие расширению данные внутри транзакции владельца действия. Метод не создаёт комментарий, оценку, избранное, ресурс или жалобу и не запускает необратимую работу.
- `NodeQuery::setNodeExtension(?NodeExtension $ext): self` назначает расширение до выполнения выборки. Несовпадение с ключом текущего типа отклоняется; стандартный тип использует `null`.
- `addNodeData()` вызывается после создания основной записи и стандартных наборов, но до фиксации общей транзакции.
- `updateNodeData()` вызывается после получения снимка `before` и стандартного обновления, но до фиксации. Для изменения содержимого передаётся канонический массив, для отдельной смены состояния — `null`; состояния доступны в `before` и `after`.
- `deleteNodeData()` вызывается до физического удаления основной строки внутри той же транзакции.
- Любое исключение метода записи откатывает основную и дополнительную запись. Сетевые запросы и другие необратимые действия внутри этих методов запрещены.
- `getNodeData()` принимает уже доступные материалы одной страницы или один материал в массиве и возвращает карту `nid => array`. Реализация обязана читать её пакетно без N+1 и возвращать только данные, разрешённые текущему контексту.
- Специальные административные действия и фоновые задачи не входят в общий интерфейс: они принадлежат конкретному зарегистрированному классу и утверждаются вместе с ним.

`NodeSupport` дополнительно предоставляет одну команду рабочей карточки:

```php
public function updateNodeSupport(
    int $id,
    int $aid,
    int $state,
    int $prio,
    int $version
): void;
```

Команда атомарно проверяет доступ, существование обращения, текущую `version`, допустимые значения и назначаемого администратора, затем изменяет только разрешённые текущему контексту поля `_node_support`. Раздельные методы назначения, приоритета, закрытия и повторного открытия не создаются.

Специальная административная очередь использует один метод чтения:

```php
public function getNodeSupportList(
    NodeType $type,
    int $page,
    int $limit,
    ?int $state = null,
    ?int $aid = null,
    ?int $prio = null
): array;
```

Метод возвращает точные ключи `nodes`, `ext`, `count`: список лёгких `NodeTarget`, карту данных поддержки по `nid` и общее число строк до пагинации. `null` отключает соответствующий фильтр; `aid = 0` означает только неназначенные обращения. Страница и предел проходят общие ограничения Node, неизвестные значения состояния и приоритета отклоняются. Публичный список владельца остаётся обычным `NodeQuery`; специальная выборка существует только для административной очереди по `state`, `aid`, `prio` и `activity`.

`NodeSync` дополнительно предоставляет две операции фонового обновления:

```php
public function updateNodeSync(int $id): array
public function updateNodeSyncList(int $limit): array
```

- `updateNodeSync()` проверяет один материал независимо от `due`; его используют явный административный запуск и пакетный метод. Результат содержит только `id`, `status` и `error`, где `status` равен `updated`, `unchanged`, `failed` или `skipped`.
- `updateNodeSyncList()` принимает предел `1..50`, выбирает готовые строки по `due, id`, вызывает одиночную операцию последовательно и возвращает совместимый с планировщиком массив `status`, `message`, `extra`. В `extra` находятся числовые `checked`, `updated`, `unchanged`, `failed`, `skipped`.
- Сетевой запрос выполняется через общий `Feed` вне транзакции. Сохранение повторно проверяет источник и версию материала; изменённое тело проходит `checkEditorTextRoom(..., 'nodes.body')`, после чего узкий условный SQL меняет только `_nodes.body`, `_nodes.updated` и `_nodes.version` в одной транзакции со служебным состоянием. Ошибка никогда не очищает прежний `_nodes.body`.
- Обычные хуки `filterNodeData()`, `addNodeData()`, `updateNodeData()` и `deleteNodeData()` управляют строкой `_node_sync` вместе с материалом и не выполняют сеть. Дополнительные CRUD-методы источника не создаются.
- `NodeSync` получает `Feed` через закрытый `getNodeExtension()` только для ключа `sync`. Системное задание вызывает его через фиксированный `addNodeSyncTask()`; общий реестр callback и циклическая зависимость с `NodeService` отсутствуют.

### Подготовка данных представления

`final class NodeView` из `core/classes/node/view.php` предоставляет один публичный метод:

```php
public function __construct(Parser $prs, Field $field)
public function getNodeView(NodeType $type, Node|NodeTarget $node, string $mode): array
```

- Закрытые режимы `list`, `view`, `card` принимают полный `Node`; `card`, `block`, `search` принимают лёгкий `NodeTarget`.
- Несовместимая пара объекта и режима, несовпадение переданного `NodeType` и цели либо неизвестный режим дают `NodeException::INVALID`.
- Класс не выполняет SQL, не читает запрос или пользователя, не формирует HTML и не вызывает шаблоны. Он обрабатывает разрешённый текст через `Parser`, использует общий `Field`, строит публичные URL штатным `getSeoUrl()` и возвращает только данные, безопасный HTML парсера и семантические флаги.
- Контроллер списка применяет метод к уже полученной странице `Node[]`; связанные карточки, блоки и поиск передают пакетно полученные `NodeTarget[]`. Дополнительное чтение из подготовщика и отдельные методы для каждого режима не создаются.

Каждый режим возвращает один массив с точными короткими ключами:

```php
[
    'id' => 1050,
    'type' => 'news',
    'mode' => 'view',
    'href' => 'index.php?name=news&op=view&id=1050',
    'title' => 'Заголовок',
    'intro' => 'Краткий текст без разметки',
    'intro_html' => '<p>...</p>',
    'body_html' => '<p>...</p>',
    'author' => 'Admin',
    'ahref' => 'index.php?name=account&op=view&uname=Admin',
    'ctitle' => 'Категория',
    'chref' => 'index.php?name=news&cat=1',
    'date' => '05.09.2026',
    'date_iso' => '2026-09-05T12:00:00+02:00',
    'mtime_iso' => '2026-09-05T13:00:00+02:00',
    'views' => 0,
    'comnum' => 0,
    'rating' => null,
    'ratings' => 0,
    'fields' => [],
    'assets' => [],
]
```

- Массив существует только во время запроса и не сохраняется в базе, конфигурации или отдельном кеше; HTML-кеш при разрешённом маршруте хранит уже готовую страницу.
- `title`, `intro`, `author`, `ctitle` и `date` являются обычным текстом. Только `intro_html` и `body_html` содержат разрешённый HTML от `Parser`; `fields.*.value_html` сохраняет отдельную утверждённую границу `Field`.
- `href`, `ahref` и `chref` являются необработанными URL для однократного экранирования шаблоном. `ahref` существует только у доступного зарегистрированного автора, `chref` — у основной категории.
- `rating` равен `null` без голосов, иначе содержит нормализованную десятичную строку средней оценки; `ratings` хранит число голосов.
- Полный `Node` заполняет доступные содержательные значения. `NodeTarget` возвращает тот же набор ключей, но оставляет недоступные ему текст, даты, поля и ресурсы пустыми либо `null`; форма массива от режима и класса объекта не меняется.
- `assets` группируется по устойчивому имени роли. Каждый элемент содержит только `id`, `kind`, `role`, `href`, `rhref`, `name`, `title`, `intro`, `mime`, `size`, `stext`, `width`, `height`, `duration`, `hits`, `islink`; физический `src`, `reported` и `ruid` в представление не входят. `rhref` пуст, если жалоба для роли недоступна.

## Удаление связи с общим опросом

Для удаления общего опроса NodeService получает deleteNodePoll(int $id): void. Метод доступен только доверенному административному контексту с правом удаления опросов, внутри транзакции владельца после блокировки всех затронутых типов по ID и до строки опроса. Он очищает только poll, увеличивает version и updated материалов, инвалидирует кеш после COMMIT владельца; произвольная форма Node не вызывает этот метод. Это не удаление материала и не каскадное удаление глобального опроса из Node.

## Системные задачи и отложенная публикация

NodeContext.task по умолчанию false. Только фиксированные адаптеры штатного планировщика создают task=true с uid=aid=0, groups=mods=[], manage=super=false. Публичный/admin/AJAX bootstrap не читает task из запроса и всегда оставляет false. Системный контекст разрешает только updateNodePublishList и пакетный NodeSync; он не даёт права обычного CRUD, публикации произвольного ID или аннулирования рейтинга. NodeQuery не снимает ACL лишь из-за task.

NodeService::updateNodePublishList(int $limit = 50): array принимает 1..500 и требует task=true. Результат ровно status:string, message:string, extra:array; status=success|failed — статусы штатного планировщика, которые принимает setSchedulerDone(); crashed выставляет только сам планировщик; message — безопасный текст, extra содержит processed/failed/skipped как int. Метод использует _node_publish по 03, общий Point и отдельную транзакцию каждого материала. Обработка очереди не меняет version/updated материала и не начисляет в публичном просмотре.

Фиксированный addNodePublishTask() в core/system.php создаёт системный контекст, собирает NodeService и вызывает этот метод. Задание nodepublish: * * * * *, limit=50, lock_timeout=180. Первый успешный запуск после срока начисляет награду; точность до секунды и работа остановленного планировщика не обещаются. Ручной запуск — только штатный административный экран планировщика, отдельного HTTP op нет. Системное задание регистрируется в четырёх местах: getSchedulerJob() и addSchedulerSystemJob() в core/system.php, config/scheduler.php для чистой установки и дополнение заданий ветки update6_3 в setup/index.php для обновляемого сайта; пропуск любого оставляет задание невидимым либо незапускаемым.

addNodeSyncTask() также создаёт task=true. updateNodeSyncList требует этот контекст; одиночный административный updateNodeSync требует обычного права модератора. Внутренний вызов одиночной синхронизации из очереди допускается только для выбранного очередью ID в системном контексте; этот контекст не расширяет публичные права Node.

## Экспорт и импорт определения типа

```php
public function getNodeTypeExport(string $name): string        // NodeQuery
public function addNodeTypeImport(string $json, string $name = ''): NodeType   // NodeService
```

- getNodeTypeExport() требует manage или super, читает тип, включая отключённый, и возвращает канонический UTF-8 JSON формата `slaed.node` из 06-types.md: ровно девять ключей типа, без id, active, версии записи, дат, материалов, путей и секретов.
- addNodeTypeImport() принимает JSON до 1 МиБ, проверяет формат, версию формата, закрытый набор ключей и зависимости, собирает NodeTypeInput и вызывает addNodeType(): результат — новый отключённый тип с version = 1. Непустой `$name` заменяет имя из файла; существующий тип не перезаписывается. Ошибка формата — NodeException::INVALID до любой записи.
- JSON-кодек и валидатор формата принадлежат только этим двум методам. Клонирование — экспорт существующего типа и импорт с новым именем; создание из профиля — импорт файла `modules/node/profiles/<name>.json`; чистая установка использует тот же путь и затем updateNodeTypeStatus(). Отдельных методов клонирования и профилей нет.

Он получает сохранённый раздел типа без метаданных `version` (отличия от `defaults`), объединяет его с `defaults` и проверяет весь закрытый состав 06-types.md: `list`, `view`, `form`, `workflow`, `admin`, `features`, `assets`, `integrations` и `ext` через `filterNodeConfig()` зарегистрированного расширения. Права категорий модератор проходит всегда, ограничение расширения действует всегда. Обычный контекст с `setNodeStatus(X)` получает пересечение X с опубликованным — доступ не расширяется.

Реализация (S09, `core/classes/node/query.php`):

- `NodeType.uploads` — двенадцать именованных частей сохранённой строки правила в порядке `setUploadRuleData()` (`extensions` строкой, остальные `int`), `NodeType.rating` — сохранённое правило `node.<name>` из четырёх строковых ключей в форме Rating. Отсутствие или порча раздела `node.types.<name>`, его настроек или `fields.node.<name>` делает тип невалидным; ошибка пишется `Logger::addSite()` строкой `Node: …` с `name` и путём первой ошибки. Отсутствующее или испорченное правило загрузок или рейтинга типа не делает тип невалидным: `uploads` или `rating` равны `[]`, блокируется только своя подсистема (ratings.md: «неверное правило блокирует соответствующий рейтинг с диагностикой»), причина пишется в журнал.
- Несовпадение `version` строки и конфигурации или отсутствие раздела: один `getConfig()` без `fresh`; тип собирается из свежего снимка и уже прочитанной строки, а повторный SELECT этих строк выполняется, только если свежий снимок несёт раздел другой версии; глобальный `$conf` не меняется; сохраняющееся несовпадение — невалидный тип с записью в журнал.
- Отключённый валидный тип получают главный администратор, `manage` и модератор этого типа. `setNodeType()`/`setNodeTypes()` отклоняют тип, который контекст не может читать (`INVALID`). Цели и sitemap берут только активные типы.
- Проверка расширения одиночного чтения: назначенный экземпляр обязан быть того класса, который закрытая фабрика создаёт для ключа типа; смешанная выборка с назначенным экземпляром — `INVALID`. Каждое вхождение значения из `getNodeScope()` получает своё имя `<ветка>x<имя>o<n>` (родные подготовленные выражения PDO не допускают повтор имени).
- Тип без `features.categories` публично читает только `cid = 0`; материал с категорией чужого модуля или удалённой категорией закрыт для всех, кроме модератора типа. Фильтры, которые настройки типа не допускают (`setNodeCategory` без категорий, буква без `list.alpha`, `setNodeHome` без `features.home`, сортировка вне `list.orders` любого типа выборки), дают `INVALID` при чтении.
- Размер страницы — не больше `limits.maxlist` и `list.limit` каждого выбранного типа; по умолчанию — наименьший из них. Смешанная выборка без `setNodeOrder()` сортируется по `published desc`. Буква и поиск сравниваются по сопоставлению таблицы (`utf8mb4_unicode_ci`: без учёта регистра и диакритики).
- `getNodeAsset()` требует активную роль типа от любого контекста. Родитель в `getNodeTree()` виден через `EXISTS` с тем же предикатом доступа (опубликован, даты, права и язык категорий, расширение). `getNodeDeadline()` берёт `UNIX_TIMESTAMP()` на часах БД.
- Сохранённые значения полей, не являющиеся JSON-объектом, читаются как `[]`; строка с неизвестным `status` или `comon` пропускается; оба случая журналируются с `nid`.
- `getNodeContext()` в core/system.php: группы — тем же соединением `_users`/`_groups`, что `is_acess()`; права администратора — один SELECT `_admins.modules` через `getAdminModuleNames()`: ключ `node` — `manage`, `node-<name>` по грамматике имени — `mods` (уникальные, отсортированные), прочее отбрасывается; главный администратор получает `manage = true`; `lang` — `$locale` при `multilingual`, иначе `''`; снимок статический на запрос; сбой SQL — `NodeException::STORAGE`. Значения запроса (`task`, `super`, `aid`, `mods`, `groups`) не читаются.
- Проверка существования групп `workflow.groups/publish` и констант подписей ролей требует SQL и языка; `filterNodeSettings()` проверяет только форму, существование проверяет запись S10.

Реализация (S10, `core/classes/node/service.php`):

- `final class NodeService` с конструктором `Database, NodeContext, Field, Point` и пятью публичными методами этапа: четыре операции типа и `addNodeTypeImport()`. `NodeQuery::getNodeTypeExport()` — канонический JSON (`JSON_PRETTY_PRINT`, без экранирования слешей и Unicode), публичные константы `NodeQuery::FORMAT`, `EXPORT`, `UPLOAD`, `ROLEDEF` — общий состав формата, частей правила загрузок и умолчаний роли для читателя и писателя; тип со сломанным правилом загрузок или рейтинга не экспортируется (`INVALID export`).
- Каждая операция — замыкание `setConfigFile()` в порядке 11-security-performance.md: lock конфигурации → `FileManager::getPathLock(uploads/<name>)` → `Cache::getWriteGuard()` → BEGIN → `SELECT … FOR UPDATE` строки типа по имени → проверки по свежим областям → SQL → `$save($pack, $proof)` → COMMIT. После публикации `Cache::addEpoch(true)` и снятие guard; подтверждённый откат снимает guard, неизвестный COMMIT или несостоявшееся поколение его оставляют (восстанавливает `checkWriteGuard()`). Proof — `kind` (`add|update|status|delete`), `name`, `id`, `old`, `new`; у создания `old = 0`, у удаления `new = 0`.
- Проверки записи сверх `filterNodeSettings()`: `manage` или `super`, иначе `DENIED` до чтения; грамматика имени до блокировок; резервирование (02, плюс любой ключ `$conf['modules']` и каталог `modules/<name>` вне девяти штатных замен, ключ одной из четырёх областей — `all`, `dir`, `typ`, …), каталог `uploads` с тем же именем в другом регистре, категории с `modul = name` (NOD-200, наследство прежнего владельца); подписи типа (до 100 символов) и ролей — простой текст или определённая языковая константа; существование групп `workflow.groups/publish` одним SQL; поля — общим `Field::filterFieldList()`; правило загрузок — двенадцать частей, расширения из `Upload::getSupportedTypes()` без повторов, пределы целыми 0…18 цифр, `userupload`/`guestupload` 0 или 1; рейтинг — четыре строковых ключа в форме Rating. Глобальная часть `config/node.php` (`version`, `limits`, `support`, `defaults`) под блокировкой обязана совпасть с загруженной запросом, иначе `CONFLICT`.
- Хранение — отличия от `defaults`: карты сравниваются по ключам, списки и значения целиком, у роли остаются только отличающиеся от `NodeQuery::ROLEDEF` ключи и три обязательных; запись проверяет, что сохранённые отличия дают ровно проверенные эффективные настройки, иначе `STORAGE`. Пустой набор полей раздела `fields.node.<name>` не создаёт, пустой `fields.node` удаляется.
- Файловая область: создание берёт существующий `uploads/<name>` только если в нём, включая `thumb` и скрытые файлы, нет ничего кроме `index.html`, байт в байт равного `uploads/index.html` поставки; ссылка или нечитаемое место — пользовательские данные. Отсутствующий каталог создаётся с этим guard до INSERT. Включение требует существующий, записываемый и не являющийся ссылкой каталог; удаление проверяет ту же пустоту и каталог не трогает.
- `updateNodeType()` защищает сохранённые ресурсы: роль, у которой в материалах типа есть строки `_node_assets`, удалить нельзя (`INVALID assets.<роль>`); роль режима `link` допустима только если все её ресурсы — адреса `http://`/`https://` без повторов, сравнение побайтное (`CAST(src AS BINARY)`, колонка сортирует без учёта регистра), иначе `INVALID assets.<роль>.mode` (06 → «Ресурсы типа», NOD-202).
- `updateNodeTypeStatus()` в текущем состоянии — успех без записи и без новой версии; включение повторяет полную проверку того, что хранится (строка, раздел, поля, правило загрузок, рейтинг). `deleteNodeType()` в той же транзакции убирает ключ `node-<name>` у всех администраторов — новая регистрация имени прав не наследует (11 → «Единый порядок блокировок»).
- `setConfigRestore()` без аргумента решает Node-proof блокирующим чтением строки типа по имени на соединении запроса: версия `new` — новый снимок, `old` (0 — строки нет) — старый, чужой ID или иная версия — отказ с маркером. После публикации версия типа в свежем снимке сверяется с версией строки. Экран restore показывает вердикт `_NODE_PROOF` и кнопку восстановления.
- `NodeQuery` удерживает типы из `marker.json` (нечитаемый маркер — все типы): `getNodeType()` отдаёт `null` с записью `Node: a type is invalid or held by an unfinished configuration operation`; состояние файла маркера запрашивается без кеша stat. Сборка после расхождения версий — «Заметки реализации S09»: так тип, записанный этим же запросом, читается без лишнего SQL, а бюджет списка с типом без раздела остаётся 1.
- Общие экраны: области `node.<name>` на экране полей (HTML-идентификаторы с `-` вместо `.`), блоки типов на экранах загрузок и оценок; каждая форма несёт `ver[<name>]`, неизменённая часть типа не сохраняется, а формы с позиционными полями (uploads, ratings) несут отрендеренный список ключей и отклоняют сохранение целиком, если он изменился. Редактор прав принимает `node` и `node-<name>` зарегистрированных типов, а сохранение сохраняет ключи `node-*` типов, которых редактор не показывает. `config/node.php` поставляется с `types => []`.

Реализация (S12):

- `getFileStream(string $path, string $name, string $mime = 'application/octet-stream', bool $inline = false, bool $cached = false, ?callable $start = null): void` в core/system.php. Закрытый реестр inline: `image/gif|jpeg|png|webp|avif`, `audio/mpeg|wav|x-wav|vnd.wave|flac|x-flac|ogg|mp4|x-m4a|webm`, `video/mp4|webm|ogg`. Любой другой MIME отдаётся как `application/octet-stream` вложением. ETag — `"<32 hex>"` от канонического пути, размера и `mtime`, файл для него не читается. Без `cached` ответ получает `private, no-store, …, no-transform` — это же требование 07 к предпросмотру. `Range` читается только у `GET`: `bytes=` без учёта регистра, один диапазон `a-b`, `a-` или `-n`. Повреждённый или неудовлетворимый диапазон даёт `416` с `Content-Range: bytes */size`. Несколько корректных диапазонов дают полный `200`, другая единица игнорируется. `If-Range` совпадает только с сильным ETag или точной датой `Last-Modified`. Тело читается блоками по 64 KiB до `connection_aborted()`, `zlib.output_compression` выключается.
- `Cache::setPrivateHeaders()` построен на `setHeaders(false, …)`: снимает `Pragma` и `Expires` сессии и выдаёт `private, no-cache, must-revalidate, no-transform` и `ETag`. `Cache::checkNotModified($mtime, $etag)` при непустом теге решает по `If-None-Match` (список, `W/`, `*`) без отката к дате. Вызов без тега прежний.
- `Cache::setPageUntil(?int)` хранит минимум границы; `null` связывает страницу без известного момента (`PHP_INT_MAX`). Sidecar пишет `until` (0 — страница не связана). `getMeta()` возвращает `until`; повреждённый sidecar отвечает `until = 1`, поэтому такая копия больше не отдаётся и страница строится заново. `setHead()` не отдаёт свежую и устаревшую копию при `now >= until`. У связанной страницы нет публичного браузерного кеша: при чтении и при заполнении — `no-store`. Маршрут Node на S13 вызывает `Cache::setPageUntil(getNodeDeadline())` только при построении HTML-кеша.
- `FileManager::getGuardFiles()` возвращает `['index.html' => <байты uploads/index.html>, '.htaccess' => 'deny from all']`. Им пользуются `NodeService` (создание, удаление и включение типа, отказ привязки), `Upload` (подсчёт занятого места) и два upload helper; прежних списков имён больше нет.
- `NodeService::getNodeFile()`: `key` — целое управляемое имя `FileManager::checkFileName()`, равное своему basename, не длиннее 255 байт. Расширение входит в правило типа и в `Upload::getSupportedTypes()`. Сохранённая ветка — `getNodeContent()` и `getAttachList()` для `intro` и `body`, 1 SQL внутри метода и 2 вместе с типом маршрута. Предпросмотр: модератор типа или посетитель, допущенный `checkFlowAccess()` (активный тип, `features.submit`, `workflow.access`), владелец через `getFileToken()` — общий для привязки и предпросмотра. SQL не выполняется. Путь проверяется `FileManager::getFileData()` (realpath внутри корня); `thumb` — только после оригинала.
- Включение неактивного типа сначала проверяет право `manage`, затем `checkTypeGuard()`: дописывает стражей и вызывает `getSchedulerFetch()` — до `setConfigFile()` и всех блокировок.
- Parser: `nid > 0` даёт `index.php?name=<mod>&amp;op=attach&amp;id=<nid>&amp;key=<rawurlencode>` в `[src]` и `&amp;thumb=1` в `[tsrc]` при существующей копии. `nid` входит в ключ памяти запроса и дискового кеша парсера; `nid <= 0` оставляет прежний прямой адрес.
