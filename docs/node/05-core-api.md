# Публичный API ядра Node

Статус: каркас.

## Цель

Определить минимальный стабильный API, через который модуль `node` и другие подсистемы SLAED читают и изменяют материалы.

## Утверждённые базовые имена

- `Node`
- `NodeType`
- `NodeInput`
- `NodeContext`
- `NodeService`
- `NodeQuery`
- `enum NodeStatus`

## Принципы API

- Чтение не раскрывает структуру SQL и таблиц.
- Запись всегда проходит права, валидацию, транзакции и очистку кеша.
- Публичный API не содержит условий по имени типа.
- Входные данные представлены типизированными объектами, а не необязательным массивом произвольной формы.
- `NodeInput` допускает только поля пользовательского ввода; ID, счётчики, даты аудита и вычисляемые значения назначает сервис.
- `NodeContext` создаётся адаптером модуля один раз на запрос и передаётся явно; ядро не читает глобальные `$user`, `$locale` и адрес клиента.
- Ошибки имеют различимые причины и не зависят от текста локализации.
- Отдельный репозиторий первой версии не создаётся: чтение принадлежит `NodeQuery`, запись и транзакции — `NodeService`.

## Контракты, которые необходимо описать

### Чтение одного материала

Поиск по ID или устойчивому публичному идентификатору с проверкой типа, статуса и доступа.

### Списки

Тип, категория, автор, статус, дата, сортировка, пагинация, дополнительные поля и связи.

### Запись

Создание, изменение, отправка на проверку, публикация, отключение, восстановление и удаление.

### Типы

Регистрация, загрузка, изменение настроек, включение и отключение.

### Расширения

Регистрация поведения, проверка входных данных, участие в транзакции и подготовка данных представления.

## Критерии готовности

- Все публичные классы и методы утверждены в `02-naming.md`.
- Для каждого метода описаны параметры, результат, ошибки, права и транзакционность.
- Список публичных методов минимален и не дублирует один сценарий несколькими способами.
- По API можно реализовать публичный маршрут, админку, блок, RSS и sitemap без прямого SQL.
