# План консолидации шаблонов и стилей кабинета

Составлен 2026-09-08 по итогам переноса страницы фаворитов и доводки страницы личных сообщений.
Шесть батчей, каждый со своими файлами, шагами и критерием приёмки. Работа ведётся в отдельной
сессии; **все проверки один раз по окончании всех батчей**, по ходу только `php -l`,
`phpunit --filter` одного набора и `node tools/ui-shots.mjs --after --only=<page>` одной страницы.

## 1. Правила игры

- Правила проекта из `.rules/*` и `CLAUDE.md` старше этого плана; для темы решает `tools/ui-contract.php`.
- Никаких новых токенов и новых компонентов: батчи *убирают* варианты, а не добавляют. Новое правило
  CSS допустимо только как слияние двух старых в один селекторный список.
- Поведение, адреса и имена `op` не меняются. htmx-контракты (`#repfavorliste`, `#prlist`, `#prview`,
  `#prnotes`, `#prshown`, `#favshelves`, `#favchips`, `#favtally`) сохраняются дословно.
- Канон темы: правки в `fragments/` и `partials/` lite сверяются с admin-темой там, где файл общий
  (пример: `changelog-body.html` идентичен в обеих темах и правится парой).
- Снимок `npm run ui:before` берётся **один раз до первой правки CSS** первого батча и не
  пересоздаётся. Каталог `%LOCALAPPDATA%\Temp\slaed-ui-guard` перед ним очищается от старого набора.
- Дупликатор аудита: если новое тело правила совпало со старым, селектор присоединяется к старому
  правилу или пара вносится в допущения `tools/ui-contract.php` с причиной. Никогда не поднимать
  базовую линию `tools/ui-audit-baseline.json` ради батча.

**Стоп-условия.** Схема БД, адрес или контракт API должны измениться; причина не сводится к
file:line; батч расползается за пределы кабинета и ЛС. В этих случаях вопрос через
`AskUserQuestion`, не прозой.

страницу рельса.

## 3. Батчи

### A. Мелкие безопасные

**A1. Лампы во фрагмент.** Блок `<div class="sl-opt-lamps">…` скопирован в
`partials/account-settings.html` и `partials/account-favorites.html`. Вынести в
`fragments/opt-lamps.html` с полями `label`, `value`, `note`, `cat`/`tone`, `is_meter`, `left`; оба
партиала подключают его через `{% include 'fragments/opt-lamps.html' %}` (тест
`TemplateValidationTest::testConcreteTemplateReferencesExist` требует полный путь). Приёмка:
разметка ламп на обеих страницах побайтно совпадает с текущей.

**A2. Чипс профиля без блочного варианта.** Правило `.sl-profile-chips .sl-chip { display: inline-block … }`
и ручной `.sl-profile-chips .sl-chip > .bi { margin-right }` убрать; многоточие длинной подписи дать
вложенному `<span>` с `overflow: hidden; text-overflow: ellipsis` внутри флекс-чипса. Разметка:
`account-home.html`, `account-profile.html`, `account-favorites-chips.html`. Приёмка: замер зазора
иконки во всех чипсах девяти страниц даёт 4 px (скрипт замера описан в памяти проекта
`chip-icon-gap-standard`), длинная подпись группы по-прежнему обрезается.

**A3. Одно сообщение всегда строкой.** `addPrivateMessage()` в `core/user.php` передаёт ошибку как
`[$note]`; договорённость: массив только для нескольких сообщений. Пройти по вызовам
`getHtmlFrag('alert', …)` с `messages` и оставить массив там, где сообщений действительно несколько.
Приёмка: `grep` не находит массивов из одного литерала.

**A4. Слот уведомлений кабинета.** Модель `fragments/privat-notes.html` (`#prnotes`, OOB на
htmx-запросах) распространить на фавориты: `getFavoriteList()` печатает `_NO_INFO` и будущие ошибки
в слот под навигацией, а не внутрь списка. Имя слота одно на кабинет (сейчас `prnotes`; при
обобщении переименовать в обеих страницах одновременно, htmx-цели правятся вместе). Приёмка:
удаление последнего фаворита показывает алерт в слоте, полки исчезают.

### B. Одна шапка панели

Сейчас CSS уже держит одну строку для трёх форм разметки (селекторный список в `theme.css` у правил
на `.sl-opt-tile-head` и `:is(.sl-profile-panel, …) h3`). Сделать так же в разметке: фрагмент
`fragments/panel-head.html` с полями `icon`, `title`, `title_id`, `total_html` (правый слот под чипсы
и стрелку), `toggle_id` (если шапка складывает блок, см. D). Заменить им:

- `.sl-opt-tile-head` в `account-settings.html` и в плитках, которые его получат от A1;
- `.sl-profile-hub-head` в `account-profile.html`, `account-favorites.html`, `account-favorites-shelves.html`;
- 13 заголовков `<h3><i class="bi">` в `account-home.html`, `account-profile.html`, `account-profile-feed.html`.

После замены оставить один класс шапки в CSS и слить правила на `.sl-opt-tile-head`,
`.sl-profile-hub-head` и `h3`-варианты в одно; удалить осиротевшие (`.sl-profile-hub-head h3 { margin: 0 }`
и подобные). Приёмка: `php tools/ui-audit.php --theme=lite` показывает падение счётчиков, ни один не
растёт; `--only=profile,settings,favorites,private` визуально без сдвигов, кроме перечисленных в
отчёте батча.

### C. Одна строка списка

Метрики уже общие (высота `--sl-entry-height`, нижняя граница, колонка иконки 30 px). Оставить один
компонент строки, например `.sl-cab-row` как самый простой (3 колонки: иконка, текст, правый слот),
с модификатором ведущей ячейки для даты или чипса (4 колонки, как у `.sl-profile-entry`). Перевести
на него:

- `.sl-profile-entry` в `account-profile.html` (хаб и лента) и `account-profile-feed-list.html`;
- `.sl-pmf-item` в `fragments/privat-row.html`: сетка `22px 26px 1fr auto` становится модификатором с
  чекбоксом и аватаром, свой `padding` и состояния `sl-pmf-new`, `aria-current` остаются
  модификаторами одной строки;
- `.sl-profile-info-row` в `account-profile.html`, если её сетка `22px fit-content(60%) 1fr` сводится
  к тому же ряду; если нет, оставить и записать причину.

Приёмка: обход Playwright по страницам профиля, кабинета, фаворитов и ЛС не находит строки,
вылезающей за родителя (скрипт замера переполнений из сессии 2026-09-07); высота строк не изменилась.

### D. Одна механика сворачивания

Оставить `data-sl-toggle` из `plugins/system/slaed.js`: он помнит состояние в `localStorage`,
перевзводится после `htmx:afterSwap` и не ломается внутри плитки-сетки, в отличие от `details` с
боксом `::details-content` (память проекта `details-content-grid-gotcha`). Перевести фокус ЛС
(`fragments/privat-focus.html`, правила `.sl-pmf-focus`, стрелка через `::after` и кодпоинт) на ту же
пару иконок `.sl-panel-toggle-open`/`.sl-panel-toggle-closed`, что у полок фаворитов, через шапку из
B. Удалить правила `.sl-pmf-focus > summary*`. Приёмка: состояние фокуса переживает перезагрузку,
стрелка меняется, ни одного `<details>` в `templates/lite` не остаётся (или список оставшихся с
причиной).

### E. Одна карта иконок

Сейчас иконку модуля дают `getProfileModules()`, `getFavoriteIcon()` и `$conf['modules'][x]['icon']`,
а иконки понятий («профиль», «сайт», «прочитано») захардкожены в 67 местах PHP. Завести одну функцию
`getIconName(string $key): string` в `core/system.php` рядом с `getModuleName()`: ключи модулей и
ключи понятий, значения — имена Bootstrap Icons. Перевести на неё `getProfileModules()`,
`getFavoriteIcon()` (удалить), навигацию кабинета `getUserNavItems()`, чипсы письма, разделы
настроек. Не трогать словарь `templates/admin/assets/js/i18n/icon-tags.json` и демо-файлы. Приёмка:
`grep -rho "'icon' => '[a-z0-9-]*'" core modules admin` даёт список только в самой карте; страницы
кабинета рендерят те же глифы, что и до батча (сравнение списка классов `bi-*` до и после скриптом).

### F. Уборка после

- Пройти `.sl-pmf-*` и `.sl-profile-*` на предмет правил, у которых после A–E нет разметки; удалить.
- Пейджер списка ЛС: строка «Всего … на … страницах» дублирует «Показано …» в блоке фильтров;
  решение пользователя — скрыть её только в колонке писем (`.sl-pmf-foot .sl-pager-info`) либо
  сократить формулировку глобально через `_NUMOF`. Открытый вопрос, задать перед батчем.
- Справка `admin/info/*` по кабинету и ЛС: описание текущего состояния, без «что изменилось».
- `php tools/ui-audit.php --store` один раз в самом конце, чтобы базовая линия зафиксировала
  упавшие счётчики.

## 5. Проверки

**По ходу** (после каждого батча, не чаще): `php -l` тронутых файлов;
`php vendor/phpunit/phpunit/phpunit --filter TemplateValidation` после правок шаблонов;
`node tools/ui-shots.mjs --after --only=<страница>` для одной-двух страниц батча; обход Playwright
временным скриптом **в корне репозитория** (ESM ищет playwright от каталога скрипта), скрипт
удаляется сразу после прогона.

**Один раз в конце**, последовательно, без параллели рельса и `phpunit`:

```
php -l …                       # все тронутые PHP
php vendor/bin/phpstan analyse --no-progress core/user.php core/system.php modules/account/index.php
php vendor/bin/php-cs-fixer check --config=.php-cs-fixer.dist.php <тронутые php>
npm run ui:gates
php vendor/phpunit/phpunit/phpunit
set SLAED_UI_USER / SLAED_UI_PASS  и  npm run ui:after
php tools/ui-audit.php --store   # только если все счётчики упали или не изменились
```

Учётные данные стенда в скилле `/browser-debugging`, раздел «Logging in»; без них рельс молча
пропускает все страницы с сессией. Страницы кабинета в манифесте `tools/ui-shots.json`: `profile`,
`settings`, `favorites`, `private`.

**Критерий готовности всего плана.** Одна шапка, одна строка, одна механика сворачивания, одна
карта иконок, один фрагмент ламп, один слот уведомлений; `theme.css` короче, чем 11 024 строки; все
счётчики `ui-audit` не выше базовой линии; поведение страниц кабинета и ЛС в обходе совпадает с
описанным в памяти проекта (`favorites-transfer-plan`, `htmx-confirm-hook`,
`pager-window-semantics`, `chip-icon-gap-standard`).
