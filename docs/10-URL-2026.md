# URL 2026

Work plan for the public addresses of release 8.0: every page of the site gets one readable address without an
`id` — `/files/adaptivnyi-shablon-pure` — kept in one registry of routes; every other form of the same page answers
301 to it, an address once given never points anywhere else. Taken out of `docs/2027-CORE.md` on
2026-10-13 and moved before the release, so the index of a search engine moves once — from the `index.php?…`
addresses of 6.2 straight to the final form.

"Parsing", the inventory stands under "Inventory"; `_routes`, the class `Route` and `filterSlug()` stand as "The
registry" and "The name" describe them; every writer of "When an entity gets and changes its path" gives, moves and

## Decisions

Taken by the owner on 2026-10-13, after the light `id-slug` form of 2026-10-08 was weighed and dropped as a half
measure. Settled; a batch does not reopen them.

| Page | Address |
|---|---|
| Home of a type or a module | `/files`, `/forum`, `/users` |
| Material | `/files/adaptivnyi-shablon-pure` |
| Category of a type | `/files/moduli` |
| Page of a list | `/files/moduli?page=2` |
| Sorting, letter, filter | `/files?sort=pop`, `/files?let=a` |
| Forum topic, forum section | `/forum/modul-poiska`, `/forum/obshchie-voprosy` |
| Profile | `/users/eduard` |
| Poll | `/voting/kak-vam-novyi-dizain` |
| Operations | `/files/add`, `/files/edit/5061`, `/account/login`, `/account/privat` |

- **No `id` in the address of a page.** The `id` stays the identity of the entity; the address is a stored name.
- **One registry of routes.** One table maps a path to an entity — the current path and every former one. One
  uniqueness, one lookup, one place for 301. The price is one indexed query per page view, accepted by the owner; no
  cache in front of it.
- **An address is never reused.** A path once given stays bound to its entity forever: a former path answers 301 to
  the current one, the path of a deleted entity answers 410 and stays taken.
- **The prefix of the type is part of the address**, not the site root: a section is the natural bound of
  uniqueness, keeps forum topics and materials from taking root names for ever, and keeps sections visible as
  folders to `robots.txt` and Search Console. On the migrated production base the root would hold 103 groups of
  equal titles (41 across kinds, "Модули" five times); inside the sections materials and topics hold 64.
- **The separator is a fixed `/`.** No setting: `rewrite`, `sep`, `tsep`, `title`, `ctitle` leave the panel and
  `config/global.php`. A separator that can change rewrites every address of a site at once.
- **Materials and categories of a type share one namespace**: `/files/moduli` is a category, `/files/adaptivnyi-…` a
  material. The category is not in the address of a material, so moving a material keeps its address.
- **The forum works the same way**: topics and sections by name under `/forum`.
- **The profile lives under the list of users**: `/users/eduard`. The operations of `users` (`rules`, `stats`) are
  reserved; the operations of the profile stay under `/account/…`. **A new login moves the profile address**: the
  profile is named by its login, so a rename in the panel gives `/users/<new>` and the old path answers 301 to it
  for ever — it is never handed to the next user who takes the freed login.
- **The address follows the title only until it is first published.** After that it changes only by hand, in the
  field "Адрес" of the form; a new title, category or display name never moves it.
- **`page` replaces `num`** as the page number of a public list; `?num=` answers 301. A `num` that is not a page
  number keeps its name — the activation code of `account` is one. The panel keeps its `num`.
- **301 and canonical live in the core**, in one function of `core/system.php` (`setSeoMove()`) that `setHead()` /
  `getSeoRoute()` use, for `GET` and `HEAD` only (never `POST`, never htmx). An entity page calls it right after the
  read of the entity and the access check, so a redirect never pays for the rest of the page; every other page
  reaches it through `setHead()`. No module carries a check of its own.
- **A private type has no address in the registry.** The materials of a type with `ext` `support` (`help`) keep
  `/help/view/5061` with `noindex`: the title of a request never enters an address, and a guest gets the same 403 for
  every number, existing or not, as today.
- **Transliteration, no Cyrillic in the address:** the letters of all six locales, lowercase, `-` between words.
- **The name of a Node type is permanent**: it is part of every address of the type. The code already keeps it —
  `NodeService::updateNodeType()` writes `title`, `intro`, `ext` and `sort`, never `name`; the plan makes it a
  stated contract.
- AJAX and feeds (`go=…`, `go=rss` included), the panel, `/uploads/` and the module sub-files (`&file=…`) keep their
  addresses: they are not pages for people.

## Design

### The registry

```sql
CREATE TABLE `{prefix}_routes` (
  `id` INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `path` VARCHAR(255) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  `kind` VARCHAR(10) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  `oid` INT UNSIGNED NOT NULL,
  `state` TINYINT UNSIGNED NOT NULL DEFAULT 1,
  `cur` TINYINT UNSIGNED AS (IF(`state` = 1, 1, NULL)) STORED,
  `created` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `path` (`path`),
  UNIQUE KEY `owner` (`kind`, `oid`, `cur`),
  CONSTRAINT `{prefix}_chk_routes_state` CHECK (`state` IN (0, 1, 2))
);
```

- `path` without the leading slash, lowercase, `[a-z0-9-]` after the prefix: `files/adaptivnyi-shablon-pure`.
- `kind`: `type`, `node`, `cat`, `topic`, `user`, `poll`. A Node type has a row of its own (`files`), so a deleted
  type keeps its home and its paths answering 410.
- `state`: `1` current, `0` former (301 to the current path of the same entity), `2` gone (410).
- `cur` is `1` on the current row and `NULL` on every other: MariaDB and MySQL allow many `NULL` in a unique key, so
  `owner` lets an entity hold any number of former rows and **at most one current** — the database refuses a second.
  No foreign key: the rows outlive the entity on purpose.
- `cur` mirrors `state` (`cur = 1` exactly when `state = 1`), so the two columns must never disagree. Batch 1 made
  `cur` a stored generated column of `state`: MariaDB 10.5.2+ and MySQL 8.0.16+, the floor of `setup.php`, both take
  one in a unique key, so no writer — `Route`, a hand edit, a restore — can set them apart; the server refuses a
  written `cur`, and `Backup` already leaves generated columns out of its `INSERT`. A `CHECK` keeps `state` to the
  three values. `SchemaConventionTest` and "Schema conventions" of `docs/NODE.md` list `_routes.cur` among the
  allowed NULLs.
- When an entity is gone, **every** row of it — the current one and all former ones — gets `state = 2` and
  `cur = NULL`.
- **Writes.** The entity and its routes change in **one transaction**: the writer locks the row of the entity
  (`SELECT … FOR UPDATE`, or the `version` check Node already has), turns the old current row into former
  (`state = 0`, `cur = NULL`), inserts the new current row. Two writers racing for the same free path meet the
  unique `path`: the loser takes the next suffix and retries inside its transaction, a bounded number of times.
  Writers without a transaction today get one in batch 2.
- One class `Route` in `core/classes/route.php` owns the table — no second writer anywhere. It finds a path, gives
  an entity its first path, moves it, marks it gone, and answers the current paths of a set of entities in one query.
  Built in batch 1 over the connection (`new Route($db)`, loaded by `core/system.php`, no global instance yet):
  `getRoute($path)` — kind, id, state and the current path of the entity, one query with a self-join;
  `getRouteList($kind, $ids)` — the set lookup; `addRoute($kind, $oid, $prefix, $title)` — the first path, an entity
  that has one keeps it; `setRoute()` — the move, a type never moves; `deleteRoute($kind, $oid)` — every row gone;
  `isRouteReserved($prefix, $name)`; `checkTypeName($name)`. A write inside an open transaction of its writer runs
  behind a savepoint and joins it; otherwise it opens its own. The free suffix is found from one read of the name and
  its suffixes; a racing writer that took a path first answers 1062 on `path`, and the write moves on to the next
  suffix inside the same transaction, at most 20 times. A move to a path the entity held before takes that row back.

### The name

`filterSlug()` transliterates the letters of ru, uk, de, pl, fr from one table (en needs none) — the letters ru and uk
share take the Russian form (`г` → `g`, `и` → `i`), only `і ї є ґ` get their own; the locale of a title is not
known, so one table is the price of one name — lowercases, turns
every run of other characters into one `-`, trims, and cuts to 80 characters: at the last `-` before the limit, or —
when the first 80 characters hold no `-` (one long word) — hard at 80. No `intl`: it is not on every server. An
empty result (a title of symbols only) takes the `id` as its name. A path that is taken — current, former or gone —
or a reserved word takes the first free suffix `-2`, `-3` …. Batch 1 fixed the forms the decision left open: `і` → `i`,
`ї` → `yi`, `є` → `ye`, `ґ` → `g`; `ü` → `ue`, the German form, also in a French title; an apostrophe (`'`, `’`, `ʼ`)
joins its word instead of splitting it (`п’ять` → `pyat`, `l’été` → `lete`). A title is stored escaped (13 materials
and 661 forum topics of the stand carry `&quot;`, `&gt;` or `&lt;`), so `filterSlug()` decodes the entities first and
a writer passes the stored title as it is: `Доработка модуля &quot;shop&quot;` → `dorabotka-modulya-shop`.

**Reserved** within a prefix: the operations of its module — a list in the core, checked by a test against the
`switch` of every module, since the parser cannot load a module to ask it. Reserved for the name of a new Node type,
as an explicit list in the core and never derived from `robots.txt`: the names of the modules, the folders and files
of `public/`, `uploads` (the light path answers `/uploads/…` before the core, so a type of that name could never be
reached), `api` (the prefix `/api/v1/…` of the connector of `docs/2027-CONNECTOR.md`, whose rewrite rule stands
before the fallback to `index.php`), and every `type` row of the registry — the name of a deleted type is never
given again. Batch 1 keeps the lists in `Route`: `OPS` per module (a prefix that is no module there is a Node type and
takes the operations of `getNodeOps()`), `COMMON` for `mode` and `newlang` that `public/index.php` answers under any
name, and `TYPES` for the entries of `public/`, `uploads` and `api`; the modules are their folders.
`RouteRegistryTest` holds the three against the switches, `getNodeOps()`, the `$op` checks of `public/index.php` and

### Parsing

Two stages, because the registry needs the database and the block "Retired addresses" runs before it.

**Stage 1 — the cut, before the database** (`core/security.php`, the block "Retired addresses"). For
`public/index.php` it replaces both the 301 of `/index.php/…` (which today drops the rest of the path and lands on
the root) and the line that sets 404 for any non-root path; for the other scripts (`admin.php`, `setup.php`,
`update.php`) the block keeps today's behaviour. Pure string work, no query, no redirect:

1. Take the path after the base; `/index.php/<rest>` is read as `/<rest>`. A bare `/index.php` keeps its 301 to the
   root.
2. An encoded or non-ASCII byte, or more than five segments — 404 as today.
3. Otherwise keep the segments, lowercased, in a global for stage 2, together with two flags: the raw path differed
   (upper case, a trailing slash, `/index.php/`), and the request came through a path at all.

**Stage 2 — the resolution, after `$db`** (`public/index.php`, before the first `getVar()` of the route), by one
grammar, first match wins:

| Segments | Grammar | Result |
|---|---|---|
| 1 | a type or module of the loaded configuration | its home |
| 2 | type/module + a reserved operation | `op` |
| 2 | anything else | the registry by the full path: current → the page of the entity; former → the page of the entity, marked for 301; gone → 410; none → 404 |
| 3 | type/module + reserved operation + digits | `op` + `id` (`/files/edit/5061`) |
| any | a first segment unknown to the configuration | the registry by the full path (410 of a deleted type); else 404 |

**No 6.2 path form is parsed** (batch 0, 2026-10-13). The production site links only `index.php?…`: its start page
on 2026-10-13 carries 96 links of that form (`index.php?name=faq&op=view&id=4048`,
`index.php?name=forum&op=view&id=16336&last`, `index.php?name=account&op=view&uname=…`) and none of a path or of
`.html`. The only path form 6.2 had is the output filter of `config/config_rewrite.php`, switched by
`$confse['rewrite']`: it turned the printed links into one segment with `.html` (`files-view-123.html`,
`news-cat-2.html`), while the 6.2 `getVar()` asked `getUrlMeta()` for such a path, which answers `false`. The
production log confirms that nothing parsed them: `/news.html` rendered the start page with 200 — the
"long-retired `.html` scheme" of `docs/VERSIONS.md`, 7058 requests in 2.9 days, almost all machines — and since the
owner's decision of 2026-10-06 such a path answers 404 with no table of the old scheme, on production as well
(`/news.html` and `/files-view-1.html` on 2026-10-13). The 6.2 addresses that search engines hold are the query

The page of an entity: `type` → `name=<type>`, `node` → `name=<type>&op=view&id=`, `cat` → `name=<prefix>&cat=`
(a type or `forum`),
`topic` → `name=forum&op=view&id=`, `user` → `name=account&op=view&id=`, `poll` → `name=voting&op=view&id=`. The
removed 6.2 names are not listed anywhere at run time: `_node_legacy` is the only source, asked on the not-found
path only.

`filter_input()` and reads `$_GET` / `$_POST` like its array branch already does; stage 2 writes the route keys into
`$_GET`, and a key the path set wins over the same key of the query. An HTTP test asks a path and checks what
`getVar('get', …)` returns in the module.

### Building

`getSeoUrl()` stays the one builder and follows the table under "Decisions": the stored path of an entity, or the
module, then the operation, then a numeric `id` **in the path** (`/files/add`, `/files/edit/5061`); `page` above 1,

The stored path reaches the builder in the parameters (`'route' => …`); it never looks one up on its own. A list
brings it from a `LEFT JOIN` of the registry (`cur = 1`) in its own query. Where a set of entities is known before
its links are built but no join fits (comment targets, favorites, blocks of mixed kinds), the caller asks
`Route` once for the whole set by `kind` and ids and passes each path on. A call that gets no `route` for an entity
link is a defect: a test counts the queries of every list page against the baseline of batch 0, and a debug check
names the caller. An entity that has no path by design — Draft, Pending, a private type — is passed with
`'route' => null` and gets `/<type>/view/<id>`; only a missing key is the defect. Every address the site prints
starts at the root of the site, `HOME_PATH` (owner, 2026-10-14, see "Addresses from the root"); `getPublicUrl()`
makes it absolute.

### Query parameters

- `num` → `page` only where `num` is the number of a list page; `getPageNumbers()` gets `page` as its key. The
  activation code of `account` and every other `num` keep their name; the panel keeps its `num`.
- `name`, `op`, `id`, `cat`, `uname` leave the query only when the resolved route **absorbs** them: the page of
  `node` 5061 absorbs `name`, `op=view`, `id=5061`, and nothing else. A key the route does not absorb stays.
- Kept as they are: the fields of forms, codes of activation and recovery, tokens, `go=…` endpoints, `sort`, `let`,
  filters.
- Canonical: the page itself. Page 2 and on carry their own canonical with `?page=N`; `?page=1` is the page without
  it.

### One redirect, at the end

The parser never redirects. All the reasons are collected and answered **once**, after the module has loaded the
entity and checked access, by `setSeoMove()`. An entity page calls it right after the read and the access check —
`setNodeView()` today builds the related cards, the poll, the data of the extension and the tree before `setHead()`,
and after the migration the search engines walk every 6.2 address through a 301, so the answer must not pay for any
of that. Every other page (a home, a list) reaches it through `setHead()`. The current path comes from the entity
itself: a path
request already has it from the stage 2 query, a query request (`index.php?name=files&op=view&id=5061`) gets it from
the `LEFT JOIN` of the registry in the read of the entity (`NodeQuery::getNode()`, the topic, the profile, the
poll), so no query is added; every entity page passes it to `setSeoMove()` right after the read, and to `setHead()`
with its other facts for the canonical.

- the target is the canonical address: the configured scheme and host (`forcessl`, `forcehost`), the current path,
  and the query with every absorbed key removed, `num` renamed, `page=1` dropped, every functional key kept;
- reasons: a former path, upper case, a trailing slash, `/index.php/…`, a query address of 6.2 or 8.0
  (`index.php?name=files&op=view&id=5061`, `?uname=`, `?num=`), the wrong scheme or host — any mix of them is one 301;
- `GET` and `HEAD` alike (a `HEAD` gets the same status and `Location` with no body, and still counts no view);
  `POST` and htmx requests are never redirected;
- a request refused by the module (403, 404) is never redirected: the current path of a closed entity — a material
  of a type the visitor may not see — never leaks through the 301 of a former one;
- the early `forcessl` / `forcehost` block in `core/security.php` stays for everything that is not a page of
  `public/index.php` (the `go=…` endpoints, files); a page request leaves it to the final redirect, so the wrong
  host plus an old path is one hop, not two;
- `getNodeLegacyUrl()` answers the current registry path, and its two callers — the not-found branch of
  `setNodeView()` and the unknown-name branch of `public/index.php` — answer through `setSeoMove()` instead of their
  own `setRedirect()`, so the target is absolute on the configured scheme and host and a 6.2 address is one hop as
  well.
