# Идеи 2027

Все сырые идеи по системе SLAED после релиза 8.0, по пунктам. Проработанные планы с решениями и шагами лежат
отдельно: `docs/2027-CONNECTOR.md`, `docs/2027-CORE.md`, `docs/2027-ADMIN-UX.md`, `docs/2027-VINE-MONITOR.md`.

Статус: идеи, ничего не решено и не реализовано.

Как пользоваться:
- новая идея — следующий номер в своём разделе; номера сквозные и не переиспользуются, чтобы «идея 4» всегда значила
  одно и то же;
- пункт — заголовок и несколько строк: что, зачем, чем рискует; без устройства и шагов;
- владелец решает делать — идея переезжает в проработанный план (2027-й или новый план 2026 года в roadmap), а здесь
  остаётся строка «→ перенесена в <файл>» под её номером;
- владелец отказывается — строка «отклонена <дата>: <почему>», чтобы не предлагать её снова.

Номеров строк здесь нет намеренно: каждая ссылка называет функцию, файл или константу, их и искать.

Устройство обновлений — постоянная справка `docs/UPDATE.md`.

  агрегаты, без доменов и `sid`.

### 3. Подробные отчёты об ошибках по согласию

- В 8.0 мастер получает только число ошибок PHP и базы. Здесь — отдельная галочка, по умолчанию выключена:
  отправлять место ошибки (`file:line` от корня, версия, канал журнала), без текста сообщения.
- Перед включением админ видит предпросмотр ровно того, что уйдёт; на мастере — вкладка «Ошибки» с самыми частыми
  местами по версиям.
- Риск: путь и строка — уже сведения о коде сайта; поэтому только по согласию и без текста.

## Шаблоны и формы

Граница шаблонов — `.rules/global.md`, раздел «Template boundary»; справка — `docs/TEMPLATES.md`.

### 4. Пункты выпадающего списка — данными, а не HTML

- Сейчас PHP склеивает HTML опций: около двухсот вызовов фрагмента `select-option` в трёх десятках файлов, итог
  уходит во фрагмент `select` ключом `options_html`.
- Фрагмент `select.html` темы admin уже принимает массив `options` и рисует опции сам, у lite такого нет.
  Свести обе темы к массиву, вызывающие передают данные; `options_html` уходит.
- Зачем: PHP перестаёт собирать разметку, одна форма передачи опций во всех модулях.
- Риск: широкая механическая правка по модулям и админке, проверять каждую форму и её сохранение.

## PHP 8.4

Правила кода — `.rules/global.md`, раздел «PHP and code style». Границы для всех пунктов ниже: без
`declare(strict_types=1)` в коде приложения, маршрутизация панели остаётся на `switch ($op)`, процедурный код ради
новых возможностей в классы не переводится.

### 5. Мелкие средства 8.2–8.4 по всему дереву

- `#[\SensitiveParameter]` на параметрах с паролем, секретом и токеном — сейчас ни одного; значение не попадает в
  трассировку и журнал `Logger`.
- Типизированные константы классов (`private const array OPS` в `Route`), `#[\Override]` на методах классов с
  `implements`.
- `array_all()`, `array_find()`, `array_any()` вместо `preg_grep(..., PREG_GREP_INVERT) === []` в разрезе пути
  `core/security.php` и циклов `foreach` с `break`; `new Route($db)->...` без лишних скобок, как в `setSeoMove()`.
- Зачем: безопасность журналов и типы, которые видит анализатор, без смены поведения.
- Риск: малый, правка механическая; проверять полным прогоном тестов.

### 6. Enum для закрытых наборов чисел

- Числа-состояния, смысл которых держится на памяти: `view` модуля 0/1/2 в проверке доступа `public/index.php`,
  состояния пути `Route::FORMER`/`CURRENT`/`GONE`, режимы `go` 3/4/5, уровень `$conf['error']`.
- Backed enum с методами (`from()` на границе, проверка доступа методом), хранимые значения в базе и конфиге
  остаются числами.
- Следом — слой чтения конфига с типами: `setConfigFile()` хранит каждое значение строкой, отсюда `intval()` и
  `=== '1'` по всему коду.
- Зачем: перепутанное состояние ловит анализатор, а не посетитель.
- Риск: новые типы; по одному набору за раз; слой конфига — отдельная, крупная работа.

### 7. Property hooks, ленивые объекты и новый DOM

- Property hooks и `public private(set)` в классах-значениях `core/classes/*` (Node, API): меньше пар
  геттер/сеттер, инвариант в `set`. Только в существующих классах, когда класс и так меняется.
- Ленивые объекты (`ReflectionClass::newLazyGhost`) для `$prs` и `$tpl`, которые сейчас строятся на каждый запрос,
  AJAX и RSS тоже; вызовы `global $prs` не меняются.
- `Dom\HTMLDocument` / `Dom\XMLDocument` вместо `DOMDocument` в `core/classes/feed.php`: разбор по стандарту HTML5
  и `querySelector`. Парсеру контента не нужно — он экранирует всё, кроме `[usehtml]`.
- Риск: ленивые объекты — только после замера выигрыша; hooks точечно, без волны по всем классам.

### 8. Анализатор вместо подсказок

- phpstan сейчас на уровне 0 и только по `core` и `modules`: изменения в `admin` и плагинах он не видит, а типы
  8.4 без анализа остаются подсказками, которые никто не проверяет.
- Поднимать уровень по шагам (1 → 3 → 5) и добавить `admin`; с этого пункта и начинать, пункты 5–7 после него.
- Потолок типизации — около 800 строк `global` (`$conf`, `$tpl`, `$afile`, `$db` впереди): глобальная переменная
  для анализатора — `mixed`. Это отдельная большая тема, не про версию языка.
- Риск: каждый уровень приносит пачку находок; не прятать их в `ignoreErrors` или базовую линию, а разбирать по
  уровню.
