# Промт: корректное экранирование URL в HTML (`&` → `&amp;`)

## Принцип (единственно верный)
URL — это данные. Данные хранятся и передаются **сырыми** (`&`), а экранируются **один раз на границе вывода в HTML-атрибут** (`{{ href }}`). В билдере URL экранировать нельзя — та же строка идёт в `header('Location: …')`, где нужен сырой `&`.

Итоговое состояние: каждый href в шаблоне выводится через `{{ href }}` (escaped), а любой продюсер URL отдаёт сырой `&`.

## Задача
Привести весь HTML-вывод ссылок к `{{ href }}` (escaped) и всех продюсеров URL — к сырому `&`. Отдельным focused-таском со своим планом и верификацией.

## Шаги
1. **Канонический билдер.** `getSeoUrl()` уже возвращает сырой `&` (`return 'index.php?'.implode('&', $query)`, core/system.php ~3201) — это правильно, оставить. Все ссылки строить через него.
2. **Вывод в шаблонах.** Все URL-атрибуты выводить escaped `{{ href }}` вместо raw `{{{ href }}}`.
3. **Убрать легаси-двойную работу.** ~41 PHP-файл собирает href вручную с зашитым `&amp;`. Заменить на сырой `&` (лучше — на `getSeoUrl`), чтобы escape-на-выводе давал ровно один `&amp;`, а не `&amp;amp;`.

## Границы
- Продюсеры URL (getSeoUrl + ручные) → сырой `&`.
- HTML-вывод → escaped `{{ href }}`.
- Не-HTML контексты (redirect / `Location` / inline-JS) → сырой `&` (не экранировать).

## Scope
- ~8 фрагментов с `{{{ href }}}`.
- ~20 URL-переменных: `title_href`, `category_href`, `comm_href`, `edit_href`, `read_href`, `action_url`, `image_url`, `pager` и др.

## Верификация
- Рендер ключевых страниц каждого модуля; в HTML только `&amp;`, ни одного `&amp;amp;`.
- Переходы по ссылкам и редиректы работают (URL декодируется в сырой `&`).

## Статус
Крошки категорий (`category-crumb.html`) уже приведены к правильному `{{ href }}` → выдают `&amp;`. Остальной сайт мигрируется этим таском.
Память: `project_global_ampersand_href_escaping`.
